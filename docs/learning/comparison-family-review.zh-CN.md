# 为什么这次先不跑因果，而回到AI产品？

我们已经查到了具体原因，不再只是说“对照不够”。

上次剩下792个没有拟议征税重叠的对照，但很多是服装、食品等，不能随便用来代表机械设备。本次按更细的行业和商品类别整理，剩下3组两侧都有商品。逐项看说明，发现类似这样的比较：

- 工厂的装袋秤，对比家里的体重秤。
- 大功率变压器，对比灯具镇流器。
- 灯具零件或弧光灯，对比家用灯泡。

它们分类接近，不代表客户、用途和需求变化相同。因此我没有继续拿它们跑一个看起来漂亮的结果。详细代码和依据见[本阶段决定](../decisions/0069-comparison-family-review.zh-CN.md)。这只是我们当前分组规则下的审查，不是证明世界上没有任何好对照。

## 你需要能解释的问题与参考答案

**之前修时间、修代码白做了吗？** 不是。那些修正让我们发现哪些对照有政策风险，也消除了两项来源错误。它们改善研究依据，但不会把不同用途的商品变成相同商品。

**是不是项目不能用了？** 不是。政策原文检索、贸易数据计算、中文报告和证据核查仍有独立价值。不能把描述性变化写成因果，但也不该把整个AI工程停在反复找对照上。

**因果以后怎么办？** 保留另一条明确路线：结合商品和来源国研究采购来源重组。它回答的是相对变化，仍要设计双重比较、解释替代影响并补足数据，不能承诺一定成功。不会马上全量下载或直接跑回归。

**现在该真正做什么？** 把已有AI组件接成一个完整入口：你用中文提问，它先告诉你理解的范围，你确认后，它查政策、算贸易数据、给出有来源的报告。这个接口已在0066设计，不必再买一个框架，也不需要训练一个新模型。

**这轮提高了AI准确率吗？** 没有新模型调用，不能说提高了准确率。这轮改善的是研究边界。下一步才做AI整合和对应验证，届时分别报告理解是否正确、工具是否执行正确、最终回答是否完整。

下一阶段建议Luna最高：执行已经锁定的AI整合规范；最终语义审查建议Astra中。用户切换模型由用户操作，不自动切换。
