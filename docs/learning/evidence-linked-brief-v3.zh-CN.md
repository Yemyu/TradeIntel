# v3 学习说明：为什么先让程序写清楚事实，再让 AI 做解释

## 先记住一句话

程序负责“数字到底是什么”；AI负责“这些数字对当前问题说明了什么”。

这次改造来自一个真实错误：数据里的 4.7% 是“中国金额占美国从所有来源进口该商品的比例”，模型把它写成了“全球进口额的4.7%”。模型读对了数字，却读错了统计范围。

## 事实目录是什么

`brief_fact_catalog.py` 把每个指标做成一条完整事实，里面同时保存：

- 统计期，例如 `2026-07`；
- 商品 HTS8；
- 美国作为统计报告方；
- 消费进口这个贸易口径；
- 中国原产或所有原产地；
- 分子和分母的指标 ID；
- 数据版本和来源。

所以“4.7%”不再是一个孤立数字，而是完整的：

> 2026年7月，38180000 的中国原产金额占美国从所有来源进口该商品的消费进口金额 4.7061%。

## 政策原文是怎么进入 AI 的

`catalog.json` 同时保存两类材料：

- `policy_facts`：政策身份、税率、日期/入境事件、商品条款，以及明确标记的未知条件和例外；
- `sources`：带来源 ID、文本和 URL 的原文证据。

`messages.json` 会传递这两类业务材料，`evidence_snapshot` 则只留在磁盘做审计，避免把实现元数据一起送给模型。`policy_refs` 是“某商品事实对应哪些政策来源”的连接表，不是新的事实。

## AI 在 v3 中做什么

AI从事实目录里选择与问题有关的事实，用 `fact_ids` 引用它们，再用中文解释事实之间的关系。页面先显示程序生成的完整事实句，再显示 AI 原文。

AI不能自行改数字、改分母、把美国统计扩大成全球，也不能把进口来源占比直接说成整体供应依赖。它可以说“金额榜首和来源占比榜首关注角度不同”，但不能凭这些数据推断因果、税款、损失或未来走势。

## 为什么还要人工审阅

程序能检查：

- 数字、来源和版本是否存在；
- AI引用的事实是否真的对应观察；
- 是否引用了本次商品范围之外的政策资料；
- JSON格式是否完整。

程序不能仅靠关键词判断一句经济话是否合理。因此 v3 仍然返回 `manual_review_required`，不会把结构正确当作内容正确。

数字或“依赖/全球”等边界词现在只会形成 `review_warnings`，不会自动把合法的限定句判成失败；人工仍需判断语义是否越界。

## 为什么离线样例不能直接调用

完整政策原文很长。主案例的消息保守估算约 31,341 tokens，超过当前 8,000 的输入预算，所以 `manifest.json` 会写 `status: blocked_budget`、`callable: false`。这不是程序失败，也不是把政策截短的理由；下一步要由更高推理阶段决定“完整业务视图如何压缩或拆分”，并重新验收预算。

## 本地离线运行

使用真实已登记案例的证据包生成目录，不需要 API：

```bash
.venv/bin/python scripts/prepare_brief_v3_offline.py \
  --bundle tmp/g2-revision1-ready-20260915/development/evidence-bundle.json \
  --question '请解释本月商品的中国原产进口规模与政策范围。' \
  --output /tmp/tradeintel-v3-output
```

输出包括：

- `catalog.json`：带摘要的事实目录；
- `program-report.zh-CN.md`：确定性程序基准；
- `messages.json`：未来可发送给模型的请求，不是模型结果；
- `manifest.json`：明确记录本次 API 调用数为 0。

这些文件可以帮助学习数据工程中的“版本绑定、分母定义、来源追溯和不可静默改写”。本次只是离线原型，尚未接入生产页面，也没有证明 AI 质量已经提升。
