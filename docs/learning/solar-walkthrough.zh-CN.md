# 可以直接打开的单商品离线流程演示

打开项目`web/solar-demo.html`，或在现有本地网站点击研究问题上方“先看一份完整流程演示”。服务器路由为`/demo/solar`，启动命令仍为`.venv/bin/python scripts/run_web.py`。这是一份单商品85414300、2026年6月的离线重放，帮助理解流程，不代表第二案例已经上线或双商品验收通过。

页面按顺序展示：用户问题→真实数据及计算→政策原文→开发助手补核意见→完整重放报告。打开不会调用模型，没有脚本请求；也不会启用第二案例实时问答。第一案例原入口保留。

本次具体补核：原模型说明其他税费时没有明确“如适用”，页面单独给出建议表述，并明确是开发助手审阅意见，不是原模型输出、独立法律审查或已批准结论。没有修改原回答、引用、数据或历史失败状态。

生成命令：`PYTHONPATH=src:. .venv/bin/python scripts/build_solar_demo.py`。从已保存运行资料生成，核对案例、月份、版本一致性及原文绑定；这不是从零下载复现，也不是新的模型成功。静态页面不会随未来数据自动更新。

17项本轮相关测试通过，包括只读页面内容、HTTP入口与原业务回归；尚未做浏览器截图/视觉验收。本轮0API，没有提交或推送。

现在已有可读可打开的具体成果。第二案例实时开放仍需完整双商品内容验收、发布副本与状态切换等收尾，不能把演示页面上线等同于功能全部验收。不要再为这个静态示例不断新增终审阶段。

## 后续页面检查

网页案例选项现在从`/api/cases`读取后台登记，不再硬编码“已开放/候选”。加载失败时禁用提问提交并提示刷新，不猜测状态；候选仍可选择以获取状态说明，后台依然拒绝实际查询。登记开放不代表模型健康或内容已批准，执行时还会验证版本。

本轮38项相关回归测试及页面JavaScript语法检查通过，HTTP检查确认读取案例目录不需要密钥、不暴露本地资源路径。页面内容审计已补充说明单商品重放与双商品失败验证的区别，没有新增API调用或启用候选。

再次尝试浏览器视觉检查时，Cua浏览器请求策略无法加载，工作区也没有可用的本地渲染器；未绕过限制。因此本轮完成了内容、代码和HTTP检查，但不能宣称已经亲眼验收布局。用户可以在自己的环境中打开演示文件确认效果。第二案例仍未达到原定真实整链验收条件，不能仅因页面可打开就解除候选状态。详细记录见[0143内容审计](../decisions/0143-solar-demo-content-audit.zh-CN.md)。
