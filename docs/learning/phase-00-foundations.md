# 第 0 阶段：怎样与 AI 一起完成一个可靠项目

## 这阶段学什么

这不是 Python 语法课。目标是理解整个项目有哪些部分、AI 能完成什么、你必须负责什么，以及怎样检查 AI 的工作。

## 1. 项目的四个部分

```text
真实数据 → 确定性分析工具 → AI 组织和解释 → 用户得到答案
   ↑              ↑                ↑
 数据质量检查    计算结果测试       AI 评估题
```

### 数据层

负责取得、保存、清洗和说明贸易数据。核心问题不是“代码能否运行”，而是数据来自哪里、字段代表什么、有没有缺失或口径变化。

### 分析层

用 SQL 和 Python 完成查询、计算、异常检测与政策分析。这里尽量使用确定性程序：同样的输入应该得到同样的数字。

### AI 层

理解用户问题、选择分析工具、安排调用顺序并解释结果。AI 不负责凭记忆猜贸易数字，也不能绕过分析工具直接宣称政策产生了因果影响。

### 评估层

给数据、分析和 AI 分别设置检查。它负责回答：数据有没有坏、计算有没有错、AI 有没有选错工具、最终表述是否超过证据。

## 2. AI 能自动完成到什么程度

| 工作 | 自动化程度 | 人需要负责什么 |
|---|---|---|
| 创建目录、环境和配置 | 高 | 确认没有污染系统、结构符合项目目标 |
| 编写 Python、SQL 和测试 | 高 | 定义输入输出，检查结果和边界情况 |
| 调用 API、分页和失败重试 | 高 | 确认数据来源、许可、字段含义和完整性 |
| 数据清洗与 HS 映射 | 中 | 决定模糊映射是否可接受，检查异常样本 |
| 选择统计与因果方法 | 中 | 判断问题与假设是否匹配，防止错误解释 |
| 写 Agent 流程和界面 | 高 | 规定允许调用的工具、禁止行为和验收指标 |
| 解释真实经济影响 | 低到中 | 结合领域知识、证据强度和现实背景作最终判断 |
| 决定项目故事和最终结论 | 人主导 | AI 可以起草，但不能替申请者承担真实性责任 |

## 3. 你需要掌握的不是语法，而是任务合同

让 AI 写代码前，应先把任务说明成六部分：

1. **目标**：要解决什么问题；
2. **输入**：数据从哪里来，包含哪些字段；
3. **输出**：需要生成什么文件、表格或指标；
4. **规则**：计算口径和不能违反的限制；
5. **异常情况**：缺失、重复、API 失败时怎么办；
6. **验收标准**：怎样证明已经正确完成。

例如，“帮我读取贸易数据”太模糊。更好的任务是：

> 读取指定 CSV，验证必须包含 reporter、partner 和 trade_value_usd；把金额转换为数值；遇到空值或负数时报出具体行号；输出记录数和总额；用六行样例数据验证结果为 605000。

AI 可以据此写代码，人可以据此检查代码，而不需要从头记忆 `for` 循环语法。

## 4. 为什么 CSV 数字需要转换

这不只是 `int()` 的代码语法问题，而是“数据类型”问题。

CSV 本质是文本文件，所以其中的 `120000` 最初是六个字符。分析系统需要明确知道它是金额，才能正确求和、排序、比较和检查范围。

你不需要记住用 `int()` 还是其他函数，但需要知道数据进入系统时必须：

- 给字段指定正确类型；
- 无法转换时不能悄悄忽略；
- 金额还要考虑单位、货币和小数；
- 测试应检查转换后的总额是否正确。

这是数据工程概念，会直接影响分析结果，因此值得理解；具体语法交给 AI。

## 5. AI 不能替你负责的部分

- AI 不知道一个经济问题是否值得研究，除非我们先定义目标；
- AI 可能误解数据字段，也可能生成能运行但口径错误的代码；
- AI 可以选择一个统计模型，却不能自动保证它满足因果识别假设；
- AI 可以写出很自信的报告，但自信不等于证据充分；
- AI 无法替你对申请材料中的个人贡献和真实性负责。

因此，你的角色不是手工程序员，而是项目的产品负责人、领域判断者和验收者。

## 6. 第 0 阶段的验收

不需要写代码。你只需要能够解释：

1. 数据层、分析层、AI 层和评估层分别负责什么；
2. 为什么 AI 适合写实现代码，却不能独自决定最终经济结论；
3. 一个合格的 AI 开发任务为什么需要输入、输出、规则和验收标准；
4. “数字在 CSV 中是文本”为什么可能影响真实分析。

配套示例 `src/phase_00_read_csv.py` 已由 AI 实现。它用于展示“任务合同 → 实现 → 验证”，不再是手写作业。

## 7. “你需要能够解释的内容”：参考答案

### 1. 数据层、分析层、AI 层和评估层分别负责什么？

数据层负责把真实世界的数据可靠地取得、保存、清洗并说明清楚；分析层负责用确定性的 SQL 或 Python 查询和计算；AI 层负责理解自然语言、选择合适的分析工具并组织回答；评估层负责检查数据、计算和 AI 输出是否达到预先定义的标准。

它们不是四个互相独立的功能。数据层提供可信输入，分析层产生可复核结果，AI 层把结果变成容易使用的交互，评估层从旁边检查前三层有没有越界或出错。

### 2. 为什么 AI 适合写实现代码，却不能独自决定最终经济结论？

AI 很擅长把明确的规则转成代码、补测试和处理重复工作，但它可能误解字段含义、统计假设或现实背景。经济结论还涉及研究问题、证据强度和限制条件，这些不能因为一段代码运行成功就自动成立。

所以 AI 可以起草“怎么算”，你和我共同确认“为什么这样算”和“结果最多能说明什么”。

### 3. 一个合格的 AI 开发任务为什么需要输入、输出、规则和验收标准？

因为“帮我做数据分析”没有明确边界。输入说明数据从哪里来，输出说明要交付什么，规则说明不能改变的口径和限制，验收标准说明如何判断完成且正确。异常情况则告诉 AI 出错时要停下、报告还是重试。

这份任务合同把 AI 的自由生成变成了可检查的工作，也让以后换模型或换实现方式时仍然可以比较结果。

### 4. “数字在 CSV 中是文本”为什么可能影响真实分析？

CSV 只保存字符，不保存“这是金额”或“这是日期”的类型。若金额仍被当作文本，排序可能按字符顺序进行，求和可能失败或变成拼接，空值和负数也可能被悄悄忽略。

因此我们关心的不是 `int()` 这个语法，而是数据进入分析系统时有没有被赋予正确、可验证的业务类型。具体转换代码可以由 AI 写，但类型和验收规则必须由人确认。
