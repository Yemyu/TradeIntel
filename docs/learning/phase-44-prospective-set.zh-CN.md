# Phase 44：什么叫“真正的未见题验收”？

> 最新更正（0112）：这一阶段准备的是候选试卷，审查发现部分题干缺条件、评分程序也有漏洞，因此尚不能用来正式考试。在线验收入口已暂停；下面的“锁定”只是当时保存了文件，不能等同试卷质量已通过。详见[0112](../decisions/0112-prospective-audit.zh-CN.md)。

## 这次审查让你理解什么

比如题目只说“进口额”，产品规则却要求说明“美元消费进口额”。系统追问是合理的，试卷不能把它判错。另一个例子是网络断开：人工误点通过，也不能让程序记成答对。此次先修评分程序和题目条件，GLM还没有参加这套考试；552项旧测试也没有覆盖这些漏洞。已有四道开发题跑通的结果仍然有效。

## 这一阶段在做什么

前面我们用过 0109 的 4 道已知开发题，证明的是“这条流程在我们已经看过的题上能工作”。这不能代表系统遇到新问题也可靠。

这一阶段准备 24 道从未给模型看过的新题，并在模型看到题目之前把题目、正确范围、数据参考值和停止规则全部锁定。这样以后模型第一次回答时，结果才有一点类似考试的意义。

## 24 道题怎么分

- 12 道支持题：要求它完成当前确实支持的政策、贸易或组合任务；
- 6 道澄清题：故意不说清月份、原产地、指标或比较窗口，看它会不会先问问题；
- 6 道边界题：故意要求份额、企业级数据、因果结论、未知国家、未来月份或写入数据库，看它会不会停止越界。

这里的“边界题答对”不是把答案编出来，而是明确告诉用户当前不能做、为什么不能做，并且不执行被偷偷缩小的子问题。

## 为什么参考答案不能发给模型

如果把正确金额、正确月份和期望状态一起放进模型提示里，模型很可能只是照着抄。那样得到的是“提示写得好”，不是“模型真的理解了用户问题”。

所以程序只把用户问题发给规划器；参考值只留在人工审查材料和独立预检脚本里。预检脚本还会直接从另一条 CSV 读取路径重新计算金额，避免“同一段代码自己对自己说正确”。

## 现在有没有调用 API

没有。当前得到的是：题集结构通过、数据参考值通过、旧题没有重复、在线运行需要第二道明确开关。真正的模型验收要在下一阶段审查通过后才开始。
