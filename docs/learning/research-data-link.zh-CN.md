# 分析结果为什么要附固定版本链接？

假设你问的是六月某商品。即使后来数据库补到七月，六月回答仍应指向当时使用的版本，而不是悄悄换成现在的数据。

结构化任务和自由提问的结果现在都会尝试附“查看本次分析使用的数据版本”。程序核对运行记录、证据版本、政策、月份和金额，再校验发布副本。单商品查询还要与快照中的对应商品金额一致。核对不了就不生成链接，不能拿最新版本凑数。

链接页面是同版本完整窗口、全部登记商品的背景页；结果旁边另外写明本次实际月份和商品。背景页范围较大，不等于AI结论适用于整个范围。版本正确也不等于解释正确，原有解释审阅要求不变。

本阶段19项相关测试通过，覆盖固定版本、不查询活动版本、金额错配、商品缺失和旧记录缺版本等情况。未进行新模型调用、未替用户审批。既有缺版本历史记录不修补猜测；新增链接需要运行本身有完整可核对的证据。尚未进行浏览器视觉验收。

下一步应检查完整使用体验：提交具体问题→查看同版数据→审阅解释→导出。优先修复实际断点，不添加泛化评估轮次。

## 链路检查与修复

审阅页面现在也提供同版本数据入口，不必返回提问页面找链接。无法核对版本时显示不可用，仍可对照原始来源资料，不伪造对应关系。修复了缺少版本副本会导致审阅请求异常中断的问题。

导出表格增加月份列；单商品没有分项表时使用该次查询金额，不再输出空表；中国份额按同一行金额重算，缺失/零分母显示未知，不把未知值拼成百分比。旧审阅及原始回答未被修改。

22项Python测试和1项页面脚本测试通过，包含临时目录中的HTTP审阅、导出、撤回导出资格、跨运行隔离；没有替用户批准真实运行。页面测试使用模拟DOM，不是浏览器视觉验收。本次没有新的真实模型调用，也不代表从新提问到导出的生产全链路已重新实测。
