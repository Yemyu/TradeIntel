# Phase 28：为什么模型漏掉月份，程序也要发现

假设你问“看2018年9月和10月”，AI却把它整理成“使用预设的十个月比较”。即使后面的金额全部算对，系统仍然回答了另一个问题。上阶段这种情况会进入待确认页面；本次为常见时间写法加了原话检查，会先要求澄清。

这一步改善的是需求保留。你以后指挥AI做数据项目时，需要同时检查两件事：它算对了没有，以及它算的是不是你要求的范围。大量计算测试通过，也不能替代第二项检查。

## 已确认设置怎样用

可以明确说：“第一批何时生效？沿用已确认的政策资料截止日”。模型提出复用后，程序填入案例保存的2018-07-06，并在预览里标明日期来自设置；用户仍需确认计划。如果又写“改为2019-01-01”，就需要先澄清，不能静默沿用旧日期。

这个日期表示允许使用哪些日期之前公布的资料。它不是强制所有政策都在这一天生效，也不是交易观察月份。当前复用采用明确短语，尚不支持任意聊天记忆或所有同义说法。

## 为什么不能自动判断所有冲突

自然语言可能包含多个日期：“按照2018年的公告，比较2019年的贸易”。程序需要分清各自用途。当前新增检查会对部分复杂问法要求澄清，因此可能比理想产品更保守。它是对已复现漏洞的保护，不是完整的语言理解能力。

## 接下来做什么

下一单元完善政策检索：正确区分历史与现行政策问题，把同页重复证据合并且保留出处，然后检查一个完整问题是否都得到交付。你无需输入密钥；真实模型验证需要等这些规则和新的问题集准备好。

本轮没有训练模型，也没有新因果结果。主要学习点是：用户原话、AI提出的计划、系统采用的设置，这三者必须能够相互核对。
