# 0068：先查清谁真正适合当对照

## 这一步做成了什么？

不是训练AI，也不是重新计算政策效果。这一步查的是：原来准备拿来比较的商品，是否也被政府点过名？

| 核对项 | 实际结果 | 意义 |
| --- | --- | --- |
| 2018年4月拟议名单 | 1,333个HTS8代码 | 当时公开考虑征税的范围 |
| 最终第一批名单 | 818个，全部包含在上述名单里 | 拟议不等于最终第一批实施；余下515个不能因此认定永远没征税 |
| 314个处理候选 | 全部与拟议名单重叠 | 符合政策时间线 |
| 890个对照候选 | 98个有拟议重叠，792个没有 | 98个有预期影响风险；792个也不是自动合格的对照 |
| 2个无法映射的豁免代码 | 找到官方更正，修正后的代码均可映射 | 解决了具体来源问题，而不是猜着补代码 |

这里的候选单位是HS6商品组。组内只要某个HTS8代码被拟议名单点名，就标记为有重叠；不表示整个HS6都被拟议征税。本轮只加风险标记，没有删除候选或改变旧实验成绩。

## 为什么“后来没进第一批”也可能不适合当对照？

假设两家企业都被通知可能加税，最后只有一家真正被加税。另一家此前也可能提前进口、延迟订单或调整供应商。它不一定代表“完全没有政策时会怎样”。

这是风险解释，不是已经证明这98个商品发生了提前反应。我们不能看哪个商品后来走势好，再挑它当对照。

## 两个坏代码是什么问题？

2019年7月9日官方公告第6页明确更正此前的两处代码：

- `8404.40.4000` → `8504.40.4000`，对应注释20(m)(53)。
- `8504.40.0000` → `8504.40.4000`，对应注释20(m)(54)。

旧程序收集了公告里出现的所有代码，没有区分“删掉的旧代码”和“替换后的新代码”。这次单独建立更正记录，保留旧原文。182个不同代码字符串按这两项更正归并为180个，原有的两个未映射项消失。

注意：这不是完整豁免数据库。某些豁免还限定产品尺寸、用途、电流等，不能把整个代码下的商品都当作免税。更正2019年才公布，虽然法律适用追溯到2018年7月6日，也不能说企业在2018年已经知道这份更正。

来源：[官方更正公告](https://www.govinfo.gov/content/pkg/FR-2019-07-09/pdf/2019-14562.pdf)。

## 官方PDF也会读错吗？

会。数据来自官网，不等于提取过程自动正确。公报版PDF的数字与表格线粘连，严格提取只得到1,295个代码。改用官方新闻稿附带的原文件，得到1,333个不重复代码，818个最终代码全部在内，并保留页码、原文行和文件指纹。

没有把两份PDF的机器提取差异冒充政策内容差异；也没有声称逐行人工核对完两份名单。一个代码84807140没有2018明细映射行，明确记录为同版HS前六位范围映射，不编造贸易记录。

来源：[官方拟议名单原文件](https://ustr.gov/sites/default/files/files/Press/Releases/301FRN.pdf)。

## 你需要能解释的问题与参考答案

**现在因果分析成功了吗？** 没有。这次修好了政策身份核对中的两个具体缺口，没有估计关税影响。下一步仍需判断商品用途、政策前走势和推断设计是否支持公平比较。

**是不是只剩792个可用了？** 不是。792个只是没有4月拟议重叠；其他政策、行业用途、共同冲击仍要考虑。98个也未自动删除，是否排除要先确定研究问题与规则。

**必须把所有豁免都弄清才能研究吗？** 不一定。研究“被分到第一批名单的总体影响”，与研究“实际持续缴纳25%额外关税的影响”不是同一个问题。前者不要求把后来豁免的商品全部删掉，后者则需要更细的实际税负资料。

**这一步与AI有什么关系？** 这是AI分析工具的证据基础，不是训练或微调。以后AI若回答某商品何时受什么政策影响，需要保留这些日期、范围和更正关系。本轮新PDF尚未接入原有RAG索引，不能宣称检索功能已经扩充。

## 接下来做什么？

下一阶段推荐Astra中：把风险标记与商品实际用途结合，明确一个有经济意义的比较问题，再决定是否值得启动新的实验。新实验必须先锁定假设、旧基准、防泄漏规则、采纳门槛和停止条件；不原样重跑失败匹配，不为得到好看结果挑样本。

自然语言规划接入已有报告的AI工程任务仍在0066计划中，可独立推进，不因因果结果尚未采纳而取消，也不把本轮来源整理当作AI功能完成。

本轮补存两份小型官方政策PDF，保留29个贸易ZIP；零模型调用、零回归/优化、不推送GitHub。详见[机器结果](../experiments/proposal-scope-audit/summary.json)及[事先规则](../decisions/0068-proposal-and-correction-audit.zh-CN.md)。

验收：新增5项测试，全套368项测试通过（16.331秒）；另行核对输入/输出文件指纹及CSV计数一致。这证明本轮程序按规则执行，不是AI准确率或因果有效性分数。模型理解质量本轮未做新生成测试；业务交付是范围审计，不是政策效果报告。
