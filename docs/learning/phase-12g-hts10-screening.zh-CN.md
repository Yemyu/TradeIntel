# Phase 12g：细分数据到底帮我们解决了什么？

## 先说结论

我们现在确实拥有了政策前29个月的细分数据，而且原始压缩包也保留下来了。但这只解决了“看得更细”的问题，没有自动解决“谁能当对照”的问题。

## 一个简单例子

之前把一个HS6大类看成一盒零件。现在我们把盒子拆开，看到里面每个HTS10零件的金额和月份。这样能发现：有些零件没有直接被List1列入，但同一盒里另一些零件被列入了。

没有直接加税的零件，仍可能因为客户改买它、供应链变化或同一行业冲击而受到影响。所以“代码没在名单上”只能说明“没有直接覆盖”，不能直接等于“干净对照”。

## 17个候选的质量差异

有些候选29个月几乎都有中国记录，金额也比较大；有些候选只有几个月中国有正金额，金额很小。后者不是代码错误，而是现实中该商品的贸易很少或断续。把断续商品补成零，会制造假的趋势。

因此我们把它们当成“待设计候选”，没有直接加入原来的对照组。

## 为什么这一步仍然有价值

即使最后不做新的因果估计，这张细分表也可以支持：

- 更准确的商品范围查询；
- 政策覆盖与未覆盖代码的逐项解释；
- 后续AI/RAG按HTS10、月份和来源回答问题；
- 检查HS6合并是否掩盖了不同商品的行为。

## 下一步要先回答什么

下一阶段不再下载数据，也不先跑模型，而是先决定研究单位：是比较同一个HS6家族内部的政策代码和未覆盖代码，还是只保留完全没有同期政策污染的商品。如果不能讲清楚为什么未覆盖商品没有被间接影响，就停止这条因果路线，但保留细分数据用于描述性分析和AI应用。

你不需要操作终端。原始ZIP会暂时留在项目里，等数据设计基本定稿后再统一讨论是否删除。
