# 第二案例的数据准备与隔离

这次把光伏电池/组件的2025-01至2026-07共19个月数据从已有原包全部提取出来，并通过窗口验收。没有重新下载贸易数据，没有修改第一案例的月表或活动版本，没有调用大模型。

## 为什么要“隔离”

同样问“光伏政策”，可能指2024年的电池组件，也可能指2025年的硅片/多晶硅。两者商品、公告日期、税号和生效条件不同。程序必须先知道查哪个案例，不能遇到新政策就拿旧政策数据顶替。

现在有一份宿主控制的案例配置，明确每个案例的商品表、月表、索引与版本目录。未知案例会拒绝；第二案例仍标记candidate（候选），不能查询。第一案例查询开始前也会检查发布快照所属政策是否正确。

**验收通过为什么还不能用？** 本次验证的是数据文件：月份连续、指纹与清单一致、键不重复、两个登记税号每月存在、细分编码在当月CONCORD中、金额和行数与提取清单一致。它不是独立重新计算全部原始明细，也不是政策条件、跨月编码定义或整套AI报告已验证。

**原包留着有什么好处？** 这次新增两个商品范围，直接重用19个原包就可以提取，不必再下载。原包是完整资源，先前的五税号月表只是从其中筛出来的一部分。

**下一步还缺什么？** 独立政策原文索引、完整事件登记、按案例选择并固定版本的执行路径，以及第二案例发布/查询的正向测试。不能只把candidate改成enabled就声称上线；当前AI入口仍按第一案例设计，版本选择也尚未完成多案例泛化。

数据目录：`data/candidates/solar2024/`；验收结果：`window_validation_2025-01_2026-07.json`。已有功能的回归测试和候选拒绝测试通过，不等于第二案例完整业务验收通过。

## 政策原文也已准备好

现在第二案例有自己的事件登记和四组原文索引：商品描述、税率、生效范围、一般适用限定。检索会一起返回四组，不把一般限定挤出结果。程序核对官方HTML的指纹及每段原文的准确位置，避免改了索引却仍显示“有来源”。

**为什么区分日期？** 公告出版日不一定是首次宣布日，也不是生效日。当前事件登记明确记录2024-09-18为出版日、2024-09-27为生效日，尚未登记的宣布日期留空，不偷用出版日填上。

**已经可以在网页问了吗？** 还不可以。候选政策检索独立测试通过，但正式查询的多案例版本绑定和AI路由未接通。当前80项相关测试通过，包括原文/索引变动、旧案例税号混入和早于出版日的请求；没有新模型调用。

## 后续进度：版本选择已按案例隔离

可以把版本理解为“一份封存的资料包”。以前底层默认找第一案例的资料包，现在会按照所问案例选择版本目录，还会检查包里的政策编号。如果查询已经绑定了一个案例，再要求换成另一个案例，会直接停止，不能偷偷串用。

发布副本的月表、清单和索引路径也已改为读取案例配置。不过第二案例仍是候选，没有开放正式查询；政策检索分发、快照构建和AI问答路由还需要整合。不能把这些底层修复说成第二案例已经上线。

本轮83项相关离线测试通过，包含三个新增的版本隔离检查；它们验证程序行为，不代表模型回答准确率。没有训练模型，也没有新增API调用。下一步要把第二案例自己的政策证据和数据版本接成完整路径，然后再接网页问答。

## 后续进度：第二案例资料包已通过隔离整链测试

第二案例的数据查询现在可以分发到它自己的四组政策原文；快照构建也按案例记录月表、商品、事件、原文索引及来源元数据，不再固定使用第一案例。

我们在临时目录复制真实候选资料，仅在测试作用域里启用第二案例，完成“生成快照 → 封存副本 → 查询19个月 → 取四组政策证据”。旧案例的38180000在这里会被拒绝。破坏临时工作区的来源元数据，已封存查询不变；破坏封存副本，查询立即停止。测试结束恢复配置，真实项目未启用候选，也未修改第一案例资料包。

这意味着“数据和政策能一起查”已经在隔离环境跑通，不代表“网页上用自然语言能问”已经跑通。下一步是让业务规划、允许的参数和网页入口明确选择案例；模糊的“光伏政策”要追问是哪次政策，不能猜。84项相关测试通过，0模型调用；本轮不是训练，也没有新的模型准确率成绩。

## 后续进度：问题入口先分清案例

现在业务问答入口在调用模型、读取版本之前，先做保守的案例判断：

- “光伏政策是什么？”会追问指电池/组件，还是硅片/多晶硅。
- 明确85414300或2024-21217公告，会识别为第二案例；因尚未开放，当前返回验收状态，不借用第一案例。
- 同时出现两个案例，或指定案例与问题冲突，会追问，不自动合并。

这不是训练模型，而是给模型工作流程设置一道可测试的范围检查。旧版没有明确政策线索的普通问题仍保留第一案例默认行为；这不是任意新政策的自动识别能力。

业务流程的提示、数据调用、政策检索和末尾版本核对已传递所选案例，跨月审阅文件也按案例隔离。在临时测试内启用第二案例后，预置模型回答可以生成引用其真实四组原文的政策核查报告。87项相关测试通过，真实API调用0次；预置回答验证接线，不是模型准确率。

正式第二案例仍未开放。下一步还需发布状态语义、网页明确显示所选案例及完整综合简报验证，再进行有预算和停止条件的真实模型验证。

为什么候选也列出来？让你知道第二案例存在但仍不能正式用。选它只返回状态，不会调用模型。模糊问题的追问同样不需要API密钥；之前网页先读密钥的问题已修复。
