# Phase 10r：怎么测AI有没有听懂

## 本阶段做完了什么

- 编写12道语义开发题，覆盖正常请求、否定、引用指令、缺信息、多任务和不支持国家。
- 做好离线预检与历史响应重放评分入口，不访问网络。
- 修复评分边界：模型主动澄清与接口失败分开统计。
- 制定下一批24题内部留出验收规则；**留出题还没建立，真实GLM还没运行**。

## 你需要能够解释的问题与参考答案

**为什么不能看到“请澄清”就认为模型做对了？**

因为网络断开、JSON格式错误也会触发同一句保护提示。真正要测的是模型发现问题缺信息并主动澄清，不是接口出了故障。现在这两类状态分别记录。

**如果模型每个问题都要求澄清，是不是很安全？**

它避免了执行，但也没有完成明确任务。开发集12题中只有3题应该澄清，所以全部澄清只符合3/12的参考，不会被当成优秀表现。

**为什么还要留出题？**

开发题已经影响了设计；做对它们可能只是适应了已知案例。留出题要等方案稳定后冻结，不能一边看答案一边改。内部留出也不等于第三方认证。

**为什么不直接用大模型给自己打分？**

字段、国家、月份等可以先精确对照；否定含义和任务是否遗漏仍需语义审查。只让模型自评可能漏掉它自己的误解。当前脚本不会因为格式和字段一致就宣布模型采纳。

**现在我需要跑什么吗？**

暂时不用。离线预检已经由助手完成。下一步要把真实运行的调用上限、进度日志和安全密钥入口做好，才适合让你启动一次小批测试，避免再次不知道是否运行结束。
