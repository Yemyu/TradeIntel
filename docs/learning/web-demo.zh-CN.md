# 本阶段学习说明：本地中文页面怎么使用

更新：2026-09-14

这一个页面是 TradeShock AI 的“可操作入口”，不是新的模型，也不是把整个项目突然变成实时平台。它把已经验收的政策暴露工具放进一个容易观察的本地网页，让你能看见：输入范围 → 程序查数据 → AI（只有明确点击时）选择后续调查 → 程序生成受约束报告。页面还会显示数据的活动版本和最近一次更新差异。

## 1. 启动页面

在项目根目录打开终端，使用项目自己的虚拟环境：

```bash
.venv/bin/python scripts/run_web.py
```

终端会显示类似 `http://127.0.0.1:8765` 的地址。把这个地址复制到浏览器即可。`127.0.0.1` 表示只在本机提供服务，不会自动发布到互联网。按 `Ctrl-C` 停止页面。

如果端口被占用，可以换一个端口：

```bash
.venv/bin/python scripts/run_web.py --port 8766
```

## 2. 页面上的两类按钮有什么不同

### “查询数据”

这是确定性查询：

1. 你选择开始月份、结束月份、原产地和 HTS8 税号。
2. 页面把这些条件发给本地服务。
3. 服务只允许已登记政策的五个精确 HTS8，并检查月份是否在 2025-01 至 2026-07 的验收窗口内。
4. Python 读取带来源哈希的月度文件，重新计算全部来源金额、中国金额和中国份额。
5. 页面显示月度表、金额条形图和最近月份的分商品拆分。

这里没有“模型猜答案”这一步，所以同样的条件应得到同样的数字。查询结果是美国消费进口的描述性暴露，不是损失额、出口依赖率或政策因果效果。

### “AI 演示”

三个按钮对应三个固定案例：2026-05 单税号、2026-06 保留的格式失败案例、2026-07 五税号整体。点击后浏览器还会再次确认，因为这一步会消耗模型请求。

后端最多发出三次 GLM 请求：

1. **选择范围**：模型选择登记工具以及中国/全部来源两个查询，不允许自行改商品或月份。
2. **选择后续调查方向**：模型只返回 `next_steps`，例如“查其他原产地分布”。它不能把数字、网址或自由经济结论写进这个字段。
3. **无工具对照**：同一个问题直接问模型，作为开发记录中的对照；它不参与报告事实。

随后由程序把真实工具结果、计算出的百分比、政策原文候选证据、来源和硬限制填进 Markdown 报告。因此“模型会不会算对数字”不再决定报告里的数字；模型主要负责理解任务和选择下一步。报告仍标记为“待审阅”，因为这不是独立人工金标，也不证明通用模型在所有问题上都可靠。

### “数据版本更新”

这块不是下载按钮，而是版本指针的可视化。每次刷新先把新快照放进候选区，检查月度覆盖、来源指纹和政策文件是否变化；检查通过后才把它登记为活动版本。页面会告诉你：

- 当前查询核对了哪个活动版本（显示 SHA-256 的短前缀，完整值保存在项目目录）；
- 最近一次是新增月份、修订月份还是删除月份；
- 是否有编码连续性复核、待审查候选或失败记录。

本次回放中，活动版本从 18 个月切换到 19 个月，只新增 `2026-07`，共同月份没有修订，政策登记文件没有变化。页面还展示 `38180000` 的六月到七月可比金额变化，但它只说明名义金额变动，不自动说成关税造成的效果。

如果候选校验失败，旧活动版本指针和独立数据副本保留，工作月表改坏后仍可查询旧副本。发布副本自身损坏时则停止查询。新案例AI报告和确定性查询使用同一个版本读取入口，报告记录版本号。具体说明见 [版本审查](version-binding-review.zh-CN.md)。当前页面不会联网采集或自动发布。

## 3. 页面显示的文件和数据从哪里来

- 政策登记：`data/processed/policy/section301_review2025_event.csv` 和 `section301_review2025_products.csv`。
- 政策原文候选：`data/processed/policy_exposure/policy_corpus.json`，每个段落绑定本地文件哈希和官方网址。
- 贸易月度文件：`data/processed/policy_exposure/monthly/`，由美国 Census 官方 ZIP 提取；原始 ZIP 仍保留在 `data/raw/`，没有在本阶段删除。
- 月度验收：`manifest.json` 和 `window_validation_2025-01_2026-07.json`。读取时如果来源哈希、税号覆盖或金额对不上，页面会报错，不会悄悄补零或继续编一个结果。

## 4. 怎么读页面上的数字

假设选“中国”和“五个税号整体”：

- “全部来源消费进口额”是美国从世界各地进口登记范围商品的金额。
- “中国原产金额”是其中原产地代码为中国的金额。
- “中国占比” = 中国原产金额 ÷ 全部来源金额 × 100%。

它能告诉分析人员“这项登记范围在该月有多大贸易规模、来源结构如何”，可以决定下一步先查哪个商品或来源国；它不能单凭一个份额告诉我们是否短缺、谁能替代、政策造成了多少变化。

## 5. 为什么没有把 API key 放在网页里

浏览器属于用户可见的一侧，放 key 会让任何能打开开发者工具的人拿到密钥。当前页面只在后端读取项目本地的 `.local/glm.json`，健康状态只显示“是否已配置”和模型名称，不显示地址或 key。没有 key 时，确定性查询仍可用，AI 演示应明确失败而不是偷偷改成模拟成功。

## 6. 这一阶段学到的核心概念

| 概念 | 在页面里的具体含义 |
|---|---|
| HTTP 接口 | 浏览器用 URL 和 JSON 请求服务；服务返回数据或明确的错误状态。 |
| 确定性工具 | Python 按固定契约读取和计算，同一输入不会因为模型措辞不同而换数字。 |
| Agent 边界 | 模型可以选择登记工具和后续动作，但不能越过工具读取任意文件或 SQL。 |
| 证据链 | 每个事实都回到政策登记、月度文件、来源 URL 和 SHA-256 哈希。 |
| 失败保留 | 模型格式错或运输失败时保留运行记录，不把失败改写成成功；数据候选校验失败时继续使用旧活动版本。 |
| 版本指针 | 查询固定读取已发布副本，返回对应版本号；副本校验不通过时停止。 |
| 最小权限 | 网页只提供固定接口；报告下载只接受程序生成的运行编号，拒绝路径穿越。 |

## 7. 当前明确没有做的事

页面不支持任意新政策上传、现行全部税率、自动联网更新、因果识别、企业报关裁决或未经审阅的自动发布。下一步若要扩展，必须先增加真实数据覆盖和独立验收，不是把下拉框改成“全部”就算完成。
