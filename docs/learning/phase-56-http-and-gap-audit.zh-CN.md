# Phase 56：程序准备的请求，最后有没有被改变？

## 本轮做了什么？

我们没有连GLM，而是让模拟服务接收程序真正构造的请求。检查中间是否多了参数、换了地址、改了提示词，并检查保存的记录有没有被改。

## 你需要能够解释的问题与参考答案

**问：为什么两组都增加同一个参数也不行？**

答：公平不只是两边一样，还要与事先确定的方案一致。否则你无法解释当时到底用什么设置测出来的。需要新参数可以先登记，不能跑的时候偷偷多出来。

**问：这里的“实际请求”是不是已经请求了GLM？**

答：不是。本轮实际构造了HTTP请求，但由内存里的模拟服务接收，没有发送到外网，也没有扣额度。

**问：gap审核是什么？**

答：AI拆分用户需求时可能漏掉标点或片段。程序不能擅自认定遗漏无关紧要，因此需要先检查。现在保存检查前的内容、提交意见、处理结果，并确认最终用的确实是同一份审核。

**问：这么多测试通过，是否可以算模型成绩？**

答：不可以。它们说明特定程序错误能被拦住；参考答案是否正确、模型新问题答得怎样，仍需要另行复核和真实评测。
