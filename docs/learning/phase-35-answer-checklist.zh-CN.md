# Phase 35：该检查的是回答，不是它分了几行

## 这次查明了什么？

上一轮AI把“什么时候生效、税率多少”放进了一行。我按当时的规则停下来了。但再查代码发现：即使它分成两行，系统也只是给两行贴同一个“等待检查”的状态，并没有真的分别核验答案。

因此，我需要修正之前方案的重点：**分成两行不等于回答了两问；合成一行也不等于漏答。** 旧批次仍保留原来的拒绝记录，不临时改成成功。

## 应当怎么做？

像批改试卷一样，先根据原问题列出必答点，再对照实际答案和材料逐项检查。例如：

| 必答点 | 最终需要核对的内容 |
|---|---|
| 生效时间 | 答案有没有日期，引用的公告是否支持这个日期 |
| 额外税率 | 答案有没有税率，引用是否支持，是否误说成现行税率 |

AI怎么分段可以不同，但两项都必须得到检查。一项没有回答，就不能把整题标成完成。来源里没证据，也不能凭AI说得像真的就通过。

## 你需要能解释的问题与答案

**为什么不让AI自己说“我都答完了”？**

因为它可能没发现自己的遗漏。检查清单应当从你的原问题出发，不是它想答几项就检查几项。当前阶段由审查者核对；程序负责保存记录、检查引用和文件有没有变化。

**这次是在训练模型吗？**

不是。没有调用API，没有训练或微调。我们是在修正应用的验收方法，让“通过”更接近真正答对、答全。

**是不是为了让项目通过而降低标准？**

取消的是不必要的格式门槛；必须答全、事实正确、引用支持的要求没有取消。以后“拆成两行但漏答”必须被拒，“合成一行但两问都有充分证据”可以通过。新规则会另立版本，不能拿来改写之前的成绩。

**现在已经修好了吗？**

还没有实现新的清单功能。本阶段查清了问题，用5项新离线测试复现了边界，并锁定了后续实现规范。连同相关回归26项通过，这不是AI正确率。
