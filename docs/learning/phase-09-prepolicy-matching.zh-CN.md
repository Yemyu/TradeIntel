# Phase 09 学习版：政策前匹配为什么没有通过

> 当前状态：`blocked_before_pretrend`

这一步是一个很重要的真实研究环节：我们没有为了让项目“看起来成功”而放宽标准。覆盖率达标，但政策前平衡性没有达标，所以项目现在停在趋势检验之前。

## 这一阶段到底想解决什么

我们想比较两类商品：

- 处理组：被纳入 Section 301 List 1 的 HS6 商品家族；
- 对照组：没有直接受到冻结清单中同期贸易措施影响的 HS6 商品家族。

如果处理组和对照组在政策前就完全不同，那么政策后的差异可能本来就会发生，不能直接归因于政策。匹配的作用，是先从政策前信息中找出“尽量相似”的对照商品。

它不是让 AI 猜一个答案，也不是让两个商品每个月的数值完全一样，而是把比较起点做得更公平。

## 本阶段实际做了什么

1. 读取 Phase 07 已经通过资格审查的 315 个处理候选和 893 个对照候选。
2. 只使用 2016-01 至 2018-05 的 29 个月；政策后数据在匹配门槛通过前甚至没有加载。
3. 对每个 HS6 补齐缺少的月份。没有记录不等于程序坏了，而是把该月进口额按 0 处理。
4. 对 NAICS3 不唯一的商品不猜行业。284 个处理候选和 829 个对照候选因此进入主匹配。
5. 在同一个三位行业内，用四个政策前特征计算距离，并为每个处理商品选择 3 个最近对照。
6. 检查匹配后的覆盖率和四个连续特征的标准化均值差（SMD）。

## 四个特征用人话怎么理解

| 特征 | 它回答的问题 | 为什么有用 |
|---|---|---|
| `log_mean_monthly_china_import_value` | 这个商品通常从中国进口多少？ | 让大商品和小商品不要只因为金额数量级不同就被错误比较 |
| `pretrend_slope` | 政策前进口是在上升、下降还是基本稳定？ | 避免把原本已经在不同趋势上的商品硬放在一起 |
| `monthly_volatility` | 月度进口是否经常大幅波动？ | 区分稳定供应链和容易跳动的商品 |
| `china_share_of_all_origin_imports` | 美国对这个商品有多依赖中国来源？ | 区分中国是主要供应来源还是只是很小一部分 |

金额特征先取 `log(1 + 金额)`，是为了压缩极端大数；这不是删除大商品，而是让距离计算不被几个超大金额商品完全支配。趋势斜率和波动也在对数金额上计算。中国份额用 29 个月中国总额除以所有来源总额，而不是简单平均每月百分比，这样某个月所有来源都是 0 时不会制造无意义的比例。

## NAICS3 是什么

NAICS 是北美行业分类。`333` 这样的三位代码代表一个较宽的制造业行业。我们要求处理商品和对照商品的 NAICS3 完全相同，相当于先说“必须属于同一个大行业”，再比较规模、趋势和中国依赖度。

有些 HS6 通过映射可以对应多个行业。此时我们不知道应该选哪一个，主分析不猜测，直接记录为 `ambiguous_naics3_candidates`。这是保守做法，牺牲一部分样本换取可解释性。

## 覆盖率通过意味着什么

284 个处理候选各自找到了 3 个对照，因此至少有 2 个对照的比例是：

`284 / 315 = 90.16%`

这个数超过事先冻结的 80% 门槛。分母仍然是全部 315 个处理候选，不能先删掉难匹配的 31 个再计算比例。

覆盖率只回答“有多少处理商品找得到足够的对照”，不回答“这些对照是否足够相似”。所以覆盖率通过并不等于匹配通过。

## SMD 是什么

SMD 是 standardized mean difference，中文常译为“标准化均值差”。它的思路很简单：

1. 比较处理组和加权对照组的平均特征；
2. 再除以匹配前两组的合并标准差；
3. 看差异相对于原始波动是否足够小。

0 表示两组平均值完全相同。绝对值越小越好。本项目事先固定每个连续特征都必须满足 `|SMD| < 0.10`。它不是预测准确率，也不是 AI 得分；它是比较两组起点是否接近的诊断指标。

## 这次的结果

| 特征 | 匹配前 SMD | 匹配后 SMD | 结果 |
|---|---:|---:|---|
| 平均中国进口规模（对数） | -0.238 | 0.002 | 通过 |
| 政策前趋势斜率 | 0.282 | 0.167 | 未通过 |
| 月度波动 | 0.052 | 0.053 | 通过 |
| 中国进口份额 | -1.164 | -0.159 | 未通过 |

这说明当前“同 NAICS3 内选 3 个最近邻”确实改善了进口规模和部分差异，但没有把政策前趋势与中国份额的组平均差异压到 0.10 以内。它不是代码报错，也不是数据下载失败，而是这个匹配规则在当前样本上没有达到我们自己设定的研究标准。

## 为什么最近的三个也可能不够好

“每个处理商品分别找最近的三个”优化的是单个商品到对照的距离；SMD 检查的是整个匹配后群体的平均值。两者不是同一个目标。

例如，一个处理商品可能只能找到中国份额偏高的三个对照。对它单独看，这三个已经是候选池中最近的；但 284 个处理商品累积起来后，对照组平均中国份额仍然偏高，于是整体 SMD 失败。允许对照重复使用也会放大这种累积现象。

## 为什么现在不生成候选面板

`causal_candidate_panel.csv` 是供后续事件研究使用的稳定商品×月份面板。匹配平衡没有通过时继续生成并估计，会让后续数字看起来很精确，却没有满足项目预先承诺的可比性条件。因此这轮只生成：

- [control_candidate_features.csv](/Users/ye/dev/projects/TradeIntel/data/processed/causal/control_candidate_features.csv)：政策前特征；
- [matched_control_pairs.csv](/Users/ye/dev/projects/TradeIntel/data/processed/causal/matched_control_pairs.csv)：匹配关系和距离；
- [matching_balance_report.md](/Users/ye/dev/projects/TradeIntel/data/processed/causal/matching_balance_report.md)：覆盖和平衡审计。

没有生成候选面板，也没有运行事件研究或发布关税因果效果。

## 下一步会怎么做

当前方向已经按停止条件停下。下一步需要重新由 Sol 高设计一份新的、仍然只使用政策前数据的匹配方案，例如比较更多对照数量、加入距离卡尺，或使用能够直接控制组平均特征的加权方法。新的方案必须先写清楚：

- 新假设是什么；
- 和哪一个基准比较；
- 怎样防止数据泄漏；
- 覆盖率和平衡门槛是什么；
- 失败时什么时候停止。

只有新方案在不看政策后结果的前提下通过，才会生成候选面板并进入政策前趋势检验。

## 你需要掌握的重点

你不需要现在背住脚本里的每一行 Python。更重要的是能解释：

- 为什么对照组必须在政策前选择；
- 为什么同一个行业仍可能有不可比的规模、趋势和中国依赖度；
- 覆盖率和 SMD 分别检查什么；
- 为什么“匹配失败”比偷偷降低标准更可信；
- 为什么没有候选面板并不是项目没做完，而是研究设计主动阻止了不可靠的因果结论。
