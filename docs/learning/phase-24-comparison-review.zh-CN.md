# 学习参考：为什么测试通过后还要检查实际问题

这轮发现：如果比较需要的一个月金额缺失，计算器能标出缺失，但报告仍假设一定有数字，结果会报错。现在修复了，报告会写明缺失，并保留你指定的基准月。

## 419项测试通过意味着什么？

意味着当时测试覆盖的情况通过了。之前覆盖了“计算器发现缺失”，没有覆盖“带着缺失结果继续生成完整报告”。这次把后半段也纳入检查。评价项目应同时看正常情况能否交付、出问题时能否解释，而不只看测试数量。

## 为什么不能让模型选择旧模式？

假如你让它算10月相对9月，但它没有填比较方式，旧模式会自己取首尾月份。现在真实自然语言入口要求明确比较字段，省略就报告规划失败，让你看到问题出在哪里。

## 那AI已经一定理解方向了吗？

还没有这样的证据。程序可以核对日期是否合法，却不能仅靠一句话里出现了两个日期就证明方向理解正确。确认预览和后续独立语义测试仍有必要。我们需要检查模型是否准确保留你的要求。

## 接下来三个东西分别干什么？

- 请求清单：记录你问了哪些事，避免少回答一部分；明确参数来自你本次话语还是已确认的设置。
- 政策检索桥接：把中文问题转成能在英文公告里找到相应段落的检索表达，答案仍要依据公告原文。
- 调用记录：记清模型何时被调用、返回了什么、哪里失败、消耗多少。这样运行中断后能检查，而不用反复重新运行。

这些都是让AI应用能交付研究结果的工程工作。因果分析是否可信，仍取决于研究设计和对照证据。
