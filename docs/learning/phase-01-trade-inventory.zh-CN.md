# 第 1 阶段：盘点第一份真实贸易数据（中文版）

> 这是一份学习说明，不要求你手写代码。程序由 AI 编写，你需要理解数据的含义、选择和验证方法。

## 1. 这一步解决什么问题

政策清单只告诉我们“哪些商品被列入 List 1”。它不能告诉我们每个月美国实际从哪些国家进口了多少。

因此我们先取得 Census 的一份真实月度进口档案，只做盘点：

- 文件是否完整；
- 一行数据代表什么；
- 数据覆盖哪个月份；
- 哪些字段能支持我们的研究；
- 原始记录需要怎样汇总。

这一步还不回答“关税是否造成了变化”。

## 2. 这份文件和普通 CSV 有什么不同

下载的 ZIP 里面有一个 `IMP_DETL.TXT`。它是**定长文本**（fixed-width text）：每个字段占用固定的字符位置，而不是用逗号分隔。

例如一行的前几段依次是：

| 位置 | 内容 |
|---|---|
| 1–10 | 10 位 HTS 商品编码 |
| 11–14 | 4 位原产国代码 |
| 23–26 | 年份 |
| 27–28 | 月份 |
| 74–88 | 进入消费的进口金额 |

“固定位置”是来源方的数据格式决定的，不是我们随便选择的代码写法。AI 可以负责按位置读取，但人必须知道每个位置的业务含义。

## 3. 为什么一行还不能直接用于分析

原始一行还拆分到了国家子代码、入境地区和税率条款等更细的层级。同一个“商品 × 国家 × 月份”可能有多行。

所以我们需要把相同的：

> 商品编码 + 原产国 + 月份

的金额加总，才能得到分析表中的一行。

这就是“汇总粒度”（grain）的概念：**先声明一行代表什么，再决定哪些原始行应该合并。**

## 4. 本次盘点结果

使用 2018 年 7 月档案后，得到：

- 原始明细：1,716,983 行；
- 与 List 1 清单匹配：305,647 行；
- 匹配后的商品—国家组合：约 3 万组；
- 覆盖 211 个原产国；
- 818 个政策税号中，812 个当月出现了贸易记录，6 个没有记录；
- 所有匹配记录的进入消费金额合计约 395.6 亿美元；
- 其中中国约 25.7 亿美元。

“6 个税号没有记录”只说明这个月没有观察到对应贸易记录。它不等于数据缺失，也不等于商品永远没有贸易。

## 5. AI 做什么，人做什么

AI 负责：

- 从 ZIP 中读取定长文本；
- 按官方字段位置解析；
- 用已审核的 818 个税号筛选；
- 汇总金额；
- 生成报告和测试。

你需要负责理解和检查：

- 为什么选择“进入消费金额”这个口径；
- 为什么不能把一行直接当作商品—国家—月份；
- 为什么“没有记录”和“数据缺失”不同；
- 这个盘点结果为什么还不能证明政策造成了变化。

## 6. 本阶段的验收

你不需要背固定位置，也不需要记住 Python 语法。你只需要能够说明：

1. 政策表和贸易表分别回答什么问题；
2. 为什么原始贸易明细需要汇总；
3. 为什么金额口径必须在数据契约中明确；
4. 为什么一次月度盘点不能直接推出因果结论。

完成这一步后，下一步才是把 2016–2019 年 48 个月的文件按同一规则整理出来。
