# 现在怎样使用 TradeShock

这是本机已有数据上的中文终端入口。模型负责理解问题和解释政策；程序读取贸易数据、计算金额与变化率。你要检查的是它理解的范围是否符合你的问题。

在终端运行下面两行。项目会读取已保存的本地密钥，无需重新输入。示例预计调用两次模型：一次理解问题，一次生成政策回答；只有确认后才执行后者。

```bash
cd /Users/ye/dev/projects/TradeIntel
TRADEINTEL_MODEL_TIMEOUT=180 .venv/bin/python scripts/run_unified_research.py --question '第一批关税何时生效，额外税率是多少？政策资料截止日是2018-07-06；查询其他原产地整体2018-09和2018-10的美元消费进口额，比较2018-10相对于2018-09，只做描述性比较，不做因果分析；第一批关税，政策整体范围。' --confirm --generate
```

出现待确认计划后，看四件事：国家范围、商品范围、月份、比较方向。这次应该是“不含中国的其他原产地、List1暴露整体、2018年9月和10月、10月相对于9月”。政策文件截止日是另一项限制，不是贸易月份。

确认正确就输入`yes`回车；其他输入会取消。末尾`report`后面的路径就是中文报告，用Codex打开该文件即可。计划、源文和结果会一起留在本次输出目录。默认输出在项目`tmp/unified-research/`。

仅看计划可以去掉`--confirm --generate`，但仍需一次规划调用。之后重新启动命令会重新规划，所以日常建议直接用上面的交互模式，看完计划当场确认。`--verbose`才显示完整JSON。

## 你需要理解的三个问题及答案

**为什么还要确认？** AI可能把“中国”理解为“其他国家”，或者把比较方向反过来。确认是在数据查询前检查研究范围，并不要求你看代码。

**为什么完成后仍写“草稿”？** 文件生成成功不等于每个政策句子都正确。0140示例有额外宿主审核记录；你输入的新问题产生的新报告需要单独核对引用，不会自动继承旧案例的审核通过状态。

**这次修复帮我解决什么？** 日常入口现在会复用本地密钥，显示中文范围预览，并使用0140验证过的政策提示和时间换算。原本这些改进只在开发测试入口中生效，使用普通入口时没有全部跟上。

## 你现在最需要理解的一个真实例子

“以10月为基准，看9月变化”和“以9月为基准，看10月变化”不是同一个问题：前者用9月减10月、再除以10月；后者反过来。AI在这次验收中确实把前者理解反了，系统因另一项引文错误拦住它，没有给出错误报告。

因此，看见它找到原话、输出格式正确，还不代表理解正确。你确认前要检查预览中的“某月相对于某月”；顺序不对就不要输入yes。这轮是在检查软件，不是在出题训练GLM：没有更新模型参数，下一步要改善的是程序对错误理解的保护。

现在已经加入这层保护：比如你写“以2018-10为基准，比较2018-09”，模型却给出相反方向，入口会直接停下来说明不一致，不会替它改答案。月份请写完整的`YYYY-MM`，比较引文可使用上面的“以……为基准，比较……”或“2018-09相对于2018-10”。暂时识别不了的表达也会暂停，请按提示重新明确；这是避免错误执行，不代表数据库坏了。

正确方向的程序计算已离线验证，但没有重新调用GLM验证它能否一次理解正确。因此上一轮的一题失败仍然保留，不改成六题全通过。

## 运行前检查配套数据

普通Git clone不会带上两个政策PDF和约45 MB的HS6贸易面板。第一次运行或换电脑时，先在项目根目录执行：

```bash
.venv/bin/python scripts/verify_portable_data.py
```

看到`"status": "ready"`才表示这四个文件存在且指纹一致。出现`incomplete`或哈希不一致时，查看[data/PORTABLE_DATA_MANIFEST.json](../../data/PORTABLE_DATA_MANIFEST.json)中的公开来源和生成脚本；核验命令本身不会替你下载或覆盖文件。
