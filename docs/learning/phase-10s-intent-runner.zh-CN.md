# Phase 10s：把语义测试安全地跑一次

## 本阶段完成情况

已经实现并冻结12题真实运行器，但刚才只做了离线预检，没有调用GLM。当前运行配置是：GLM-4.5-Air、temperature 0、每题一次请求、最多12次、没有任何数据工具、遇到网络/鉴权错误立即停止。

195项本地测试通过；旧v2.1验收仍保持原样。运行器会逐题打印进度，同时写入两个文件：一个汇总JSON、一个逐行日志JSONL。日志不保存API Key，结果不会覆盖旧运行。

## 你需要理解的运行逻辑

1. 程序先核对题目、提示词、模型适配器和运行器的SHA-256指纹；版本不一致就不花钱调用。
2. 每题只把“系统规则 + 用户问题”发给模型，不发参考答案、题号、类别，也不给贸易工具。
3. 模型只能返回“proposal（待确认理解）”或“clarify（需要澄清）”。它不能查询数据，也不能执行SQL。
4. 每题结果立刻写日志并刷新磁盘；中断时已完成的题仍保留，并有`run_finished`状态。
5. 运行完成只表示收集到了12份模型输出，不表示模型已通过验收，也不自动接入正式AI项目。

没有问题。当前阶段代码和离线检查已经完成，不会因为等待而丢失。不要重复运行同一个输出文件；每次运行器都会要求新文件名。真实运行完成前，不应修改冻结题目、提示或评分规则。

## 你需要能够解释的问题与参考答案

**为什么这次比之前的验收短？**

之前48份是工具型AI的完整任务验收；这次只测“AI能否把自然语言整理成请求”，而且不让它碰数据。把问题拆开，才能知道错误发生在理解层还是取数层。

**为什么不能让它顺便查数据？**

如果解析和执行同时发生，出现错误时无法判断是理解错、工具选错还是数据报告错。先锁定理解，再由确认后的请求进入执行流程，问题更容易追踪。

**看到模型输出后是不是马上采用？**

不是。我要先检查是否保留国家、月份、指标、粒度和否定语义；还要区分主动澄清和接口失败。通过也只代表可以继续保留“待确认”步骤，不代表取消确认。
