# Phase 27 学习说明：为什么要登记案例设置和比较窗口

## 这一步到底做了什么？

上一阶段已经有“用户提问 → AI 生成计划 → 预览 → 用户确认 → 读取数据”的流程。本阶段补的是计划里的两个容易被忽略的基础问题：

1. **案例设置**：这次研究固定的是美国进口、Section 301 List 1、进入消费进口额、只读，而且不估计因果效果。它们不应每次让 AI 自己猜。
2. **登记窗口**：例如 `immediate_post_same_months` 代表 2017 年 8–12 月与 2018 年 8–12 月的同期比较。以前这些月份隐藏在旧摘要里；现在单独登记，预览时可以直接看见。

## 用通俗的话理解“确认设置”

可以把它理解成研究项目的“题目封面”。AI 可以帮忙读懂用户说的“看关税前后变化”，但不能自行把进口国改成中国、把金额改成数量、把描述性变化改成因果结论。宿主保存的 `case_settings` 就像一张不可由模型改写的范围卡。

这不是把 AI 训练成经济学家，而是在 AI 外面加一层规则：

```text
AI：理解用户说了什么
宿主：检查是否落在已经确认的研究口径内
程序：按固定公式读取和计算
```

## 什么是“登记窗口”？

研究中的窗口就是“拿哪些月份和哪些月份比较”。例如：

```text
参考组：2017-08、09、10、11、12
当前组：2018-08、09、10、11、12
```

“登记”表示这组月份已经由项目设计确定并写入文件，而不是模型临时想到一组日期。“同期”表示两个窗口的日历月份相同；它有助于做描述性对照，但不能自动消除所有经济差异。

## 为什么要单独放一个元数据文件？

元数据可以理解成“数据的说明卡”，不是金额本身。本阶段的文件只包含：

- 比较 ID 和两组月份；
- 这组窗口想说明什么；
- 当前覆盖可比性检查的状态和局限；
- 它对应哪一版统计摘要的 SHA-256 指纹。

这样做有两个好处。第一，用户可以追溯窗口来源；第二，加载窗口定义时不会因为顺便打开统计摘要而把金额提前带入计划阶段。指纹不匹配时，程序会停下来，而不是悄悄使用新旧混杂的文件。

## AI 在这里做什么，不能做什么？

AI 可以从自然语言中识别“我要用登记同期窗口比较”并提出一个计划。它不能：

- 把 `2017-08` 偷换成 `2017-09`；
- 在用户已经给出月份时偷偷替换成登记月份；
- 因为比较结果存在，就声称政策造成了变化；
- 把元数据中的解释当作模型自己证明的经济结论。

如果用户明确选择登记 ID 但没有手写月份，宿主才会派生完整月份，并在预览中展示 `trade.months` 的来源和规则。若用户写了冲突月份，流程会停止，要求重新确认。

## 这和“训练模型”有什么区别？

没有训练。训练会改变模型参数，需要训练数据、验证集和训练过程；本阶段只是在应用层建立可追溯的配置和校验。它提升的是“系统不会悄悄换口径”的可靠性，不是模型语言能力或预测准确率。

## 本阶段学到的工程概念

### 1. 配置（setting）和用户输入不是一回事

用户输入可能含糊，配置是项目已经确认的边界。把边界单独记录，能避免 AI 的猜测覆盖研究设计。

### 2. 元数据（metadata）和数据（data）不是一回事

月份、来源、版本、局限属于元数据；进口金额属于数据。先看元数据可以决定“能不能做”，不等于已经读取金额。

### 3. 指纹（SHA-256）是版本封条

同一个文件只要内容改变，指纹通常就会改变。程序用它确认窗口说明和统计摘要仍然属于同一版本。指纹不能证明研究设计正确，只能证明文件没有被无声替换。

### 4. 派生参数必须有规则和来源

`trade.months` 现在可能是用户明确写出的，也可能是登记窗口派生的。两者在 provenance 里区分，后续审查时能回答“这个月份是谁决定的”。
