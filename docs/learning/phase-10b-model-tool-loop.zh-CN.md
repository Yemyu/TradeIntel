# Phase 10b 学习版：模型怎样调用工具，而不是自己编数字

> 当前状态：供应商无关的模型—工具循环、因果安全后卫和 HTTP 适配器已完成离线测试；真实 provider 接入与评估待下一阶段

## 先理解“循环”

一次工具型问答不是“模型直接写答案”，而是一个很短的循环：

1. 用户提出问题；
2. 模型从固定清单选择一个或多个工具；
3. Python 执行工具并把结构化结果回传；
4. 模型根据结果写最终文字；
5. 安全后卫检查最终文字有没有越过因果状态。

模型可以决定“查什么”，但工具决定“数字是多少”。如果模型没有调用工具，系统不会把它的自由发挥当成有证据的答案。

## 为什么现在不直接绑定某家模型

不同模型服务商的请求格式不同，但我们需要的核心只有两种消息：普通文本和工具调用。`ChatModel` 接口把这部分抽象出来，`model_adapter.py` 再把它翻译成 OpenAI-compatible HTTP 格式，后面可以切换远程或本地兼容服务，而不用重写工具和测试。

这也是学习上的重要边界：模型供应商是可替换的工程选择；工具输入输出、来源链和因果拒答是不能随便改变的研究规则。

## 安全后卫做什么

即使模型收到 `blocked_before_pretrend_v3`，也可能写出“关税导致了下降”。因此代码在最终文字离开系统前再次检查：

- 问题是否在问因果；
- 是否拿到了 `get_causal_readiness`；
- 因果状态是否 blocked；
- 模型文字是否出现没有拒绝语气的因果断言。

一旦同时满足，系统会丢弃那句越界文字，换成明确的拒答，并在结果中记录 `safety_guard_triggered=true`。这不是为了让模型“看起来更聪明”，而是把不能越过的权限放在确定性代码里。

## 为什么要有 Mock 模型

现在没有把 API 密钥写进仓库，也没有让测试依赖网络。`MockModel` 只模拟两步：先请求工具，再生成一段文字；它在因果问题上故意输出错误断言，用来证明安全后卫确实能拦截。

运行演示：

```bash
source .venv/bin/activate
python scripts/run_tradeintel_ai.py --mock-agent "关税导致中国进口下降了吗？"
```

观察三个字段：

- `tool_results`：模型实际请求了哪些固定工具；
- `safety_guard_triggered`：是否拦截了越界文字；
- `evidence_bundle.safety`：最终证据包是否仍然禁止因果语言。

## 你需要掌握的重点

- **模型适配器**：把某个服务商的消息格式转换成项目统一的 `ModelResponse`。
- **工具调用**：模型发出函数名和参数请求，不等于函数已经成功；程序必须验证参数并返回错误或证据。
- **最大轮数**：防止模型不断调用工具造成死循环和成本失控。
- **安全后卫**：把高风险规则从 prompt 中拿出来，交给可测试的确定性代码。

当前这一步仍然没有训练模型、没有 RAG、没有多 Agent。先把一个可解释的工具循环跑通，才知道以后增加框架是否真的有价值。
