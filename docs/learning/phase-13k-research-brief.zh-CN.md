# 整合阶段：终于把贸易数据与政策解释放进同一份报告

## 先说你现在得到什么

以前是分别运行贸易查询、政策检索和AI试验；这次新增一个统一入口，生成一份中文研究简报。你明确选择月份、原产地及政策问题，核对范围后，它会完成：

1. 检查现有数据能否回答，不能就停，不擅自换问题。
2. 查询真实贸易金额，计算所选月份合计及首末月变化。
3. 从固定政策资料库找相关段落，补充同页上下文。
4. 可选调用GLM解释政策，每条主张带证据编号。
5. 把数据、AI原话、审查提醒和不能得出的结论合成报告。

它不是只测试“JSON能否读出来”了；但仍是实验性、需核查的研究报告入口，不是最终完成的自主研究助手。

## 看一个实际例子

先打开[这份实际中文报告](../experiments/phase13k-delivery/report.zh-CN.md)，无需自己运行终端。报告中AI原话保留；以下说明帮你理解和审查它。

本次问题：第一批公告的公布日期与关税生效日期是否相同？同时展示2018年9月、10月其他原产地的美国进口额。

| 部分 | 本次结果 | 谁完成 |
|---|---|---|
| 9月进口额 | 36,587,820,118美元 | 已有贸易数据工具 |
| 10月进口额 | 41,012,723,839美元 | 已有贸易数据工具 |
| 所选两月合计 | 77,600,543,957美元 | 程序计算 |
| 10月相对9月变化 | +4,424,903,721美元，+12.09% | 程序计算 |
| 政策解释 | 模型区分了公告出版日6月20日与生效日7月6日 | GLM根据文档生成 |
| 因果结论 | 没有估计，不能说增长由关税导致 | 研究边界 |

“公布”有口语歧义：本次6月20日是所引用《联邦公报》公告的出版日期，不应理解成6月15日政策宣布事件。日期信息分别来自引用元数据和原文生效条款。模型原话保存，开发审查的这条补充说明不偷偷混进模型原答案。

金额口径是List 1暴露商品范围，而不是所有美国进口商品，也不是逐笔实际被征税的交易。原产地选的是“中国以外整体”，不是某个单独国家。政策原文解释对中国产品的规则，并不表示其他原产地也适用这一附加税。

## 你需要理解的问题与参考答案

**这就是训练AI吗？** 不是。没有修改GLM参数。我们在改善应用：给它什么资料、允许它做什么、如何检查输出、如何呈现结果。这叫检索增强生成与工作流整合，不等于微调。

**为什么金额不让AI直接写？** 算术与数据库查询有明确规则，交给程序更容易核验。模型擅长把资料组织成解释，但可能编错数字。报告把两类职责分开。

**这次是不是已经有RAG？** 有一个有限资料库的词法RAG路径：BM25找段落→同页扩窗→把段落提供给模型→附上引用。RAG不要求必须用向量数据库。现在没有向量检索、重排序模型或完整政策数据库，不应该写成已经实现。

**为什么还要确认范围？** “贸易下降了吗”没有说明哪些商品、哪个原产地、哪些月份。先锁定这些条件，可以避免模型答对了数字却答错了问题。本入口使用明确选项，不声称已经自动理解复杂自然语言意图。

**报告中的政策资料截止日为什么比贸易月份早？** 一个限制能引用哪些政策文件，一个指定要观察哪段历史贸易数据。它们不是同一种日期。这个功能也不是严格的历史实时回测，因为没有重建各时点的数据修订版本。

**模型调用成功，就等于答案正确？** 不等于。本次正常结束、有引用，逐条开发检查未发现日期事实错误；但只是一例，不能得出总体准确率。表述提醒没有报警也不等于语义审定通过。

**离线版本是不是假结果？** 不是。贸易数据与计算都是真实的，只是不生成AI政策主张，而展示候选原文。模拟测试用假响应检查故障处理，另行标注；不把模拟当真实成绩。

## 怎么用

入口：`scripts/run_research_brief.py`。下面命令先预览，不查金额或调用模型；能力预检可以读取本地覆盖和边界元数据。

```bash
.venv/bin/python scripts/run_research_brief.py \
  --question '第一批公告的公布日期与关税生效日期相同吗？请区分这两个日期。' \
  --months 2018-09 2018-10 --origin other_origins
```

核对后加 `--confirm`，生成零API报告。再加 `--generate` 才请求GLM；最多一次，不自动重试。没有政策候选资料时不要求密钥。密钥隐藏输入、不保存，不需要发到聊天里。

每次产生新目录，里面有 `report.zh-CN.md`（给你看）、`result.json`（完整证据记录）；真实调用另保留原始响应、格式规范化后的响应、调用用量。旧目录不能覆盖。原始压缩包没有删除，本阶段也没有推送GitHub。

真实GLM仅1次：正常结束，3条政策主张，2,655 tokens，6.142秒。全套测试是工程回归，不是AI准确率；这个样例也不是盲测。没有重新跑旧失败批次，没有修改其成绩。

下一大阶段建议Astra中：把已有自然语言规划与这个报告入口连接起来，检查从“一个完整业务问题”到“用户确认范围”再到“报告”的端到端可靠性，并整理可演示案例。需要方法判断与整体审查，不再按一个格式修补拆阶段。因果研究仍是一条独立、尚未解决的研究线，不能用AI界面完成来替代它。
