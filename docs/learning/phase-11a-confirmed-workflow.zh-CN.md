# Phase 11a：从需求预览到证据报告

## 本阶段完成什么

新增本地交互入口，将已有解析、中文预览、能力拒绝和结构化证据执行连接起来。先展示待确认理解；只有输入“确认”，程序才进入只读查询。取消、解析失败、必要澄清或明确拒绝都不会进入查询。

本阶段未调用API、未改旧实验和成绩，也没有推送GitHub。端到端测试使用模拟模型或已归档响应，程序化输入的确认只是测试，不代表你本人确认了某条业务查询。真实模型模式入口已实现，但本阶段没有实测新的在线会话。

## 如何体验（不需要Key）

在项目目录运行：

```sh
.venv/bin/python scripts/run_confirmed_workflow.py --demo
```

演示会明确标注使用归档H04响应，并展示“解释三种商品计数口径”的理解。看过之后输入“确认”，得到由本地证据生成的报告；其他输入取消。关闭终端也不会自动确认。

演示不是让模型重新回答，也不是虚构证据：需求解析使用旧响应，确认后的报告调用现有本地证据模块生成。

不带`--demo`时使用项目环境变量中的模型配置，接受新问题并进行一次解析。为避免密钥误发，当前入口仅接受已有智谱API地址。尚未配置时会停止，不要求把Key写入代码。命令行输出是本阶段交付形式，尚无网页或多人服务。

## 你需要能够解释的问题（附答案）

### 1. 为什么确认后不能再给程序另一份请求？

否则用户确认的是中国某月，执行时可能被换成别的范围。现在程序在内存中保留请求副本，确认只匹配一次性标识，然后执行这份副本。展示内容被外部修改也不会改掉保存的请求。重新提问会使旧确认失效。

### 2. 确认意味着模型已经验证正确吗？

不意味着。`user_confirmed`只记录用户选择继续；`intent_verified`仍为false，质量验收指标也不改。用户确认不能替代独立测试或事实证据。

### 3. 确认之后，AI能随便写SQL吗？

这个入口不会让模型生成或执行SQL。模型负责提出结构化需求，宿主程序按固定任务选择登记只读工具，再核对范围、缺失、金额合计和证据。现有能力模块会在执行时再次检查请求，不因为确认就允许删除或不支持的范围。

### 4. 为什么执行失败也消耗一次确认？

避免程序在用户没有再次查看的情况下重复执行。同一个标识只能尝试一次；失败后应先检查原因，再重新预览和确认。本地流程仅查询，但仍采用清楚的一次性规则。

### 5. 这是生产级安全系统了吗？

不是。本阶段是本地、单用户、单进程边界。它不防御拥有本机进程控制权的人，也不包含远程身份认证、会话隔离或网页权限系统。关闭程序会失去待确认状态，不把随机标识当作可跨进程使用的凭据。
