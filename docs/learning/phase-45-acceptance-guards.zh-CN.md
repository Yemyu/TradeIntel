# Phase 45：为什么要先做“验收保护层”

## 这一阶段在学什么

前面的 0112 审查发现，程序即使保存了文件，也可能把“连接失败”或“回答没有
完整交付”交给人工按钮，人工一按通过，批次就被误记为成功。这个阶段先解决的
不是模型聪不聪明，而是**什么结果才有资格被评价**。

可以把它想成医院的检验报告：医生可以解释报告，但不能把“样本没送到实验室”
改写成“检验阴性”。

## 你需要掌握的几个概念

### 1. 硬门槛和人工审查不是一回事

硬门槛是程序可以确定的事实，例如：网络连接断了、响应不是完整结构、交付文件
缺失、题目要求澄清却拿到了可执行 token。人工可以对业务含义发表意见，但不能
推翻这些基础事实。

### 2. `reserved` 是什么

调用模型之前，账本先写一行 `reserved`。这样即使模型超时、电脑断电或程序被
按停，也知道这次调用已经尝试过，不能偷偷再发一次。调用返回后才补充用量、耗时
和返回状态。

### 3. 为什么“用量未知”不能当作 0

供应商没有返回 token 用量，不代表消耗了 0。若把未知当 0，累计预算可能被悄悄
突破，所以本项目直接停止，并把原因写成 `unknown_usage`。

### 4. `not_run` 为什么要保留

假设 24 道题做到第 3 题网络断了，剩下 21 题不是“答错”，也不是“答对”，而是
没有运行。它们必须继续留在分母中，否则报告会看起来比实际更好。

### 5. 文件哈希有什么用

冻结时给运行器、提示、题目、参考、语料和数据各算 SHA-256。下一次调用前再算一
遍；只要其中一个字节变了，就停止。这相当于先给研究材料盖封条，防止“改完再跑”
却仍沿用旧成绩。

## 这次实际做了什么

- 写了通用验收保护模块，而不是修改真实模型提示；
- 写了 11 个合成反例，专门测试恶意审查、串改、未知用量、失败状态、原始材料脱敏和预算边界；
- 当时最终完整工程测试为 566 项，0 API；后续漏洞和修复见[Phase 46](phase-46-review-vs-return.zh-CN.md)；
- 0111 在线入口继续保持禁用。

## 当前限制

这些测试只证明“明显的流程错误不会被当成成功”。它们不能证明模型理解了题目，
不能证明政策引文在截止日前可得，也不能证明因果分析成立。下一阶段必须由更高
推理模型复核边界，再决定正式题目和接线方式。
