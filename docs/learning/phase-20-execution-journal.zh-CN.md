# 本阶段学习：为什么要记录“每一部分”而不是只看最后结果

## obligation 是什么？

它就是用户问题里的一个小任务。比如一句话同时要求“解释政策”和“列出两个月金额”，系统会把它拆成政策任务和贸易任务。每个任务都有自己的状态，避免一边成功时看起来像整句都完成了。

## 审计日志有什么用？

最终 JSON 只能告诉我们最后留下了什么，不能说明中间哪一步发生了超时或失败。execution-audit.jsonl 会按时间写下确认、贸易开始和结束、政策开始和结束、最终状态。模型超时后，能知道贸易数字已经完成，政策只完成到哪一步。

## 为什么政策草稿仍是 needs_review？

模型输出结构正确、引用编号存在，只代表它产生了一个可审查草稿。它是否真的回答了问题，仍要逐条对照原文，所以不能直接叫完成。

## 比较方式为什么还要单独做？

“列出一串月份”是序列；“10月比9月”是首末月比较；登记的政策前后窗口又是另一种比较。它们的输入和含义不同。下一阶段会把比较方式写入计划字段，缺失时追问，防止程序自行替换研究问题。

本阶段只改善执行记录和任务边界，没有训练模型、没有增加多智能体，也没有解决因果识别。
