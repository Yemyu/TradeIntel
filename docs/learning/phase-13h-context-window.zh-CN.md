# Phase13h：找到一句话以后，把附近的条件也带上

## 这次具体改变了什么

以前检索找到3个短片段，就直接交给模型。这次不改变它找中的位置，只把每个片段前后各最多600字符带上。就像读书查到一行之后，再读附近上下文，减少漏掉“但是”“另外适用”等限定条件。

窗口不跨页、不越过原先允许读取的正文，不把第一页夹带的其他通知混进来。每段仍有精确原文位置；总长度最多7200字符。旧检索器、旧实验和默认入口都没改。

## 已看到的效果和代价

原问题“25%是否包含其他税费”的三个短片段缺少明确说明叠加税费的句子。扩窗后，原文中的这项条件进入了上下文：附加税还要与其他适用税费叠加。

但这道题提供给模型的原文由3600增加到7200字符，翻了一倍；其他题也有重复或无关内容增加。所以目前只能说“补回了缺失证据”，不能说回答准确率提高，更不能说速度更快、成本不变。

## 需要理解的问题：附参考答案

### 这次是在调模型吗？

不是。这是在改变模型看到哪些资料。本轮没有API调用，没有训练，没有修改提示词，避免同时改很多东西后不知道是哪一项起作用。

### 为什么不干脆把所有文件都给它？

内容越多，处理时间和费用可能越高，也会混进别的批次、申请步骤和历史回顾。我们先限制范围，再观察收益与代价，不假定更多文字一定更好。

### 把那句话找回来，是不是原失败题已经修好？

只修补了一个证据缺口。模型还可能理解错、引用错或表述不清楚，需要在新协议下检查生成。已经看过的题以后属于开发材料，不再包装成未见题成绩。

### 因果和贸易部分有没有被改掉？

没有。项目仍要结合政策与贸易数据形成完整报告。本轮只改政策检索候选模块，没有运行因果回归、修改贸易金额或删除压缩包。

## 下一步

推荐Astra中决定真实生成对照的预算与停止规则，并明确批次名称和时刻表达的处理顺序。先判断上下文扩展有没有带来足够收益，再考虑接入统一入口；不直接替换旧版本、不重跑已关闭的8题批次。
