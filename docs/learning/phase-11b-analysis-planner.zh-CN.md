# Phase 11b：组合任务规划原型

## 已完成与未完成

新增独立AnalysisPlanner：一次模型调用提出1至3个任务，宿主逐项检查字段、原文引用和能力边界，展示完整计划，再接受一次性整体确认。确认后执行本地只读证据流程，各任务报告分别保留来源；任一步失败不把部分结果称为完成。

已增加5项本地测试，覆盖两个子任务的真实本地证据执行、重复与超过上限任务、伪造引用、预览修改、取消及执行失败停止。本轮零API，模拟模型返回不能证明真实模型规划准确。

命令行原入口增加`--plan`选择实验规划器，读取已有环境模型配置。不能和`--demo`混用，因为旧归档单任务响应不是新规划模型的输出。尚未真实运行该模式，暂不要求用户启动。

## 这次AI能力增加在哪里

过去模型只能选择一个任务，多任务请求需要拆开。现在模型可以提出一个有多个任务的计划，程序按计划顺序执行。与固定拼几个报告不同，未来需要真实验证模型能否针对不同问题选择合适任务、保留共享条件且不漏答。

但当前只实现“受限规划接口”，不能宣称语义规划已经验收。特别是比较任务仍需要明确登记窗口；自然语言到登记窗口的可靠映射尚未完成，含糊的“政策后”不允许默认选择。

## 你需要能够解释的问题（附答案）

### 1. 多任务是不是多Agent？

不是。这里一个模型一次提出最多三个分析任务，宿主调用工具。多个任务不需要多个模型角色，不能把它宣传成多Agent协作。

### 2. 怎么保证没有漏答？

目前不能仅凭JSON校验证明没有漏答。预览明确提醒用户核对覆盖，下一步要用带任务清单的参考答案评估遗漏与额外任务。程序能证明的是不超过任务上限、字段合法、证据引用存在和确认后执行固定请求。

### 3. 为什么一个不支持的任务会阻止全部确认？

防止用户问了三件事，系统悄悄只做两件。先明确说明不支持的部分，调整后重新确认；这不同于数据库事务回滚。若执行第二步才发生故障，第一步只读查询可能已经发生，会在记录中保留。

### 4. 现在报告是AI写的吗？

最终仍由现有证据模块分别生成，尚未实现跨任务的模型综合解释。规划能力和解释能力分开建设、分开验收。
