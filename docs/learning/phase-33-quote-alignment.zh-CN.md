# Phase 33：让AI负责理解，让程序负责定位和记录

之前要求AI既列出每项要求，又数出它在中文原文里是第几个字。后一件事可以由程序完成。本轮改成AI按顺序引用原话、标明是要求还是背景，程序计算位置并核对有没有漏字、改字或漏段。

**这样会不会降低检查要求？** 不会降低原文完整性检查。程序不能跳过有内容的句子，也不能模糊匹配。模型复制了错误原文时会停止。但如果模型把要求误分类成背景，仍需要语义核对。

**1536和768是什么意思？** 是一次规划和一次回答最多允许生成的token数量。它们限制输出长度，不是总费用预算，中文字符数也不等于token数。现在实际发送的模型名、温度、输出上限、思考开关等会被记录，便于复现。模型名和超时仍要在真实运行前核对。

**这次是否提高了准确率？** 还没有这样的证据。固定样例的规划JSON少了119字符，程序检查全部通过；本轮没有调用在线模型。下一轮用4个开发问题、最多6次调用，检查模型是否能按新格式回答，并核对每个政策要求的证据。

这4个问题覆盖：政策双问题、政策加贸易、方向明确的月份比较、金额加暂不支持份额。遇到错误就保存记录停止，不重复刷到成功。它们是开发检查，正式验收会另行准备。

本轮5项新检查通过，全套462项测试通过。下一阶段可以用Luna最高实现已锁定的运行规则；实际答案的语义和引用由Astra中审查。当前尚无可用的项目环境密钥，先完成零调用准备，你不需要现在重跑旧命令。
