# Phase 42：为什么通过程序测试后还要检查真实回答？

> 0109最新：这次真实四题都通过了，包括之前卡住的月份比较！它证明的是“这四种已知情况，这一轮在逐项审查下能完成”，不是所有问题都会答对。下一步不再反复考原题，而是先设计没有用于改程序的新题验收。

### 这次你可以怎样理解？

AI负责读懂问题、提出查询计划，并根据找到的政策原文组织回答；贸易金额与增长率由程序读取、计算。我们核对它有没有漏掉需求、把九月十月弄反、编造引用或因果结论。第四题故意问暂不支持的份额，正确结果是说明限制并停止，而不是编个数字。

**为什么不是在训练模型？** 我们没有更新GLM的模型参数；是在验证和改善使用它的应用流程。

**四题全对能写进简历吗？** 可以如实说完成了四种开发场景的端到端验证，不能写成“模型准确率100%”。这些题在开发时已经看过，需要额外未见题来衡量泛化能力。

> 0108更新：简单连接探测已能得到回应，但新业务请求仍中断。探测像“拨通服务台”，正式请求还涉及认证、传输正文和等待生成；前者成功不能保证后者成功。我们补上更细的错误记录，下一次才能区分TLS、DNS或连接重置等方向。暂未锁定原因，也没有新的AI回答成绩。

> 0107真实运行更新：首个请求超时，没有收到AI计划；后续不带密钥的连通性检查也出现异常。此次不能判断AI答得对不对。可以理解为“电话没有顺利接通，还没听到对方的回答”。下一步先检查连接；上一轮本地539项测试通过也不能保证外部服务随时可用。

## 这次完成了什么？

我们检查了上一步的接线，发现说明里新旧标签规则同时存在，容易让AI困惑；还发现标点审查材料没有直接带上原来的标签。现在说明已统一，原始标签与比较方向也一起保存、核对。

另一个修复是：用户没写清月份时，AI可以正常提出澄清，系统会显示需要补什么，而不会直接把这种回答归为格式错误。

## 你需要能够解释的问题（附参考答案）

### 1. 539项测试通过，代表AI已经很准确了吗？

不代表。这些测试主要检查程序行为，例如“审查者发现十月和九月写反，点了不通过后，程序是否真的停止”。测试里的AI回应是我们预先安排的，可以稳定制造错误。真实GLM是否会理解正确，还需要真实运行。

### 2. 把原始标签保存下来有什么用？

可以区分AI实际填了什么、程序根据它推导了什么。例如AI只填“贸易请求”，程序根据comparison生成“十月相对九月”。发生错误后，我们能检查错误来自原意理解还是程序处理。

### 3. 这次真正验证成功了什么？

用模拟计划接到真实本地贸易工具，正确计划能完成查询，并核对金额和差额。负向审查、缺少审查记录、文件被改动都会阻止后续执行。这验证了流程；真实模型表现仍待验证。

### 4. 下一步还要继续设计吗？

本阶段审查已完成。下一步用Astra中按冻结条件直接检查四个真实场景：政策问题、政策加贸易、月份比较、包含额外份额的请求。任何一题失败就记录并停止，不反复挑最好的一次。

### 5. 因果分析也解决了吗？

没有。这次改善的是AI理解请求、调用数据工具与交付报告的可靠性。贸易金额变化能算出来，是否由关税造成仍取决于独立的因果研究证据。
