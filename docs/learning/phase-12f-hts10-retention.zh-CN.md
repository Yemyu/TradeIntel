# Phase 12f：这次为什么把压缩包留下？

## 用最简单的话说

之前下载的是完整月包，但处理完只留下了当时需要的结果：部分细明细和全商品HS6汇总。现在我们发现研究问题可能要看更细的HTS10商品，所以这次把“所有商品的细分结果”先保存，同时把原始ZIP也留下。

这样以后如果要把商品按不同方式合并，就能从细分表重新计算，不必每次重新下载。原始ZIP是最后的底稿，等数据结构基本确定、金额都对账后再考虑删除。

## 这次表里有什么

每个月每个出现过的HTS10有：

- 中国进口金额；
- 所有原产地合计金额；
- 中国是否出现过；
- 原始明细行数；
- 下载地址和文件校验值。

如果一个商品当月只有加拿大等其他国家、没有中国记录，它仍会留下，`china_observed=0`。如果整个商品没有任何国家记录，就不会凭空写成零。这两个情况不能混为一谈。

## 为什么先做一个月

一个月能验证代码是否正确、金额能否和旧结果对上、原始包是否真的留下。2016年1月已对账成功后，才启动29个月批量处理。这样如果发现错误，不会先产生一大批不可信文件。

## 这和AI项目的关系

AI以后可以帮助研究者按商品、年份和政策范围查询这张表；但AI不能把缺失明细变出来，也不能因为细分表存在就保证因果关系。先把数据底座做可复用，后续的RAG和Agent才有可靠资料可调用。

你现在不需要操作终端或输入API。批量完成后我会说明：下载了多少、保留了多少、金额是否逐月对账，以及17个候选是否值得进入新的研究设计。
