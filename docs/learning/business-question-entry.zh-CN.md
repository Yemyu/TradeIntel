# 现在可以输入自己的研究问题了

本轮交付：中文网页新增“提出研究问题”，后端入口 `/api/research`。启动仍是 `.venv/bin/python scripts/run_web.py`。点击“提交问题（调用模型）”会使用本地配置，最多两次请求。

后续真实验收提醒：首次四题未通过，出现误路由、否定句误拦截和模板回复；已有离线修复，但尚未验证改善。输入框仍是实验功能，不能按下方功能说明推断真实模型已可靠完成任务。详见 [首次结果](../experiments/business-tasks-v1-first-review.zh-CN.md)。

支持范围仍是已登记美国钨、硅片、多晶硅政策。新增的是提问方式与任务选择；欧盟或其他新政策的数据库尚未增加。

## 使用流程

你写问题 → 模型识别任务 → 程序检查条件 → 查询数据或检索政策 → 输出待审阅报告。

- 单月数据任务：明确月份、整体/税号；排序还要明确指标、从大到小及前几项。程序做求和、排序和份额计算。
- 政策解释：检索已存CBP段落，模型写逐项中文主张和引用。程序检查引用ID存在；是否准确解释原文仍需人工审阅。
- 条件缺失：回复补问，不执行贸易查询。把补全后的完整问题重新提交即可，目前不自动保存多轮对话。
- 不支持的政策：说明缺口；不会凭空下载新国家数据或替换成美国登记商品。

示例：`2026年4月全部登记商品按中国金额从大到小列前3项。` 请注意该示例仅说明支持语法，没有声称真实模型已验证此题。

## 你可能关心的几个问题

**AI现在多做了什么？** 原来用户只能点三个固定按钮，现在模型需要识别用户要查数、解释政策还是补问条件，并提出具体查询参数。

**是不是训练模型？** 没有。仍调用已有模型；本轮增加了应用工作流程和任务校验。

**报告会算错吗？** 数字使用版本固定的查询结果，排序和百分比由程序执行。模型仍可能识别错意图；参数校验能拦住一部分错误，但不能证明自然语言理解全部正确。

**引用存在就说明解释正确吗？** 不说明。引用检查只确认引用来自本次检索结果。模型可能漏读或误读条件，政策报告仍标记待审阅，后续业务验收专门检查这一点。

**已经测过真实GLM了吗？** 测过。首次四题没有通过；修复后用三条新措辞做了一次开发验证，排序的数字正确、缺月份时能实际补问，政策回答的税率与日期正确，但把凌晨00:01写成了容易误解的“上午12:01”，所以不能算全部通过。原失败没有删除，也没有反复跑到成功为止。

**这和训练有什么不同？** 我们没有修改大模型的参数。这次是在改善它收到的任务说明、提供可靠的数据库范围，并让程序检查结果。就像给助手更清楚的工作说明和检查表，而不是重新培养一个模型。

**时间问题怎么处理？** 新入口现在复用原有的时间转换提示，要求写24小时制，并拦住这类歧义表达。19项相关离线测试通过，但这次修复尚未再用真实模型验证；仍需审阅政策解释，不能认为有引用就一定正确。详见 [实际结果](../experiments/business-repair-v1.zh-CN.md)。

## 边界

### 综合简报怎么用

在网页提问区输入：“解释登记的2024年12月CBP政策，并查询2026年3月38180000的美国消费进口金额、中国金额和份额，形成综合简报。”

新增的 `brief` 任务把已有两类工具接起来：模型识别月份和商品 → 程序查真实金额 → 检索存档政策 → 检查该税号是否出现在原文 → 模型解释政策条件 → 程序生成包含两部分的报告。最多两次模型请求，不自动重试；缺月份或商品时应补问。

**这为什么不只是拼接？** 贸易查询和政策原文来自同一个固定发布版本，而且每个查询税号要能连到原文段落；未找到对应原文会保留缺口记录，不交付貌似完整的简报。但“编码出现”只是可追溯关系，不证明该编码下每笔进口都适用同一税率，商品限定仍需审阅。

**这些数字有什么用？** 帮你判断涉及的贸易规模和美国进口来源结构。例如真实发布数据中，2026年3月38180000全部来源为162,467,115美元，中国原产为6,515,523美元，占4.01%。这不是中国对美出口依赖率，也不是实际税款、损失或政策造成的变化。

本阶段31项相关测试通过；真实发布数据的离线整链也已核对上述数字。该检查用了预置模型响应，没有调用API，因此只能说明接线与计算可用，尚未证明真实模型会稳定选择综合简报任务或正确解释政策。记录在 `tmp/brief-integration-tj8oldg5/run/`，不要把其中预置说明当真实AI产出。

随后已完成一次真实综合任务：2026年4月81019400，模型选对任务，程序查得全部来源2,374,813美元、中国338,657美元、14.26%；模型据原文解释了额外25%及生效条件。[看真实报告](../showcase/business-brief-first-live.zh-CN.md)。其中“未锻造”应规范为“未锻轧”，报告仍需编辑审阅。

**这次真正证明了什么？** 证明这一条完整任务能把政策原文和真实数字接起来，不再只是模拟接线。无工具对照误认了商品和政策背景，说明本题的信息支持有价值；但只有一题，且两组可用信息不同，不能说项目整体准确率高或所有政策都能处理。总共3次请求，没有反复重跑。

### 如何检查AI的政策解释

现在政策报告会把每一句主张与对应英文原文放在一起，显示公告日期、抓取时间和从原文换算的24小时制时刻。你主要检查：商品与原产地是否匹配、额外税率是否被说成总税率、生效时间与入境条件有没有遗漏。无需读代码，也不必从整篇公告重新找段落。

**为什么仍保留英文？** 中文是AI解释，英文是原始证据。全部换成AI翻译会失去独立核查依据。程序只排版、展示和转换时刻，不替模型宣布解释正确。

**看到了原文就算通过吗？** 不算。比如原文写凌晨00:01，AI写“上午12:01”，即使引用正确仍需修正。报告的清单默认没有勾选，不能把展示证据说成已完成审阅。

可以看 [历史回答核查示例](../showcase/policy-review-example.zh-CN.md)：这是旧回答重新排版，保留了那处错误，未新增模型调用或成功成绩。新生成政策报告会自动采用相同核查布局。

当前是单月、降序和明确指标的受限入口；支持登记政策解释与单月金额的综合简报，不支持任意跨期比较、任意混合多任务或多轮会话。部分自然语言表达会被保守校验拒绝，失败记录保留在本地运行目录。模型无法完成时不会自动换题、重试或改成模拟回答。发布数据副本和原始ZIP没有在本轮修改。
