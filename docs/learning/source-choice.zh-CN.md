# AI解释，程序提供原文

过去要求模型同时写中文解释、复制连续英文原文。官方公告有多列表格和长段落，模型容易跳列或省略句子，导致无法核验。新接口不再让模型承担“复印原文”的工作。

第二案例综合简报现在要求五项条件各提供：税号、条件类型、是否有证据、中文说明、证据编号。程序核对编号是否属于本次检索及对应条件，随后展示该段完整原文，并保存source_bindings。

这不是允许伪造引用。不存在的编号、错误类型段落、缺项仍拒绝；unknown明确列缺口。模型提供quote字段也拒绝，不静默转换旧协议。旧三项/五项摘录评估保留原结果，不能算成新接口成功。

## 解决什么、不解决什么

- 解决：不必让模型重复复制长篇排版原文，程序能逐字提供来源。
- 不解决：模型可能把额外税率解释成综合税率，或者误解例外。选对编号不等于说对含义，semantic_approval始终为false。
- 本轮验证：真实封存资料＋预置回答的综合简报通过；114项相关程序测试通过，0API。没有新真实回答质量成绩，也没有验证速度或token节省。

仅第二案例brief/series_brief切换；第一案例及纯policy格式未迁移。第二案例仍候选。下一步应针对新接口安排一次有预算的验证，同时独立审阅税率与一般限定语义，而不是再扩建检查框架。

## 接收规则收束：两种等价排法，不猜内容

后续真实运行返回了合法JSON，但把五项分组，旧接口要求平铺，因此失败。这不是打开JSON模式就能保证修好的问题。现在预先固定两种可接受结构：全部平铺，或完整五项分组；不混用、不改值、不猜缺项。层级名称与内部field、税号必须一致，展开后仍做全部原有检查。规范见[输入契约](../contracts/solar-source-normalization.zh-CN.md)。

用旧回答离线重放已得到完整待审阅简报，没有调用API，没有修改原回答或原失败成绩；general_conditions里其他税费的实际适用性仍需人审。新检查覆盖多商品、明确未知、重复、混合结构、字段冲突等，116项相关测试通过。不要把程序显示manual_review_required当成内容没有问题。
