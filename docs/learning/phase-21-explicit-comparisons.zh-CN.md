# 本阶段学习：AI不能偷偷改变你的“比较”

## 这次在做什么？

让“AI理解问题”和“程序计算金额”之间有清楚的约定。例如你问10月比9月下降多少，AI要明确9月是基准，程序再按这个方向算。这不是训练GLM，而是改进我们使用GLM的业务流程。

## 为什么方向重要？

假设9月100美元、10月80美元：10月比9月下降20%；反过来，9月比10月高25%。金额相差相同，但基准不同，百分比不同。不能把两个日期排个序就当作理解了问题。

## 列出金额不就是比较了吗？

不是。“列9月和10月金额”只要求给两个数字；“比较”还要知道谁相对谁、比较金额还是份额。程序不应该擅自追加一个看起来像政策效果的结论。

## 这些变化是不是关税造成的？

不能这样说。80比100低，是观察到的变化；说其中多少由关税造成，仍需要可信的对照与研究设计。本次没有解决此前的因果识别阻断。

## 现在做好了多少？

新的比较计算组件已经编写并有离线测试，但自然语言主入口尚未接上。还修正了“拿到不完整数据却标为完成”的状态，以及任务记录可能重新带回敏感文本的问题。测试通过只能证明所检查的规则，不证明大模型已经能稳定理解各种问法。

## 接下来做什么？需要我学写代码吗？

下一步把比较方式接进理解预览、你的确认、实际计算和报告。你不用学具体语法；需要会检查四件事：分析谁、哪段时间、谁作基准、结果是描述还是因果。这些才是你对AI分析工作的业务把关。

后面仍有RAG检索改进、完整问题覆盖和真实模型验收，不是只剩一个按钮就完成项目。
