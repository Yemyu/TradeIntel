# Phase 10z：把年月格式交给程序，把不确定性说清楚

## 这次完成什么

新增独立`intent-presentation-1`开发适配层，沿用原模型提示与严格校验，不修改被冻结的旧版本。

1. 把明确的“2017年4月”转换成接口要求的“2017-04”。只转换原问题及月份引文中出现的完整、有效年月，不改变引文、月份顺序或查询范围。
2. 模型主动澄清时，用固定中文标签展示它认为需要确认的字段，例如国家、月份；未知字段不直接照抄模型文字。
3. 程序解析失败显示“需要检查解析记录”，不再混同用户缺少信息。
4. 部分月份超出数据覆盖范围时，在待确认文字中明确提醒；保留全部原请求，不悄悄删除越界月份。

## 你需要能够解释的问题（附答案）

### 为什么用程序转日期，而不继续让模型尝试？

本例年和月已经明确，差别只是表示方法。固定规则适合处理这种可精确定义的转换，且可以测试非法日期。对于“去年”“上次那段时间”等不明确表达，程序不能擅自猜测。

### 这是否放松了安全校验？

只增加了一个有限的输入格式适配，随后仍经过原校验。日期非法、重复月份、伪造引文、响应截断等仍会失败。原文引用不会被程序修成“看似正确”。

### “需要澄清”和“需要检查”有什么不同？

“需要澄清”表示模型认为国家、月份等信息还不确定，也可能是模型理解错了，用户可以纠正。“需要检查”表示模型返回没有满足程序接口要求，不能因此断言用户表达有问题。

### 为什么模型missing字段不能直接显示？

它仍是模型生成的文字，可能包含无关甚至误导性内容。程序把已知字段映射成固定中文标签，未知内容使用一般提示，不把模型自由文字当作指令或事实。

### 为什么35份都通过了还不能说验收完成？

这些响应已经被看过，我们针对失败案例设计了修复。它证明旧问题在这些样本上被解决，不能代替新题测试。另外还有一题没有响应，不能给它补一个成功成绩。
