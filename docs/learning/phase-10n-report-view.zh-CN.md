# Phase 10n：报告怎样更清楚，又保留原始证据

日期：2026-09-08。独立展示适配层已经完成，未接入正在运行的验收。

## 本阶段完成

新模块 `src/tradeintel_ai/report_view.py` 读取已有v2.1执行记录，不调用GLM、不改变模型工具选择、不重新取数。

它把离散月份直接列为月份集合，把合计标为“所列请求月份合计”；全部不可查时显示“无可计算观测”和“本次没有取得任何可用月份金额”；部分可查时只列出实际返回金额的月份。真实观测到的0仍显示为0。

模型没有主动请求匹配结果时，主报告保留因果限制，把较长的匹配事实保存在原始证据账本。用户主动请求匹配结果时，仍完整展示。模型草稿不进入主报告。

## 为什么保留两份表示

原始事实账本包含当时程序返回的全部数值和来源，不能为了美化报告而改写。展示层可以将空观测合计0解释为“无可计算观测”，但原始记录仍保留；两份表示的关系由代码和测试验证。

这不是新的模型成绩。对已完成8题的离线展示对照可以检查账本是否保留，却不能证明模型更聪明或已经回答全部新问题。

## 你需要理解的问题与参考答案

**为什么不把所有事实都放在主答案？** 过多重复合计和匹配状态会遮住用户所问金额。主答案保留有关事实及限制，原始账本保存全部证据，仍可追溯。

**有哈希就能证明答案真的吗？** 哈希能确认文件版本是否变过。重新生成事实与账本一致，只说明记录内部一致；若上游输入本来错误，还需要数据来源审查。

**展示层会修复模型选错月份吗？** 不会。它按实际查询月份展示，不擅自猜用户本来想问什么。选错范围仍要由任务审查发现。

**为什么没有观测和真实0要分别测试？** 因为显示“无数据”时不能把真实零进口隐藏；显示金额时也不能把缺失误当成零。

**这会影响我终端正在跑的结果吗？** 不会。当前运行没有导入这个新增模块，原冻结文件保持不变，仍按原协议审查。
