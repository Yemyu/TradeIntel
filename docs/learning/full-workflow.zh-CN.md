# 从提问到审阅稿：完整使用流程

这套流程把“数据事实”和“AI建议”分开。数据先由程序从已登记版本中计算，AI只提出需要人工核查的解释或下一步调查方向。

## 1. 启动本地页面

在项目根目录运行：

```bash
.venv/bin/python scripts/run_web.py
```

打开终端打印的本地地址。页面可以先使用“数据版本更新”和数据查询，这些确定性功能不需要API密钥。

## 2. 提出一个范围明确的问题

问题至少说清统计月份和商品范围，例如“查询2026年7月登记政策五个税号的中国原产进口额，并给出后续调查方向”。不明确月份或商品时，助手会补问，不会替你猜。

页面可能出现两类结果：

- 只有程序结果：可以查看数字、来源和固定数据版本。
- 有AI待审阅附件：AI已经提出建议，但页面会明确标记“未批准”，不能直接当成研究结论。

## 3. 查看同一个数据版本

结果旁边的“查看本次分析使用的数据版本”会打开固定版本页。它展示这个版本的完整窗口、月表、规模图和来源。它是背景资料，不代表本次问题实际分析了所有月份，也不会随着新版本悄悄改变。

如果运行记录缺少版本、月份或金额无法核对，链接会显示“不可用”，不会把结果配到最新版本。

## 4. 审阅AI建议

点击“审阅本次结果并导出”后：

1. 先打开来源资料和同版本数据页；
2. 对照金额、政策事实、范围和来源；
3. 每条AI建议分别选择“采纳、拒绝或需要修改”，并写理由；
4. 勾选已经核查事实后保存。

只有至少一条建议被采纳、没有“需要修改”、且事实确认完成时，才会生成“人工审阅稿”。这仍然不是案例发布批准或法律意见，只是保留了人工选择的研究材料。原始回答、未采纳内容和历史审阅版本都保留。

## 5. 数据更新后怎么办

新版本会有新的固定版本号。旧问题和旧审阅稿继续指向原版本；程序不会把七月数据强行写回六月报告。若旧报告使用的月份被修订或政策文件指纹变化，更新简报会标记“需要重新核查”；如果只增加了新月份，固定历史范围不会自动失效。

## 6. 这条链路目前能保证什么

它能保证版本绑定、金额由程序计算、来源可追溯、人工审阅不覆盖原文。它不能保证AI每次解释都正确，也不能从贸易金额推出政策因果、企业税负、价格或产能变化。当前泛化的“让AI自动解释所有更新”已停止；AI只在具体问题和人工审阅边界内使用。

本阶段新增导出稿和来源包的固定版本链接；31项相关Python测试、页面脚本测试通过。完整测试套件中还有历史冻结实验因代码基线已变化而拒绝运行，这些不是本阶段链路测试的失败；没有修改旧冻结清单来掩盖差异。尚未进行真实浏览器视觉验收。
