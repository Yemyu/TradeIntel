# Phase 58：先用离线演示看懂严格 AI 流程

## 这次做了什么？

我们没有再向模型发新问题，而是用一个“假模型”把已经设计好的流程从头跑一遍。这个假模型只返回固定 JSON，不访问网络，所以它适合学习文件如何流转，不适合测模型聪不聪明。

## 你需要理解的三个概念

**1. 离线 fixture 是什么？**

它像排练时的替身演员：回答内容预先写好，作用是检查舞台、灯光和流程是否接得上。它不是考试成绩。真正模型需要 API、真实新问题和人工或独立参考答案才能评价。

**2. 为什么同一个政策问题要跑两份？**

一份带检索到的政策证据，一份不带证据。两份使用同一公共问题和同一模型配置，系统只记录证据差异，方便观察“证据是否真的被用到”。这仍然是工程对照，不代表一次运行就能证明因果关系。

**3. `acceptance_ready=false` 为什么仍然算完成？**

本次完成的是“流程排练”：三类问题都走到合法终点，审计文件也能生成。`acceptance_ready` 是“是否可以把真实模型结果当作正式验收”的开关；没有独立参考复核和真实未见题成绩，就必须保持关闭。

## 运行与查看

```bash
source .venv/bin/activate
python scripts/run_strict_offline_demo.py --output /tmp/tradeintel-offline-demo-0126
```

重点查看：

- `run-summary.json`：总状态、调用数和为什么不能当准确率；
- `SYN-POLICY-01/policy-pair-contract.json`：主组和 B 组的共同设置；
- `SYN-POLICY-01/fact-review-summary.json`：事实审核包是否结构完整；
- `SYN-CLARIFY-01/preview.json`：信息不足时系统如何停下并请求澄清。

每次请使用新的输出目录。结果中的哈希和时间会变化，这是审计指纹的正常现象。

## 这次学到什么、还没学到什么

已经学到：一个研究型 AI 应用不是“模型说一句话”就结束，而是要把问题规划、证据、程序结果、审核和最终报告连成可追溯的链。

还没学到：真实模型准确率、RAG 在未见问题上的泛化、微调效果、多智能体协作和因果估计。这些需要单独的研究设计，不能由这个离线演示代替。

## 参考答案（通俗版）

问：这是不是把 AI 训练好了？

答：不是。这里没有训练，也没有调用 GLM；只是用固定返回值检查严格流程。

问：为什么不直接让通用大模型回答？

答：通用模型可以回答，但这个项目要额外证明范围、来源、公式和限制没有被偷偷改变。离线演示检查的正是这些“护栏”。

问：下一步是不是马上跑真实 API？

答：还不是。先完成政策事实的独立人工复核，并写清正式题目的指标、预算和停止条件；通过这道门再考虑小批量真实运行。
