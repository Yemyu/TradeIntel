# Phase 10a 学习版：先把 AI 能调用的工具做可靠

> 当前状态：六个只读工具和确定性路由基线已完成；下一步是 60 道评估题

## 这一阶段到底做了什么

我们没有先接一个聊天模型，而是先把“模型可以请求什么能力”做成普通 Python 函数。这样做的原因很简单：如果工具本身不能稳定返回数字、来源和限制，接不接大模型都不会可靠。

当前工具只读取已经审计过的 CSV/JSON 快照。MySQL 仍然是项目的数据工程和学习数据库；为了让别人不用配置密码也能运行最小 Demo，第一版工具把经过 CSV—MySQL 对账的结果作为只读快照。以后可以增加同一份契约的 MySQL 适配器，不改变工具的输入输出。

## 六个工具

| 工具 | 它解决的问题 | 关键限制 |
|---|---|---|
| `get_policy_event` | 政策叫什么、何时宣布、何时生效、税率是多少 | 只能读取登记过的政策 |
| `get_trade_series` | 在固定 List 1 范围内读取月度进口序列 | 日期必须在 2016-01—2019-12；不能写 SQL |
| `get_descriptive_change` | 读取已经登记的相同月份同比比较 | 结果永远标记为描述性，不是因果 |
| `get_data_quality_status` | 查看质量规则、失败项和复核项 | `pass_with_review` 不能被说成“全部通过” |
| `get_causal_readiness` | 查看资格、匹配和前趋势是否允许继续 | `blocked` 时硬性返回不能做因果表述 |
| `build_evidence_bundle` | 把工具结果、公式、文件哈希和限制打成证据包 | 只接受已登记工具的结果 |

## AI 和确定性代码怎样分工

可以把一次问答想成三层：

1. **AI/路由层**：理解用户在问政策事实、描述性变化、质量，还是因果可行性；选择工具；把结果组织成自然语言。
2. **工具层**：检查参数，执行固定读取和计算，返回结构化数字、时间窗口、来源和限制。
3. **数据层**：保存官方数据、哈希、质量报告和匹配阻断证据。

AI 可以选择“查什么”，但不能选择“把哪一行改成什么数字”，也不能解除 `blocked_before_pretrend_v3`。

## 什么是工具契约

契约就是一份明确的约定：输入有哪些字段、允许什么值、成功时返回什么、出错时怎么说。例如 `get_trade_series` 不接受任意日期，而只接受项目 48 个月范围；`hs6` 如果提供，必须是已登记的 6 位 List 1 暴露代码。

契约的价值在于：模型可以换，数据库可以换，但工具测试仍然可以检查“数字有没有变、来源还在不在、边界有没有被绕过”。

## 为什么证据包很重要

单独一段聊天文字很难审核。证据包会把以下内容放在一起：

- 用户问题；
- 哪些工具被调用；
- 工具返回的结构化数字；
- 计算公式和月份窗口；
- 官方 URL、文件名和 SHA-256；
- 数据质量复核项；
- 因果状态和不能越过的限制。

例如当前系统可以说“2018 年 8—12 月中国相关商品进口额比 2017 年同月下降 23.7%”，同时带上 `causal_claim=false`。它不能把同一个数字改写成“关税导致下降”，因为 `get_causal_readiness` 返回了阻断状态。

## 你现在需要掌握的重点

不需要背 Python 语法，先能回答四个问题：

1. 为什么模型不能直接生成 SQL？——因为任意 SQL 会扩大读取范围、带来越权和不可重复查询；固定工具可以验证参数。
2. 为什么工具要返回来源，而不是只返回数字？——数字必须能回到文件、官方链接和版本指纹。
3. 为什么质量状态和因果状态是两个工具？——数据格式通过不等于研究设计可以识别因果效应。
4. 为什么“正确拒答”算功能？——当证据不够时拒绝越界结论，正是可信 AI 的验收条件。

## 本阶段怎么运行

在项目虚拟环境中：

```bash
source .venv/bin/activate
python scripts/run_tradeintel_ai.py "2018年关税后中国进口下降多少？能证明关税导致下降吗？"
python scripts/run_tradeintel_ai.py --schemas
```

输出中的 `tool_results` 是机器可读证据，`response` 是当前的确定性基线回答。它还不是最终的大模型 Demo；先通过下一阶段的 60 道评估题，再接入可替换的模型适配器。
