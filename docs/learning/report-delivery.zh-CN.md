# 报告生成了，是否就可以直接使用？

不能把“文件存在”当成“结论正确”。现在研究问答统一区分：

| 情况 | 用户看到什么 | 能否当成已核准结论 |
|---|---|---|
| 查询或引用检查失败 | 失败记录，不生成完整报告 | 不能 |
| 有未知条件、范围遗漏风险、未审阅比较或未绑定版本 | 待补核草稿，列明具体原因 | 不能 |
| 未检测到上述问题 | 待人工审阅初稿 | 仍不能自动认定 |

报告正文顶部、delivery.json和网页问答返回结果同步状态。下载链接只是方便核查，并不是批准。此规则用于新业务问答；旧固定演示和历史报告没有被追改。

第二案例上次回答属于“待补核草稿”：金额正确，但模型中文条件遗漏中国原产范围，一般限定也未引用。程序展示原文可以帮助补核，不能证明模型已经改正。当前仍未达到第二案例正式开放的原定要求。

## 接下来只做哪些收尾

1. 明确结构化原产地和一般限定的填写规则：需要写什么、证据不足时怎么说明，不能只靠关键词提示宣布成功。
2. 用离线反例验证规则后，预先登记一次新的迁移任务及预算；保留全部结果，不反复重跑旧题。
3. 达到原定条件后再准备第二案例真实发布副本、核对候选/启用标识及浏览器展示。未达条件就报告具体缺口，不无限改题。

这是收尾顺序，不是本轮已完成清单。更广泛的联网更新、周期简报依然在总体计划内，不与本次第二案例开放混为一谈。本轮没有API调用，106项相关程序测试通过，不是全仓通过或模型准确率。
