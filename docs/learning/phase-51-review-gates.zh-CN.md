# Phase 51：审核结果必须真正影响流程

这次检查发现：程序收到“答案没答对”的审核表，却仍把整道题标成完成。相当于老师已经判错，但成绩系统没有读取判卷结果。

现在主回答未审核或审核不通过，程序都会停止；独立参考答案算错也会在调用AI前停止。无文档对照组如果认真审核后答错，可以记录为对照结果；没有审核不能直接算零分。

## 你需要能够解释的问题

**为什么602项测试通过，还能发现漏洞？** 测试只能覆盖写出的情形。原测试甚至规定“待审核也显示完成”，所以测试通过仍不代表业务规则正确。本轮补了故意审核失败、故意算错基准等反例，并修正旧测试。

**现在AI准确率提高了吗？** 本轮没有调用GLM，无法知道。改进的是检验方法，让错误和未审查状态更难被误报成成功。

**两个组配置相同，为什么还要查发送记录？** 模型对象上写的设置，可能与实际发给服务商的请求不同。现在运行器会在兼容模型最终`urllib` opener边界临时捕获不含密钥的请求体指纹；静态测试模型没有这个边界时，程序仍显示未核实。适配器历史源文件不需要为了审计而改写。

**接下来做什么？** 首轮离线接线已完成：统一两组回答格式、冻结官方事实依据、登记窗口独立复算、gap审批入口、最终交付复核和运行时快照都已加入。下一阶段推荐Astra中审查完整组合fixture、转移依赖边界和人工语义门槛；不需要准备密钥，也不会因此调用API。

**gap审查到底是什么？** 它只处理“模型引用漏掉了逗号、分号等普通分隔符”的机械问题，不替模型补商品、月份或政策范围。运行器会先停在`needs_gap_review`，把原问题和缺口交给独立审查函数；没有明确通过，就不会发出确认令牌，也不会读取金额或调用政策回答模型。通过后还要再次审核整份计划，这个步骤不是语义正确证明。
