# Phase 26：为什么这次审查还发现问题

上一轮说三个部分已经接入，说得太满了。实际接上了检索表达和部分记录，但原计划里还有设置复用、日期推导、片段合并等没有实现。这轮已把缺口重新写清，后续按原清单继续。

## 为什么不能更新旧实验指纹让测试通过？

指纹类似实验版本的封条。原来的成绩是在原来代码上取得的，改了代码，就该保存新的实验记录。把旧封条换掉会让人误以为旧成绩验证过新功能。这轮恢复了旧封条；旧实验现在拒绝用新代码运行，是正确行为。

## 模型超时为什么也要算一次？

请求可能已经送到供应商，但回答没有及时回来。我们不能因为没收到结果就认为没调用过。现在先写下“准备发送一次”，再发请求；超时会记下失败，用量未知。同一个记录目录不能重发，避免无意重复。

## 这是不是又在给模型训练？

本轮是在修程序的记录与失败处理。测试用模拟返回检查“超时怎么办、文件写不进去怎么办”。模型本身的参数没有改变。后面还需要真实问题检查模型有没有理解正确，但要先把原定功能完成。
