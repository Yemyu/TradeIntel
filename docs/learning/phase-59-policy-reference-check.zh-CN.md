# Phase 59：为什么要独立复核政策答案？

> 0128更正：AI可根据官方原文核对并推进开发测试，结果标为AI辅助审核。你无需专门读英文PDF或填写审核记录才能继续。下文“先完成人工核对才能测试”的要求已撤销；只有声称独立人工审核时才需要对应真人记录。下一步是让真实模型接入现有严格流程，规范见[0128](../decisions/0128-ai-reviewed-development-route.zh-CN.md)。

## 这次做了什么？

我们写了一个小检查程序，重新打开项目里保存的 USTR 官方 PDF，而不是只相信 `section301_list1_facts.json`。它确认原文中确实出现：

- 2018 年 7 月 6 日起生效；
- 额外从价税率 25%；
- 适用于进入消费或从仓库提取消费的相关商品。

## 你需要理解的重点

**程序检查和人工复核不是一回事。**

程序擅长检查文件有没有被替换、页码和哈希是否一致、关键文字是否存在。人需要判断这段话有没有被正确翻译和概括。两者都重要，但不能把前者冒充后者。

**为什么不直接让模型自己说“我审核过了”？**

因为模型是被测对象。让被测对象自己发证书，会把“回答”和“标准答案”混在一起，无法知道它是否真的答对。参考答案必须先由来源和独立审核确定，再用于评价模型。

**为什么当前仍是 pending？**

因为项目还没有一条真实的人类复核记录。不是 PDF 有问题，而是我们不伪造最后一步的责任链。

## 运行和查看

```bash
source .venv/bin/activate
python scripts/verify_policy_reference.py
```

退出码为 0 只表示 AI 辅助结构检查通过。输出里的 `human_review.status` 必须仍是 `pending_independent_human_review`，直到人直接读 PDF 并写下可追踪记录。

## 参考答案（通俗版）

问：是不是程序检查通过，就说明答案百分之百正确？

答：不是。它说明“预期原文和文件完整性对得上”。语义上的最终确认仍需要人。

问：这一步和训练模型有关系吗？

答：没有。这是给模型准备公平参考答案的前置工作，避免把模型输出当标准。

问：下一步要不要马上调用 GLM？

答：独立人工核对不是开发前提，0128已更正。助手可以读取官方原文支持明确标记的开发测试；当前先修复0130发现的审核与恢复代码，再运行已授权批次。
