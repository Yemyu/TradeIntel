# 这轮终于拿到真实回答了：但连接、内容和程序要分开看

## 发生了什么

先问模型“回复OK”，2.09秒成功。这说明当前密钥和模型可以用，不需要不停换密钥。

随后把原来的政策问题与检索出的三段原文交给GLM。模型真的回答了：第一批2018年7月6日生效，额外从价税25%，并给了对应原文编号。

程序却拦下了答案，因为JSON外包着一层代码框。换句话说：这次不是模型不知道答案，而是新接口没有兼容常见的返回包装。我们用已经保存的回答做了离线处理，没有再次花额度提同一道题。

## 你需要理解的三个问题

### 为什么之前会超时，现在能回复？

新请求显式关闭了模型的思考模式，并限制输出长度。这是可能改善响应时间的配置，但我们不能确定它就是此前超时的唯一原因。服务繁忙和网络也可能变化。能确定的是这次小请求成功，随后政策问题也取得了正文。

### 去掉代码框是在帮模型改答案吗？

不是。只去掉包在整份JSON外面的标记，里面的中文回答和引用一个字不改。原来被拒绝的记录照样保留，另存“离线规范化结果”。如果改了日期、税率或证据编号，就不能再说只是格式兼容。

### 所以这个AI环节算完成了吗？

现在有一条真实的正向链路：中文问题→检索官方原文→真实GLM回答→引用核对。但仅测了一个已知问题，程序入口还需统一，不能说完整项目通过验收。

还发现一个小但真实的表述问题：模型写“美东时间上午12:01”，原文是美国东部夏令时12:01 a.m.，中文写“凌晨00:01”更清楚。我们保留原文并提出修订建议，没把助手修过的文字冒充模型原答案。

## 下一步你要学什么

如何判断一份AI回答能不能交付：既要答案对，也要适用范围清楚、引用能点开、错误能定位。下一步会把这些做进统一入口，不是继续训练模型，也不是不停重复同一道题。
