# Phase 12d：到底缺什么数据？

## 先用一句话说明

我们在查：原来按“大类”排除的商品，拆成“小类”以后，是否能找到值得进一步核查的对照。不是训练AI，也不是改参数让结果过关。

## 你需要能够解释的问题与参考答案

**为什么大类被排除，小类可能没被加税？**

就像一个“机器配件”大类里有多种配件，政策可能只针对其中几种。为了避免把受影响商品放进对照，我们之前会保守排除整个大类。拆开看，可以分清直接加税范围；但剩下的配件也可能被替代需求影响，所以还不能直接宣布它是好对照。

**这次找到对照了吗？**

找到10个大类里的17个待核查细分代码，还没有找到17个合格对照。大类每个月有交易，不代表里面每一种配件都有交易。

**既然以前下载过，为什么可能还要下载？**

以前保存了全商品的“大类汇总”，以及List1商品的细明细；这些未加税候选的细明细没有留下。汇总以后不能倒推出每种商品的金额。原始ZIP按之前约定删除了，来源链接和校验记录仍在，所以可以重新获取。这正是来源记录有用的一种实际情况，并不意味着必须永久保留所有ZIP。

**现在要多下载几年吗？**

暂时不需要。首先缺的是同一段时间里“更细的数据”，不一定是“更多年份”。先弄清代码跨年有没有变化，确定细分研究有意义，再补提取政策前数据。

**这个环节跟AI有什么关系？**

它是AI背后的研究依据。AI可以帮我们查询与解释，但不能把不合格对照说成合格。RAG和AI交互仍需继续建设；这次没有新增这些功能。
