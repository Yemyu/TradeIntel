# Phase 10d：工具查对了，AI为什么还是可能说错？

日期：2026-09-06。本阶段修正评估与证据边界，确定真实模型实验的验收标准。

本次完成验证：84项测试通过（相较审查前71项新增13项）；60题工具开发回归重新执行；两个离线演示分别返回固定拒答和待复核草稿；`git diff --check`通过。真实模型指标仍未测。本次不是对所有原始数据和历史统计实现的全面认证。

## 一个你能判断的例子

工具查到：2018年8–12月相比2017年同期，中国相关商品进口额下降约23.7%，这只是描述性变化。

模型却回答：“关税使中国进口下降了99%。”数字错了，还把观察到的变化写成了因果效果。只检查工具返回值，测试仍可能全部通过。

这一阶段只要理解两个概念：**分层验证**和**证据边界**。

## 1. 分层验证：分数取决于检查对象

| 检查对象 | 通过说明什么 | 仍不能说明什么 |
| --- | --- | --- |
| 数据/工具 | 字段、查询和边界符合测试要求 | 模型理解了问题 |
| 工具选择 | 调用了相关工具，参数合适 | 最终文字准确 |
| 最终答案 | 数字、范围、引用和结论经过检查 | 所有未来问题都会答对 |
| 使用流程 | 用户能完成任务，失败有提示 | 已经在企业生产环境使用 |

旧60题属于开发回归，检查工具字段、固定路由、来源记录存在与拒答状态开关。它不理解最终文字，也不检查一句话是否真的被引用支持。

旧报告的“直接回答0%／13次越界”没有真实模型运行，是程序预设，已经撤回并改成“未运行”。这不是模型变差，而是纠正测量方法。

### 参考答案

**为什么测试全通过，还不能立即宣布项目完成？** 测试只覆盖明确检查的行为。以前一项测试甚至只读取保存的通过报告；现在会重跑60题工具评估，但真实模型的文字要另外检查。

**为什么旧60题不能当最终考试？** 它反复用于开发，程序可能适应了题目。下一阶段先冻结方案，再按任务模板隔离最终题集。根据结果改过程序的题，降为回归题。公开题目不能保证模型预训练从没见过，我们控制的是本项目的开发泄漏。

**全部拒答是不是就能得高分？** 不行。还要检查可回答问题的完成率。应当回答却拒绝、超时和调用失败，都计入任务失败。

## 2. 证据边界：模型可以点菜，不能伪造出餐记录

旧接口允许模型调用“打包证据”，把自己生成的一串工具结果传进去。格式正确不代表查询真的发生。

新流程：用户提问 → 模型请求五个查询工具之一 → 程序执行并记录 → 程序核验因果状态 → 程序用实际成功结果打包 → 输出固定拒答或待复核草稿。

报错结果保留在轨迹里，但不会混入成功证据。程序补查的因果状态单独记录，不能冒充模型主动选对了工具。

### 参考答案

**安全检查能保证模型没有乱说吗？** 不能。以前“无法证明其他事情，但关税导致下降”可能绕过检查，现在能拦截；但“萎缩完全归因于加税”未必命中关键词。没拦截的模型原文标为 `needs_review`（待复核），不是自动正确。

**为什么保留原文？** 区分模型错误与程序后处理纠正。不能把程序替换的固定拒答算成模型答对。普通草稿见 `response`，被替换原稿见 `original_model_response`。

**`causal_claim=false`为什么不证明没有因果断言？** 它可能只是程序写的标签。现在未验证草稿顶层为 `null`（未知）；证据里的 `false` 只表示工具不授权因果结论。

**没有数据与0有什么区别？** 没有数据表示没观察到，0表示确实观测为零。缺失月份现在返回空值，完整窗口总计也留空，已观测合计单独列出。你需要判断这个口径，转换语法可以由AI写。

## 3. 历史匹配的更正

v3是在“至少保留252个商品”和其他约束同时满足时无可行解。原报告的0个是失败占位，不是证明最多只能匹配0个；真实最大数量未测。工具现在返回空值表达未得到解。保留原实验记录，没有放宽规则，也没有重跑第四个匹配实验。

## 4. 可以自己看的离线演示

在项目目录执行：

```bash
.venv/bin/python scripts/run_tradeintel_ai.py --mock-agent "关税导致中国进口下降了吗？"
.venv/bin/python scripts/run_tradeintel_ai.py --mock-agent "Section 301 List 1 什么时候生效？"
```

第一条故意让模拟模型说错，再观察固定拒答。第二条返回待复核：模拟模型泛泛的回答没有回答生效日期，查到数据不等于任务完成。退出码3表示待复核，不是网络故障。这两条均不是实际大模型能力演示。
