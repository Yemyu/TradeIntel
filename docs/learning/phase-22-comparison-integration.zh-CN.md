# 本阶段学习：把“比较”接进真正的业务流程

## 这次新增了什么？

上一阶段只是写了一个计算器；这次把它接到完整流程：AI先提出计划 → 系统展示计划 → 用户确认 → 系统读取数据 → 程序计算 → 报告说明比较方式。

这就是“AI组件”和“业务系统”的区别。模型负责把自然语言整理成候选计划，宿主程序负责检查范围和执行。模型不能自己决定月份，也不能把两个窗口偷偷换掉。

## 三种请求怎么区分？

- `sequence`：只要逐月数字，例如列出9月、10月。不自动说“涨了多少”。
- `endpoint`：明确方向，例如10月相对9月。9月是基准，10月是当前月；反过来问，百分比也会反过来。
- `registered`：选择项目预先登记的同期窗口，例如2017年8–12月和2018年8–12月。系统会展示窗口月份，且只做描述性比较。

## 为什么保留旧兼容模式？

项目中已有旧调用方，它们没有 `comparison` 字段。直接删除会破坏旧测试和旧结果，所以保留它们，并把它们视为旧版首末月行为。新入口应该使用版本2的明确比较字段；兼容模式不代表新的语义理解已经验收。

## 这能不能证明关税造成了变化？

不能。比较只是把“两个时间点或两个窗口的数字差异”算清楚。要说政策造成变化，还需要可信对照组和因果研究设计；当前因果门槛仍未通过。

## 你需要掌握的业务检查

你不需要记住代码。每次看报告时只检查：谁的进口额、哪些月份、谁是基准、是金额还是份额、结果是描述还是因果。只要这五点没有混淆，AI才是在帮助研究，而不是替你改变研究问题。
