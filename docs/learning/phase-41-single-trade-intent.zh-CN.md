# Phase 41：同一件事不要让AI重复填写，但仍要检查是否理解对

## 这次在做什么？

上次第三题要求“十月相对九月比较”。AI在比较栏填对了，却在任务名称栏填成“逐月列数”。就像申请表上一处写“往返票”，另一处写“单程票”：两处打架，程序不知道应该相信谁，因而停止。

新设计是：任务名称只写“贸易查询”，具体是列数还是比较，只在比较栏写一次。现在这个设计已经接到开发检查入口，但必须显式打开0105选项；默认入口和旧记录不变。程序按它生成待核对的执行说明，而不是替AI修改过去的错误回答。

## 你需要能够解释的问题（附参考答案）

### 1. 这是不是放宽标准，让失败变成成功？

不是。旧的失败记录不动。新格式只减少重复信息；国家、商品、金额口径、月份、比较方向和额外要求仍要核对。当前完成的是开发入口接线和本地验证，还没让真实模型按新格式再做题。

### 2. 为什么只填一次仍可能错？

因为AI可能把“十月相对九月”理解成“九月相对十月”。填表格式完全正确，业务意思却反了。格式检查像检查身份证号码是否有足够位数，不等于证明它就是这个人的号码。

### 3. 哪些是程序能确定检查的，哪些仍需判断？

程序能检查日期格式、月份是否落在请求内、是否漏抄原话、文件是否改变。判断“这句话到底要什么”，则需要把原话与计划逐项对照。尤其不能把“额外算份额”标成背景后装作没看见。

### 4. 这次是训练模型吗？

没有。是在设计AI应用的任务协议与安全边界。模型像填表的助手，程序像负责执行的办事系统；本轮既不更新模型参数，也没有调用API。

### 5. 现在修好了哪些，还有哪些没修好？

已修好报告中的来源说明：自然语言生成的计划不会再写成“没有使用模型理解”。新任务格式已经接入开发检查入口并做了正反例验证，但尚未进行真实重跑；第三题也尚未重新运行。所以项目还没有因此完成稳定验收，因果问题也没有因这次工程修复而解决。
