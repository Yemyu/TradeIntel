# Phase 13a：现在终于开始让 AI 读政策原文了

## 先说你这轮学什么

之前，程序主要从已经整理好的表里取日期、税率、进口金额。这次新增的是另一种能力：从官方政策文件中找出支持回答的原文，并告诉你它在第几页。

这不是把模型重新训练了一遍。更像给一个分析师配好资料室：问到什么，先找到相关页，再请它解释。

## 现在项目里各部分做什么

| 你问的问题 | 谁负责 | 为什么这样分工 |
|---|---|---|
| 关税什么时候生效，公告怎么写？ | 政策文档检索 | 给原文和页码，避免凭模型记忆 |
| 两个月的进口额各是多少？ | 原有数据工具 | 程序计算金额，减少模型算错 |
| 把文件规定与金额变化写成中文解释 | 大模型生成接口 | 适合整理语言，但仍需核对引用和范围 |
| 能否说关税导致金额下降？ | 经济研究设计与证据门槛 | 不能靠语言流畅或引用一份公告证明因果 |

模型、检索器、数据库、统计方法各有分工。这才是“AI应用”，不是所有步骤都让AI自由猜。

## 这轮已经做了什么

1. 检查本地官方PDF有没有变化，用文件指纹核对。
2. 阅读并检查页面，只把两份公告的5页正文放入第一版检索，合计34个片段。
3. 去掉第一页夹带的其他通知。第二份公告不简单标为“第一批”：它同时讲第二批及第一批的修订。
4. 中文问题通过一个可查看的术语表转换成英文检索词，再由BM25排序。
5. 展示原文、页码、原始链接和文件指纹。
6. 写好了可选的模型调用入口：把这些片段交给模型，请它写中文主张并附证据编号；错误编号或不合规输出会被拦下。
7. 把政策证据接到现有金额报告中，完成了离线联合演示。

第6步目前只用模拟模型测试了接口，尚未执行这轮真实GLM生成；没有训练或微调。联合演示的规划沿用旧归档响应，不是新的自然语言理解成绩。

## 你需要能够解释的问题：附参考答案

### 1. BM25是什么？我需要学公式吗？

先不需要。把它理解成“根据关键词来给资料片段排序”的办法：问题里比较有区分度的词，在某段中出现时，这段可能更值得看。它不会真正理解全部中文语义，所以我们暂时用了公开的中英术语表帮助检索。

你要知道的选择是：当前用了词法检索，还没有向量检索。以后如果遇到大量不同说法找不到相同意思，才有理由对比embedding检索，而不是为了堆工具先加。

### 2. 这是不是RAG？

RAG的核心流程是“检索资料，再据此生成”。这次检索已在真实PDF上跑通，生成接口与引用身份检查也写好了，但还没有完成新的真实模型回答验收。所以准确表述是：**RAG原型的检索层和生成接口已完成，完整效果待验收**。

### 3. 找到了正确页，是不是就能保证回答正确？

不是。例如你问第二批的豁免程序，第一名结果可能讲第一批，第二名才讲第二批。页里也可能同时有已生效规定和拟议方案。模型若没有分清，引用是真的，回答仍可能错。

因此要分开检查：有没有找到资料、有没有引用真实片段、回答是不是被那个片段支持。这三件事不能只测一件。

### 4. 为什么6道题全命中，也不能说准确率100%？

因为这里只检查前三个片段里有没有目标页，没有检查模型是否完整准确地回答。另外只有6道开发题，题目已被开发者看过，也没有覆盖所有问法。真实成绩必须讲清楚测了什么。

### 5. 为什么不一次把所有PDF和整个互联网都接进来？

可以逐步扩展，但文件越多，越需要处理不同批次、修订、豁免和日期关系。先把少量文件的出处和引用做对，是为了有可检查的基础，并不是最终只允许读这两份。

本版不回答“现在税率是多少”或“某个税号一定免税吗”；不是这些问题永远做不了，而是当前索引没覆盖所需资料。没有命中也只表示当前资料不足，不表示世界上不存在答案。

### 6. 因果研究这轮有什么变化？

确认两个缺失月份在原始ZIP中也没有中国记录，不是程序提取漏了。又发现所谓“工业机械”实际混有造纸、食品、印刷、塑料和纺织设备。比如造纸机械有11个处理候选，却没有同子行业的对照候选。

所以没启动新的回归。不是“AI不够聪明算不出来”，而是还需要说明为什么这两组商品能比较。这个研究难点保留，但不再让政策检索这条产品主线一直等它。

## 怎样体验

在项目目录运行，不需要API：

```bash
.venv/bin/python scripts/run_policy_retrieval.py
```

生成的中文说明和英文原文片段在 `tmp/policy-retrieval/evidence.zh-CN.md`。这是一份证据预览，不是模型写的最终回答。

```bash
.venv/bin/python scripts/run_policy_retrieval.py --question "第二批关税何时生效？" --as-of 2018-08-23
```

`--as-of`的意思是只读截至这天已经出版的文件，不是自动判定某天所有法律的有效状态。

如果本地数据和旧规划归档都在，也可运行：

```bash
.venv/bin/python scripts/check_policy_business_delivery.py
```

报告在 `tmp/policy-business-delivery/report.zh-CN.md`，可以一起看原有金额和新增原文证据。

新克隆仓库需要先按已有数据下载流程准备官方PDF与清单；原始PDF没有直接提交到Git。

## 接下来做什么

### Phase13b：现在只需要这一条命令

```bash
.venv/bin/python scripts/run_policy_smoke.py --execute
```

在TradeIntel项目目录运行。程序会提示你粘贴GLM密钥，输入时屏幕不显示字符，这是正常的；回车后只发送一次请求，最多等待约60秒，结果自动保存。密钥不保存到文件，不要贴进聊天。

结果在`tmp/policy-smoke-13b/result.json`。看到完成提示后告诉助手即可，不必自己读JSON。若失败也先保留结果，不重复运行；程序会阻止同一轮再次发送。

这次测试的是“模型能否根据现有原文正确写出第一批生效日期与额外税率”，不是重新训练模型。助手随后会检查每句话是否引用了正确片段；格式通过不代表内容通过。

下一阶段优先做一次真实模型的有依据中文回答，并逐条检查“有没有用错政策、有没有把将来程序说成已经获批、有没有乱下因果结论”。不是再出一堆题来训练模型。

已有单次入口为 `scripts/run_policy_retrieval.py --generate`，使用项目已有的环境变量配置。没有密钥时不需要你反复尝试，也不要把密钥写进学习文档或提交仓库。当前阶段没有调用API、没有新增下载、没有删除原始ZIP、没有推送GitHub。
