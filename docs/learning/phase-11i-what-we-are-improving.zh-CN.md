# 当前到底在做什么？不是训练模型，是修好 AI 应用的接口

## 先说结论

现在做的是：让用户用中文提出贸易数据问题，AI 把它变成查询计划，程序检查并在用户确认后查询真实数据、生成带依据的报告。

**我们没有训练 GLM，没有更新它的模型参数，也没有把测试题提交给供应商做微调。** 当前是使用现成模型的 AI 应用工程，不是模型训练项目。

## 一次使用的完整逻辑

1. **你说业务需求**：例如查询某两个月、中国以外原产地合计的进口额。
2. **GLM 理解和规划**：把需求写成结构化字段，比如任务、月份、国家范围、指标。这里可能误解或漏任务。
3. **程序转换和检查**：把明确的中文写法转换成统一名称，检查字段、原文依据和本项目的数据能力。这里不让模型凭空编数字。
4. **候选多任务流程还有一次模型复核**：检查计划是否覆盖原问题。它也可能错，不等于人工确认或独立证明。
5. **你确认后执行**：固定的只读工具查询已有数据，由程序组织证据报告。不能回答的范围必须说明，不能偷换国家或编造因果关系。

这是目标工作流程；目前候选多任务入口仍在开发，不能说已经稳定通过整体验收。不是每次离线测试都把这五步全部跑了一遍。

## 你需要能够解释的问题（附参考答案）

### 不断出题是在训练 AI 吗？

不是。出题是在测试系统。发现错误后，我们改过提示词（给模型的任务说明），也改过程序的检查和转换逻辑，再查看问题有没有解决。模型不会因为我们运行这些题就自动学会它们。

真正的模型训练通常要准备训练数据，通过训练程序更新模型参数；本项目没有做这件事。简历应该写“调用大模型进行需求解析、计划生成和复核”，不能写“训练了大模型”。

### 旧题和新题分别干什么？

旧题用于回归测试：确认已知错误被修好，而且其他功能没被破坏。新题用于观察未见表达能否处理。但看过结果后再针对它修复，这题就是开发材料，不能继续当成独立考试来证明泛化能力。

### 为什么模型已经看懂了，程序还可能失败？

因为“意思相同”和“格式完全一致”不是一回事。例如模型给出“2018年10月”，而程序要求“2018-10”；或者用户说“2018年9月与10月”，第二个月省略了年份。接口必须处理明确的等价表示，同时不能胡乱补足含糊信息。

### 本轮修了什么？

- 识别有限、明确的年月列表：“2018年9月与10月”可以转换为两个月份；不猜“去年”，不自动展开月份区间，不猜省略年份的跨年表达。
- 统一已登记的中文字段，例如“只读查”和“除中国外其他原产地合计”。原文引用不变，未知值不替换。
- “日本”只转换成统一名称 Japan；当前工具不支持单独日本，仍拒绝，不转换成其他原产地合计。
- 保留月份顺序和重复项；重复项继续交给既有校验拒绝，不能悄悄删除。

本轮没有调用 API、没有新出一批模型评测题、没有训练。新增的是程序边界测试和旧响应离线重放。

检查结果：新增 8 项边界测试，全套 273 项程序测试通过，旧实验文件指纹未变化。程序测试通过说明已检查的代码行为符合预期，不等于模型回答全部正确。

### 修复以后是不是准确率提高到 100%？

不能这样说。旧四份规划响应经新转换后，请求字段均与参考一致：N01 的日期和原产地转换问题解决，N04 只剩正确的国家能力拒绝，N02/N03 仍要求澄清。

但这是**看过错误后的规划阶段回放**，不是四次新的完整模型运行。尤其 N01 原来在复核前就失败，没有可回放的复核结果。这次也没查询金额或生成报告。因此旧真实结果仍然是 2/4；不能把离线修复写成新的模型准确率。

### 下一步该做什么，而不是无限出题？

收敛到一个明确业务场景，安排一轮有界的端到端验证：检查需求理解、用户确认、真实取数和最终报告是否完整一致。开始前先确定问题范围、调用上限、通过要求和停止条件；失败则定位环节，不反复同配置碰运气。

本轮的转换模块是可选适配器，尚未替换默认入口。下一阶段建议 Sol 高：决定接入边界和收尾验收标准，再执行有限验证。你现在不用运行终端或提供新的 API Key。
