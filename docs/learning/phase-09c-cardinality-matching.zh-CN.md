# Phase 09c 学习版：最大基数平衡匹配为什么仍然被阻断

> 当前状态：`blocked_before_pretrend_v3`

这一阶段是匹配路线的最后一次预登记实验。它不是把 v2 的参数偷偷放宽，而是把原始覆盖要求准确写进了模型：315 个处理候选中至少保留 252 个（80%），并在保留的商品上同时满足同产业、三对照、复用、平衡和距离门槛。

## 先回顾 v1 和 v2

- v1 对每个处理商品独立找三个最近对照，覆盖率 90.16%，但政策前趋势斜率和中国份额的 SMD 失败。
- v2 把全部 284 个可以唯一确定 NAICS3 的处理商品强制放进一个全局整数优化，结果证明无可行解。

v2 的“无解”只说明“284 个全部留下”做不到，并不自动说明“保留至少 252 个”也做不到。因此 Sol 高审查后，预先登记了 v3。

## v3 在解决什么问题

给每个处理商品增加一个二元变量 `z`：

- `z = 1`：商品进入重叠子样本，必须选择三个不同的同 NAICS3 对照；
- `z = 0`：商品因政策前共同支持不足被透明地排除。

每一条“处理商品—对照商品”配对又是一个二元变量 `x`。整数优化器必须满足：

1. 每个进入的处理商品恰好选择 3 条边；
2. 一个对照商品最多被不同处理商品复用 10 次；
3. 四项政策前特征的总体绝对 SMD 在优化阶段不超过 0.09；
4. 进入的处理商品数量至少为 252。

优化分两步：先最大化进入的处理商品数，再固定这个最大数量、最小化标准化距离。第一步没有可行解时，不运行第二步，也不读取政策后数据。

## 运行结果

第一阶段的 HiGHS 整数优化器返回：

```text
The problem is infeasible.
```

这不是超时，也不是“模型没想好答案”。在当前四项政策前特征、同产业、每个处理三个对照、对照复用最多 10 次和至少 252 个处理商品的联合规则下，数据不存在满足全部条件的组合。因此：

- `matched_control_pairs_v3.csv` 只有表头；
- `matching_excluded_treated_v3.csv` 列出 284 个唯一产业处理候选，说明它们没有进入一个达到覆盖门槛的整体解；
- 没有生成 `causal_candidate_panel_v3.csv`；
- 没有运行前趋势检验、事件研究或任何政策后因果估计。

报告中的“选中 0 个”不是说没有任何商品能找到对照，而是说“至少 252 个同时满足全部联合门槛”的解不存在。单独看，v1 已经证明很多商品各自能找到近邻；失败发生在把共同支持、总体平衡和复用上限放在一起之后。

为了区分“没有对照”与“联合限制冲突”，我们做了只读的约束归因检查：去掉四项平衡时，复用上限10仍可保留全部284个；去掉复用上限时，四项平衡也可保留全部284个；只保留中国份额平衡时最多保留267个。完整 v3 同时要求四项平衡、复用上限和至少252个，因此被判定无解。这些检查只解释失败，不改变主实验，也不查看政策后结果。

## 这对项目意味着什么

当前数据支持可靠的描述性分析和来源追溯，但不支持按预先登记的规则识别一个可信的政策因果效应。继续设计第四种匹配会把研究问题变成追逐通过门槛的数字，也会破坏停止规则。

这不是项目“没有结果”。相反，系统展示了一个真实分析系统应有的能力：

- 规则在看结果前冻结；
- 不满足条件时自动阻断；
- 失败原因、求解器状态和退出样本可审计；
- 不用政策后结果反向调参；
- 把“当前不能回答”作为数据证据的一部分。

## 你需要掌握的概念

### 什么是整数优化

它不是另一个聊天模型，而是一个严格执行数学约束的求解器。`x` 和 `z` 只能取 0 或 1，代表“不选/选”。目标函数告诉它先追求多少处理商品，再追求多近的对照；约束告诉它什么组合绝对不允许。

### 什么是共同支持

如果处理商品的政策前特征在对照池里几乎找不到相近对象，就很难把“处理组”和“对照组”公平比较。共同支持不足时，删除一部分处理商品可以改变研究对象；所以 v3 必须保存退出清单，并明确结果（若存在）只能适用于重叠子样本。

### 为什么不能看到政策后再挑商品

如果用 2018 年 7 月之后的进口变化来决定谁留下，就等于用结果选择样本，会把政策影响混进匹配规则，产生数据泄漏。v3 的脚本在求解通过前只读取政策前特征文件，候选面板只有在全部门槛通过时才会生成。
