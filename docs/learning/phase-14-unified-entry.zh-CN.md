# Phase 14：把 AI 接到真正的研究流程里

> 0073 审查更正：以下是历史阶段记录，不代表完整入口或正式验收已完成。旧24题已降为开发材料并禁止在线执行；当前状态见 [本轮中文解释](phase-17-integration-review.zh-CN.md)。

## 这一阶段到底做了什么？

以前我们有两个分开的东西：一边可以用固定参数算贸易金额，另一边可以检索政策并让模型写政策草稿。现在增加了一个入口，把它们接起来。

你用中文提出问题后，AI 只负责先整理成一张“待确认计划”：

- 你究竟要问哪条政策；
- 政策资料看到哪一天；
- 查哪个原产地、哪几个月、什么指标；
- 是政策整体还是某个六位商品；
- 你要描述变化，还是要求因果结论。

计划展示给你。你确认后，程序才读金额、检索证据，最后生成研究简报。

## 为什么不让 AI 直接查？

因为“听懂了”不等于“范围正确”。比如“最近几个月”可能是2025年，也可能是项目已有的2018年；“其他国家”也可能被模型误解成全部国家。让 AI 先列出计划，用户确认，程序再执行，是把错误拦在读数据之前。

这和你在数据库里先检查 SQL 再执行很像：AI 可以帮你写查询意图，但不能因为它很自信就直接改数据或偷偷换条件。

## 哪些事情由谁完成？

| 环节 | 负责者 | 作用 |
|---|---|---|
| 理解中文问题 | 规划模型 | 提出结构化计划，并保留原文引文 |
| 判断是否能做 | 程序 | 检查月份、商品、指标和因果状态 |
| 读取金额和计算变化率 | 固定 Python 工具 | 不让模型编数字 |
| 找政策原文 | BM25 与上下文模块 | 返回页码、原文和文件指纹 |
| 写政策解释 | 可选一次模型调用 | 只能在证据范围内生成，结果仍需人工审查 |
| 证明因果 | 当前没有完成 | 系统会明确显示“未估计”，不把描述变化说成因果 |

## 你需要记住的三个概念

**计划（plan）**：AI 对问题的结构化理解，不是答案。

**确认（confirmation）**：你批准这组范围。确认前不会读金额；确认令牌只能用一次。

**证据约束（evidence-grounded）**：金额来自固定数据工具，政策主张必须能回到有页码的原文。引用存在，不代表语义已经自动证明，所以报告仍有审查提醒。

## 这阶段是否已经“完成 AI 项目”？

工程入口已经完成，并且用本地真实贸易数据跑通了；但这不是自然语言准确率，也不是完整产品验收。还没有新 API 盲测，没有模型训练/微调，也没有多智能体。下一步要做的是先用离线测试确认边界，再决定是否按已封存的验收协议运行有限在线题目。
