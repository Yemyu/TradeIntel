# Phase13g：为什么“连通了”还不代表“好用了”

这轮不是训练模型，而是按事先定好的问题检查应用。实际发了4次请求：3次收到答案，第4次超时；按规则停下，后4题没运行。

## 两类问题要分开看

**回答质量：**模型知道两批生效日期，但把政策行动称为“修订”；还把凌晨00:01写成不清楚的“上午12:01”。不是全部事实都错，但这种表述不适合直接当可靠政策报告。

**资料是否给全：**我们问“额外25%是否包含其他税费”，模型没回答。核查发现，原文件明明有“在其他税费之外叠加”的句子，但本题检索出的三个片段刚好没带上它。这说明需要改善选取上下文的方式，而不只是让模型更聪明。

## 需要能解释的问题与参考答案

### 明明用了RAG，为什么还漏资料？

RAG并不等于模型读完所有文件。当前检索只选最相关的三个片段，排名可能偏重“25%”，却漏掉旁边说明“额外”的关键句。下一步考虑带上相关上下文，但要控制长度，不能无限把全部文件塞进去。

### 模型不回答算不算好？

比编造好，属于安全表现；但用户确实需要这项答案，所以业务交付仍没完成。“没有胡说”和“能解决问题”要分开评分。

### 第四题超时是不是代表问题不会答？

不是。没有返回正文，无法判断它会如何作答；也没有返回token用量，不能说这次没有消耗。后面的题未执行，不能填成失败或成功。

### 接下来是不是再跑一次直到通过？

不是。当前批次关闭，保留问题；下一阶段先设计针对“片段缺少限定条件”的改进，再按新开发协议比较。已经看过的这些题不能继续包装成未见题。

本轮不宣布模块验收成功，也不否定已有数据工程和真实调用能力。它告诉我们具体要改的是哪一层。项目最终仍要交付政策+贸易数据的完整经济研究回答，不会变成只做答题测试。
