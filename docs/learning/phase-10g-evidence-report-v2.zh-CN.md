# Phase 10g：AI查资料，程序负责准确展示

日期：2026-09-07。本阶段完成v2代码、离线验证和演示入口；尚未调用真实GLM测试v2。

## 你现在得到什么

以前模型查完资料后自由写答案，可能把金额抄错，也可能引用不对应的文件；程序的关键词安全检查又可能把正确内容一起删掉。

v2保留模型理解提问和选工具的职责。工具查到的数据由程序直接生成证据报告：政策日期、进口额、比较窗口、匹配计数及来源都原样或按确定公式展示。模型写的解释暂存于审计记录，不直接成为面向用户的结论。

例如询问政策后进口变化，报告会显示：

- 基期2017年8—12月：中国原产进口13,623,956,741美元；
- 当期2018年8—12月：中国原产进口10,393,832,954美元；
- 描述性变化约-23.7091%，并链接到对应统计摘要的来源标识；
- 匹配处理商品分母315、至少有两个对照的处理商品284；因果识别仍被阻断。

这些数字均由登记证据返回，模型不能随意改成另一个数。数值是否对应用户真正想问的时期，仍要检查模型的选择。

## 已验证的结果怎么理解

7项新增离线测试通过。将111条旧的成功生成轨迹固定回放，111条均能生成证据报告；原先21条被替换成短拒答的回答，现在仍保留查询事实及来源。9条旧生成失败轨迹没有被伪造成成功。

“回放”就是按旧记录重做当时的工具选择，用新程序展示结果。没有重新让GLM理解问题或接收新增字段，所以不能称为“新模型正确率100%”。本次API调用为0。

## 参考答案

**模型只负责选工具，这还算AI应用吗？** 算。理解问题、选择查询范围和组合工具仍由模型承担；数字准确展示由普通程序负责。不同组件负责自己擅长的部分。但固定离线演示本身不证明AI能完成真实任务。

**是不是降低了项目目标？** 这一步把输出收敛成可靠证据报告，暂时限制自由解释。代价是复杂改写、完整论证等需求可能答不全，不能宣称所有旧题都被解决。以后开放解释层，需要单独检验其事实和来源。

**来源标识有什么用？** 每条事实指向证据目录中的具体路径、URL和哈希，贸易金额对应统计数据，政策日期对应政策文件。模型说“来源：某机构”不等于已经证明这句话。

**为什么仍写needs_review？** 程序保证展示值来自执行的工具，不保证工具选择符合用户意图。问2018年而模型查2017年，即使金额完全抄对仍是任务失败。

**下一步做什么？** 设计新版本的小规模验收题与对照，先确认GLM在新增字段和证据报告模式下是否选对工具，再决定是否批量运行。暂时不需要再次输入Key。
