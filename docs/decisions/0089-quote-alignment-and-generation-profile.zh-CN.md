# 0089：原文定位与真实生成配置审查

## 判断与实施

0088要求模型输出quote和精确字符偏移。偏移是可以从原文确定计算的字段，人工计数或模型计数不会增加语义保障。因此增加宿主控制的derive_request_offsets模式：模型只按顺序输出quote/kind/target；程序逐段精确定位，填入start/end后继续通过原有校验。传输格式由模式开关明确指定，不把错误数字偷偷修掉，也不混收两种格式。

新CLI使用顺序引文模式；research-plan-4内部仍保留带偏移的完整计划，request_unit_positions注明derived/ordered_exact_quotes_v1。原带数字偏移模式留作编程兼容。原响应保留原样，规范化规则写入规划审计，开关与代码参与确认指纹。

算法只能跳过空白；引文改字、调序、漏掉非空白内容、漏掉末尾、重复占用同一位置都会失败。重复文字与Unicode字符按实际原文顺序定位。不做模糊匹配，不改模型的分类。模型将需求误分为context、错误判断比较方向的风险仍需语义审查。

新ResearchPlannerModel/ResearchPolicyModel替换当前CLI的历史适配器，分别固定max_tokens=1536/768、thinking disabled、stream false。历史BoundedModel及旧实验未改。新的配置快照从实际payload构造器提取model/temperature/max_tokens/thinking/stream，加上已有timeout/端点信息；不保存消息、请求头或密钥。

模型名、温度、超时仍来自用户配置，**没有强制把所有调用改成某个模型或60秒**。正式试运行前须核对glm-4.7、temperature=0、timeout=60；新增适配器解决的是输出上限与可观测配置，不能把配置快照等同已经完成整批预算控制。

## 离线验证

新增5项测试：顺序引文得到同样待确认计划及可核对交付；改字/重排/漏段被拒；Unicode和重复位置；模式变更撤销确认；用模拟HTTP传输检查真实请求体及调用前保存的配置一致。无网络请求。

全套462项通过（15.688秒）。固定开发样例的紧凑JSON从1319字符降为1200字符，减少119字符；不是token实测、速度收益或准确率。输入提示、事实要求及模型分类负担仍存在；1536输出上限下的真实可用性尚待观察，不能因格式简化就宣布更准确。

政策多需求仍交给同一生成调用，原文各项须包含在policy_question中，最终逐项needs_review。当前没有自动逐claim语义对齐，不自动宣称每个政策子问题都回答了。分散原文仍须使用覆盖它们的连续policy_question，这一限制未扩大。
