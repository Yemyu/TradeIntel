# Phase13c：最小连接诊断

依据：上一轮只确认超时，未确认具体环节。无密钥GET于本轮约0.7秒返回HTTP401；这是端点可达证据，不是密钥鉴权结果。

官方文档说明GLM-4.7默认思考，且允许通过thinking.type=disabled关闭：https://docs.bigmodel.cn/cn/guide/capabilities/thinking-mode 。旧通用适配器没有指定thinking/max_tokens；这是待检验的延迟因素，不是已确认的失败根因。

- 假设：若同端点、同glm-4.7和最近用户提供凭据，在短输入、关闭思考、最多16输出tokens时能完成，则可确认这次鉴权和小请求成功；不能单独证明此前超时由思考模式造成。
- 对照：保留前两轮完整政策请求结果；同时有本轮无凭据GET可达检查。此诊断同时改变输入和生成参数，因此不是隔离单变量的因果实验。
- 输入：仅要求回复OK，不含政策题、原文、参考答案或贸易数据。
- 预算：一次生成请求，60秒网络超时，不自动重试；不更换模型。
- 采纳：记录HTTP响应头到达耗时、总耗时及是否收到非空正文。只有这些连接能力可报告，不形成业务准确率或RAG成绩。
- 停止：任何错误或单次完成即停止本诊断；输出独占目录，保留异常类别和HTTP状态，不保留错误正文/URL/请求头/凭据。

若最小请求成功，下一步应单独冻结原政策题的受限生成验证；不在本次探测脚本中暗中连续发送。
