# 0079：比较作为独立交付任务

日期：2026-09-11。承接0078。本轮只调整任务状态，不改变数据或比较算法。

## 为什么要拆开

“贸易序列拿到了”与“用户要求的比较已完成”不是同一件事。比如数据完整但比较基准缺失，金额任务可以完成，比较任务必须是不完整。若只保存一个trade状态，报告会把部分完成误读成整句完成。

## 实现

- 带新版 `comparison` 的计划现在产生三个可能的宿主任务：政策问题、贸易序列、贸易比较；没有政策或比较时不虚构任务。
- 比较状态从确定性计算结果读取：`completed`、`incomplete` 或 `failed`。模型不能自报完成。
- 旧research-plan-1不增加新任务，保持既有回归结果；这次也没有改变因果门槛。

## 验证

已有419项全套本地测试仍通过；新版端到端回归现在同时核对贸易序列和比较 obligation。零在线API、零训练/微调、零因果拟合。

## 学习重点

obligation可以理解成“交付清单的一行”。一行对应一个问题，一个状态对应这行是否真的交付。把它拆开后，系统可以诚实地说“数字拿到了，但比较还缺数据”，而不是给一个模糊的整体成功。
