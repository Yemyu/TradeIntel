# 决策0028：明确意图的拒绝出口与逐字引用

模型假设：区分记录请求与执行请求，明确company/delete等属于可转写但不可执行的值，可减少过度澄清；逐字连续引用规则可减少模型加省略号。整份JSON围栏和比较证据路径别名归一化已经离线验证，一并接入新开发版。

对照为原catalog配置的12题开发全对、暴露留出第一轮19/24和后续停止记录。新配置仅改提示与确定性格式适配，glm-4.7、thinking disabled、2048tokens、180秒超时、原严格字段/引文校验不变。所有已暴露题都称开发回归，不称新留出。

验证集合是旧12题加已暴露24题，共36题一轮。先H16企业粒度、H17删除、H24引用三题，全部符合参考才继续其余33题；单题一次，无自动重试，首次API异常/额外工具请求停止。完整结果不得挑选拼接，未调用项保留分母。模型只见问题和固定提示，参考仅宿主用于检查。

对于合法解析但不支持的请求，宿主能力模块给出具体字段和值及拒绝理由，保留来源与用户原意，没有金额查询和写操作。该拒绝基于“当前理解”，intent_verified仍false；可执行任务保留确认步骤。模型自由文本不会成为拒绝依据。

本地验收：旧非法引文仍拒绝、只修无歧义格式、明确delete/company不执行、可查任务不越过确认、能力文件错误可说明。真实回归通过后逐题核对含义及拒绝出口；即使36/36也不是独立验收通过，后续需要新题或独立评审。
