## 本轮交付

### 1. 每个真实子任务都有宿主编号

新版研究计划在确认前生成宿主维护的 `task_ids`，当前组合任务会分别记录：

- `policy_question`：政策问题；
- `trade_series`：贸易月度序列；
- `trade_comparison`：用户明确要求的比较。

模型不能填写这些任务的完成状态。执行结束后，宿主才根据结构化结果把每项标成 `completed`、`incomplete`、`failed` 或 `needs_review`。这样“金额查到了”不会自动等于“比较问题也完成了”。

### 2. 政策问题增加检索桥接，但不替换原问题

规划器可以给出一条不超过240字符的短英文 `policy_search_query`。它只用于在英文政策公告中寻找候选片段；政策回答仍然保存并使用用户原来的中文 `policy_question`。计划、`request.json`、检索结果和报告都会同时保存两者。

宿主拒绝空值、中文-only、控制字符或超长桥接表达。没有政策任务时，桥接必须为 `null`。这不是把英文表达当成事实，也不是把自然语言翻译后直接当答案。

### 3. 规划与政策回答都有调用账本

确认后的运行目录新增 `model-call-ledger.json`，每条记录只包含：阶段、attempt_id、来源类型、模型调用次数、新 API 调用次数、有限的供应商元数据和状态；不保存密钥，也不把原始回答塞进账本。政策回答的独占尝试目录也在 `attempt.json` 和 `audit` 中保存自己的 `attempt_id`。

当前账本覆盖：

- 规划模型：一次结构化计划调用；
- 政策回答模型：最多一次有界调用；
- 贸易工具和程序计算：不计为模型调用。

fixture 与 live 分开计数。没有请求政策回答模型时，会记录 `no_model` 的零次尝试，而不是假装调用成功。规划失败会在返回对象中保留脱敏诊断和规划 attempt_id。

## 保留的边界

这轮没有训练或微调模型，没有新增向量数据库或多智能体，没有改变因果研究的阻断状态，也没有进行在线 API 验收。桥接改善的是英文政策语料的候选检索，不等于政策语义准确率已经通过；任务编号和账本改善的是可追溯交付，不等于模型已经正确理解所有中文问题。

为了让旧的政策回归预检继续明确发现代码版本变化，本轮同步更新了政策检索和生成模块的本地指纹。旧的真实批次仍然是历史材料，不能把新的工程回归当成旧批次成绩。
