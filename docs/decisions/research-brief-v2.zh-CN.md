## 一、结论：不能归咎于模型不够强，也不需要推倒重建

数据查询、版本固定、来源追溯与本地审阅已经有可复用基础。卡点主要是**任务设计过度收缩、证据接口缺少含义与范围、多个入口契约不一致**。GLM 真实回答也确有未经支持的推断，但单次三条回答不足以判定更换模型就能解决。

选择：在现有 `business_workflow` 上统一任务与证据接口，保留确定性计算、版本隔离和人工审阅。不是重写整个框架，不靠继续追加禁词，也不默认增加模型裁判、向量数据库或多智能体。

不变的目标：连接政策和贸易数据，为分析人员写有内容、可核查的研究初稿。自研因果已取消；此次不是恢复因果，也不是改成纯查数工具。

## 二、已经复现的根因

| 根因 | 代码或原始结果证据 | 为什么影响产品 |

## 三、锁定两个用户任务，分别解决不同问题

### T1：登记政策范围内的单月贸易结构解读（本轮集中实施目标）

输入：用户明确选择政策案例、月份、单个商品或全部登记商品，以及关注角度：`china_amount`（中国原产金额）、`china_share`（美国该商品进口的中国来源占比）、`contrast`（两者对照）。默认网页选择 contrast，不能擅自推断用户明确要求的其他任务。

输出：政策条件摘要、确定性数值、与任务有关的数据观察、AI 对观察的解释、具体缺口和来源。不是预测，也不是采购/合规建议。

为什么有用：同样问“关注哪些商品”，金额较大与来源较集中是两个不同问题。数据库能给出答案的数值依据，AI 应解释区别，而不是把“风险高”当作无依据的结论。

已知七月开发数据独立 CSV 复算示例（是本次方案说明，不是模型成绩）：

- 38180000 中国原产金额 8,385,427 美元，占五税号中国原产金额的 **81.80%**；但中国仅占该商品美国全部来源进口的 **4.71%**。
- 81019910 中国原产金额 742,146 美元，规模较小，但中国占该商品美国进口的 **28.63%**。
- 因此可以明确呈现：“关注中国原产贸易金额时，两者的排序，与关注美国进口来源占比时不同。”这不推出哪个企业损失更大，也不证明替代供应能力。

这些关系由程序计算和核对，AI 负责针对用户关注点组织解释、区分两个概念、指出继续研究需要的具体资料。是否比无 AI 的表格更有帮助必须单独验收，不能预先宣称。

### T2：新政策原文接入与范围确认（后续产品目标，不冒充已经支持）

输入官方文件，提取候选政策字段和税号，显示逐字段原文，让人确认，再匹配数据库覆盖情况。新条款只能进入 candidate，不准自动替换现行规则或把 HS6 扩展当精确匹配。

本轮先使两个已有案例走同一 T1 接口，第二案例用隔离验收资源。之后才接 T2：复用已存第二案例检验登记流程，再选择一份新公告检验真实接入。不能仅增加一个常量就宣称“任意新政策能力”。若需要新官方数据或条文，在那一阶段明确来源与验收。

## 四、锁定技术方案：一条业务链，事实与解释分层

`明确请求 → 固定案例/数据版本 → 政策条款与贸易计算 → 带范围的观察记录 → AI解释 → 程序检查＋人工内容审阅 → 报告`

### 1. 统一 ResearchRequest，原文与结构化输入保留

T1 的内部契约：`schema_version="research-request-v2"`、`task="monthly_exposure"`、`policy_id`、`month`、`product`（单个精确 HTS8 或 all）、`focus`、`policy_view="archived_event"`。版本由宿主固定，不由模型编造；同时保存原始 question 和解析来源。

- 结构化表单直接校验后生成该对象，不编一段自然语言再调用旧计划校验器。
- 自然语言只多一个解析步骤，同样产生该对象；字段缺失或冲突要明确补问，解析无法确认时不执行，不改成默认第一案例。已明确 policy_id 的表单不需要再猜案例。
- 自然语言 v2 先返回参数预览，展示政策、月份、商品、关注点和不支持部分，由用户确认后使用同一结构化执行器。不要把 LLM 自报“理解正确”当验证；也不要重新开发逐字覆盖整段问题的巨大校验框架。预览绑定原问题、参数及版本摘要，服务端保存一次性确认令牌；参数/版本变化时重新确认，未确认不能调用生成模型。明确结构化表单的提交本身即确认，不再多问一次。
- 日期区分统计月份、报告生成日、政策原文发布日期/获取日、政策视图；“最新可用数据”按固定发布快照解析并回显月份，不解释为“所有现行税则”。“现在总税率是多少”仍不支持。
- v1 的纯查数、政策问答、多月请求保留并明确标 legacy；不得静默把用户的多月问题转成单月。不在同一阶段重写所有历史入口。
- 当前模型输出 JSON 语法模式可以复用；不把提示中的 Schema 当成供应商严格 schema 保证。暂不引入新 SDK 或猜测新的供应商能力。

### 2. 统一 PolicyFacts：每个商品有自己的证据和限制

使用共同版本化结构，两个旧 builder 转换为同一接口，而非在每个消费者里判断 `if product_rates`。

每个商品条目必须有：hts8、登记中文名称、原文商品限定、原产条件、额外税率、生效时点/时区/适用事件、一般条件/例外状态、各字段的 source_refs。`unknown` 必须带原因，不允许以“同上”跨商品偷用不适用的条款。

每个 source_ref 至少绑定：policy_id、文档哈希、chunk_id、片段哈希、来源地址；数值来自经过核查的登记映射，模型提取只能生成待审映射。短卡只显示本次请求商品，其他商品原文可以在背景中展示，但不能混入可引用的当前分析事实。

同一存档的单一额外税率不代表综合税率；没有旧税率证据就不计算“上调了多少个百分点”。一般条件未核完不影响展示有依据的历史条款与统计，但必须显式显示缺口；不得据此给逐笔法律适用结论。

### 3. 统一 EvidenceBundle：金额、份额和关系都带含义

版本：`evidence-bundle-v2`。外层保存 request、policy_id、data_version、工具结果哈希、政策映射哈希、实际 source_refs、限制及 comparability 状态。只从本次固定的工具结果派生，不再次查“最新表”混入。

每个 metric 包含 id、metric_type、product_scope、period、measure、unit、value、status、numerator_id/denominator_id（比例时必填）、derived_from、source_refs。金额为非负整数美元；计算用 Decimal，展示按两位小数；零分母为 null 并说明，缺失不是零。

本轮计算且冻结的指标：

1. 单商品全部来源金额与中国原产金额；范围内两项金额合计。
2. 中国原产金额 / 该商品全部来源金额。
3. 单商品全部来源金额 / 本次商品范围全部来源金额。
4. 单商品中国原产金额 / 本次商品范围中国原产金额。
5. 按中国原产金额、按中国来源占比分别降序的排名（相等时并列，不以税号顺序伪造经济差异）。

由这些指标生成 observation：`amount_leader`、`share_leader`、`rank_contrast`、`single_product_profile`。每条绑定指标、比较对象与范围，并由程序生成准确事实句；未满足条件不生成，不能硬写“显著”“异常”“高风险”。单商品时不产出虚假的跨商品排名，也不要求模型凑够两个发现。

不新增 HHI、产能替代、因果或走势模型；数据虽含国家明细，当前 T1 尚未定义这些额外分析。跨期比较保留现有已核查能力，但 v2 单月入口不开放未经核查的同比。

### 4. 模型输出从“只准提待办”改为“解释已证实的观察”

契约 `research-brief-v2`：

```json
{
  "schema_version": "research-brief-v2",
  "findings": [{
    "observation_id": "本次观察ID",
    "explanation": "该观察对用户所选关注角度意味着什么；不得超出证据",
    "limitation_ids": ["本次证据局限ID"]
  }],
  "followups": [{
    "observation_ids": ["触发此问题的本次观察ID"],
    "missing_evidence": "还缺哪种具体材料",
    "question": "用它回答什么问题，而非预设答案"
  }]
}
```

findings 为 1—3 条，observation_id 不重复；followups 为 0—2 条，**不强制为了有输出而编调查问题**。explanation 最长 300 字，其余文本最长 200 字。unknown/无可用观察由宿主走资料不全分支，不要求模型硬填。各对象额外字段拒绝，引用集合必须来自本次范围。

准确事实句和数值由 observation 自动展示，AI 在它下面解释含义；不再把所有数值出现一律当作错误。若 AI 在自由文字内重复数字/税率/日期，作为需逐项人工核查的内容提示，不能仅凭数字出现否定整段，也不能仅凭数字相等证明语义。

这不是“自动验证所有中文推理”：程序保证引用存在、案例/版本/商品/指标关系和数字计算；人检查解释是否受到该观察支持。没有现行法源/交易证据，免税判断和规避指控不进入 T1 的已支持能力。真实输出仍可能写错，必须保留原答并单独记录，不通过自评循环偷偷重写。

禁止把 `trade.available` 这种“调用已成功”的过程标记当成论据；limitation 单列，不再充当一条合格的核心发现。

### 5. 原始响应只解析一次；保存统一中间表示

- 将当前 `object_response` 的严格去重 JSON 解析移到共用模块，维持既定完整围栏兼容；无自动补 JSON、无丢弃冲突字段。
- v2 在保存 raw response 后生成 `canonical-response.json`，记录原始响应哈希、parser_version、contract_version；内容只做无损格式解析，不能润色或改写模型答案。
- 生成、展示、审阅、导出只消费这个经过校验且绑定原答的对象。旧记录读取时可使用同一解析器在内存转换，不覆盖旧文件、旧成绩或旧审阅。
- v2 审阅指纹至少覆盖 request、evidence bundle、canonical response、raw response、事实资料。展示的是哪些字节，就批准哪些字节；保持原审阅追加修订、变更后失效的机制。
- 数据页链接加入案例身份并核对对应版本库；第一案例旧链接仍可读取，第二案例不得回退第一案例。candidate 只在已有隔离测试工具中可用，不加对外绕过开关。

对外兼容：保留旧端点为 legacy；新增 v2 预览/确认入口时复用 `web_app` 的本地 JSON/来源校验和并发锁，不新建服务。确认令牌只能取出服务端保存的参数，不能接受客户端重新替换版本或请求对象。未满足 v2 条件的旧响应仍可以作为旧资料查看，不按新任务采纳标准倒改成绩。

### 6. 分清三个状态，不再混成“项目过/不过”

1. 工程：生成成功 / 参数或数据失败 / 模型请求失败 / 格式失败。
2. 任务：必需事实完整或有明确缺口；内容待审 / 有内容错误 / 可用。
3. 人工：未审 / 指定条目采纳或拒绝；不等于案例发布、法律批准或已验证准确率。

人工拒绝两条、保留一条局限仍允许导出资料，但**不能算 T1 分析完成**。T1 至少要有一条被采纳且支持用户关注点的核心 finding；全部范围的 contrast 在榜首确实不同时须覆盖两个观察及其区别。局限数量不是成果指标。

## 五、一次集中实施包，避免继续无限分期

建议 Luna 最高按以下锁定顺序完成同一个实施阶段；它们是提交前检查点，不要求用户每一步说“继续”。遇到协议矛盾再交 Astra 判断，不自行放宽。

1. 共用 JSON 解析和 canonical response；补完整围栏/重复键/原答篡改/历史只读测试；移除当前产品测试对私人 tmp 响应的依赖，使用明确标注的合成 fixture。
2. 两案例 PolicyFacts 适配、EvidenceBundle、指标/观察计算；复用现有查询和发布副本，不改原始数据或历史实验。
3. T1 的结构化入口和自然语言解析共用执行器，接 v2 解释与现有审阅/下载；只改必要交互和标签，不做装饰性看板。
4. 在临时目录测试第二案例封存/查询/审阅/数据链接，生产仍 candidate；按案例参数化固定版本链接。
5. 完成下表离线矩阵、记录当前产品测试集合与历史测试清单；交付一个可直接有限验收的入口，不再新增另一个平行框架。

涉及文件：主要为 `structured_task`、`business_workflow`、两种 fact_sheet、`fact_interpretation`、`interpretation_review_store`、`research_data_link`、`version_report`、`web_app`、首页；最多按职责新增共用 parser 和 evidence bundle 模块。旧 agent/冻结实验执行逻辑不为这次方案改动。

- 补接后再次验证：47 项聚焦 Python 测试、1 项 DOM 测试通过。全量 `unittest discover` 为 880 项、3 failures、44 errors；44 errors 与 1 个 failure 属旧试验冻结文件/历史行为断言，另外 2 个旧 CLI/逆向审阅断言仍单独保留，未把它们改成“绿色”。

- 尚未完成：第二案例正式开放、真实模型对照、浏览器实际点击验收。因此本轮仍是 **G1 核心子集完成，整体 G1 尚未宣称通过**。

### G1 离线工程门槛（Luna 执行）

| 必须覆盖 | 通过条件 |
|---|---|
| 解析到导出 | 普通 JSON、完整围栏行为一致；重复键/混合冲突拒绝；旧原答不变 |
| 证据隔离 | 错误案例、版本、商品、无关事实 ID、改写原文/原答不能混入已审报告 |
| 数学与分母 | 合成数据独立期望值和真实月表独立求和一致；两类份额不混；并列/零/缺失分开处理 |
| 业务内容结构 | 单商品合法；金额榜首与来源份额榜首不同的样例可表达；仅局限不判任务完成 |
| 请求语义 | 合法否定约束及“最新可用数据”能进入正确的存档任务；肯定的因果/现行总税率请求明确拒绝/补问；解析不确定不能执行 |
| 入口一致性 | 同一明确 T1 请求经两种入口得到同一固定数据和观察；自然语言仅增加规划调用 |
| 候选与旧版 | 第二案例不能公开绕过状态；同版链接可追溯；旧报告不受新契约强制重写 |
| 可复现 | 当前产品测试不读取私人 tmp 或真实凭证；干净资源清单和合成 fixture 足够；失败明确显示 |

本轮已有的反例只能证明已知缺陷是否修复，不当作模型盲测。既有冻结测试独立列为历史验证：记录应使用的原版本，不删除它们或重新冻结覆盖老成绩。当前产品集合必须按真实依赖/用户入口选择，不按“哪些测试刚好能过”选择；新测试未归类时 CI 应提醒。

### G2 模型验收协议（Astra 复核后执行，不在本轮调用）

假设：完整、带含义的观察记录加任务型输出，比当前泛化待办更能产生有证据的有用解读。不是假设“新 prompt 一定更准”。

对照：A 为程序事实报告（零模型，实用性下限）；B 为同一模型拿到同样官方条款、数值、所有派生指标和限制后的单次自由中文回答；C 为 v2 工作流。B 与 C 获得相同业务信息，不用“不给 B 数据”制造优势。不同输出组织方式属于系统比较，不称纯 RAG 消融或模型训练效果。

模型先固定 GLM-4.7、temperature=0、thinking disabled；本阶段不同时改模型和方法。一次输出最多 2,000 tokens，输入由本地先限制到 8,000 tokens 的保守估算预算（必须记录估算方法及实际 usage）；超出则停止并调整输入设计，不自动截断证据。每次最长 90 秒、无隐藏重试、无模型自评。

上限共 **12 次请求**：新结构开发诊断一题 B/C 各一次（2）；锁定四项正向业务验收 B/C 各一次（8）；两条自然语言入口各一次规划（2，后续执行用已记录的生成响应验证接线，不冒充新增端到端模型结果）。最多约 120,000 输入＋输出 tokens 的规划预算，实际供应商消耗以 usage 为准，缺失不能记零。不要借剩余额度追加问题。

四项正向验收构成固定为：主案例整体 contrast、主案例单商品 profile、第二案例整体 contrast、第二案例单商品 profile。工程完成后、真实调用前，一次性冻结具体问题/月份/版本和参考答案哈希；月份不得按模型预跑表现选择。第二案例测试只在隔离环境，不自动上线。

防泄漏：参考答案/评分说明不进入模型请求；开发题与验收问法/任务实例区分。两个政策已被多次开发使用，因此这只是**已知政策内的迁移验收**，不能称新政策盲测。保留全部输出、错误、预算；主案例旧七月三条输出及其针对性修复不能计成独立成绩。

采纳门槛（事先固定）：四题均交付完整资料；零严重政策/金额/分母/范围错误；至少三题的核心解读在不重写模型文字的情况下可用，其中两个整体 contrast 都应解释两种关注角度的差别；至少三题相较 A 增加具体且受到证据支持的解释。单商品不要求凭空制造反差。B/C 逐项公开，不预设 C 必须胜出。

内容由 Astra 逐条依据资料记录审阅，明确这是开发者助手审阅，不冒充独立专家/用户金标。界面中的真实用户批准仍由用户操作。最终展示需要用户完成一次实际任务，才能记录真实使用反馈或耗时。

停止条件：G1 不通过，不调用模型；开发题发现严重依据错误，先停并定位机制，不跑完验收刷成功；认证/费用/连续性不明等运行故障即停，未知 usage 单列。锁定四题中首次严重内容错误即停止扩大调用，已调用的全部保留、未调用题记未运行。完成一轮后未达门槛，最多提交一次基于具体根因的修复决策，不能自动换月份重测。

只有在 G1 通过且证据已充分、GLM 仍稳定出现可归因内容失败时，才设计独立模型对照。模型对照另行冻结配置/预算，当前不承诺哪一型号会赢。若解释长期不优于 A，承认该功能收益不足，交用户决定改任务或模型，不把模板报告包装成高质量 AI 研究。

### G3 本地使用验收（工程与真实输出准备好以后）

启动本地页面，完成选择案例/月份/商品 → 生成 → 查看观察与原文 → 人工采纳/拒绝 → 导出 → 固定数据链接；另测失败可理解、重新打开能恢复记录。G2 的一个 C 请求应通过真实网页完成，计入同一 12 次预算；G3 的后续审阅/导出复用该记录，不另起免费重跑。自然语言预览/确认的工程接线可用 fixture 验证，明确不冒充新增真实模型整链。浏览器核验不能由 HTTP fixture 替代；环境无法检查时明确留一项待核验，不编造视觉通过。

## 七、结束后再做什么

v2 达标仅表示“登记政策的数据支持型研究初稿”完成一个可信阶段，不是整个原目标全部完成。随后按顺序做 T2 新政策候选接入、受控的官方资源更新、具体报告更新/简报交付；不先建设任意国家平台或恢复泛化更新闲聊实验。

本阶段没有证明 GLM 质量提升，也没有开始 G2 真实验收。Astra 中已完成复核并拒绝 G1；下一步按复核清单修复，再审 G1。实现建议 Luna 最高，复杂语义和结果采纳用 Astra 中；用户保留当前 Astra 中也可执行。
