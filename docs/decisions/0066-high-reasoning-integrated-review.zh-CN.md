## 2. 旧因果失败：哪些复核了，哪些没有

### 2.1 可复现的只读审计

新增 `scripts/audit_frozen_causal_design.py`。它只构建矩阵，不调用优化器；不使用政策后金额。结果在[审计 JSON](../experiments/high-reasoning-review/frozen-causal-audit.json)。

- 284处理、829对照、14,671条候选边；711行约束、14,955个变量，与v3存档一致。
- 每个处理都有边，最少7个候选对照；没有“处理商品根本没有候选边”的情况。
- 使用5个固定随机测试向量，独立按约束公式计算，矩阵乘积最大差约1.02e-10。测试向量不是求解结果。
- 独立复算v1 SMD：规模0.001540、趋势0.167172、波动0.053286、中国份额-0.158861；与存档最大差小于8e-13。
- 有资格商品的29月面板预期32,277行，全部存在，未发现重复键、空金额、非有限特征。这不能证明所有原始国家记录缺席都等于经济上的零。

因此，**这轮没有找到足以解释旧无解的矩阵规模或平衡公式错误。** 没有重新运行独立求解器、没有给出不可行性数学证书，不能把本审计说成再次证明所有研究方法都无解。

### 2.2 对旧解释必须作的限定

1. v3的无解对应内部 **SMD≤0.09**、至少252处理、每处理3对照、同NAICS3、复用≤10的联合条件；不能外推到所有允许SMD<0.10的设计。
2. 3个对照、80%覆盖、复用10次是本项目选择，不是因果识别的通用必要条件。不能一边把自定门槛当自然定律，一边据此宣布原问题不可做。
3. 距离和有效对照数是在求得解之后检查的采纳门槛，不是当前v3第一阶段无解的直接原因。
4. v3报告的选择数0是失败占位，不是“最多只能匹配0个”。现有证据工具已转成null，应继续保持。
5. 0006还记录过移除部分约束后的284/284/267诊断。本轮只确认该文字记录，未定位并重建它们各自的独立原始求解产物，不把它们算作本轮新验证结果。

### 2.3 发现的潜在代码风险不等于旧失败原因

- v3矩阵按全部合格处理计变量，目标向量按有边处理计变量：未来若出现无边处理会维度不一致。本批没有这种商品，所以不能拿这个潜在缺陷解释本批无解。
- v1会把空单元格或缺月当零。本轮合格样本没有这种输入；源级无记录的经济含义仍需单独审核。
- SMD采用两组自由度加权的合并标准差，不是两组方差简单等权平均。新实现必须遵循具体协议，不能在审计时混用定义。

旧冻结实现不在此轮改写。若新版本复用，必须先加入明确输入检查；旧结果保持原样。

## 3. 实质性新发现：所谓“干净政策前”包含已宣布阶段

旧配置将2016-01至2018-05全部标成clean_pre，只把2018-06标为预期月。但官方资料明确记载：

- 2018-03-22宣布采取行动并要求公布拟议清单。[USTR 3月资料](https://ustr.gov/about-us/policy-offices/press-office/fact-sheets/2018/march/section-301-fact-sheet)
- 2018-04-03公布拟议商品清单；4月6日进入公报程序。[USTR 4月公告](https://ustr.gov/about-us/policy-offices/press-office/press-releases/2018/april/under-section-301-action-ustr)
- 6月15日确定首批，6月20日公报出版，7月6日生效。最终818项由拟议清单收窄而来。[USTR 6月说明](https://ustr.gov/about-us/policy-offices/press-office/press-releases/2018/june/ustr-issues-tariffs-chinese-products)

这意味着3—5月**可能**已有提前采购、推迟采购或合同调整。不是证明这些反应已经发生，也不是说3月以前绝对没有预期。2017年调查等更早信息仍应在时间线披露。

尤其0043/0044用2018-01至05作为“政策前检查期”，其中3月与4月的目标减预测差分别0.110490、0.197890，后者也是最大误差月。旧RMSE为0.105546，门槛0.10。由此不能确认误差来自政策，但**不能不经讨论就把已宣布阶段的偏离当成反事实失败**。

必须保留旧失败，不删除3/4月后重新给旧实验打“通过”。本轮发现支持一个新的时间线修正设计，不支持伪造旧成绩。

另一个重要问题：拟议清单形成时考虑过替代来源和行业技术性质。处理不是随机分配，数据来自官网不等于选择过程外生。[4月拟议行动原文](https://ustr.gov/sites/default/files/enforcement/301Investigations/FRN301.pdf)

## 4. 文献核对：新维度有依据，但不自动解决识别

核对了Fajgelbaum等《The Return to Protectionism》2019年10月作者稿的II.A、II.D、III.C、IV.A/B/F，并渲染核对事件研究公式页。其事件研究使用商品—国家、商品—月份、国家—月份效应；弹性估计还需要关税变化、价格和数量等信息，并讨论预期、未观察冲击和推断层级。[作者稿及方法](https://business.columbia.edu/sites/default/files-efs/pubfiles/26111/return_to_protectionism.pdf)

与本项目比较：论文不是先要求每件商品找到三个同产业对照；也不是只把“中国”和“其他国家合计”相减后就得到绝对政策损失。其全贸易战、多国多税率设计和结构模型不能直接搬给单批清单、有限国家汇总数据。以下路线判断是本项目据此作出的推论，不是论文验证了我们的样本。

### 决定及价值排序（不是成功概率）

| 顺序 | 路线与回答的问题 | 主要价值 | 主要障碍 | 当前决定 |
|---|---|---|---|---|
| 1 | 原问题的时间线修正版：中国相关商品如果没有该政策，本来会怎样 | 最贴合原目标；利用已有48月HS6和政策前细码资料 | 对照外生性、预期、商品用途、政策污染仍未解决 | **先补特定证据**：完成第5节一次准备审查，再决定是否拟合 |
| 2 | 商品×原产地：受税商品的中国来源相对其他来源怎样变化 | 能研究采购来源重组；可控制共同商品需求和国家冲击 | 来源替代、国家专属商品冲击；逐国与政策后细码资料不足 | **备选设计，不立即估计**；相对效应不能冒充中国绝对损失 |
| 3 | 食品设备等狭窄用途的中国进口效应 | 经济机制较具体，可能更可解释 | 真正同用途样本极少，3对3也不等于独立6个足够精确 | **暂停拟合**，没有证据支持目前优于前两条 |
| 4 | 比较中国商品销往美国和外部进口市场 | 增加市场维度，有机会分辨共同中国供给冲击 | 新数据口径/覆盖/运费差异，外部市场也受贸易转移 | **暂不补采**，先证明新增市场可比较、数据可统一 |

商品×原产地的候选方程可写成：

`E[进口额(p,o,t)] = exp(商品×来源效应 + 商品×月效应 + 来源×月效应 + β×List1商品×中国来源×政策后)`。

这是待审的PPML条件均值框架，不是已估计模型。β在这些控制及假设下反映中国相对来源表现；其他来源也会受替代影响，不能直接转为无关税世界的中国美元损失。只保留List1商品会让中国×政策后与来源×月效应共线，**还需要明确的未处理商品维度**；加几个国家不会自动解决原来的比较问题。

即便有未处理商品，目标商品×中国专属的同期需求或供给冲击仍会混淆β。国家×月效应只能吸收国家层共同冲击；商品×月效应只能吸收来源共同商品冲击。固定效应不是自动消除一切现实因素的开关。

## 5. 原路线下一步：只批准准备工作，不批准效果搜索

### 一次性准备协议

**假设：**旧“干净政策前”的定义过晚，可能让资格/特征包含预期反应，也让时间检查混淆预期与反事实误差。修正可以改善设计有效性，但结果未必更好。

**基准：**保留旧29月资格、特征、三轮匹配、333时间检查的原始数值与失败标签；新输出逐项列差异，不覆写。

**固定窗口：**以2016-01至2018-02的26个月作为“3月行动宣布前”的准备窗口，不把它称完全无预期。2018-03至06单列预期/宣布阶段，7月过渡；原主要观察期2018-08至2019-07先保留，不选择效果最大的月份。若另需2017年底截止的敏感性，只能先登记并完整报告，不挑较好版本。

**资格重建：**不仅截短特征，还要重建依赖旧29月的活跃度、处理纯度和金额权重。活跃度保留原24/29比例后向上取整为22/26；这是透明的准备规则，不是因果采纳门槛。代码历史有效性、List2/3及201/232污染规则不因数量不足而放松。保留全部进出原因。

**数据事实检查：**在既有HTS10/HS6与ZIP中核对拟议名单、最终名单、后续排除及生效日期的映射；拟议但最终未征税的商品也可能有预期反应，不能不披露就当完全未受影响。数量单位不一致时不拼数量；金额变化不等于数量变化。

**防泄漏：**不使用2018-03以后金额来选资格/权重/行业；旧资料已探索，不能声称新独立盲测。该准备阶段不拟合权重或效果，不计算删除坏月份后是否“达标”。只按日期、法定名单与规则产生资格表和缺口报告。

**采纳门槛：**月份与映射可核对、无隐式补零、处理/对照纯度明确、用途机制说得清；达到这些条件只允许制定估计协议。不能以候选变多或SMD更好代替识别。

**停止条件：**拟议或排除范围无法可靠编码、必要来源缺失、候选变化主要靠不当补零、或无法解释对照的经济机制时，停止拟合，列出具体缺口。最多一次准备版本；不反复挑截止月。

### 任何后续估计协议仍必须补齐

- 目标是原清单分配的意向处理效应，不是逐笔始终承受25%额外税的效果。排除具有追溯及选择问题；“删所有后来获排除商品”只能是改变样本的敏感性，不能当无偏主估计。
- 若研究子样本，对外只说该子样本，不外推全部818项。原log1p商品等权目标不是美元总损失，也不是严格对数弹性。
- 用途比较依据必须先于政策后分析；SMD只检查所选特征，不能证明反事实成立。
- 拟合前固定基准、预期段/动态项、季节性处理、权重上限的经济理由及不确定性容忍度。不能把预趋势p>0.05当成立证据。
- 月份不是独立政策样本；需针对商品/相关行业依赖设计聚类和敏感性。单一受影响国家、多月堆叠、少量HTS8不能假装有大量独立政策冲击；先评估精度和最小可检测效应，再决定是否值得估计。
- 置信区间、符号不稳、零/缺失和规格失败都报告；不以显著负系数作为“完成”标准。

## 6. 自然语言到报告：一个计划，一条主入口

### 真实问题

- `ResearchBrief.prepare`要求显式policy_question、policy_as_of、trade；13k的真实报告据此成功，不是自然语言自动规划成功。
- 旧规划器的policy任务只是登记政策资料，没有容纳任意政策问题和检索截止日的槽位。
- 旧规划器要求各贸易字段都带用户原文证据；但只读操作、固定政策ID等属于应用约定。强迫用户逐项念出来是不合理契约，不应靠编造“原文”解决。
- v4再调用模型复核也不等于独立事实审定。默认增加一次复核会增加成本与新失败点；在收益验证前不作为新链条强制步骤。
- 复现入口契约冲突：报告层接受到12000字符，检索层最多2000；2001字符问题报错时`_pending`仍存在。另有确认token只绑定请求、未绑定语料/数据指纹及会话版本的问题。当前本地一次性消费不等于未来跨会话安全保证。

### 锁定的接口

新版本计划 `research-plan-1` 是唯一自然语言入口输出，不再创建一套孤立的报告功能。复用现有执行器、确定性计算、证据登记和报告内容；冻结旧版本用于回归。

| 字段 | 谁负责 | 规则 |
|---|---|---|
| original_question / conversation_revision | 宿主 | 保留原文、修订号；任何新消息使旧待确认计划失效 |
| task_ids / obligations | 模型提出，宿主检查 | 政策回答、贸易序列/指定变化、因果边界等子问题逐项列出；不能把“比较”换成“readiness” |
| trade | 模型提出 | 国家、月份、商品、指标与比较种类；缺关键范围须问，不擅自补成中国或首末月变化 |
| policy_question / publication_cutoff | 模型提出+宿主日期校验 | 政策子问题与贸易时间分离；出版截止日不等于法律适用日，也不等于贸易数据实时版本 |
| provenance | 宿主核对 | 每个参数标user_quote、confirmed_context、app_default或derived；只有user_quote要求原文连续片段；派生值附规则与输入 |
| blockers / clarifications | 宿主及模型 | 不支持国家、现行税率、未知商品、不完整比较明确列出；模型解析失败不得归咎用户缺信息 |
| confirmation | 宿主 | 预览全部默认/推导范围、能力不足；确认绑定规范计划、会话修订、数据/语料/契约指纹及nonce，不由模型生成 |

固定默认仅允许：美国为进口国、List1为页面研究案例、只读、不估计因果。默认必须在预览明显显示。资料截止日可以来自已确认的案例设置；没有设置就问，不用运行当天悄悄代入。政策/贸易单独任务也可提出，不强迫用户附加另一个任务。

### 流程和失败规则

`用户表达 → 一次规划 → 规范化及能力核验 → 中文预览/澄清 → 用户确认 → 贸易工具与政策检索 → 一次受证据约束生成 → 报告`

| 情况 | 行为 |
|---|---|
| 明确请求 | 展示准确预览，确认前不执行贸易/调用回答模型 |
| 少国家、少月份或不清比较基准 | 具体追问；保留已经明确的参数，不要求用户重讲全部 |
| 一部分超能力 | 先说明不能做的部分；用户明确选择保留可做部分后才执行，不能默默丢任务 |
| 模型格式或理解失败 | 说明规划失败，可改用显式选项；不改写问题让它看似成功 |
| 确认前文件/配置变化 | 旧token失效，重新预览；执行前重新校验指纹，不依赖旧对象缓存 |
| 贸易失败 | 不生成金额；按已确认计划保留独立政策部分，整体标partial/failed |
| 政策无证据/超时 | 保留真实贸易结果，政策部分单独失败，不标整题成功 |
| 引用ID存在但不支持主张 | 不标语义已验证；保留原响应供审查；事实安全门槛由验收判定 |

统一输入上限为2000字符，超出明确要求精简，不截断。所有校验和检索预检成功后才创建pending；token不应由请求内容单独决定。文档文本和模型文本视为数据，不作为新指令；公开网页渲染必须使用安全转义/消毒，不能仅依赖当前Markdown替换函数。

比较操作必须显式标记：列月序列、首末所选月变化、登记同比/窗口比较。现有首末月变化不得冒充“政策前后影响”。输出按obligations逐项回答，不让政策段与数值段互相拼出未经估计的因果解释。

**修改清单：**统一计划适配器与校验 → 现有report入口接收确认计划 → 指纹和失效机制 → 政策接入层 → 报告逐项状态。旧实验模块不批量重写；不另建新聊天系统、不先引入多智能体。

### 用户实际会看到的样子（设计示意，不是本轮新模型输出）

输入：“第一批关税公报出版和生效是同一天吗？再列出2018年9月、10月其他原产地整体的消费进口额，算10月比9月的增幅。”

预览：“研究案例为美国2018年List1；其他原产地整体不含中国；美元消费进口额；9月与10月；计算10月相对9月增幅，不是同比或因果效果。政策出版截止日使用已确认的案例设置2018-08-16。是否执行？”若案例日期尚未设置，就先问，不能伪造已确认上下文。

报告组织：先分别说明公报出版与生效；再给9月36,587,820,118美元、10月41,012,723,839美元，变化4,424,903,721美元、12.09%；最后说明来源、期间、该描述不能证明关税导致变化。这里的数字来自[既有13k存档](../experiments/phase13k-delivery/report.zh-CN.md)，不是本轮新API调用或新验收题。

落地文件边界：增加统一计划适配器（新模块），修改`run_research_brief.py`以支持自然语言/显式参数两种输入但共享确认和执行；新报告版本承接逐任务状态，旧`research_brief.py`保持归档基线；新增政策接入层，不改冻结`policy_retrieval.py`指纹。新组件只连接已有执行器，不复制金额计算或建第二套数据库。测试必须覆盖缺字段、默认披露、修改失效、越界、重复确认、政策/贸易独立失败和逐任务覆盖。

## 7. RAG：唯一优先方案是修好政策证据接入层

### 分层诊断

| 层 | 已确认问题 | 不能误判为 |
|---|---|---|
| 覆盖 | 仅2份公告5页正文、34片段；附件与完整排除历史不在索引 | 换模型就能从不存在的资料找到答案 |
| 中文检索 | 依赖有限中文词表扩展，其他汉字被英文tokenizer丢掉 | 只要用了BM25就支持任意中文 |
| 范围 | 出现“目前”即拒当前政策，可能误拒“目前我只想了解2018年……” | 安全拒答都算成功 |
| 上下文 | 13g漏掉叠加税费限定，13i扩窗有改善；窗口可重叠 | 扩窗就补全政策库 |
| 生成 | 名称混淆、无关时刻、弃答；新聚焦提示只有有限开发证据 | 格式正确就是内容完整 |
| 引用 | ID/偏移有效只验证来源身份 | 自动证明每条主张受支持 |

本轮复现：`这份通告在报纸上刊载的那一天就是开始收税的日子吗？`产生空检索词；`目前我只想了解2018年第一批关税何时生效？`被当前政策正则拒绝。两个例子现在属于开发诊断，不得用于新验收并称盲测。

### 一项完整改进，而非技术堆叠

**版本化政策证据接入层**：把已确认的政策子问题转换成带批次/历史时点的检索请求；保留原问题，使用统一规划调用提出的短英文检索表达加固定历史术语，不再额外调用一个翻译模型。检索改写不能改日期、税率、国家；这些字段由原问题/明确设置核对。证据仍必须来自原文。

首轮语料保持原2份正文以分离效果；修正范围判定、查询桥接和上下文去重，不同时改语料。超过范围仍明确拒答。默认保留BM25，暂不加向量库/重排序：已确认问题首先在入参和覆盖层，34片段并未证明需要这些组件。若新未见表达仍系统性漏检，另立多语向量对照，不能凭名词提前采纳。

随后按固定研究需求扩充版本化资料：3月行动说明、4月拟议行动正文及清单、6月最终清单、8月后续行动、观察期内List1排除与修订。每项记录宣布/出版/生效/追溯日期、批次、原文位置、替代关系；附件表另作结构化索引。来源先用[USTR List1官方目录](https://www.ustr.gov/issue-areas/enforcement/section-301-investigations/section-301-china/34-billion-trade-action)。暂不承诺现行税费或企业逐笔适用判断，不让资料扩容拖住首个可验收版本。

### 对照与消融

- 固定语料和下游生成设置：旧查询/BM25/扩窗，对比新接入层；每题核对必要证据召回、限制句完整、重复字符和送入长度。
- 分别关闭查询桥接、关闭范围修正、关闭去重，区分谁产生收益。离线检索消融不使用API。
- 语义评测参考需定位原文必要证据；不能只标某个chunk ID为唯一答案而惩罚同义完整段落。
- 不续跑13g，不反复用P03调提示；新诊断题进入开发库，验收另建。

## 8. 整体验收：协议锁定，尚未运行

### 题型及隔离

新24项内部前瞻任务：12项可回答研究请求、6项需要具体澄清、6项越界/安全/部分可答。清楚记录参考范围、预期任务、必需事实、来源段、禁止结论及允许的澄清。

本轮锁定类别与计分规则，**尚未制作并封存24道完整题目及参考文件，不能启动验收**。实施完成后、第一次调用前，保存题目/参考/语料/提示/代码/模型参数哈希和审查签名。题目不得写进运行提示或示例；作者可能是同一开发助手，需披露内部评测而非外部独立盲测。已读过的旧题和本文件例子不能入新集。

### 成功不是解析通过

- 整任务成功：正确理解全部子问题、范围正确、按要求确认、必要事实完整、数值精确、证据支持、限制清楚；一项实质失败即整题失败。澄清题以问对问题且不执行为成功，不要求生成数字。
- 数值正确：对独立参考计算核对金额、分母、比较方向和月份；引用了真数据但用错范围仍失败。
- 事实支持：人工逐主张核对；报告支持率和必需事实覆盖率。空回答不能靠“没有幻觉”取得完整通过。
- 澄清/拒答：分别报告正确澄清、正确拒答、误拒可答问题、漏拒越界请求；不能用总拒答率代替质量。
- 运行状态：成功、实质失败、安全弃答、超时、未执行分别保留。主要发布“完成成功数/预定24项”及执行覆盖；辅助发布“成功数/实际尝试项”。未执行不算模型内容错，也不能从总交付分母消失。
- 成本：新调用数、输入/输出tokens、逐任务耗时、p50/p95和样本数。超时没有返回用量就是未知，不写0、不推断免费。

### 基准及预算

1. **显式正确参数基准（零API）**：人工/参考参数交给现有贸易工具和证据片段。证明确定性计算底座，不参加自然语言理解排名，也不能冒充通用AI基线。
2. **无检索生成**：只给政策问题，不给政策原文；在12项可答任务的已核对参数上新调用，比较事实/引用，而不是比格式。
3. **当前RAG**：固定相同政策问题、当前词法/扩窗/聚焦组件，新调用而非旧截图；用于组件配对对照。
4. **新整链候选**：24项，每项最多一次规划和一次回答；无自动复核/重试。需要澄清的题本轮到澄清结束，不偷偷多轮补成成功。

上限：新整链48次＋无检索12次＋旧RAG12次，合计最多72次调用尝试；实际部分题不调用回答模型。固定使用先前能返回的GLM-4.7作为候选，不在同批换模型；开跑前确认账户可用性和授权预算。规划输出上限1536 tokens、回答768，单调用60秒；输入总长度在调用前核对，累计已返回用量达300,000 tokens时停止，不再启动下一题。上限不是预期消耗或已发生费用，也不能阻止最后一次调用略跨累计阈值。

任一鉴权/配额错误立即停；连续两次传输失败/超时停止批次。危险执行、来源指纹变化或密钥进入产物立即停止。保留剩余题未执行；不无限换key或重试。对照臂调用顺序在运行前固定交错，降低服务时段差异；失败也保留配对位置。

### 原型发布门槛

24项全部有明确终态，整任务至少22/24成功；12项可答中至少11/12；6项澄清至少5/6；6项越界/安全/部分可答全部符合预期。所有已发布数字正确、无越权执行、无捏造来源、无未经估计的因果主张；任一严重事实错误不能靠总分覆盖。

这只是小规模研究原型门槛，不是“真实准确率至少90%”。需给24项成功比例的Wilson区间，说明样本选择和作者自评限制。首次失败后本批关门；修复可以用已暴露题开发回归，任何新验收另行登记，不能追刷到通过。

## 9. 交接与公开口径

验证结果：新增6项只读审计测试、全套357项测试通过，用时21.3秒。测试锁住审计不调用优化器、独立公式与存档一致、合格预期行完整，以及缺失/重复/空值诊断和合并标准差定义。未增加任何在线AI分数。

- 此轮交付是研究设计和产品架构的纠偏，有可运行只读审计；不是又产出一个因果模型或新的在线AI成绩。
- 原研究问题保留。先执行第5节时间线/资格准备，是否拟合仍须方法审查；不要直接跳到商品×原产地估计。
- AI实现按第6—7节收敛一个入口，先离线契约测试，再封存新题，最后有界真实运行。因果阻断不妨碍完成政策和描述性研究助手。
- 模型建议：规范锁定的入口实现与常规测试用Luna最高；资格变化、比较解释、指标异常和采纳决定用Astra中。用户已开极高时可继续做复杂审查，不声称能自动切换，也不要求为机械执行保持极高。
- 不再声称“没有RAG”“只有失败”或“项目已完成”。准确表述：有真实RAG开发成功和显式整链报告，完整自然语言验收仍待完成；因果仍阻断，时间线修正准备获得新依据。
