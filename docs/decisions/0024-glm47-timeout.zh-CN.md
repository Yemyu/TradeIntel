# 决策0024：单独检验GLM-4.7响应等待上限

60秒版首题记录timeout，无回答，后续未调用。不能据此断言模型语义差。新假设是服务需要更长响应时间；只将timeout从60改到180秒，其余模型、提示、thinking、输出预算、3题门槛和12次上限保持一致。

这是对超时配置的有界验证，不重复相同配置，也不将多轮中最好的一次拼成单次成绩。若再次首题超时或调用异常立即停止，不继续放宽等待。旧请求是否在服务端继续计费未知，token统计只能包含已返回usage。

本轮输入仍为开发题；模型不见参考。即使通过也需内容审查和后续留出验证。允许等待超过60秒的是API进程，助手分段读取进度并继续向用户说明。
