# 0073：整合审查未通过，先修产品与验收契约

日期：2026-09-11。方法依据仍为 0066；本决定覆盖 0070–0072 的完成状态，不覆盖旧实验原始记录。

## 结论

0070 是局部原型，不是 0066 约定的完整入口。0071–0072 的 24 题只保留为开发检查材料，禁止在线运行，不再称已冻结的正式验收。此次没有 API 调用、模型训练、因果拟合或推送。

## 审查发现

1. 入口强制同时包含政策与贸易任务，不支持原定单独查询；字段要求全部逐字引用，没有原定默认值来源、会话修订及逐子任务覆盖。
2. 新建了独立入口，未整合到原研究报告入口；确认没有绑定数据、语料、契约版本。两路任务的部分失败保留机制仍不足。
3. 用户确认被写成 `intent_verified=true`，但确认不证明模型理解正确。预览还与内部待执行对象共享可变数据。
4. 模拟规划超时返回 `needs_review`，异常没有到达运行器；因此“遇错停止”不能由外层异常捕获保证。
5. `expected_terminal` 会把通用解析失败的 `needs_review` 当作 R20 的预期状态；正确的 `needs_clarification` 又与参考的 `clarify` 不相等。状态匹配不能代替业务正确。
6. 预检重新计算指纹，却不比较冻结指纹；没有独立数值、政策事实和引文参考，不能验收完整答案。原计划的对照组、token 预算、调用前登记和及时持久化也未完整落实。

上述问题是实现和验收设计的缺口，不是已证明 GLM 无法完成任务。此前将局部测试通过描述为整体完成不准确。

## 已修复及未修复边界

- 禁止旧批次在线执行，且在读取密钥、建立输出目录和调用模型前阻断；离线输出明确 `online_eligible=false`。
- 新问题先撤销内外两层待确认状态，输入限制改为 2000 字符，预检异常清理残留。
- 预览返回深拷贝；用户确认单独记录为 `user_confirmed`，不宣称意图已验证。
- CLI 的执行开关不再自动确认重新生成的计划，必须现场确认当前预览；非交互输入不执行。
- 新增 4 项回归测试，含真实本地贸易计算一致性检查；测试中的模型响应是模拟，不是准确率成绩。

验证：全套 387 项本地测试通过（26.483 秒）；其中模型调用为模拟，不是新的在线成绩。仍不能用测试数量证明完整业务能力。

尚未修复：完整任务契约、会话及来源指纹绑定、部分交付、错误分类穿透、完整调用账本和语义评分。旧运行器剩余代码仅供审计，不以禁用代替最终修复。
