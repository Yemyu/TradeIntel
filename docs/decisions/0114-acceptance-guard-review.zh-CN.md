## 复现和修复

新测试 `tests/test_acceptance_audit_0114.py` 最初6个测试中出现7个失败断言（含两个子案例）：

1. 两题仅完成planning返回，账本就能finalize为complete。现返回后只标awaiting_review；正式finalize在运行器接线前明确拒绝。不能把调用完成当业务通过。
2. 原始响应保存后被改写，下一次reserve仍可继续。现预约前核对保存的响应、审查材料及磁盘账本；串改即持久化停止。
3. finish_reason=length仍算returned。现截断或缺少stop均停止，保留已报告用量。
4. response_status=needs_review提前走fail，丢弃已返回17 tokens和原始文本。现先保存返回与用量，再记录结构失败；网络未返回时仍记未知。
5. 同题同阶段第二次record_review覆盖第一次记录。现审计材料独占写入，拒绝覆盖；同时限制软链接逃出批次目录。
6. 虚构citation_id与错误数字可通过新审查器。现政策witness须绑定真实claim索引、claim文字、claim引用和检索摘录；数字复用既有路径读取规则，逐项核对冻结参考值及类型。

另补两项测试：缺少政策生成不能通过；后来的澄清状态不能掩盖先前可执行预览。共8个新增测试，连同0113的11个测试共19项通过。旧测试中“审查漏项”的案例原来先被缺packet哈希挡住，本轮补齐哈希，确保确实测到漏项。

最终完整回归：`PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -q`，574项通过，26.706秒；`git diff --check`通过。测试使用模拟模型，0次外部API。

## 仍未完成的协议要求

- 新组件未接入产品调用，不能从模拟返回推断端到端可用。还需真实工作流的零网络整链测试。
- 显式文件哈希工具不自动保证依赖清单完整；须包含运行器、所有实际执行代码、有效配置、数据、语料、问题及审查规则，并固定初始快照。当前工具函数不能替代这份清单。
- structured-review-0112只适用于最终结果形状，不能冒充规划阶段审查。规划与gap复用现有answer_checklist的plan协议；最终结果仍需inspect_delivery核对真实目录，禁止注入任意verified=true。
- 当前policy witness检查引用链接和原文存在，不证明语义蕴含、完整答题或截止日前可得；这些仍由独立逐项清单及审查者核对。
- assert_no_reference_leakage是字符串筛查：合法提问/证据可能含参考答案同样的日期或数字；它既会误报，也不能识别所有泄漏。禁止把它当正式防泄漏门槛。防泄漏靠接口隔离：只有问题进入prepare，参考只进入评分；以哨兵参考值和实际消息捕获验证。
- 对照A/B、最终逐题状态、审查时间与总计分尚未接入。当前没有新的正式题集。
