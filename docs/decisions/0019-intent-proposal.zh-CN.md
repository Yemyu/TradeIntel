# 决策0019：自然语言只生成待确认请求

本阶段为离线接口开发，不是新模型效果实验。假设：把解析与执行分离、对字段逐项保留原文依据并显示完整请求，可以发现误解，避免模型自报“理解正确”就执行。对照为直接执行结构化请求；不读取旧24题参考，不宣称改善真实准确率。

模型只允许返回一个JSON对象，不获得数据工具，不执行任何查询。输出为proposal或clarify，包含request、逐字段原文引文evidence和缺失项missing。原文片段必须确实出现在问题中，但出现不等于语义匹配：例如“不是中国，是德国”中的“中国”不能证明应查询中国。因此即使全部格式校验通过，仍返回needs_confirmation，不自动执行。

字段不明确、多个任务、否定歧义、引用指令、无法映射的业务要求应进入clarify。不得用支持的国家/指标替换不支持的值；明确的不支持请求也可生成待确认proposal，后续能力层负责拒绝。模型不能追加SQL、权限字段或任意工具名。

范围：最多一次模型调用；解析不重试。截断、额外工具调用、重复JSON键、非标准常数、非法字段、缺失依据直接澄清。模型异常只显示固定错误，不回显可能含秘密的异常文本。

验收：使用模拟模型检查上述程序行为、原文引用校验、拒绝执行和与现有模型接口兼容；全部旧测试与冻结预检保持通过。模拟模型不证明真实模型理解力。遇到误执行、隐藏替换范围、旧文件指纹变化立即停止扩展。

下一步：设计小批语义开发案例和独立留出集，锁定逐字段一致性、必要澄清、错误放行、任务覆盖与成本指标及停止条件，才启动真实GLM。确认步骤暂时保留，不因为本地测试全通过就移除。
