# 决策0030：有限年月转换和明确提示

假设：将模型返回的完整中文年月转换为YYYY-MM，可以修复H19接口格式失败，而不改变时间范围。对照为冻结guarded和continuation两批36次尝试；旧成绩不变，本阶段零API调用，仅离线重放35份已返回响应。没有新留出或正式采纳。

独立新模块，不修改被冻结的提示、解析器、能力模块。只处理trade.months列表中完整ASCII四位年+一至两位数字月+“月”的中文年月；年份0001至9999、月份1至12。转换项必须完整出现在原问题和合法的request.months原文引用中。不猜相对时间、不补范围、不改变顺序、不去重；转换后的重复月份仍被旧校验拒绝。引文保持不变。整份候选仍需通过旧严格校验。

澄清只从已通过校验的missing字段映射到固定中文标签，不回显任意模型字符串；未知字段给固定一般说明，标明模型认为需要确认。解析失败改成needs_review，说明程序未完成解析，不要求用户为程序错误负责。部分越界月份在待确认文字中显式显示，保留原请求和未执行状态。

验收：H19离线恢复，原成功34份不退步；篡改引文、非法日期、重复日期、截断响应及工具调用仍失败。已知题修复不能证明泛化效果。若发现请求含义变化或成功项退步，停止扩大修改，不发API重试。
