# 0142：人工审阅稿与案例发布边界审计

## 本阶段问题

审阅稿已经可以在满足条件时导出，但必须确认用户看到的页面、接口和 Markdown 结果不会把“人工采纳的 AI 建议”误解为“第二案例已经验收或发布”。

## 已核对的规则

1. `/review/interpretation` 首屏明确说明：这是固定回答的人工审阅，不是案例发布批准。
2. 审阅稿下载入口只在事实已核查、至少一条建议被采纳、没有 `needs_revision` 且来源指纹仍匹配时出现；文字同时注明“只含采纳项；不发布案例”。
3. `/api/saved-interpretation-draft` 在待审阅、过期或不满足条件时返回 409，不调用模型；条件满足时只输出采纳项，保留数据、政策来源、哈希和审阅元数据。
4. 审阅决定和原始回答不能由页面覆盖；`case_publication_allowed` 始终为 `false`，第二案例仍为 `candidate`。
5. 固定真实运行仍没有用户审阅记录，因此本次没有替用户批准或生成真实正式稿。

## 验证结果

- 新增页面边界、待审阅导出拒绝和已记录导出检查。
- 相关回归批次 37 项测试通过，JavaScript 语法检查通过，`git diff --check` 通过。
- 本阶段 0 API、0 模型调用，未修改真实运行目录。

## 结论与后续

最小发布边界已闭合，可以把审阅稿作为“人工继续复核材料”查看；不能把它写成第二案例已发布、模型已普遍正确或因果结论。后续若要正式发布第二案例，仍需独立的整链内容验收和页面视觉检查，不应通过重复抽样或修改审阅稿来替代。
