# 0132：四场景运行器接入持久化审核与恢复

后续：公共入口已由[0133](0133-live-entry-lifecycle.zh-CN.md)接通并通过686项回归。下文“入口阻断”是本阶段历史状态；当前缺的是本地GLM配置与真实批次结果。

本轮复用原运行器、账本、工作流，未调用真实模型。

`run(checkpoint_reviews=True, persisted_host_reviews=True, resume=...)` 已接入宿主审核存储。规划、交付、无证据回答保存阶段产物；恢复时读取完成产物，不重发模型或重新生成报告。完成题跳过但再次核对交付。审核回调缺少提交时保存waiting_review检查点；提交文件由宿主明确填写，程序不产生事实标签。

规划/最终报告、两组逐事实和gap审核已接线。通过JSON规范化修复了内存tuple与磁盘list导致同一材料被误判冲突的问题。重复读取已保存产物要求内容一致，缓存的审核结果也必须对应同一个完整材料指纹。没有完整阶段结果、只有执行意图的中断仍拒绝恢复；目前支持明确的审核暂停，不承诺任意崩溃都能续跑。

验证结果：完整回归683项通过（60.134秒）。其中四场景逐审核暂停/重建运行器测试完成，固定模型总调用8次；持久化宿主提交版本同样完成8次，无重发。另有gap→规划→报告暂停恢复，规划模型仅调用1次。测试判断均为显式fixture，不是新模型准确率。

随后新增真实配置检查：当live账本提供冻结provider配置时，模型/端点/温度/超时/生成参数需先匹配；返回时检查实际HTTP捕获的参数、消息、端点及超时。配置不符在预约前拒绝，实际捕获不符停止，不重试。相关27项定向测试通过。历史model_adapter.py未修改。

## 当前限制和下一步

公共live入口仍阻断；预检中的旧阻塞描述需在统一入口交付时更新。还需接通预检冻结→运行至待审→读取材料→提交→恢复命令，审核现有恢复路径的损坏/失败/并发边界，并在真实请求捕获中严格限制额外参数。不得仅因离线四场景通过就开放入口。
