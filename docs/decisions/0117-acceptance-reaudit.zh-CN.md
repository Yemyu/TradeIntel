# 0117：验收复审与结果口径修正

## 结论

0116的589项工程测试通过属实，但“完整验收绑定、完整冻结、事实召回”表述过强。上轮代码保留了真实业务执行和控制记录，尚不符合原0114/0116完整验收要求。本轮不启动API，先修复能复现的问题，保持已有0109开发演示及因果状态。

## 复现与修复

1. 零次模型调用、空packet/submission，仅传`validation={approved:true}`就能完成澄清案例。现账本重新执行结构校验并比较验证决定；接受案例还要求存在已保存的规划响应，禁止把planning审核当answer审核。
2. B回答“并非2018-07-06生效，税率不是25%”原被打为pass、召回1.0。现只保存literal_matches与字面命中比例；fact_recall为空、answer_quality=unreviewed。需审查否定、关系、遗漏及无依据断言后才能形成事实分数。
3. A只对每月金额及总额，未对变化额；即使change_usd被改成0也通过。现显式endpoint追加日期方向、变化额和变化率复算。没有明确月份时不再从被检验答案反推测试范围；登记窗口控制暂不支持并明确停止。
4. HS6其他原产地源表不存在独立others列。现按all_origin减china计算；保留负值检查。
5. 旧清单适配按列表位置配对，乱序提交可能对应错规则；改为按id匹配。
6. 快照只保存hash且遗漏依赖，不能称完整冻结。现保存frozen-snapshot.json本体，声明文件缺失不再静默跳过；配置明确标注partial。注入模型/审查器及传递依赖尚未完整冻结。

离线完成现命名`synthetic_protocol_completed`；`acceptance_ready`始终false。合成示例通过仍可证明已有路径运行，但不能触发正式题验收。

## 保留的工作与剩余要求

A目前是对“模型所生成且确认的请求”作独立算术复核；如果模型把中国理解成其他原产地，两条路径可能同时查错范围。因此真正的A还需**调用前独立冻结结构化请求**，运行明确参数入口并与主组比较。不能从主组结果取参数后称独立意图基线。

B当前可保存无证据回答，但主/B两组未约束相同模型配置和输出预算，也没有同一逐事实审查清单。它尚不能回答“RAG提高了多少准确率”。需要固定两组配置、原问题、历史范围、输出格式及允许的提示差别，并由审查者对两组实际主张统一判定。

fixture_review仍是机械测试替身，引用ID存在不保证主张受支持；不能授予正式验收。现有plan/gap协议需要实际接入完整案例，并覆盖组合、澄清、拒绝及审查后改文件等路径。

## 后续执行规范

下一阶段建议三段式：Astra中先锁定独立A请求、主/B共有审查包和完整冻结清单；Luna最高执行接线；Astra中审查实际差异。复用现有模块，不重建数据层、不重跑已知四题、不改因果结论。

实验假设：独立参数入口能揭示自然语言理解误差，带证据组在统一事实审查下可能优于无证据组。基准为独立A及无证据B；参考仅供审查，不能进入模型工厂或请求。采纳要求每个支持题都有同题绑定的原始调用、明确参数基准、实际报告、逐事实审查及控制记录；不以字符串命中判正确。首个传输/用量故障停止且不重试。若需要改变上述方法，先记录原因再实现。
