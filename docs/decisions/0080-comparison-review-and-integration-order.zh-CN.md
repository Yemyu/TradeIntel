# 0080：比较交付审查与剩余整合次序

日期：2026-09-11。承接0066、0077–0079。方法与集成审查阶段。

## 本轮发现与修复

1. 缺失金额时calculate未返回比较窗口，两个报告读取窗口会报错；贸易单独报告还试图将null格式化为整数。现在不完整结果保留方向、状态missing_data；两种报告共用展示函数，明确缺失不可计算。缺失与零基准分开解释。
2. 0078提示词允许模型自行省略comparison而退回旧计划。现在自然语言CLI由宿主固定require_comparison=True；模型缺字段为规划失败，无确认令牌。旧编程调用保留兼容默认；该模式写入契约指纹，待确认期间改变模式令牌失效。提示词只描述新版字段，不鼓励降级。
3. 两个报告的登记窗口提醒不一致，现共用展示函数。历史clean名称仅作历史标识，不能暗示因果可识别。

验证：53项相关测试通过，包含旧兼容回归、实际数据比较、缺失金额通过两条完整交付路径、严格模式拒绝旧计划、模式变化使确认失效。模拟缺失工具结果用于检查报告与状态，不是新数据质量或模型准确率成绩。零在线API。

## 对0078–0079完成表述的限定

显式比较确已接到计算和报告，但尚未达到0077的全部验收要求：

- 原文引文仅检查是连续子串；“2018-09和2018-10”不证明哪个是基准。提示规则已强调这一点，但不宣称语义判断已由程序证明。
- 只点名登记窗口时的宿主派生月份、来源说明尚未接入。当前仍需完整月份；不把这部分记为完成。
- 登记窗口从含金额的统计摘要加载，虽只提取月份，但不能宣称预览过程物理上从未读取金额字节。当前保证是确认前不执行贸易金额工具或回答生成；未来应导出独立窗口元数据以加强隔离。
- 0079为sequence也生成comparison obligation，这只是额外状态记录，不等于识别了新的用户子问题。
- 显式ResearchBrief兼容入口本身仍不像统一入口那样绑定所有数据/语料指纹；不能将统一入口的保障泛化到所有调用。
- 既有419项测试记录有效，但没有覆盖本轮发现的缺失报告与模型自行降级问题，不能当作完整业务验收。

## 下一完整工作单元：统一计划与证据接入

按以下顺序在同一个入口实施。出现语义范围变化或实验采纳需要判断时先审查，不新增孤立聊天系统。

### A. 先锁定请求与来源

把当前问题的独立子请求保存在计划中：原文片段、任务类型、参数、待澄清项。宿主分配稳定ID，模型不得给执行状态。每项只对应实际要求；逐月序列不重复登记为比较。预览覆盖用户问题并显示模型理解未独立验证，不能仅凭关键词规则宣称完整。

新增明确的宿主案例设置，允许使用已经确认的政策截止日；来源带设置版本、确认状态。登记窗口元数据从当前摘要确定性导出，仅含ID、月份、范围、摘要指纹与描述限制。仅当用户明确选择登记窗口、未指定冲突月份时派生日期；参数来源写derived及输入ID。将设置、窗口元数据和解析后计划纳入确认绑定。

### B. 接入政策查询桥接

复用一次规划调用增加短英文检索表达；用户原政策问题始终用于生成回答。检索表达只用于寻找证据，不可替换原问题或作为证据。保存原文、检索表达、发布时间截止、语料指纹、命中ID。

先保持两份正文语料和BM25不变，按0066修正历史范围判定，再做同页重叠窗口合并。合并记录所有父片段、精确偏移和正文哈希，保持原始排序来源可追踪；同页合并超过单窗2400字则保留分别窗口，总量7200字上限保持。空检索必须明确无证据，不调用模型补猜。

### C. 模型调用记录覆盖规划和回答

调用前先创建独占运行目录并写入调用意图和请求哈希、阶段、配置、来源类型。一次规划、最多一次政策回答；工具计算不计作模型调用。发送前预留预算和attempt_id，超时也计尝试，禁止自动重试。fixture/live分别计数，用量缺失记录unknown而不是0。

保存脱敏原响应、finish_reason、用量、解析与执行结果。规划失败有诊断且保留输入；程序中断留下未完成状态，重启只核对既有记录，不自动重发。最终文件成功写入后才能标交付完成，不能把工具运行完等同文件已交付。

### 验收与停止条件

先离线验证：方向被反转、遗漏子问题、缺失参数、已确认设置被改变、登记窗口冲突、中文历史问法、重叠引用、规划超时、政策超时、输出写入失败各有明确结果。A/B/C接完再进行真实模型审查；旧0071–0072批次保持禁用，0066的独立参考、对照和预算仍需正式封存，不能复用开发题宣称盲测。
