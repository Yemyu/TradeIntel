# 决策0021：GLM-4.6V三题诊断

范围：D01商品计数、D07缺信息、D12德国原产地，依次各调用一次。它们是开发题，不能称为盲测。

假设：GLM-4.6V在原提示与校验器下能产生可解析结果。对照是GLM-4.5-Air同三题的parse_failure记录；旧记录缺正文，不能据此确定模型理解强弱。本次主要目标是获得可定位的证据。

仅改变模型名称为glm-4.6v，保留原提示、temperature=0、timeout=60。沿用通用API端点与现有Key；最多3次请求，无自动重试。保持提供商默认思考设置，不同时更改JSON模式等参数。来源中的推理字段只归档用于诊断，不当作正式答案。

模型只接收系统提示和问题，不接收题号、分类、参考或历史运行。记录请求正文、HTTP响应正文、标准化响应和解析结果；Key脱敏，Authorization不记录。请求发起前记次数并落盘，解析失败不删除模型正文。所有审计内容仅存项目tmp，终端只显示阶段和路径。

首次网络/HTTP/调用异常即停止；额外工具调用即停止。普通JSON/字段失败记录后继续，最多3题。停止规则比旧12题协议更保守，本次明确采用此规则。中断保留日志，不自动重发结果未知的请求。

本地验收：模拟HTTP覆盖有效响应、代码围栏/空正文、HTTP异常、工具请求、响应重放、密钥脱敏、重复输出拒绝。冻结依赖指纹并通过旧预检后才交付运行命令。

采纳门槛：3题只用于诊断；即使全部正确也不自动采纳模型。检查正文后决定下一步最小修复，再进入完整开发与留出验收。资源包余额和抵扣只能由平台账单确认，不按调用tokens推定赠送包实际消耗。
