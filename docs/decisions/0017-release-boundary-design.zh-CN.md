# 决策0017：下一版本的输出完整性与能力边界设计

日期：2026-09-08。设计稿；未实施到正在验收的v2.1。

## 已证实的输出问题

离线只读复现：请求2023-02与2024-09，两个金额均为null，但程序仍输出“已观测月份合计0”及“已返回其余可查月份”。数值null正确，后一处说明与事实不一致。它属于程序模板问题，不能靠更换GLM或重复同一请求解决。

另有三个已确认的设计限制：离散月份报告先展示start/end和“完整窗口”；错误工具记录只显示通用失败提示；每次回答都混入较长匹配状态，主答案难读。当前贸易查询只支持中国、其他原产地和全部原产地，没有企业查询、GDP指标或写库工具；通用因果警告无法替代对这些请求的具体说明。

## 输出规则

1. 将金额状态明确分为observed、missing_in_coverage、outside_coverage。未知金额永远显示未知；当observed_month_count=0时，前台已观测合计显示“无可计算观测”，不能用空集合求和0表达进口额。
2. 缺失提示根据实际返回状态分支：全部不可查时写“本次没有可查询月份”；部分可查时列出可查月份和未知月份；仅当实际存在可查记录时才能说“已返回其余可查月份”。
3. 显式月份集合优先显示，不把最小/最大月份之间的全部月份称作窗口。连续范围与离散集合分别标注，合计必须说明对应集合。
4. 主答案显示所问事实、限制和可追溯来源；重复求和与详细因果状态放入证据详情。安全状态仍由主机核对，不因折叠而取消。

验收覆盖：全部缺失、部分缺失、真实已观测零、任意离散集合、重叠查询去重、不同原产地不混加。不得仅测试已知题号。

## 能力边界不能依靠自由文案

新增独立的能力登记表：项目覆盖时间、指标、原产地选项、粒度、政策范围、允许操作、因果状态读取方式。边界说明只能引用登记能力和已执行结果，不能暗示做了未执行的查询或修改。

用户需求可由模型先转换为结构化请求，字段包括任务、月份集合、原产地、商品粒度、指标和写操作意图；结构必须校验，但校验只证明字段合法，不能证明模型理解正确。保留对应用户文字片段和待澄清状态供审查，不用模型自报“已理解”自动授予任务完成。

能识别的写操作请求由只读能力规则拒绝；无法明确映射的指标/粒度应表达具体已知能力，并提示请求尚未被可靠映射。混合请求拆分可回答和不可回答部分，实际执行哪个部分就展示哪个部分。不能把“德国企业金额”静默替换成“其他原产地总额”。

通用正则或关键词不可靠地覆盖双重否定、引用指令和中英文混合。新需求解析层应先用独立的语义测试验证，不急于塞进当前冻结实现。可先实现不涉及模型的新输出状态，再独立设计能力声明与解析工具，保持变更可诊断。

## 后续实验边界

假设：来源不变、工具选择不变时，确定性展示修复能消除全部缺失及离散月份文案歧义。对照是同一工具轨迹经旧/新报告器生成的结果；不调用GLM，不称模型能力提升。规则要求核心金额/来源不变，仅状态与范围文案改变，全部缺失不得产生假可查陈述。出现数值/来源差异立即停止扩大修改。

能力解析是另一实验：先定义语义案例与失败条件，再单独运行真实模型；不得把正在运行的24题修复后再次称作未见验收。当前验收结束前不更改其代码或指纹。
