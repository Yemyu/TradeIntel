# 决策 0005：证据约束的 TradeShock AI 应用层

- 状态：设计已冻结；六个工具、证据包和确定性基线已实现并通过本地评估，等待 LLM 适配器
- 日期：2026-09-01
- 适用阶段：Phase 10

## 为什么现在转入 AI 应用

三次政策前匹配实验都没有解除因果阻断：第一次三近邻覆盖率达到 90.16%，但趋势斜率和中国份额的 SMD 失败；第二次全局平衡优化无可行解；第三次最大基数设计即使允许政策前透明剔除，也无法在原始 252/315 覆盖门槛下同时满足平衡与复用限制。继续换匹配算法，容易把时间花在追逐一个当前数据不支持的因果数字上。

这并不意味着项目失败。项目已经有真实数据、官方来源、跨年映射、质量门槛、失败证据和可重复脚本。下一层要把这些能力变成一个真正的 AI 应用：AI 能理解问题、选择正确工具、解释证据，并在证据不足时拒绝越界结论。

## 目标用户体验

用户可以问：

> 2018 年 Section 301 List 1 之后，中国相关商品进口下降了多少？这能证明关税导致下降吗？

系统应该：

1. 识别这是“政策信息 + 描述性变化 + 因果可行性”组合问题；
2. 查询固定政策事件和贸易数据工具；
3. 返回计算公式、数据窗口、数值、官方来源 URL 和文件哈希；
4. 明确说明目前只有描述性证据，因为因果匹配门槛被阻断；
5. 不把“下降”改写成“关税导致下降”。

## MVP 不做什么

- 不让模型自由生成 SQL；
- 不让模型自动爬网页或替换官方来源；
- 不微调模型；
- 因果状态阻断时不生成事件研究结果；
- 暂不引入 LangChain 或 LangGraph。先用普通 Python 函数把工具输入、输出和错误边界做稳定，之后再决定是否需要框架。

这使项目与“把组件接起来跑一个 RAG Demo”不同：核心难点是可靠工具、证据链、边界判断和可量化评估。

## AI 与确定性代码怎样分工

### AI 负责

- 理解自然语言问题；
- 从已声明的工具清单中选择工具；
- 把工具结果整理成人能读懂的回答；
- 根据证据状态选择“描述性回答”或“拒绝因果表述”。

### Python/MySQL 工具负责

- 执行固定查询和计算；
- 检查参数、日期范围和业务键；
- 读取质量报告和因果设计状态；
- 附上来源 URL、SHA-256、计算公式和数据窗口；
- 不允许模型绕过阻断状态。

模型不能成为“计算器”和“数据库管理员”。模型只负责语言和路由，数字与权限由可测试代码负责。

## 第一版只开放六个只读工具

1. `get_policy_event`：返回政策名称、公告日、生效日、税率和官方来源；
2. `get_trade_series`：按已允许的商品、原产国和日期窗口返回贸易序列；
3. `get_descriptive_change`：计算同比、份额、变化金额和变化百分比，并标记为 descriptive；
4. `get_data_quality_status`：返回数据质量规则、复核项、失败项和采纳状态；
5. `get_causal_readiness`：读取资格、匹配和前趋势状态；当前应返回 `blocked_before_pretrend_v3`；
6. `build_evidence_bundle`：把结论、输入参数、公式、来源 URL、文件名、哈希和限制整理成结构化证据包。

所有工具都是只读、固定参数、可重复测试的函数。模型不能调用任意 shell、任意 SQL 或未登记的网络地址。

## 评估不是聊天截图

先建立 60 道隐藏答案题，覆盖：

- 政策元数据；
- 精确数值和日期边界；
- 来源与哈希追溯；
- 因果问题的正确拒答；
- 数据质量和样本边界。

比较两个系统：

- 直接问模型，不给工具；
- 给模型工具和证据契约的 TradeShock AI。

采纳门槛在运行前固定：数值正确率至少 90%，来源引用正确率至少 95%，正确拒答至少 90%，工具选择至少 90%，不支持的因果断言必须为 0。任何不支持的因果断言都足以阻止公开 Demo。

## 防泄漏和安全边界

- 工具路由不读取隐藏答案；
- 因果选择逻辑不读取政策后结果；
- 测试集和标准答案分离，避免把答案写进 prompt；
- MySQL 凭证不进入模型上下文或日志；
- 每个回答带数据窗口和来源；
- 如果项目状态为任何 `blocked` 状态，工具层返回“只能描述，不能因果解释”的硬信号。

## 对申请的价值

这个应用把经济学背景变成了 AI 的业务规则：知道政策事件、理解贸易指标、区分描述和因果、理解共同支持与数据质量，并把这些规则交给工具和评估来执行。它不依赖夸张的多 Agent 数量，而是展示一个更难伪造的能力：AI 在证据不足时仍然可靠。

## 当前实现结果

六个只读工具、固定工具注册表、来源证据包和确定性路由基线已经实现。60 道问题分为政策元数据、数字描述性查询、来源追溯、因果拒答和数据质量五类；工具基线的工具选择、数字正确、来源引用和正确拒答均为 100%，不支持的因果断言为 0。直接无工具基线没有数字/来源契约，作为对照保留在报告中。

这个结果只证明“工具契约可运行且可测试”，不代表外部大语言模型已经通过评估。下一阶段接入模型时，模型只能使用同一份注册表，评分器和因果阻断信号保持不变。

当前还完成了供应商无关的 `ChatModel` 接口、最大轮数限制和因果安全后卫。离线 `MockModel` 会故意生成一句“关税导致了下降”，安全后卫会将其拦截并记录 `safety_guard_triggered=true`。因此在没有 API 密钥的情况下，也能先验证模型—工具协议和高风险边界。

## 验收与停止

只有当六个工具有稳定契约、60 道题达到门槛、因果越界断言为 0，并能展示一条带来源的完整问答链时，才允许进入网页 Demo。若核心门槛失败，先修工具和证据包，不通过继续堆 RAG、LangChain 或 Agent 数量。
