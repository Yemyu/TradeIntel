## 本阶段范围

按0089实现，不新增题目、不重试旧失败实验、不改变因果结论。入口为`scripts/run_development_smoke.py`，实现为`src/tradeintel_ai/development_smoke.py`。默认只做预检；真实运行是有审查者在场的开发检查，不是自动验收或盲测。

## 已实现的边界

- 固定D89-1至D89-4，始终保留四行分母。共4个规划槽位、仅前两题各1个政策回答槽位，最多6次尝试；不续跑、不重试，旧目录拒绝覆盖。
- 发送前原子写入attempt_reserved；超时、异常或中断也占用尝试。返回原文另存并脱敏，截断也保留，首个失败停止后续场景。
- 已报告累计total_tokens达到30000后不再发送。缺少total_tokens记unknown，reported_tokens仅是已报告部分，不是完整消耗；fixture不计真实API调用。6次上限不能保证完整批次成功。
- 锁定glm-4.7、温度0、超时60秒、智谱通用API端点；沿用0089规划1536/回答768上限。60秒是适配器的单次网络超时设置，不宣称它是严格的整批墙钟截止时间。
- 首次调用前保存题目、当地参考、配置和数据/代码/提示/语料指纹；每次调用和审查前后检查冻结状态。参考不送入模型消息。金额参考链接既有phase13k独立核对记录，政策仍须实际打开冻结证据核对。
- 有效计划必须显式审查才允许执行；回答也须审查，才能继续下一题。D89-4只审查范围拒绝/具体澄清，不执行金额。审查包包含原题、参考、结果和文件位置，记录审查者与包哈希。
- 自动只检查状态、任务集合、交付完整性等结构条件。范围、月份、比较方向、逐项事实和引用支持由审查者核对；不能按approve代替实际阅读。程序仍保留semantic_coverage_verified=false，审查接受只记reviewer_accepted_development_case，不改写底层标志。
- 批次确认依据明确记录为开发审查者显式批准，不把测试夹具的自动批准冒充用户或真实语义审查。

## 使用与下一阶段

在项目根目录：

```sh
.venv/bin/python scripts/run_development_smoke.py
```

以上不询问密钥、不发请求、不新建运行目录。真实运行须在本地配置TRADEINTEL_MODEL_API_KEY后，指定全新输出目录及审查者标识：

```sh
.venv/bin/python scripts/run_development_smoke.py --execute --output tmp/development-smoke-0090-live-01 --reviewer local-reviewer
```

真实入口要求交互终端，不提供自动批准开关；不要把上面的命令当作今天已经执行过。中断时查看batch.json、各题planning/delivery和响应文件，不原目录重跑；如果最后仍是attempt_reserved，表示该次是否返回未知，仍按一次尝试保留。审查者发现问题后先看原始响应，再决定是否需要新协议，不换模型反复刷当前题。

下一阶段推荐Astra中：核对可用本地配置并进行这4题真实规划/引用/数值/边界审查，决定能否进入正式验收准备。审查可由用户在终端查看、由助手帮助解释文件；不要求用户理解实现代码。若要改成助手跨轮读取和批准，须另外实现持久化审查流程，当前运行器没有该能力。没有可靠审查者或本地凭据时，不启动真实批次。
