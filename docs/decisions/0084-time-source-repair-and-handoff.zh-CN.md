# 0084：时间来源修复与整合交接

承接0080、0083和用户要求的整体审查。本阶段定位：修复两个可复现的需求保留问题，并锁定后续整合验收；不宣称完整自然语言产品完成。

## 复现与修复

0083的测试把“2018-09和2018-10”留在用户问题里，却让模拟模型返回months=null并选择十个月登记窗口，原测试竟要求通过。这个用例说明模型遗漏用户日期时，宿主没有检查原问题。现将无冲突成功用例改成确实没有额外月份的问题，原问题保留为拒绝用例，并覆盖中文月份和相对时间。

规则：空月份登记推导前检查原问题，最多去除一次与政策截止日完全相等的引文；其余出现可识别的年份、月份或相对时间则要求澄清。只处理部分常见写法，不宣称一般时间语义识别；即使额外时间实际上与窗口一致，也可能要求用户明确填写月份。已有完整月份继续走窗口一致性核验。

0083只记录了已确认截止日，没有执行复用。现仅在v3计划、用户原文包含“沿用已确认的政策资料截止日”、对应引文相等、模型返回null时允许宿主填入2018-07-06。原问题另含识别到的时间表达则澄清。来源记录confirmed_setting、版本、原文及规则，进入确认快照。普通省略日期不视作授权复用；不会伪造日期原文引文。显式日期仍按现有请求路径处理。

时间来源澄清保留规划调用审计，计一次模拟或真实尝试；本阶段仅运行模拟测试。

## 0083表述纠正

设置记录不等于跨对话设置管理，硬编码confirmed也不证明历史用户确认事件。本次提供明确的单次复用操作，没有实现通用会话记忆。

独立窗口JSON不含金额，但核验摘要哈希仍需读取摘要文件字节。正确保证是确认前不运行贸易金额查询、不向模型提供金额；不能宣称物理上不读取任何金额文件。窗口指纹绑定版本，也不能单独证明手工导出的字段与摘要全部一致，后续应补确定性导出与字段对账。

## 后续完整工作单元及验收

1. 政策证据接入：按0080保持原两份语料，修正“目前请分析2018年……”被误当现行政策的问题。区分提问时态、文件截止日和要求判断的历史状态；信息不足需澄清，不能默认把2018年正文用于2019年修订状态。
2. 同页窗口合并：仅同一文档同一页且区间重叠时合并，保存全部父片段、偏移、正文哈希与原排名。单窗2400、总量7200上限；超过单窗限制保留原窗。引用必须可准确定位原文，不能合并不同页或日期来源。
3. 请求完整性与交付：当前仅一个政策问题、一个贸易范围；多来源、多比较请求必须显式处理或说明未支持，不凭固定任务ID宣称已覆盖。统一预算、配置快照、失败恢复、文件完成状态仍需接线。
4. 以上离线通过后才设计新真实验证：假设是完整任务完成率提高；基准为明确选项的确定性流程以及冻结旧行为。新问题和参考提前保存，不把本次故障题作为未见题，不按回答修改评分；每题一次规划、至多一次回答，无自动重试。预算与采纳阈值在开始前经审查固定。来源错误、范围替换、写入失败需先修复，不能增加调用刷分。

后续历史范围需先完成语义判断；已锁定窗口合并、测试和文档同步可按既定规范执行。因果路线遵循0069停止条件，未重新拟合。
