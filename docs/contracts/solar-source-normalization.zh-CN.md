# 证据选择接口的无损输入规范（实现前确定）

问题不是JSON无法解析，而是相同字段以嵌套而非平铺表示。智谱官方结构化输出文档列出json_object模式，并示范客户端Schema校验；不能因此假定服务端保证本项目的字段层级。来源：https://docs.bigmodel.cn/cn/guide/capabilities/struct-output 。本轮不新增API参数或网络重试。

接收仅两类表示：conditions数组全部为平铺五字段条目；或全部为按五个条件名称分组的对象，每个子项仍完整包含hts8/field/status/text/citation。分组必须恰好五项，外层名称与子项field一致，同组税号一致。两类不得混用。不推断缺失值、不添加原产地、不改text或citation、不接受quote、不做递归猜测。展开后仍检查每税号五项恰好一次、合法来源与显式unknown。

每次分组展开保存normalization记录。原模型回答保持不变。此契约是有边界的表示兼容，不是语义纠错或任意格式容错。旧失败不改为真实成功；离线重放只检验新程序接线。

验收反例固定：混合形态、字段与外层键冲突、同组不同税号、缺项/重复、额外字段、未知来源、非字符串、伪造quote都拒绝。正例覆盖多个税号分组和unknown，要求展开后字典值逐项保持一致。
