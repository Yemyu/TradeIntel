# 让解释层知道程序已经完成了哪些工作

本轮解决的是上下文传递缺口：此前AI只看到政策事实，因此错误地把系统已查出的贸易金额说成缺失。本轮没有重跑那条真实回答，也没有追改成绩。

## 已接通

解释模式直接接收同一次执行的trade-evidence结果，不另查一份数据。政策事实与贸易结果必须具有同一data_version和policy_id，覆盖完整、消费进口口径、中国来源视角、月份顺序一致；不满足时在解释调用前停止。

每个商品月新增trade.月份.税号事实ID，提供全部来源金额、中国金额及中国份额。另有trade.available和trade.measure，说明计算已经完成，以及份额分母和单位。输入单独保存interpretation-trade-context.json，含原工具结果指纹及trade-evidence.json定位，便于核对模型究竟看到什么。

提示明确区分：

- 已完成：所选商品月金额、中国份额。
- 已知标签但不能越推：美国消费进口口径，不等于逐笔关税适用确认。
- 尚未建立证据：企业合同、实际税款承担、替代供应产能、逐笔适用。

AI可关联贸易事实提出待调查事项，但不应重复要求计算已有金额，或声称系统没有这些数据。没有企业税单仍然是真实限制，不能因为已有贸易表就说所有问题都有答案。

## 检查不是语义保证

新增错误报缺数据、重复查数的词面风险提示，含糊改写仍可能漏检，否定表达可能误报。所有AI解释继续单独隔离、approved=false，不因没触发提示就批准。数值来自已验证工具，本层不声称进行了新的独立数据审计。

32项聚焦离线测试通过：真实资料预置响应路径确认模型收到七月金额360659187，版本一致；跨案例/跨版本/缺月覆盖拒绝；错误报缺数据提示；企业实际税款未确认可以保留。零API，无新依赖，候选不激活，网页默认不变。

## 下一步与学习

下一阶段建议Astra中，冻结一次带贸易证据的解释验证：重点判断模型是否引用已有结果、避免重复调查，并把尚缺企业信息与现有统计分开。不能仅凭这次接线成功就宣称模型改善；不扩大成自由预测或因果结论。

通俗地说：现在把“同事已经查好的表”一起交给AI，而不只是给它政策文件。AI应该在已有工作的基础上提出下一步，而不是让你重新查一遍。
