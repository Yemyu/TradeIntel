# 调查建议首次真实验证：未进入解释阶段

固定目录：tmp/interpretation-v1-first。GLM-4.7共1次请求879tokens，无工具调用、无解释调用、无重试。6项相关离线测试通过；不是本次模型成功。

## 发生了什么

用户问题明确要求2024年登记政策下、2026年7月的双商品简报。模型却选择unsupported，声称“2024年政策”不在已保存的2024-21217公告范围内，并误提没有2024全年数据，又要求用户指定已经写明的七月。这与它所收到的案例及2025-01至2026-07能力说明相矛盾。

解释模式只接受brief/series_brief，因此宿主停止。没有来源资料包和AI调查项可供评分。本次是任务路由失败；不能说调查建议质量好或差，也不能把剩余一次预算拿去直接生成而忽略失败。

运行后仅改善未来诊断：先保存模型计划和kind，再检查实验任务类型；不兼容时记failure_stage=interpretation_task_routing。原始运行不重放、不改成绩；用户友好message仍由统一失败处理覆盖，但结构化failure_stage和原答保留供诊断。

## 对下一步的意义

不再用相同GLM不断改措辞抽样。已经有宿主案例选择、数据窗口、明确统计参数，模型不应被迫再次判断已确定的业务边界。

下一阶段建议Astra中设计一个明确的结构化研究任务入口：用户在界面选择案例、月份、商品和任务类型，程序校验并执行；AI只承担所选的解释任务。自由文本入口仍可保留为另一条有失败边界的能力，不能声称其问题已经解决。这个入口不是在实验里硬塞正确规划，而是产品明确让用户控制任务参数；真实验证必须如实标注“结构化输入”，不与旧自由问答成功率混算。

尚未实现结构化入口。本轮不更换模型、不新增API、不激活第二案例，不取消既定数据工程与政策研究目标。
