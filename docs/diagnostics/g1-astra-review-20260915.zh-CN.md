# G1 工程验收：Astra 中审查

结论：**不通过，暂不能开始 G2 真实模型对照**。高推理方案有价值，但第一轮实现不完整。此前“自然语言与结构化执行器已接通”表述需要撤回；47 项聚焦测试通过不覆盖真实贯通路径。此次未加载真实凭证，未调用外部模型。

复现命令：`.venv/bin/python scripts/audit_research_v2_g1.py`。脚本使用合成输入和临时目录，阻断网络，输出缺陷是否复现；它是诊断，不是产品测试通过率。当前七项反例全部复现。

## 已确认的阻塞问题

| 问题 | 具体证据 | 对使用者的影响 |
|---|---|---|
| 自然语言确认后无法执行 | `natural_confirm` 传入含 schema_version/focus/policy_view 且无 task 的请求；`compile_task` 只接受 policy_id/month/product/task 四字段。实际确认抛出“结构化任务参数无效” | 页面能出预览，但按确认会失败 |
| 份额没有独立核算 | 给证据包传中国金额700、全部来源1000、错误缓存份额1%，返回仍是1%，而非70% | 旧字段一旦不一致，观察会跟着出错；不等于发现官方金额错误 |
| 单商品和零分母未完整处理 | 单商品仍生成 amount_leader；全部来源为0时，渲染 None 的百分比抛 TypeError | 单商品会出现无意义排名，合法零金额无法展示 |
| 重复发现未拒绝 | 同一 observation_id 重复两次仍为 manual_review_required | 输出条数可被重复内容占满 |
| 导出丢失关键内容 | 合成报告导出只有观察的 meaning 名称、AI文字；没有700美元、贸易来源链接 | 用户下载的稿件无法独立核查数字和来源 |
| 证据包未校验案例/版本关系 | 把 bundle 改为另一政策/版本，packet 仍返回可读取对象；有旧审阅时仅变 stale | 旧批准能失效，但还缺少新审阅前的证据一致性拒绝 |

七个可执行反例中，单商品虚假排名和零分母异常分开计数。

## 代码审查发现的其他未交付要求

- focus 虽出现在自然语言预览中，执行证据包仍固定 contrast。必须保留用户选择，不能丢掉字段凑接口。
- 确认时检查版本后，structured 会再次解析活动版本；需要把同一个已核对副本传入执行，不能先用新版本执行再把返回 version 改回旧值。
- 模型解释输入只有 observations/metrics/limitations/身份字段，没有政策事实和原文。G2 若自由回答对照拿到官方条款而 v2 没拿到，会不符合“同资料”协议。
- 预览没有持久保存原问题、原始模型响应、usage 和解析记录；question_sha256 只存在内存，未传递到最终审阅资料。
- `_reviewed_v2` 在指纹校验后重新读 bundle；应直接使用本次校验取得的同一份内容，避免导出时文件变化。
- `research_data_link` 和 version-report 仍默认主案例；第二案例隔离验证还未完成。**第二案例正式上线不是 G1 条件，隔离资源中两案例可复现才是条件**。
- 当前产品审阅测试仍读取私人 `tmp/trade-aware-interpretation-v1-first/run`；不能宣称已完成干净仓库可复现。
- “最新可用数据”、明确否定约束、多月不降为单月等请求验收尚不足。不要再把引文出现当成完整意图验证，也不要回到庞大的逐字规则库。
- 比例指标引用还会把政策来源混为贸易数值来源，部分贸易来源没有 id 而被滤掉。应保留实际来源哈希及地址，分别绑定政策和统计依据。

## 修复顺序及验收

沿用原方案，集中完成四个检查点，不再新增实验路线：

1. **请求贯通**：统一规范请求并保留 focus、原问题、原始解析记录；预览到执行使用同一发布副本。增加真实 coordinator→执行器的合成贯通测试，不 mock 掉这两者；测试双击/版本变化/请求变更。
2. **计算与范围**：所有份额按整数金额和 Decimal 重算；不一致旧字段拒绝或明确处理；单商品只出 profile，零分母显示未知，完整商品范围有校验。真实月表另用独立求和确认，不用同一函数作自己的标准答案。
3. **解释及导出**：统一逐商品政策资料；给模型适用的原文和事实；拒绝重复 finding；区分素材采纳与整题完成；导出金额、分母、政策、限制、引用及同版链接，消费同一份已核验快照。
4. **可复现交付**：把私人 tmp 依赖改成可随仓库复现的合成资料；第二案例仅在隔离环境验证；补实际页面操作检查；逐项报告 G1 覆盖，不能用数量代替覆盖。

下一阶段建议 Luna 最高按这些已定位缺陷实施，Astra 中审查数据范围/输入语义和最终采纳。若用户继续保留 Astra 中，也能执行，无须再次用极高重新设计。G1 未通过之前不消耗 G2 的12次请求；已停止的因果/泛化解释实验不恢复。

此审查阶段新增诊断和修正进度文档，未修复上述业务缺陷、未提交推送。已有统一解析和金额/分母结构可继续复用。
