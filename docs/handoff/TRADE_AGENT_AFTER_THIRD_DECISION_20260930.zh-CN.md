# 第三题后的最小调整与补充检查方案

状态：2026-09-30，GPT-6 Sol Max 完成只读诊断和实施设计；本轮未改运行代码、未调用模型。下一实施阶段建议 GPT-6 Luna Max，按下述明确规则完成离线验证。

## 已确认的事实

1. 第三题的程序报告已查到正确的美国大豆进出口范围与金额，模型也正确说金额不足以判断政策效果。模型 `finish.explanation` 中的“大幅净出口”超出了本项目对进口消费额与出口 FAS 的比较规则。本案原评分、账本和停止记录保留。
2. 在实际本地 HTTP GET 中复核第三题：返回 200，公开会话不含“净出口”，两项最新金额正确，私有试跑账本哈希前后相同。现有完成摘要防护有效；这句话没有展示给用户。该结论只适用于已验证的完成摘要路径，不能外推所有澄清或解释入口。
3. 当前 `finish` schema 仍要求模型填写 `explanation`，但该字段不会进入公开报告或后续追问。强制生成它没有当前产品收益，增加 token 消耗和错误表述。增加“净出口”等关键词拒绝规则会误伤“不能计算净出口”等正常否定句，也会让正确数据报告因闲置字段而失败，因此不采纳词表过滤路线。
4. 用真实目录复现第三题搜索：`大豆` → `both:1201` 准确；`soybean` → `both:1507` 豆油、`both:2304` 豆粕被误标准确，且原料大豆未出现；`soya beans` → 其他相关编码；`soybeans`、`1201` → `both:1201` 准确。原题的商品锚点能拒绝豆油和豆粕查询，但候选标注增加了模型绕路。第三题实际四次商品搜索并触及 4 轮回复／8 个工具上限。

## 实施决定

### 1. 修正原料大豆英文别名

文件：`src/tradeintel_ai/trade_agent_tools.py`。

- 仅对去除首尾空白后、忽略大小写、**整段等于** `soybean`、`soybeans`、`soya bean`、`soya beans` 的 term 启用本次规则；不将 `soybean oil`、`soybean meal` 或包含更多商品条件的任意句子当作原料大豆。
- 原料别名使用现有目录能命中的 `soybeans` 搜索，并将本次准确商品码限定为 `1201`。合并原 term 的目录搜索结果、按候选 id 去重，保留加工商品的相关候选；所有非 `1201` 的返回项标为 `related_candidate`。
- 中文大豆及现有豆油／豆粕加工形态规则保留。对豆油和豆粕不允许退回原料大豆。不要扩展到所有商品的英文词干规则。
- 三种 flow（import/export/both）都使用对应目录 id；不得写死金额、从模型记忆补目录条目或跳过 `validate_choice`。

### 2. 完成工具只要求报告和来源引用

文件：`src/tradeintel_ai/trade_agent.py`。

- 明确常量 `TOOL_PROTOCOL = "trade-agent-tools-v2"`，用于新试跑快照区分接口版本。
- 当前给供应商的 `finish` schema 只含 `report_ids`、`source_ids`，两者均 required，`additionalProperties=false`；不再要求或描述生成自由解释。系统提示同步说明完成时提交本轮真实报告／政策引用，公开摘要由程序报告生成。
- 后端兼容接收恰好 `{report_ids, source_ids}` 或旧 `{report_ids, explanation, source_ids}`；旧 explanation 如存在仍检查为字符串及原 1,500 字符长度上限，但不进入公开状态、报告、追问或模型质量通过标记。额外键、缺引用、未知 id、跨轮 id 继续拒绝。
- 保留公开 `program_summary_v1`、旧记录隐藏规则和多报告主范围修复。不重新生成已有报告，不改旧账本，不修改通用／历史冻结适配器。
- 若供应商在 assistant 正文或旧兼容字段中仍输出错误，真实评审照实记录；去掉 schema 字段不等于已证明模型解释能力改善。

## 离线验收与执行范围

只改变上述两个运行模块及必要测试、补充试跑入口和记录；现有页面无需改版，本轮不重打交付 ZIP。
