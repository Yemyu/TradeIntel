# 贸易助手主链：实施方案

状态：2026-09-29，后端与现有网页已用真实数据＋脚本化模型贯通（见 [网页验收](runs/20260929-TRADE-AGENT-UI.zh-CN.md)）；真实供应商模型效果尚未验收。本文覆盖 STATUS 中把外发安装包列为下一步的安排。

## 交付目标

用户输入明确问题后，助手自己查目录、选定商品、查询数据，根据结果补查，生成现有图表报告并支持追问。只在真实歧义时澄清。不是把最后一次 API 解读改名为 Agent。

第一条验收路径：`最近美国大豆进口有什么变化？` → 无商品选择点击 → 实际查询和图表 → `出口呢？` → 保留大豆、改用出口数据。第二条：`最近美国大豆贸易怎么样？` → 默认进出口分别展示并明示范围，不强迫先选方向。政策查询必须只使用已登记资料；没有资料时数据报告照常可用，不退回钨/光伏固定案例。

## 已核实的阻断点

- `trade_query_flow.prepare_trade_question`：有目录且没有 selected_product_id 时必返 needs_product_choice，不论有几个候选；相对日期和同比还存在硬拒绝。
- `web_app` 的 /api/trade/prepare、report 直接执行规则流程，未调用 ToolCallingAgent；live.js 将选择按钮作为必经路径。
- 旧 ToolCallingAgent 的 MODEL_TOOL_NAMES 固定为早期政策/因果研究工具；不能原样接到当前商品查询。
- generate_trade_report 会再次解析原问题。因此不能仅让模型拼一条“标准中文问题”穿过旧解析器；需要独立结构化查询服务。
- 已有 ClassificationCatalog.search/validate_choice、进出口 repository、报告渲染及存档、OpenAICompatibleModel 可复用。当前查询支持美国、全部伙伴/中国，不能许诺巴西等未加工伙伴数据。

## 最小架构和接口

新增 `trade_agent.py`（受限工具循环）、`trade_agent_tools.py`（工具与结构化查询服务）、`trade_agent_store.py`（会话/轮次持久化）。不改旧实验 Agent 的工具白名单或冻结记录；复用其 ChatModel/ModelResponse 协议和现有模型适配器，避免为历史因果工具改写通用循环。

服务器持有数据根目录、代码根目录、时钟及本轮目录/数据版本。模型不得提交路径、SQL、数据版本或任意 URL。

| 工具 | 参数/职责 | 返回和约束 |
| --- | --- | --- |
| get_trade_coverage | 无参数 | 美国、方向、伙伴、可查月份及数据截止时间；版本服务器保存 |
| search_products | term, flow(import/export/both) | 返回已核实目录候选及本会话 candidate_id；支持模型用英文同义词再查，不能让模型凭记忆编税号 |
| query_trade | candidate_id, flow, partner(all/china), period | 校验候选来自本会话且与方向相符；按真实月份和目录校验读取 repository，生成现有报告形状和 report_id |
| search_policy | query, candidate_id（可选） | 只从已登记启用文档逐库检索，保留旧检索器隔离/依赖补全规则；空库/无命中/范围不能确定须明说，不等于政策不存在 |
| ask_user | question, choices（可选） | 结束本轮为 needs_clarification，保存待解问题；不是无条件选商品 |
| finish | report_ids, explanation, source_ids | 引用仅允许本会话实际返回的报告/来源；图表由报告数据渲染，模型文本单独标注，不能改写程序事实 |

period 用判别对象：latest_contiguous(count，默认12，上限24)、absolute(start,end)、calendar_relative(unit=month/year,offset)。相对日历按服务器日期解释，缺数据时返回 available/unavailable，不把“上月”偷换成数据末月。“最近”使用连续可用尾部并明示截止月。同比只有前后月和分类可比都成立才程序计算；零分母返回不可计算，不让模型心算填补。比较模块未完成前如实返回缺能力，不能声称已实现。

明确商品候选由模型选定，但服务端核对候选登记和目录有效性；候选数量为1也不等于语义已证明。提示要求核对产品与加工形态，真实歧义才 ask_user。开发反例必须覆盖大豆/豆油/豆粕、同名排除项，不能直接自动取排名第一。

query_trade 将读取事实及 `_report_from_facts` 复用为公共结构化服务；原规则入口也可逐步复用服务，但第一包不改变旧入口行为。both 保留两种金额口径，禁止直接相减称贸易差额。新服务不再调用 prepare_trade_question 重解析自然语言。

## 网页和会话

- 新接口 POST /api/trade/agent/turn：question、可选 session_id、唯一 request_id。正常提问一次提交即可开始；发送按钮明确“使用已配置模型”，不重复要求每一步确认。
- GET /api/trade/agent/state：读回会话与报告。模型配置缺失时打开已有设置并保留问题，不偷偷用假模型或退回固定案例。
- 服务器保存用户轮次、已解析范围、工具调用及报告引用；追问使用服务器历史，不信任浏览器传回金额/历史工具结果。换商品时不继承旧商品码。
- 单用户本地，复用现有原子写/锁风格；相同 request_id 不重复调用。终态 completed/needs_clarification/failed/unknown_outcome。HTTP明确拒绝与网络响应未知分开，不自动重试付费请求。
- live.js 增加 Agent 模式作为配置完成后的主入口；旧数据查询保留为明确命名的无模型模式。复用已有图表组件，新增简单对话记录及折叠的“本次查询”，不重做视觉设计。
- 展示解释不是证明解释正确。工具结果是数据，政策正文是资料，不接受其中的指令。不能把有合法 source_id 当作文字受来源支持的自动证明。

## 工作量边界及执行顺序

一次设计，两个实施包，不再拆出新的评测框架：

1. 后端：结构化查询服务、工具循环、状态存储、HTTP接口及假模型集成测试。建议 GPT-6 Sol High：要处理多轮工具消息和既有报告结构的局部接口判断。
2. 网页接线＋浏览器验收：复用图表和设置，连续提问、澄清、刷新恢复、错误展示。接口固定后建议 GPT-6 Luna Max；如果第一包接口未完成，不让第二包猜测。

默认限制6轮模型请求、12次工具执行、单查询24个月；工具正文和结果不能无界塞入上下文。政策原文超限须返回可见限制，不默默截断法律条件。先离线假服务，不消费任何新API；第一次真实验证前核对本机产品配置、供应商工具调用/推理兼容性及实际请求预算，再说明有限调用范围。当前设计不是新模型效果成绩或实时检索许可。

## 必须通过的验收

1. 真实数据＋脚本化模型工具调用：大豆进口无需选卡，7月金额46,041,287美元；追问出口查询出口库，7月889,379,312美元。工具顺序记录可核查，不假造模型理解成绩。
2. 泛问大豆贸易默认双向、两口径分开；换玉米后不得残留大豆范围。
3. 真实歧义进入一次澄清，用户回答后继续；未知商品不得套旧政策示例。大豆油不得映射大豆。
4. “上月”按注入日期解析；缺月不能声称最新，缺同比基期不能编比较。测试固定时钟，生产用真实时钟。
5. 模型不得绕过目录、使用未返回候选、执行SQL、读取路径或访问自给URL；无工具查询就生成数据报告须拒绝。
6. 政策命中带原文及来源，无命中仍可完成数据部分，不能把同期变化解释为已证实因果。
7. 超轮次、无效工具参数、重复请求、401/400、超时、刷新/重启均有明确结果，已有报告不丢失；重复点击不重复发起模型任务。
8. 页面真正从提交→工具→报告→追问走通。假服务通过只能称功能链通过；真实模型还要独立跑代表性问题、检查相关性和有据性，失败不能只怪供应商。

最终交付必须分别报告：实际功能链、真实模型回答质量、未支持范围。不得再用测试总数、文件数或安装包完成代替用户流程完成。
