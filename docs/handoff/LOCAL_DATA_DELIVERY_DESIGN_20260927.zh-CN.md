# 本地版数据交付方案（2026-09-27）

## 结论

**代码和数据继续分开。**代码使用固定的本地 Git 候选；数据 ZIP 解到一个独立、带版本名的目录，网页启动时用 `--trade-data-root` 指向它。报告和审阅记录仍保存在代码工作目录。第一步只把这个本机流程做通；仓库保持私有，不在本包上传 ZIP、推送分支或开放公网服务。

当前 ZIP（67,464,723 字节）已经通过无损核验，在干净克隆内也能生成相同的大豆报告，但直接解入克隆会覆盖已跟踪的旧进口清单，令 Git 工作区变脏。[实测记录](runs/20260927-ZIP-INSTALL-CLEAN-CLONE-QA.zh-CN.md)。外置目录可避免反复改动代码仓库；用现有数据读取器对独立目录试跑，确认“选择大豆→2026-07 进口 46,041,287 美元→`not_run`”与旧路径一致。本方案**不是**重建数据库或扩大商品/政策能力。

| 方案 | 现在的取舍 |
| --- | --- |
| 继续解进克隆根目录 | 已经能跑，但覆盖旧清单；后续更新容易把数据改动混进代码提交。保留为旧版兼容路径，不作为推荐上手方式。 |
| 外置数据目录 + 启动参数 | 需要少量页面接线与专门测试；之后 ZIP 不改 Git 文件，换数据版本只换目录和启动参数。**选这个。** |
| 全部放进 Git / Git LFS | 579 MB 解压数据会增加仓库与更新负担；LFS 还增加客户端和用量管理。当前没有必要。 |

## 实施边界

1. `scripts/run_web.py` 新增可选 `--trade-data-root`，参数指向**包含 `BUNDLE_MANIFEST.json` 和 `data/` 的目录**，不是 ZIP 文件，也不是内层 `data/`。未指定时保持现有行为。显式指定时先调用现有 124 文件核验；错误应在服务启动前说清楚，绝不静默退回代码目录的旧数据。
2. `create_server` 接收独立数据根。`/api/trade/catalog`、`/api/trade/query`、`/api/trade/prepare`、`/api/trade/report` 统一用它；用户的 HTTP 请求**不能**传入本机路径。报告保存、状态读取、政策资料与静态页面仍用代码根目录。
3. 公告统计的 `prepare` 和 `report` 路由把独立根传给现有的 `trade_root` 参数；公告原文、候选与报告记录仍用代码根。其他政策覆盖检查不擅自改源。这里最容易发生两个版本混读，需要专门反例。
4. 暂不做自动下载、MySQL 切换、云部署或新数据自动发布。每一版 ZIP 解到新的目录，核验通过后才更新启动参数；旧目录不自动删除。
5. 本机 ZIP 的随包 README 仍介绍可用的旧式“合并到仓库根目录”路径。推荐外置路径通过新的上手说明提供；若以后制作对外版本，再更新随包 README，生成**新文件名和新 SHA-256**，重新验收，不覆盖旧档案。

现有数据仓库、商品目录和通用报告函数已经接受任意包含相同 `data/` 结构的根目录，**不用重构读取器**。执行时的局部判断是把贸易数据根传到上述路由，同时确保报告状态、政策原文仍在代码根，不发生混读。

## 验收与停止门

- 在独立干净克隆中，把最终 ZIP 解到 Git 忽略的版本目录；核验仍为 124 文件、578,630,811 字节、三项数据版本一致；克隆的 `git status --porcelain` 不因安装数据发生变化。
- 从外置目录通过真实 HTTP 流程确认商品并生成进口、出口、双向报告；大豆 2026-07 进口 46,041,287 美元、出口 889,379,312 美元，玉米出口 1,637,235,741 美元，与旧基线一致。重启后报告摘要与数据版本不变。
- 用单独的已登记公告 fixture 检查“政策资料在代码根、贸易统计在外置根”；把外置目录换成缺失/损坏/不同版本时明确失败，不能回读代码根的旧进口清单。默认单根路径的既有测试继续通过。
- 本包 0 次模型 API、0 次 MySQL 写入、0 次对外发布。若数据版本混读或真实报告值变化，停止扩大修改，保留最小复现；不改预期数值刷绿。macOS / Python 3.13 是当前验收范围，Windows 与公网另列门槛。

## 后续分享方式（现在只定规则，不执行）

仓库目前是私有的，候选分支尚未推送，未建 Release。若以后要给获准访问仓库的人试用，优先把**固定代码提交**与**单独数据 ZIP**配成一版，在私有 GitHub Release 附上 SHA-256 和安装说明；ZIP 约 64 MiB，低于 [GitHub 当前单个 Release 附件 2 GiB 上限](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)。私有仓库只对获准访问者可见，[Release 也要求仓库读取权限](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)。这只是可选渠道，不代表已获上传授权或完成跨机器验收。

若要公开作品集，可先展示项目说明、截图和已审报告；**不要**把私有仓库、原始数据或 ZIP 因为“本机可用”就直接公开。公开代码/数据前再核对实际提交范围、来源标注和拟公开材料。美国 Census 的[引用说明](https://www.census.gov/about/policies/citation.html)要求把原始数据来源与本项目结论区分；中文商品标题也有财政部来源记录。此处不作法律结论。
