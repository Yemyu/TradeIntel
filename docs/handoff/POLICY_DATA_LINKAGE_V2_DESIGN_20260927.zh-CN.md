# 公告与贸易数据怎样相连：下一版设计

日期：2026-09-27。状态：**包 A、B1—B4 已完成开发验收；新公告独立验收待做**（见 [包 A 记录](runs/20260927-POLICY-DATA-LINKAGE-A.md)、[包 B1 记录](runs/20260927-POLICY-DATA-LINKAGE-B1.md)、[包 B2 记录](runs/20260927-POLICY-DATA-LINKAGE-B2.md)、[包 B3 记录](runs/20260927-POLICY-DATA-LINKAGE-B3.md)、[页面 B4 记录](runs/20260927-POLICY-DATA-LINKAGE-B4.md)）。依据是现有公告候选/统计报告代码、[第一轮五份筛选](runs/20260927-UNSEEN-NOTICE-SCREEN.zh-CN.md)、[第二轮事前登记与五份结果](UNSEEN_NOTICE_ROUND2_PREREG_20260927.zh-CN.md)、[原文税率修复](runs/20260927-NOTICE-RATE-SCOPE-IMPLEMENTATION.zh-CN.md)。两轮不是随机抽样，不能据此估算“多少百分比的政策可用”；但已足以证明只准完整 HTS8 的**公告统计入口**过窄。普通商品进出口查询并不受此限制，不应重做或删掉数据库。

## 目标与不做的事

产品仍是给普通读者看的“政策原文 + 可核对的贸易背景”简报。它应回答：公告明确说了什么、哪些适用条件还不知道、手头数据究竟能说明什么、接下来需要观察什么。**不是**自动判断实际税率、受影响进口额、政策因果效果或投资建议。继续保留人工确认与原文出处；AI 以后可辅助阅读，但不替人确定商品范围或生成数字。

这次不建新数据库、不买课程框架、不做多智能体、不改旧 R2 报告与冻结评测，也不把 2025 年全中国进口金额说成某项政策的征税金额。所有新报告继续显示“原公告记载的税率，报告月份实际适用状态未核对”。

## 核心裁定：把“法律对象”和“统计对象”分开

目前 `announcement_statistics_report.py` 只从已确认候选里取 `whole_hts8`；没有就拒绝。`policy_candidates.py` 虽可记 `partial_ex`、`text_limited`、`hs6_only`、`hts10_partial`，现有统计报告不会展示它们。这是正确的**精确商品报告**保护，但不该变成整个公告产品的唯一出口。下一版在现有严格路径之外加一条只读“贸易背景”路径，不修改旧 `announcement-statistics-report-v1` 的合同。

| 关系 | 什么时候可显示 | 读者看到的准确说法 | 不能说 |
| --- | --- | --- | --- |
| 编码相符 | 原公告及人工复核给出完整 HTS8，中国来源，已发布数据可查 | “这些税号的中国大陆来源美国消费进口观测”——沿用现有严格报告 | 实际征税金额、现行适用税率、政策效果 |
| 上层商品背景 | 公告只指 HTS8 内部分货品/十位细码/文字限定，能由原文核定一个上层编码，用户确认要看该**较宽**范围 | “整个上层税号/商品组的进口数据，包含公告未覆盖的货品” | “公告涉及商品进口总额”“受影响金额”“覆盖率” |
| 国家贸易背景 | 公告主体确实是广泛中国货品，例外存在但**运输方式、单件价值、企业资格、用途等不定义主体**；人工确认只看中国大陆背景 | “本数据包中的中国大陆来源消费进口逐项合计；公告还涉及未在此数中单列的例外/香港” | “全部政策对象”“中国加香港合计”“政策前后影响” |
| 暂无可连的统计 | 目标由邮寄方式、≤800 美元、企业/药品审批、用途等数据没有的维度界定；或来源/编码/版本未确认 | 原文事实卡 + 一句具体解释缺哪种数据；不画相关贸易图 | 用全行业/全国金额硬凑政策对象 |

“编码相符”也只是编码粒度相符，不代表实际入境、豁免等法律条件在月度统计里可识别。页面避免把四种关系都叫 `exact policy exposure`。**不因某个上层数据数值大，就把它叫政策覆盖额或上界**；统计数据可能还有缺行，不能无条件宣称数学上界。

第二轮已见材料可作开发反例，不再算留出成绩：[2025-02293 对华广泛货品公告](https://www.govinfo.gov/content/pkg/FR-2025-02-05/pdf/2025-02293.pdf)可试“大陆贸易背景”，但原文包含香港及入境/法定例外，所以金额只能是大陆数据背景；[2025-07325 低值邮政公告](https://www.govinfo.gov/content/pkg/FR-2025-04-28/pdf/2025-07325.pdf)按邮寄和包裹价值界定，默认不给图；[2026-19498 药品公告](https://www.govinfo.gov/content/pkg/FR-2026-09-23/html/2026-19498.htm)按用途/审批及不同司法辖区，不用中国商品数据硬接；已见 R2 留在原严格路径。[2026-17925 十位统计码排除修订](https://www.govinfo.gov/content/pkg/FR-2026-09-02/html/2026-17925.htm)仅可用于“上层背景”的开发检查，不把排除货品扩大成整税号。

## 最小实现合同

1. 保留现有禁用候选→13 字段逐项引文→人工确认启用流程。另存一份**人工确认的关联判断**，绑定 `policy_id`、`doc_version`、`candidate_digest`、原文位置、关系类型、选定统计范围和未能在贸易表中观察的关键条件；旧字段值和已保存报告不迁移、不重写。`hts_codes=unknown` 不等于“政策范围未知”：若原文说“全部中国商品，但有例外”，关联判断可准确写“未枚举完整 HTS8”；不能假造编码来通过旧入口。若引文/版本变更，关联判断失效并重新确认。
2. 新增 `announcement-context-report-v1`，只承载上层商品背景、国家贸易背景、暂无可连统计三种；严格编码相符继续用原 `announcement-statistics-report-v1`。服务端生成范围确认单，包含**政策指向的人/货/事件**与**将实际查询的统计总体**两栏、不可观察条件、月份、来源文件/数据/分类版本与摘要。用户确认后服务端重新核对，不能客户端自报金额或关系等级。
3. 背景数据优先复用现有 `TradeDataRepository`。上层商品按已确认 HS4/HS6/HTS8 查询，展示官方名称和中国大陆来源；日期间分类变化仍遵守现有可比性闸门。国家背景使用已发布 HTS10 月包的中国大陆来源消费进口逐项合计，先核每月原始 ZIP、处理 CSV 与清单完全一致；**不叫 Census 官方单列总量**，也不自动把香港并入。若无法证明所选月份的文件完整或来源口径一致，就不画连贯趋势。当前只读抽查 `2025-02`（17,333 个 HTS10/1,047,791 条原始行）和 `2026-07`（18,813/2,432,958）均经现有 `verify_trade_month.py` 核对源包摘要、CSV 和总和；这是两个月样本，不是全期验收。
4. 报告页面先写公告事实与一段自然语言解释，再给有资格的数据图表；图名必须带“上层商品背景”或“中国大陆贸易背景”，数字旁写清未被观察的资格条件。没有匹配统计时不给空白图，明确缺邮寄方式/金额/企业资格等哪些维度。图表与政策说明视觉分区，不画“政策导致变化”的箭头或自动政策前后效果线。来源/版本移到文末可展开，但关键范围提醒留在数字旁；中英文、打印/刷新一致。
5. API/快照对旧路径只做加法：新入口和新 kind 明确白名单，生成过程读绑定版本；后续活动数据改变只影响新报告，旧报告读回原快照。无 AI 时也能生成完整程序报告，AI 生成入口对新 kind 先拒绝，待后续单独定义可检验的阅读帮助任务。不得用 AI 直接升级关系等级。

关联判断的最小记录字段固定为：`policy_id/doc_version/candidate_digest`，`relation`（`code_aligned/parent_context/country_context/no_statistical_link`），`origin_alignment`（`mainland_only/mainland_subset_of_china_hk/other/unknown`），`context_code`（无则 null），`unobserved_eligibility`（如邮寄方式、单件金额、企业资格），逐条 `evidence`（原文版本、段落、逐字引文），`confirmed_by` 和记录摘要。服务端核证引文位置与摘要；语义上是否真为广泛货品仍由人工核对，不把“引文存在”写成法律验证成功。`parent_context` 的查询编码只能从已确认的部分税号推导：八位部分范围查该八位整体，十位部分范围查其八位父码，只有 HS6 时查对应 HS6；不得自由填写无关商品组。候选若同时有完整码和部分码，完整子集可走旧报告，但须标未选中的部分范围；两类金额不能相加成公告总体。

## 实施和验收顺序

这是**新版本设计**，不回填两轮五份筛选的 0/5 结果。实施分两包，不把未完成部分说成已上线：

- 包 A：只做关联判断记录、服务端准备/拒绝门和定向测试。开发样例固定为旧 R2（编码相符）、`2026-17925`（上层商品背景候选）、`2025-02293`（国家背景候选）、`2025-07325` 与 `2026-19498`（暂无对应统计）。测试伪造政策原产地、版本/引文更改、把邮政公告硬选国家背景、把部分编码说成政策金额、把香港并入大陆，以及超过可查月份；均须受控拒绝。任何未知法律条件不会默默变为“无条件”。
- 包 B：在包 A 绿灯后才接查询、存档和页面。先在隔离目录跑两个月只读样本并独立求和；后用已见公告从空白页面录入，确认关联判断→生成背景报告→重启读回，记录人工修改/不能表达的字段，旧 R2 金额回归不漂移。新报告至少有一份**有用的背景图**和一份**正确无图**的反例，读者能一眼区分“政策对象”和“统计对象”。页面刷新/打印/中英文同义。

新公告正式验收须在实现冻结后重新预登记、重新找未参与开发的官方材料；旧两轮十份和 R2 只可作开发/回归。对未见材料评价的是**正确分流率与严重误导数**：每份的人工独立参考写明应走哪条路、依据是什么；错误提升为政策影响额/现行税率/完整覆盖必须为 0。无合格材料如实报告，不无限筛到成功。AI 效果另设实验，不能把路由规则通过率算成模型成绩。

预算与止损：实现包模型 API 0 次、MySQL 写入 0 次、不推送；仅项目虚拟环境、现有月包和隔离临时根目录。旧报告数值或来源漂移、统计总体与政策对象混称、香港被混入大陆、需要企业/邮政等当前不存在的维度才能画图时停止扩大实现。方法口径或法律范围无法由原文与现成测试控制时再暂停求专门审查，不因实现困难自动换更贵模型。

## 留给执行者的最小入口

先读 `policy_candidates.py` 的 13 字段/精度与 `announcement_flow.py` 的确认存储，再读 `announcement_statistics_report.py` 的严格报告和 `trade_data_repository.py` 的 CHINA/ALL_ORIGINS 查询；只新增**关联判断**和 context kind，不删旧路径。最先交付一个完全离线的分类/拒绝门和上述五个已见开发反例；不要先写前端，也不要再找新公告刷正向。定向测试与数值回归通过后再接页面。
