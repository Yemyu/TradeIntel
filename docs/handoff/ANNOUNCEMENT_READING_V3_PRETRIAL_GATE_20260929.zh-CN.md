## 答前参考和评分：先定义真值，再看模型

- 没看模型回答的审阅者逐段写**最小原子事实**：政策动作及前后版本、每项税种/措施及各自国家来源、商品限定、适用日、每个措施或来源组的追溯起点、入境/出仓事件、排除条件的“且/或”关系、税号与文字描述的优先关系；并记录确实未说明或存在冲突的事项。公告不涉及的检查点也要给原文依据和理由，不能凭空认定 `not_applicable`。
- 每个事实写对应原文及必要前后文；有多税种×多来源×多日期时逐组合列，避免用一句“各自追溯”凑覆盖。事实数量由公告决定，**不能固定套旧案的 13 项**。参考、评分规则和来源摘要须在首次模型调用前锁定。开发者独立制作只能称“答前开发者参考”，不是独立法律金标；遇关键解释争议、官方正文与附件不一致时先停止核源，不靠模型投票决定。
- 技术层：最终 `finish_reason=stop`、服务商型号/usage合规、v3 JSON 和全部身份/来源/大小/检查点校验通过，且没有 `incomplete`。任何技术失败计本案例失败，保存原答，不用改解析器或重试将它重报通过。
- 事实层：**所有事前关键事实及其子条件正确覆盖**；逐条核输出中的所有额外主张，来源位置必须真正支持整句话；每个 `not_stated`/`not_applicable` 也逐原文核实。国家或商品范围扩张、把新增税率当总税负、把未来措施说成现行、漏决定适用的条件/例外/日期，均为严重错误；任一项出现即不通过。
- 不把“10/10 检查点已填”“JSON 有效”“引用 ID 存在”或一次案例通过写成产品准确率。真人省时保持 `not_measured`，直到另行完成两位读者×两份未见公告的交叉操作与计时、补查、改写和错误记录。
