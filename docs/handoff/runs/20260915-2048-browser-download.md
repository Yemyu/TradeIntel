# 2026-09-15 浏览器实际下载缺口验收

## 阶段目标

确认人工审阅稿在浏览器中的“下载/查看”链接能触发可观察的下载事件；若浏览器客户端不支持该响应，区分UI限制与后端导出能力，不把失败误判为内容门槛失败。

## 环境与安全边界

- 执行模型：Luna 最高。
- 页面：本地 `http://127.0.0.1:8766/review/interpretation?...`，由隔离 fixture 服务提供。
- 真实模型、外网、Docker、MySQL 写入：均为 0。

## 结果

1. 通过页面填写三条逐条采纳决定并勾选事实核对后，页面显示审阅版本已记录，并出现“下载/查看人工审阅稿（只含采纳项；不发布案例）”链接。
2. 使用浏览器下载事件监听点击该链接，5 秒内未触发下载事件；页面仍停留在审阅页，浏览器控制台错误/警告为 0。
3. 同一运行的HTTP导出端点此前已返回正确的Markdown内容；存在“需要修改”时已验证HTTP 409。因此本次失败只说明当前in-app browser未观察到原始Markdown端点的下载行为，不否定审阅/导出门槛。

## 结论与处理

核心数据和审阅安全门槛已通过；“浏览器点击后直接下载文件”作为低优先级UI缺口保留，不在本阶段强行改变后端内容类型或路由。若后续需要产品化下载，可单独把导出链接改为明确的下载响应/HTML预览，并重新做浏览器验收。
