# 下一轮高推理复测计划

## Astra实施裁定（覆盖下方原候选计划）

官方参数核对：DeepSeek两款支持reasoning_effort=high（https://api-docs.deepseek.com/guides/thinking_mode/）；GLM-4.6V文档只核实到thinking开关（https://docs.bigmodel.cn/cn/guide/models/vlm/glm-4.6v），没有足够依据安排GLM high。此前GLM已开启思考，不重复相同配置。

本轮采用新生产提示词生成的 `candidate-high-v2-20260922`，新矩阵 `evals/public_brief_v1/provider_matrix_high_v2.json`。这是新提示词+高推理的组合验收，旧low是历史参照，不作只改变推理档位的因果对照。题目、数据版本、合同及评分沿用；不向候选发送旧答案或评审结论。既有四题属于开发案例，不称盲测。

假设：新配置能具体解释数据且减少来源/单位/比较权限错误。采纳门槛为每题结构、事实、相关性、可用性均通过，无重大事实错误；正式自动发布仍须独立新材料/API验证。每配置每题最多一次，任何重大语义错误即停；预算截断、接口失败或超时也停止且不自动重试。不为高推理增加预算：总输出8192、正文估算2000、超时90秒；预算失败只代表本预算不能完成，不证明模型整体能力不足。

只接受本轮高档新冻结。响应未回显推理档位时，只记录“已发送官方支持的high参数”，不以HTTP成功冒称独立验证服务端实际思考强度。允许首题同时检查接口，无需额外消耗一次短题调用。

用户决定：下一轮优先测试 DeepSeek Flash、DeepSeek Pro 的高推理；如果 GLM 账户和接口确实提供高推理，也测试可用的 GLM 配置。当前低推理成绩保留为旧对照，不覆盖、不合并。

## 公平对照

同一 `candidate-service-20260922-v1`、同一 q1—q4、同一输出合同和预算。每个配置只用一档高推理；旧低推理结果作为对照。不会因为某题表现不好而换题或补答。若第一题出现重大事实/边界错误，按停止规则暂停该配置。

## 放行前检查

1. 由执行器登记确切 `model_id`、推理参数、总输出预算和可见正文预算；冻结文件中的参数必须与发送字节一致。
2. 先做不计成绩的配置预检，确认高档参数被接口接受；如果厂商只接受 `thinking.enabled` 而没有 high，记录为“高档不可验证”，不能冒称高推理。
3. 用户提供的 API 密钥只放在项目专用环境变量中，不写入文件、日志或回答。预检失败不自动换参数重试。
4. 真实题按 q1→审阅→q2→审阅执行；原答、usage、错误和停止原因全部保存。

## 采纳门槛

高推理必须在四项审阅中证明至少减少原低推理的已知问题：不把来源份额写成供应依赖、不越过未核验同比边界、具体解释环比变化，并在价格问题说明待验证机制与资料缺口。结构通过但事实边界仍错，不能因为“推理更高”采纳。

本计划只定义下一轮实验，当前不调用 API。开始实施前需要重新生成高档冻结文件；旧 low 冻结不能直接复用。
