# P5：按问题生成多月走势解释（v3 离线实施）

日期：2026-09-24

## 本轮目标

针对真实大豆出口报告中“最近有什么变化”仍被拆成最新月、月度变化、期间合计三段重复解释的问题，让程序计算多月走势并按用户问题挑选事实；模型每个贸易方向只写一段短解释。不得重算或改写原报告数据，不改旧 v1/v2 答案，不调用模型 API。

## 实施结果

- 将通用贸易解释协议升级为 trade-data-explanation-v3。新请求只发送用户问题所需的观察、适用范围和来源，不再发送完整月度行。
- 走势观察直接从程序报告的月度记录计算：最新月方向、截至最新月的连续同向月份、观察区间高低点及并列情况。只有完整且月份连续时才称“完整区间”；缺月或未观察值会截断连续走势，并明确资料不足。
- 当前真实大豆出口数据生成的程序事实为：2025-08 至 2026-07 的完整区间里，2026-01 最高，此后连续 6 个月逐月减少；2026-07 最低，较 2026-06 减少 3,500,150 美元。观察由数据程序计算，不是模型猜测。
- 按问法选择最新月、走势或期间合计；问题同时要求多项时可在同一段解释里关联多个观察。双方向每个方向最多一段，解析器核对引用完整性、方向、走势词、字数及新增数字。
- 页面在模型调用前展示走势事实卡；支持新协议的 observation_ids 数组，同时保留旧记录 observation_id 单值形状。人工采纳后的正文不再重复打印已经展示的事实卡。工作台措辞改为说明可查已接入商品、数据报告与模型解释是分开的步骤。

- 真实数据走势复算与已存报告一致。**本轮 0 次 API 调用**；未做完整测试集、跨模型比较、真实服务商 v3 回答审阅，也未提交或推送。

## 边界与后续

离线结构、程序事实计算和页面替身路径通过，只证明这套实现按合同工作，不证明真实模型的文字一定自然、解释一定有用。旧 v1/v2 结果与审阅状态未重算。

按用户先完成产品再做模型测试的顺序，暂不调用新 API。产品界面收口并经用户确认进入测试后，再用一个全新报告对 v3 做一次受控调用；不能把它算作准确率或跨模型成绩。之后再按同一题集做模型横评。
