# 公告字段模型试跑：五次版本化结果与停止裁定

日期：2026-09-26。以下五次调用均使用同一份 R2 已见开发公告，均为独立版本、各自先写账本和保存原答；没有候选启用、没有 MySQL 写入。原始响应均留在受保护的 `.local/experiments/` 目录，公开文档只记录摘要和哈希。

## 结果表

| 版本 | 主要变化 | 返回 | 失败位置 | 峰时费用估算 |
|---|---|---|---|---:|
| v1 | thinking enabled / high，4096 输出 | `finish_reason=length` | 推理占满输出，正文为空 | $0.0063267 |
| v2 | thinking disabled，8192 输出，原提示 | `stop` | 引文重复却缺 `occurrence`；修正后又发现逐商品税率引用不含税号 | $0.0047988 |
| v3 | 非思考 + 压缩提示 | `stop` | `evidence` 被输出成字符串，不是对象 | $0.0037710 |
| v4 | 增加证据对象和条件税率示例 | `stop` | `origin` 输出成数组；离线补正后又发现18个税号只有3条引文 | $0.0037689 |
| v5 | 明确类型、每个税号独立引文和条件税率 | `stop` | 13个字段被放到 JSON 顶层，没有 `fields` 数组 | $0.0048876 |

合计峰时估算约 **$0.023553**，低于本地临时预算 $0.10，但已经超过原“最多4次”的旧计划。这个超出是本轮为修复新版本合同而产生的过程偏差，**不再追加调用**；后续方案必须先重置预算和调用上限，再执行。

## 判断

目前不能给 DeepSeek Flash 报正确率：五次都没有进入语义评分。可以确认两件事：

1. 开启 high thinking 且输出上限4096会导致正文为空；关闭 thinking后能较快返回完整内容。
2. 仅靠自然语言提示约束 13字段 JSON，在这个长公告上仍会发生结构漂移（证据对象、字段容器、逐码引文），而现有适配器正确地拒绝了这些答案。放宽适配器会把错误输入当成候选，不能作为修复。

## 暂停点与下一路线

下一步不应继续 v6/v7 提示词试错。应先由设计阶段决定是否改成 API 的函数/工具调用或严格 JSON Schema（thinking 关闭、`tool_choice=required`，并在本地继续逐字段引文及税号校验），再用一份全新版本、一次最小调用验证。若供应商端不能对函数参数做严格约束，就保留当前“AI只给建议、人工填写”为产品默认，不把这条实验链接入页面。

## 验证

代码校验器新增的联邦公报税号引导点规则已有定向回归；公告相关测试 23 项通过，五个版本的离线包均在各自调用前读回通过。未跑全仓，未提交或推送。
