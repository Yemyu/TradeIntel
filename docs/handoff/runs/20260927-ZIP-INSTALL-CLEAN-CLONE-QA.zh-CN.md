# 最终 ZIP 装入干净克隆的本机验收（2026-09-27）

## 目标和边界

假设：已核验的最终 ZIP 能在本机干净 Git 克隆中恢复商品贸易数据，并产出与此前目录数据包验收一致的普通报告。对照是[完整依赖与报告复验](20260927-FULL-INSTALL-QA.zh-CN.md)中的 2026-07 大豆进口 46,041,287 美元。代码固定为本地 `codex/local-release-candidate` @ `0d6252d`，数据固定为 `trade-demo-data-20260927.zip`（SHA-256 `c847fda351cfbb93d856473cdac9b1d285c310e1ff8366a1273d5697713aa7ac`）。没有训练或留出集；不改数据、代码、预期金额或验收门。只建立一份临时克隆与解压副本，预期额外磁盘占用小于 1 GiB；任何清单或金额不符即停止。

## 实际步骤与结果

1. 从当前本地分支作 `--local --no-hardlinks --single-branch` 干净克隆，使用 macOS 的 Python 3.13.3；没有复制当前工作区未提交文件。
2. 比对 ZIP 条目与 Git 已跟踪路径：只有 `data/processed/trade_hts10/manifest.json` 冲突。克隆中的旧清单 SHA-256 为 `25b89e226c9bdd1154a07043d80a139468dff7333bdb2a99ca60ba421b05d442`；ZIP 中新版为 `335603c54721e8489907109e709bba209afcdeaaf5fc53ac843424ac1abaa207`。仅在此临时克隆内明确覆盖它。
3. ZIP 直接解压到克隆根目录，`scripts/trade_demo_data_bundle.py verify --root .` 返回 `verified`：124 个数据文件、578,630,811 字节，进口、出口与商品目录三个版本全部一致。
4. 查询“最近美国大豆进口有什么变化？”先收到商品候选；明确选定官方 HS4 `1201` 后，`generate_trade_report` 返回 `ready`，2026-07 消费进口额 **46,041,287 美元**，`ai_status=not_run`。与前次目录包验收一致。

临时克隆最终占用约 619 MiB，低于本次 1 GiB 预算；没有模型 API、MySQL 或外网请求。测试副本已在记录后清理。本轮没有重新安装完整依赖、跑页面或测 Windows；这些不得从此次结果外推。

项目脚本目前只有 `create` 和 `verify`，没有 ZIP 安装命令。解压后该克隆会显示旧进口清单被修改，以及包中清单和部分目录为未跟踪文件；这是当前“代码仓库 + 独立数据包”布局的直接结果，不是校验失败。正式给别人用之前，要明确说明这一次覆盖和后续更新办法，或设计外置数据目录；不能说普通 Git 克隆本身已经包含数据。ZIP 仍只保存在本机，未提交或上传；外发范围与渠道尚未决定。
