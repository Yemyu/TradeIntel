# 请求总时长与中断记账修复

本轮没有调用模型，没有重试此前未知结果，也没有修改旧冻结或成绩。

## 已完成

- 评测 CLI 在 provider 调用及响应提取外围设置真实的总时长截止，不再只依赖 socket 的无数据超时。短间隔心跳不能延长截止时间。
- 截止或 Ctrl-C 后，运行文件与账本记录 `unknown_outcome`，区分 `wall_clock_deadline`、`operator_interrupted` 和 `transport_error`。换输出目录也不能重复执行同一题。
- 截止异常绕过普通适配器的 Exception 包装；退出调用时清除计时器并恢复原信号处理器。
- 当前实现限定 POSIX 主线程 CLI。工作线程或已有进程计时器时，在领取运行记录和发送请求前拒绝，不偷偷降级成无总时长限制的调用。

这保证的是本地等待截止，不是撤销服务端任务，也不代表不会计费。服务端结果未知时仍须人工核实，不能自动重试。强制杀进程、断电等不能保证执行清理，但原有 started 记录仍阻止自动重复调用。
