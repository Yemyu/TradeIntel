# 贸易助手网页贯通验收

日期：2026-09-29。范围：把现有工作台接到受控 Agent，检查自然提问、报告、追问、语言切换与恢复。没有真实模型 API 调用、MySQL 写入、提交或推送。

## 已完成

- 工作台默认提供“研究助手（使用模型）”；保留“仅查询数据（不使用模型）”。助手模式直接提交自然问题到 `/api/trade/agent/turn`，不先强迫选择商品卡；模型配置缺失时明示设置，不伪装查询成功。
- 同一会话可追问；本地保存请求编号和会话编号，网络响应丢失时先查 `/api/trade/agent/state`，不自动再次发送可能收费的请求。刷新后从服务端恢复对话和报告；可显式开始新对话，未决请求会提示可能仍在进行或计费。
- 复用既有月度图表、报告和打印。程序数据与模型解释分开显示；模型文字仍是待核对草稿。修正中英文切换后旧静态文案覆盖助手入口、对话记录不跟随翻译的问题。
- 商品搜索保留相关候选但排在准确商品之后。问“大豆油”时 `1507` 在前，原料大豆 `1201` 只作相关候选；如果模型试图用 `1201` 生成大豆油报告，工具层拒绝。澄清后的下一轮会带上最近的用户问题与澄清内容，但旧模型解释不作事实依据。

## 验收证据

- 本地已核验贸易数据 + 脚本化假模型：浏览器独立页面提问“最近美国大豆进口有什么变化？”→自动生成 2026-07 进口 **46,041,287 美元**图表报告；返回工作台追问“出口呢？”→同一会话生成 2026-07 出口 **889,379,312 美元**报告。中文页面重载后会话和报告恢复。
- Python Agent/旧贸易查询相关 **29/29**；Node 工作台/报告交互 **14/14**；`git diff --check` 通过。真实浏览器是**脚本化模型**，仅证明页面—工具—数据—报告链路，不证明实际供应商会稳定理解商品或写出有用解释。
- 第一次普通沙箱运行的四项本地 HTTP 测试因回环端口权限失败；获本地回环权限后同一组 **29/29** 通过，不是代码失败。

## 下一步边界

先用现有产品模型配置做**有限真实模型端到端开发验证**，事前固定自然问题、正确商品和数据参考、请求上限与停止条件；核对它是否会选对工具、误用相关商品、答非所问或编写无据结论。此记录不宣称 AI 效果通过，也不宣称实时联网或公网可用。普通克隆仍需要独立数据包。
