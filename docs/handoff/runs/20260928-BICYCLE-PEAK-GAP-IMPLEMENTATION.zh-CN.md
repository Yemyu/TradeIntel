# 自行车追问：同年峰值差额事实与页面接线

日期：2026-09-28

## 目标

补上离线核对发现的一个明确缺口：报告能显示整段最高/最低和最近连续变化，但不能直接回答“某月比该年已观察峰值低多少”。本轮不调用模型、不改旧冻结题、不写 MySQL、不提交推送。

## 实现

- `trade_report_followup.build_catalog` 为每个有至少两个月观测的年份生成 `flow.year_peak_gap.YYYY-MM`，逐月绑定峰值月份、峰值金额、被比较月份、差额和原始来源；缺月不补零。
- 追问提示仍保留完整签名事实目录，但只发送点名月份的峰值事实；问题未写机器可读月份时只发送每个方向最新峰值事实，以保持双向包预算。
- `trade_explanation_v4` 增加 `flow.same_year_peak_gap`，只作为确定性页面事实，不加入 `eligible_card_ids`，所以不会让普通模型解读请求平白引入同年比较。
- `web/design-preview/live.js` 在逐月图表前增加“按同年已观察月份比较”区块，并提供英文对应文本。

## 验收

- Python：`tests.test_trade_report_followup` 与 `tests.test_trade_explanation_v4` 共 25 项通过。
- Node：`tests/trade_explanation_ui.test.cjs` 13 项通过。
- 双向追问提示仍低于 24,000 字节；单方向事实可按明确月份筛选。
- 真实自行车开发数值仍由程序报告提供：2026-05 为 81,378,250 美元，2026-07 为 75,059,483 美元，差额 6,318,767 美元；本轮没有重新抓取或调用模型。

## 边界

这只证明确定性事实和页面显示已接线，不证明模型回答准确率，也不表示缺失月份可以被推断。模型若要解释该事实，仍需独立冻结题目、模型精确 ID、预算与人工审阅；本轮不放行真实 API。
