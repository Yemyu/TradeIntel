# 公告三项阅读建议：离线原型与账本修复

日期：2026-09-27。本轮没有模型/API调用，没有提交、启用公告、写 MySQL 或推送 GitHub。旧 v6 原答与账本保持原样。

## 完成内容

1. 未来的 strict-tool 单次执行器改为：**原始响应保存后，先登记服务商返回的型号、结束原因和用量，再校验工具参数**。这样参数即使不是合法 JSON，也不会像 v6 一样把已返回的 usage 留空。价格字段仍只称“峰时估算”，不是实际账单。用旧 v6 原答做只读检查，可提取 `deepseek-flash`、`tool_calls`、输入 5,490 / 输出 2,860 / 合计 8,350 tokens；没有改写旧账本。
2. 新增隔离的 `announcement_reading_suggestions.py`：给已保存且 disabled 的单来源公告逐行编号；模型未来只可对 `rate_meaning`、`conditions`、`exceptions` 三项给简短建议及行号。程序核对公告版本、正文摘要、字段集合、JSON重复键、状态、行号和长度，返回 `review_only` 及实际原文行。它不调用服务商，不调用候选提交/人工确认/启用接口，也不计算政策影响。
3. 新增只读准备/读回命令 `prepare_announcement_reading_offline.py`，把模型将看到的消息与本地行号映射分开保存，清单最后写入；改动文件或公告版本会导致读回失败。R2 实际开发公告形成 `tmp/announcement-reading-dev-20260927/r2-v1/`：原文 326 行编号，请求 24,894 UTF-8 字节，低于 28,000 字节门，`api_calls=0`。
