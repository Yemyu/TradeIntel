# P5：通用贸易报告真实模型单次冒烟记录

日期：2026-09-24。目的仅是确认完整报告调用是否能走过产品接口和输出合同；单题单次结果不代表模型总体能力，也不并入此前冻结的四题评分。

## 固定条件

- 问题：最近美国大豆出口有什么变化。
- 范围：美国大豆 Schedule B 1201，全部目的地，2025-08 至 2026-07；出口数据版本 `4308e4a820cd86bb6a19e223b4ae887fe0a030eef4a8af0c1ce96cb8c30a4b9f`。
- 配置：DeepSeek 服务商，API 型号名 `deepseek-flash`。产品设置保存的 reasoning 为 `default`；当前适配层实际发送 `thinking=enabled`、`reasoning_effort=high`，输出上限 2,048 tokens。
- 发出请求前由程序生成并保存一份新报告；模型只收到该报告的观察、月份金额、来源及版本，不收到其他项目数据。没有重试，也没有改配置。

## 结果

- Provider 返回型号字段：`deepseek-flash`。接口只回显别名，不能据此确认后端实际模型快照版本。
- 使用量：输入 1,661 tokens，输出 1,263 tokens（其中推理 1,012），合计 2,924 tokens。
- 返回 JSON 合同通过；三条解释分别引用 `export.latest`、`export.month_change`、`export.period_total`，报告摘要绑定正确。没有生成额外数字、日期、编码或网址，也没有把大豆答成其他商品。
- 内容核查：总体能提醒读者金额不等于数量，单看金额无法判断价格、数量或政策原因；也提出补看数量、价格、目的地结构等资料。问题是表达重复且偏模板化，尤其月度变化项只说“出现金额变化”，没有说出程序报告已明确算得“较上月减少”。所以结构门通过，**内容尚未通过人工采纳**；记录仍为 `needs_review`。

原答及元数据已留在本机：`.local/trade-reports/b39d7e8c020e4c0a96c053836b71e6f1.json`。记录目录仅所有者可读写；API 密钥不写入这份记录或仓库。

## 结论与后续

一次真实调用证明：已配置的产品模型可以收到通用大豆报告并返回合同可解析的解释草稿。它没有证明解释已经足够具体、可直接发布；本例暴露出当前提示/观察定义没有促使模型清楚表达方向。不能将这次结果写成“准确率100%”或“报告已经人工审核”。

下一步由用户在报告页面逐条审阅。若希望解释明确指出升降方向，可先把程序观察改成显式方向（上升/下降/持平），在离线用例覆盖后，再基于一份新报告做一次受控验证；不要重跑或覆盖本次结果。
