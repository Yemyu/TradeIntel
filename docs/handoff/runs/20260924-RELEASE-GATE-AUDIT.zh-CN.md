## 执行顺序

1. **先验收动态报告打印。** 它直接影响用户读报告与保存结果，不依赖数据库服务。使用本机现有小麦出口报告 `9b677874d52c44edb5e0bb23848f5ab3`（含待审阅草稿）和乘用车进出口报告 `df900d9c36ae4b22b36cf550047f7141`（双方向），分别在中文、英文打印预览中检查标题、月份、图表、逐月表、来源、分页，以及待审阅草稿不会伪装成已核准正文。发现缺项后只修打印呈现并复验，保存验收截图或 PDF 记录。无需模型 API。
2. **补 MySQL 同版对账。** 先明确当前文件版本和目标 schema，补出口表与版本化装载；本机 MySQL 可连接后，以同一商品、方向、月份、伙伴核对行数、金额、观察状态和文件／来源摘要。保持网页的已核验文件快照可用，直到 SQL 副本验收完成。此项展示数据工程能力，但当前网页的数值正确性不依赖 MySQL 服务在线。
3. **做当前网页的便携数据包与干净环境复现。** 只打包运行所需的已发布加工数据、目录和摘要，不把 9.6 GB 原始包或本机密钥带进仓库；在隔离目录核对“提问→确认→真实报告”。给 README 写清所需数据与已验证版本。数据包存放位置与分发方式需在真正外发前确定。
4. **决定是否做公网服务。** 本地作品展示可先交付；若要外部在线试用，再补认证、HTTPS、配置隔离和服务器部署验收。GitHub 展示、可本机运行、公网实时服务是不同的交付状态。

AI 解释价值是与上述工程门槛并列的内容门槛。项目可先如实展示“官方数据查询＋可审阅的模型草稿”；要把“AI 稳定可用”写入展示页或简历，应完成独立内容审阅，并在新的、先冻结的材料上证明模型确实增加了程序报告没有的信息价值。v4 当前开发题已触发停止门，不应原样追加调用。
