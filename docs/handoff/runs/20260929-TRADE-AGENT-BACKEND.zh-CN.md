# 贸易助手后端第一包

日期：2026-09-29。范围：后端结构化查询、受限工具循环、会话存档、HTTP 接口。没有改网页主入口，没有新模型 API 调用，没有提交或推送。

## 做成的链路

新增 `trade_agent_tools.py`，模型只传商品搜索词、方向、伙伴与月份意图。服务端从已核验目录返回候选，并校验本轮候选身份、目录版本、实际可用月份与进出口口径。结构化工具直接读原有进出口 repository，用现有报告形状存档；不再让自然语言回流旧规则解析器。加入“豆油/豆粕不能套大豆1201”工具层拒绝，“上月”按服务器日历解释且缺2026-08时拒绝冒充2026-07。

新增 `trade_agent.py`：模型可调用 coverage、search_products、query_trade、search_policy、ask_user、finish；最多6轮模型回复/12次工具。没有查到实际报告就不能 finish 生成数据结论；报告金额与图表仍由程序计算。政策只查本地启用文档，不把无命中说成无政策。模型解释是待核对文字，不能视为自动事实证明。

新增 `trade_agent_store.py`：请求编号在首次提问也作为会话编号；原子记录进行中与结果，重复请求直接读回，不再次发模型。网络或模型结果未知保持 unknown_outcome，不自动重试。`web_app.py` 新增 POST `/api/trade/agent/turn` 和 GET `/api/trade/agent/state`，生产配置使用现有产品模型设置，测试注入脚本化假模型。

## 验证

- 本地已核验数据包 + 脚本化模型：大豆进口 2026-07 **46,041,287 美元**，追问“出口呢”同商品查出口 **889,379,312 美元**；模型实际发出 `search_products → query_trade → finish` 工具序列。
- 泛问大豆贸易产生进出口两份独立金额；HTTP 路径生成、状态读回与同请求重放通过。豆油误选大豆、未登记商品编号、日历上月缺月反例通过。
- 本轮新增6项，加旧查询/出口/目录相关共 **28/28**；`git diff --check` 通过。第一次不带 `PYTHONPATH=src:.` 的测试导入失败属于调用环境错误，重跑后通过；本机端口测试使用本地服务权限。

## 当前边界与下一步

这证明后端工具链可运转，**不证明实际供应商模型会稳定选对工具/商品**，更不证明法律解释准确。网页仍调用旧 `/api/trade/prepare`，用户尚不能从当前页面使用 Agent。下一包只接现有网页：模型配置完成后使用新 `/api/trade/agent/turn`，保留无模型查询入口，渲染存档报告和追问，做浏览器端到端验收。建议 GPT-6 Luna Max；已固定接口与页面验收，不继续扩后端框架。
