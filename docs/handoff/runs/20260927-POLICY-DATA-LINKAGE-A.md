### 已见官方原文开发回归（仅包 A）

新增 `scripts/check_policy_linkage_seen_cases.py`，离线读取五份**已见**原件，先核固定原始字节摘要，再抽取原文、按开发标注填候选、启用在临时目录、保存关联判断、服务端准备并读回核对摘要。原件分别是 R2 本机已存 HTML、[2026-17925 十位排除修订](https://www.govinfo.gov/content/pkg/FR-2026-09-02/html/2026-17925.htm)、[2025-02293 广泛中国货品公告](https://www.govinfo.gov/content/pkg/FR-2025-02-05/pdf/2025-02293.pdf)、[2025-07325 低值邮政公告](https://www.govinfo.gov/content/pkg/FR-2025-04-28/pdf/2025-07325.pdf)、[2026-19498 药品公告](https://www.govinfo.gov/content/pkg/FR-2026-09-23/html/2026-19498.htm)。两份 PDF 摘要与原先筛选记录相同；本轮取回的两份 HTML 摘要固定于脚本。原件位于 Git 忽略的 `tmp/handoff-runs/policy-linkage-seen-20260927/`，R2 复用已有本地文件；未把 PDF/HTML 加入 Git。

结果存于 `tmp/handoff-runs/policy-linkage-seen-20260927/result.json`：R2 → 旧严格报告准备；十位排除 → `84139190` 八位上层商品背景；广泛中国公告 → 标注香港未计入的大陆背景；低值邮政及药品 → 无统计事实卡。五例均 `policy_amount_status=not_determined`；最后两例没有月份或统计对象。2026-07 真实商品目录只参与范围准备，**没有读取贸易金额、没有生成新报告或独立核算国家总量**。

这一步证明原件字节、候选引文位置、人工标注的四路规则与服务端准备在这些开发样例上相连。脚本里的字段是依据已见材料整理的**开发注解**，`confirmed_by` 明示不是真实业务审批；它不验证法律语义是否正确，也不能作为未见公告成功率或新政策端到端验收。
