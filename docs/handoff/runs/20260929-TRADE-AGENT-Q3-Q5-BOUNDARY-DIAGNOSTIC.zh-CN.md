# 固定开发题③—⑤：离线边界诊断

日期：2026-09-29。只用真实已发布本地数据和临时脚本化模型；**0 次服务商模型请求**、未改正式首题与第二题账本。下面不是模型准确率，而是程序对错误模型决策的拦截能力。

## 已验证事实

1. 题⑤“上个月美国大豆进口额是多少？”以 2026-09-29 为时钟，“上个月”应为 2026-08，数据仅发布到 2026-07。`TradeAgentTools._period` 在模型确实选择 `calendar_relative(-1)` 时会拒绝缺月；但临时脚本化模型若改选 `latest_contiguous`，`TradeResearchAgent` 仍返回 `completed` 且报告截止 2026-07。**问题是问题语义与工具参数之间没有服务器端绑定**，不是数据缺失检查本身坏了。
2. 题③中带“能说明政策奏效吗？”的问法，用脚本化模型完成真实双向数据查询，再让 `finish.explanation` 写“这证明政策已经奏效。”且 `source_ids=[]`。当前 `TradeResearchAgent` 仍保存 `completed` 和这句无据结论。`finish` 只核报告/来源 ID 与字数，不核经济因果主张；系统提示的禁止语句不足以形成产品硬门。
3. 题④的豆油/大豆硬边界已有单测：`import:1507` 是直接候选，`import:1201` 仅相关，原题问豆油时强行查 1201 会被拒绝。本次未发现该边界的新故障，但也没有真实模型表现证据。

## 止损与下一阶段验收

现有第一题真实成功不受影响；第二题独立入口仍仅离线就绪，未发送。**在这两个边界修好之前，不把五题试验称为质量达标，也不自动推进③—⑤付费调用。**下一阶段要给出最小可验证方案：明确日历词与所选月份不一致时如何拒绝/澄清；政策效果主张何时由程序确定地改成“证据不足”或停止发布，不能靠一串脆弱关键词假装全面识别。先写反例和正常题回归，再实施；不动历史冻结实验或原始数据。
