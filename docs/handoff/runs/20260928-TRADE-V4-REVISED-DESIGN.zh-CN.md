## 为什么改

原候选的四份 `.local/trade-reports/` 记录均无 `explanation_protocol` 和 `relation_snapshot`，读回会按旧 v3 协议处理；不能直接代表当前 v4 页面。原 V4-2 问“钢铁出口”但确认的商品只是废碎料 `7204`；原 V4-4 只改顶层政策问题会和 `scope.question` 冲突。原 V4-3 乘用车的计划问句与旧 v3 T3 逐字一致，已有真实模型回答，不能称新题。这些问题在[预检记录](20260928-TRADE-V4-FREEZE-PREFLIGHT.zh-CN.md)和旧 `evals/trade_model_v3/frozen/` 中可核对。

修订后的四道开发题及门槛见[主方案](../TRADE_MODEL_EVAL_V4_PLAN_20260928.zh-CN.md)。V4-3 在看贸易结果前改为普通用户问“最近美国轮胎进出口分别有什么变化？”，明确确认 `both:4011` 新的充气橡胶轮胎；不将结果外推为所有轮胎。四题都必须从现行确认流程新生成，不能改旧 JSON 冒充。

## 下一执行包的固定验收

1. 在隔离目录按四题原问法、目录版本、商品和方向创建**新 v4 记录**；核对解释协议、关系快照、`not_requested`、数据版本及每层问句一致。独立走一次 HTTP prepare→report 回归，避免把纯函数预检说成已验页面。
2. 固定每题的新报告、快照、真实消息、页面已有事实基线和独立复算参考，校验输入上限、逐文件 SHA-256 与最后写入的 manifest；失败或中断保留错误，不以换题刷通过。
