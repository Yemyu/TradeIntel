# 新公告与贸易图表报告：实施方案

状态：核心实现与 R2 已启用记录的独立浏览器验收已完成。服务端准备/生成、保存恢复、新报告渲染、双语和来源布局均已接通；相关36项 Python、13项 Node 测试通过。没有调用模型/API、没有写 MySQL。实际公告全新导入到启用再到报告的组合流程仍待单独隔离验收；本实现不包含AI自动读新公告或自动监测。

## 1. 用户实际得到什么

用户保存公告、核对字段后，点击“查看相关商品贸易”。页面先确认商品、来源国和月份，再在现有 `/preview/` 显示一份可保存、刷新恢复、打印的报告：

1. 公告说了什么：公布和生效日期、商品范围、附加税率及配套条件。历史公告不是当前完整税则。
2. 这些商品的贸易数据：默认最近12个月柱状图、最近月逐商品金额表，缺失处标清楚。
3. 哪些变化能比较：只有编码范围一致、观测完整的相邻月份才计算变化；不据此推断政策造成变化。
4. 来源放在文末；原文引文、版本摘要等细节可展开，不抢占正文。

第一版只连接已人工确认的中国原产地、完整 HTS8 条目。其他来源国、部分税号和未确认字段明确提示限制，不偷换成现有案例。这是已有数据的报告接线，不是任意公告自动抓取或 AI 自动解读。

## 3. 报告与接口合同

新增 `announcement_statistics_report.py`，报告 kind 固定为 `announcement-statistics-report-v1`。保留旧 A3、`trade_coverage`、旧固定案例和其冻结记录，不向其写入虚假的 exact 覆盖。

新增两个服务端入口：

- `POST /api/announcements/statistics/prepare`：接收 policy_id、doc_version，可选 selected_codes、start_month/end_month。服务器加载已启用且确认摘要匹配的候选；默认最近可查询月向前12个日历月。不得把“最新”说成今天；不能静默删除缺月。上限沿用24个月、100个税号，超限请用户缩小。
- `POST /api/announcements/statistics/report`：接收完整已确认范围和 prepare_digest。服务器重新校验候选/启用状态/数据版本/目录版本，任何变化要求重新确认；客户端不能提供金额、来源状态或政策字段值。

prepare 返回规范化范围、排除的部分税号、候选/数据/目录版本、来源标记和规范化摘要。摘要仅用于一致性校验，不冒充认证。report 按确定日期构建，结束前再次校验上述版本，避免混版；写入成功才返回报告 ID。

报告保存：scope、完整政策字段及引文、source_provenance、按月逐税号 rows、按月目录子项及名称指纹、观察/缺失状态、comparisons、sources。`policy_amount_status=not_determined` 固定保留。商品 HTS8 名称如由子项汇总，标为汇总说明，不冒称官方 HTS8 名称。

复用 `trade_report_store.py` 的 UUID、原子快照及哈希校验，增加明确的新 kind 分支与 `explanation_protocol=none`；不能落入默认 V3/V4。同步报告摘要/读取校验的 kind 白名单。新 kind 的模型生成端点在读取供应商配置或调用之前直接拒绝；不改变旧种类的模型行为。刷新读取已保存快照，不用活动数据重新计算；新数据只能重新确认后生成另一份报告。

## 4. 查询与缺失规则（实现时不得简化）

第一版直接组合现有单月桥，不改其返回合同或旧结果摘要。为报告补一个只读目录核对助手：每月 CSV 只读取一次，按已确认代码收集 matched/observed 的 HTS10 集合；沿用发布清单路径，禁止客户端路径。核对读取前后文件 SHA 与仓库清单；金额仍由正式仓库/桥计算，助手不另造金额算法。

- expected 集合来自 `ClassificationCatalog.month`；matched/observed 集合来自对应月份已发布文件；观察字段严格为0或1，异常拒绝。matched 必须是 expected 子集，否则拒绝并要求核对发布包。
- matched 行数、observed 行数必须与桥结果一致，否则停止出报告。三组集合及来源摘要进入快照，缺目录时保持 unknown，不推算覆盖。
- 每行输出 expected_count、matched_count、observed_count、absent_codes、unobserved_codes。只有 expected 非空且三个集合完全相等才为 complete。
- 0与未知区分；没有任何观测的月金额为 null；有部分观测可显示其和，但文字必须是“已观测金额”，不能称完整进口总额。缺月仍出现在图轴/表格中，不补零。
- 月度柱状图允许展示部分观察值，显著标记不完整和编码变化；不画假装连续可比的趋势线。
- 环比仅在两个连续月份同一年、两边 complete、HTS10集合和规范化英文名称相同才计算。名称只做空白规范化，不做语义近似。基期0时百分比 null，但可给差额并说明基期为0。
- 全范围环比要求每个所选税号均满足；任一失败则不输出总环比。第一版不做跨年增长率，跨年仅逐月展示并注明未核对跨年可比性；不要求用户默认看同比。
- 不输出全来源占比、供应依赖或政策影响金额，因为本次只查中国来源；也不把商品金额变化解释成政策结果。

## 5. 页面与阅读安排

从公告页的已启用记录进入现有 `/preview/`，携带 policy_id/doc_version 仅用于选择；后台仍重新校验。增加新 kind 渲染分支，不替换普通贸易报告。先确认范围，再生成。

正文顺序：公告标题和简短范围说明 → 月度柱状图 → 最近月逐商品金额和覆盖表 → 政策条款 → 文末来源。金额图表由程序生成；不调用模型写凑字数的分析。

R2 的示例读法：“2026年7月，这18个税号中已观测的中国来源美国消费进口金额合计约7,106万美元。两项商品的数据不完整；这些金额不是政策实际征税金额。”不要写“政策带来了7,106万美元影响”。

税率必须同条件、例外和修订一起展示。R2 的初始附加税率0%、2027年后续安排、另有既存税率的原文不得拆开误导；不把旧公告解释成现行综合税率。未知时钟、时区或入境事件保持未知，不擅自补全。已知/冲突字段都保留相应原文入口。

普通打印含图表、商品表、关键条件和来源链接；不把版本哈希、重复原文全文全部自动展开。英文/中文切换需覆盖新按钮、表头、错误说明，原文不伪造翻译。手工粘贴网址仍标“来源未核验”，启用不改变来源可信级别。无需新增网站或运营看板。

页面验收：

- 同时走一条原有普通商品查询，确认没被新公告路径抢占；新报告不出现可用的模型调用按钮。
- 固定截图、结果 JSON、测试命令和真实通过/失败写入 runs。不得称盲测，R2 已被反复开发使用；未见公告 AI 候选抽取另立实验，不混入本包。

停止条件：摘要不符、出现目录外编码、读取期间版本变化、旧基线新增回归，先停止生成和扩大修改，保存最小复现。费用预算为0次模型/API调用、0次数据库写入；无需下载或改原始数据。
