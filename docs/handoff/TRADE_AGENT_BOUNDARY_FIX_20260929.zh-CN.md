# 贸易助手两处硬边界：实施决定

日期：2026-09-29。承接 [离线诊断](runs/20260929-TRADE-AGENT-Q3-Q5-BOUNDARY-DIAGNOSTIC.zh-CN.md)。方案已按 [实施验收](runs/20260929-TRADE-AGENT-BOUNDARY-FIX-OFFLINE.zh-CN.md)落地。这是程序行为修复，不是新模型实验；本文件不放行付费调用，不改已完成的首题账本或旧冻结结果。

## 决定与理由

1. **用户指定的月份由服务器绑定。** 对高置信度的“上月／上个月”表达，以服务器日期计算日历上月。模型可以选择查询工具，但不得将这个月份换成“最新已发布月”。复杂或否定表达（例如“不是上月，查最近”）不冒充已全面解析；检测器应显式排除已识别的否定，其他未识别语句仍按现有澄清流程处理。此次验收重点是固定题“上个月美国大豆进口额是多少？”，不是通用中文时间解析准确率。
2. **数据报告可以自动完成，模型自由解释不能自动作为公开结论。** `finish` 仍只接受本轮报告／来源 ID；其 `explanation` 保留协议兼容，但不写入公开的 `message`。公开摘要由已核验报告的范围、金额和必要限制程序生成，并标为 `message_kind=program_summary_v1`。无论有没有政策来源 ID，都不把同期金额变化宣布为政策效果。后续若要公开模型解释，另走现有逐项审阅流程；本包不声称自动解决所有经济语义判断。
3. **旧会话不改原文件，但读取时不能绕过新边界。** 旧的 `completed` 轮次若没有 `message_kind=program_summary_v1`，公开状态替换其自由解释为“旧版模型文字未经本规则核验，已隐藏；数据报告仍可查看”。HTTP 会话读取和重复请求返回必须走同一个公开投影，不直接返回 `read_session` 的原始轮次。私有账本保留供审计，不回写或删除历史。

## 最小实施位置

| 位置 | 工作 |
| --- | --- |
| `trade_agent_tools.py` | 加窄范围日历月锚。`query_trade` 在创建报告前查该方向的真实月份：目标月缺失，抛带目标月与最新发布月的受控异常；可用时规范化 `period`，明确单月问题要求起止均为目标月。包含比较的复合问题允许先查基期，但 `finish` 至少须引用一份覆盖目标月的报告；不替模型推算同比。正常“最近／最新可用”保持原规则。 |

| `trade_agent_store.py` 与 `web_app.py` | 统一公开投影，保护旧会话及重复请求；GET `/api/trade/agent/state` 不直接原样返回存档。不能更改旧账本内容。 |

## 验收及停止条件

- 固定日期 2026-09-29、已发布数据截止 2026-07。脚本模型对“上个月美国大豆进口额是多少？”故意选 `latest_contiguous`，结果不得 `completed`、不得公开 7 月作为上月；应给出 2026-08 缺失与 2026-07 截止。即使先试正确的 `calendar_relative(-1)`，结果也一致，且不得自动再发付费请求。
- 固定日期 2026-08-29、7 月可用时，同题选择单月 7 月可完成；“最近美国大豆进口有什么变化？”仍可完成截至 7 月的多月报告。比较题不能被“单月”规则误伤；显式否定“不是上月，查最新可用月”不按上月锁定。
- 脚本模型在 `finish.explanation` 写“这证明政策已经奏效”，无来源和有合法政策来源各测一次。数据报告可完成，但新会话、刷新后的 GET、重复请求和网页都不能展示该句；公开摘要含准确的商品／月份／金额以及“仅凭金额不能判断政策效果”。正常首题和“出口呢？”的数据与报告关联仍正确。
- 既有旧会话文件不改；GET 隐藏旧自由解释但可读报告。失败和澄清轮次 `report_ids=[]`，不把错期报告当成本轮答复。相关 Python／Node 测试全绿；不因修复更改旧冻结哈希或旧模型原答。
- 若发现日期检测需要依赖广泛中文意图分类，或程序摘要无法从报告字段可靠生成，停止扩展，记录最小反例重新裁定；不临时降低门槛刷绿。
