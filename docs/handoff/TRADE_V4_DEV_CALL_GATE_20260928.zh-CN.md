## 为什么只试一个配置

四题实际页面已展示核心变化和“金额不能证明政策原因”的边界，见[页面基线](runs/20260928-TRADE-V4-PAGE-BASELINE.zh-CN.md)。模型即使准确复述，也没有新增信息。先用一个可控的配置验证**是否真能让普通读者更容易理解**；不通过就停，不启动跨模型排名。

选择本机已有的 DeepSeek `deepseek-flash` / `thinking=enabled` / `reasoning_effort=high` 作为唯一开发候选。它此前有真实连通记录；2026-09-28 的只读本机状态仍显示 `configured=true`、`connection=connected`，但这个状态来自 **2026-09-26** 的短请求，**不能证明今天仍可调用**。不在准备阶段发送新的“测试连接”请求。DeepSeek [官方型号及价格](https://api-docs.deepseek.com/quick_start/pricing/)目前将请求名 `deepseek-flash` 对应 V4.1-Flash；服务回显别名不等于可核实的权重快照。其[思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)明确支持 `high`。GPT-6 Luna Max / Sol High 的 Codex **对话**结果不是本产品的 API 调用，后续若比较必须分渠道；[OpenAI 官方模型说明](https://developers.openai.com/api/docs/guides/model-selection)也提示不同产品的型号可用性与设置不同。

## 请求与预算（在真实调用前再次核价）

- 固定顺序：V4-1 → V4-2 → V4-3 → V4-4；每题最多一次，不自动重试。每次只读取该题 `cases/<id>/messages.json`；`reference.json`、页面基线、评分表和其他题原答绝不送模。
- API 请求名 `deepseek-flash`，地址 `https://api.deepseek.com/chat/completions`，思考开启、高推理，`max_tokens=8192`，非流式；不加工具、检索或新提示。现有适配器会发送 `temperature=0`，但 DeepSeek 官方说明它在思考模式不生效，不能声称输出可复现。执行器须保存脱敏后的**实际请求参数**，不得把凭证写入评测目录。
- 从 2,048 提高到 8,192 **总生成 token** 是调用前的公开变更：项目曾在高推理下发生 4,096 token 全用于思考、最终正文为空；另一次高推理请求实际生成 5,026 token。这里不扩大 v4 原答 20,000 UTF-8 字节、每条解释 12—160 字、最多 3 条的产品硬门。
- 90 秒总截止；超时、网络断开、服务端返回不明、空正文或非 `stop` 均保留已发生请求和可得到的 `response_id`、回显型号、`finish_reason`、用量，记失败或 `unknown_outcome`，**绝不无记录补发**。
- 四份冻结消息合计 **22,377 UTF-8 字节**，不是 token。按官方公布的峰时未命中缓存价：输入 $0.30 / 百万 token、输出 $1.20 / 百万 token；若为整批预留 40,000 输入 token 与 4 × 8,192 输出 token，估算约 **$0.052**，计划控制上限 **$0.06**。这是有余量的**事前估算**，不是账户扣费硬封顶，也不是实际账单；DeepSeek 说明实际 token 以响应 `usage` 为准，价格可调整。调用当天价格上涨、输入估算超过预留、无法确认参数上限或费用边界时不发请求；每题回报实际用量并复核剩余预算。用户未批准费用和真实调用前，执行器只允许离线预检。

## v4 专用执行器的最小实现

现有 `scripts/run_trade_model_eval.py` 绑定旧 v3 题包、旧解析器和旧账本，不能换目录就运行。网页 `/api/trade/explanation/call` 虽能用 v4，但不校验冻结清单，也没有本评测的顺序门与人工审阅门。下一执行包新建 v4 **单题**入口，复用已有适配器与安全写盘逻辑，不修改旧运行记录。

1. 离线 `--check`：完整验证冻结包逐文件摘要、代码/数据摘要、单题输入、报告与关系快照身份；检查当前本机配置正好是上面的唯一候选，并核对请求字节、固定参数、价格快照、前题账本。`--check` 不创建调用账本、不在日志或返回值中暴露密钥、不发网络请求。执行器自身代码摘要另记在单次账本，不回写冻结包。
2. 真实调用需 `--live` **和** `--authorize-one-call` 两个显式开关，且必须在用户单独同意具体配置、预算与发起真实请求之后使用。先在 `.local/trade-model-eval-v4/` 原子写 `provider_call_started` 与请求/冻结摘要，再发送**至多一次**请求；同题任何既有账本或原答都拒绝再次领取。
3. 收到响应先无论正文是否为空保存安全元数据；有正文则保存原文及 SHA，再检查 `finish_reason=stop`、输出字节/生成 token、`trade_explanation_v4.parse` 合同。合同通过仅记 `needs_review`，**不等于内容正确或可发布**。错误/未知结果不清除、不自动重试。
4. 人工审阅逐题核对方向、商品范围、时间、进口/出口口径和政策因果边界；若有严重错、合同失败或未知结果，停止后续题。前题未记录 `clear` 与阅读增益审阅，下一题不得调用。三题读完若至多只能有一题有增益，就不为凑满四题调用最后一题；早停不得写成“四题成绩”。
5. 假服务反例至少覆盖：同题并发只调用一次、冻结包篡改、配置变更、服务端 400、超时/未知结果、空正文但有元数据、`finish_reason=length`、超字节、JSON/引用拒绝、人工严重错误后下一题拒绝。全部离线通过后才请求真实调用授权。

## 怎样判“有帮助”

看模型原答**之前**，逐题把页面已经能回答的句子和潜在误读点写入审阅表：V4-1 近期转向不是全期上涨；V4-2 连续月度下降不是全年结论；V4-3 两个方向需分开读、两种统计口径不能相减；V4-4 贸易额变化不能识别政策原因。这些都是页面基线，模型重说、换词、加免责声明均记 **0 增益**。

仅当审阅者指出一处具体的新解释，使非专业读者更容易避免上述某个误读，且它严格来自已给关系卡、没有新增无证据事实，才暂记“阅读增益”。审阅需引用原答具体句子、对应页面原文并说明差别；无法说清差别即记 0。这个开发审阅仍有主观性，最好由未参与写提示的人复核；没有独立读者时只称开发判断，不宣称通用准确率。

四题均无严重错误且至少两题确有增益，才考虑下一阶段的多模型横评；否则保留原答、费用与失败记录，停止。无论技术合同通过与否，模型内容都必须保持人工复核状态，不能自动展示为正式报告。

## 放行前尚缺什么

- v4 专用单题预检、一次性账本及假服务回归已实现；人工审阅表在每题原答出现后记录到本地账本，**尚无真实原答，也无阅读增益成绩**。执行入口为 `scripts/run_trade_model_v4_dev.py`，默认只离线预检。
- 本机密钥只读状态已配置；V4-1—V4-3 各按本设计发出一次真实请求，V4-4 未发。不复制或打印历史聊天中的密钥。
- 用户在看到配置与预算后逐题确认继续；三次都执行后停下审阅。前三题增益均为 0，下一题已被真实早停门拦截；不能补发 V4-4 或把技术合同通过冒充价值门通过。
