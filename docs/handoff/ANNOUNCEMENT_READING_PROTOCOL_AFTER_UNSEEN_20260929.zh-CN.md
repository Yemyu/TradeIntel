## 问题与取舍

现行 v2 提示要求逐条列出独立事实，解析器却暗设每字段最多 6 条、每条最多 3 个引用；这份公告的返回超出两项上限，但正文未超 6,000 字节。仅把“6/3”写进提示最省代码，却会鼓励把不同法律条件硬合并，或让更复杂的公告漏项。直接放宽旧常量又会改变已冻结的源码摘要，使旧试验无法原样回放。因此选择**新版本、无固定条数上限、保留总大小门**；不在旧版上修数值、重跑本案或重算正式成绩。

另一个已知边界是 v2 的单一字段状态：`known` 要求 `reason` 为空，`unknown` 要求没有任何 `claims`。如果同一字段一部分有原文依据、一部分没有，不能同时如实表达。新版须加入可核的“部分已知”状态；不能因为某个未说明点，就把已有证据的整个字段写成 `unknown`。

## 下一版本的最小合同

1. 新建独立模块与 `announcement-reading-suggestions-v3` 标识；v2 源码、旧冻结包和执行器只用于历史回放。新包/新执行器须绑定 v3 源码及版本，不得拿 v3 解析旧原答后覆盖正式 `invalid_response`。
2. 仍为 `rate_meaning`、`conditions`、`exceptions` 三字段；每条 `claim` 继续保留具体文字和至少一个原文段落编号。所有编号必须属于这份已保存、`disabled` 的原文；拒绝重复编号、伪造版本/摘要、重复 JSON 键和未允许字段。**不再设“每字段最多几条、每条最多几个引用”的独立数量门**，而由完整回答字节门、单条文字长度与来源编号有效性限制资源。引文存在只证明位置有效，不自动证明解释正确。
3. 字段状态至少区分：`known`（有可核要点、无未决说明）、`unknown`（无可核要点且说明缺什么）、`partial`（有可核要点，同时说明尚不能判断什么）、`conflict`（明确列出相互冲突且各有出处的说法）。提示、解析器、页面显示必须使用同一套枚举及含义；冲突是否成立仍由人核对，不由 JSON 形状决定。不得用 `partial` 偷偷表示“回答太长，只列前几项”：如果不能完整列出可核的关键事实，输出应明确标为 `incomplete` 并在正式完整性门下失败。
4. 暂定完整回答上限 **16,000 UTF-8 字节**、单条文字和说明各最多 500 字符；这是资源/安全门，不是允许裁去公告或事实的目标。新提示应明确“不要省略独立的决定性条件；无法完整列出时标 `incomplete`”，并由测试校验提示与解析器字段/状态一致。超过大小门、`finish_reason` 非正常停止或 `incomplete` 均保存原答、标记未通过、不截断、不自动重试。原文输入预算先维持 28,000 字节；若新提示导致完整来源放不下，记录为本协议不支持，**不得裁原文**。是否扩容输入需另立方案和预算，不为某题临时放宽。
5. 页面只读展示新状态、所有要点、未决说明和原文位置；不自动填13字段、提交或启用公告。长列表默认折叠/展开，避免把同一段全文在每条要点下无界重复渲染。旧 v2 笔记仍可按旧界面读取，或清楚标记为历史格式，不能静默转版。

## 必须先过的离线验收
