## 必须注意的缺口

1. **停用/删除后可能继续召回旧片段。** `chunk_service.update_chunk`修改enabled只更新数据库；向量检索没有enabled过滤或数据库有效性复核。删除向量失败被忽略、数据库仍删除，向量通道可能继续返回孤儿记录。BM25过滤enabled，不代表整个混合检索都过滤了。
2. **检索未按政策/版本/知识库隔离。** `retrieve_chunks`只有query/top_k，BM25扫描所有enabled片段，向量搜索未传对应过滤。候选政策、旧版条款不能直接混进正式报告。
3. **引用编号可能换对象。** 预检索和每次工具结果都从[1]开始；工具覆盖trace.source_chunks，最终来源是最后的列表。模型若同时引用此前检索，编号可能指向错误来源。应使用请求内稳定、追加式证据ID并校验答案引用。
4. **政策例外可能被裁掉。** 工具片段截到400字符，预检索上下文截到500字符。不得照搬到税率、例外、生效条件：必须检索后补齐关联条款，而非只保留开头。
5. **提示词不等于校验。** 当前靠提示词要求“不编造”，未见相当于我们的商品、分母、版本及结论约束验收。检索文字还被拼入system消息；迁移应明确其是不可信资料，不能执行其中指令。找到了来源也不证明答案被来源支持。
6. **正式部署边界不足。** 看到的路由/中间件没有用户鉴权和会话所有权检查；不能直接公网开放上传、删除和聊天接口。Postgres记忆失败降级内存要显示降级状态，不能声称持久可靠。
7. **复现材料不完整。** README列出的backend/tests、CONFIG_REFERENCE.md、rule.md在这份可见交付中未找到；requirements虽然标题写“锁定”，实际主要是>=而非精确锁定。未看到项目级许可证。不能据此认定卖方没有这些材料，请索取对应版本。

附带观察：流式代码累积model节点的所有文本，可能把工具调用前的中间文字与最终回答拼在一起；需分轮验证最终答案。启动注释称轻量预热，但create_all需要连数据库，不能把服务进程能启动和依赖全部可用混为一谈。

## 对原方案的调整（本轮不迁移）

### 三个项目分别留下什么、明确不带什么

| 来源 | 留下 | 不带入最终贸易系统 |
|---|---|---|
| RAG Agent工作台 | 聊天/历史/来源卡片、文档和检索调试页面的交互思路 | 通用知识库提示词、只按chunk回答的链路、课程自己的文档数据库作为事实来源 |
| CloudAgent | Orchestrator路由思路、固定参数工具、工具结果交接 | 云产品/账单/营销/FinOps角色、MCP云客服工具、mock订单表、跨版本语义缓存规则 |
| DeepResearch | 意图→规划→搜索→证据池→分析→补查→报告的状态图和来源轨迹 | Bocha搜索结果直接当政策全文、解析失败fallback成功、删除非法引用后继续出报告 |

TradeIntel自身不丢弃：现有MySQL、贸易数据查询和指标计算、政策与HTS8绑定、版本锁定、证据合同、人工审阅和报告导出。到目前为止没有删除这些生产模块；“扔掉”指不把上表右栏接入最终架构。

1. S1证据/报告修复、S2真实质量验证继续保留，课程不替代这些门槛。停止旧G2方向的规则不变。
2. S3新增“课程界面复用候选”：优先评估Chat/Retrieval/Documents与现有API的适配，不搬整套数据层。现有审阅、导出、版本状态必须保留；不能为了课程界面退化成通用文档聊天。
3. S4不再提前锁定新增Haystack依赖。现有BM25是基准，课程BM25+RRF是候选；先做接口/权限和离线反例，只有确有召回缺口才测试向量路线。三套检索框架不能一起安装试运气。
4. 不引入课程的“通用Agent自由答复”覆盖事实报告链。目标仍是：读政策 → 精确匹配商品 → 调用受控统计工具 → 计算指标 → 带证据解释。文档搜索只是其中一环。
5. 三个项目只取适合的模块。按“本地参考并改成TradeIntel自己的实现”推进；不把云客服、返佣、运维和通用演示业务带入贸易研究链。
