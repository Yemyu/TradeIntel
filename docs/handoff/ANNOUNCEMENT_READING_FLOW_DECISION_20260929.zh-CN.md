# 新公告阅读辅助：下一版流程与停止门

日期：2026-09-29。状态：本文件记录**当时的方案决策**；第一、二离线包后来已实施，最新执行位置以[试验前放行门](ANNOUNCEMENT_READING_V3_PRETRIAL_GATE_20260929.zh-CN.md)为准，仍没有新公告真实调用或新成绩。本文件接续[FR2026-19516 的事后诊断](runs/20260929-UNSEEN-READING-POSTHOC-SEMANTIC-DIAGNOSTIC.zh-CN.md)。旧案正式 `invalid_response`、原答与冻结源码一律保留；不能用新版重算旧案“未见通过”。

## 结论：先选一次完整原文，不立即增加模型调用数

下一版先采用 **A：一份公告完整原文、一次模型调用、带明确检查点的只读阅读笔记**。这不是认为旧 A 已经合格；旧版提示/合同失败，且事后看到国家税种范围混说、四个追溯起点缺失。新 A 要同时修格式协议和任务覆盖，并以新的官方公告验证。若新 A 仍有严重错漏，停止这条阅读辅助的收费扩试，不自动改用更多调用或更贵模型刷结果。

| 路线 | 能改善什么 | 当前不选的理由 |
| --- | --- | --- |
| A 一次读完整公告 | 保留全部上下文；延续每案一次的账本和较低调用成本；可把关键检查点显式化 | **先试**，但检查点只防“完全没填”，不能自动证明填对；仍须人工逐句审阅 |
| B 每字段独立读完整公告三次 | 减少模型在三个大字段之间分配注意力 | 原文输入约三次，`conditions` 里仍有多个国家组/日期；跨字段矛盾还需新处理，不能保证优于 A；改变每案一次规则 |
| C 将完整公告拆段、多次抽取后合并 | 每段都有一次局部处理机会 | 脚注的税种来源、日期和修订前后条款相距较远；合并不能靠拼接或简单去重判法律含义，调用和审阅负担更高；也改变一次规则 |

未来若确需比较 A/B/C，须另立**事前配对试验**，相同未见材料、独立会话、相同模型/推理、调用顺序和整案费用先锁定，并显式修订“每案一次”授权；否则不能据不同公告上的零散结果宣布某路线更好。本轮不做横评，不选更容易的公告。OpenAI 官方的[评测实践](https://developers.openai.com/api/docs/guides/evaluation-best-practices)强调任务相关指标、日志和人工判断；这里据此把格式、事实与人工省事分开。

## v3 的具体输出合同

1. **独立版本与输入**：新建 `announcement-reading-suggestions-v3` 模块/离线包，继续只接一份完整、已保存且 `disabled` 的官方公告；原文连同编号字节级可复原，不选段、不裁剪。v2 源码、冻结包、账本和页面历史记录不改。新提示不能包含 FR2026-19516 的答案、13项参考或特定日期/国家；只能描述适用于不同公告的检查维度。
2. **一次回答、三组笔记**：继续组织为 `rate_meaning`、`conditions`、`exceptions`，但不再给整组贴一个 `known/unknown` 标签。每组有零到多条 `{claim_id,text,anchors}` 和一组固定 `checks`；每条要点应是可独立核对的事实，引用一到多个真实段落编号。未在这组找到的内容可以在别组出现，但任何要点都必须关联至少一个检查点，避免遗漏到没人审核的“附加说明”。
3. **十个通用检查点**：税费性质组核“政策动作/税种或措施性质/核定与退还等效果”；条件组核“措施对应的来源范围/商品范围/公告适用日/各措施或来源组的追溯起点/入境或出仓事件”；例外组核“排除所需全部条件/编码与书面描述的关系”。这些是**阅读提醒，不是假设每份公告都有同样的税种或退款**。每个检查点都必须给 `addressed`（关联具体要点）、`partial`（部分有证据且说明未决点）、`not_stated`（公告未说明并解释）、`not_applicable`（本公告不涉及并解释）、`conflict`（至少两条相反且分别有出处的要点）或 `incomplete`（本次回答无法完整处理）。解释缺失或把 `incomplete` 当成功都拒绝。
4. **不隐藏资源门**：不设每字段最多6条或每条最多3段这类会诱使合并/漏项的限制；保留单条文字长度、引用唯一/存在、完整输出大小、版本/原文 SHA、重复 JSON 键及正确枚举的严格校验。v3 暂以 **32,000 UTF-8 字节消息上限、34,000 字节实际 POST 体上限、16,000 字节回答上限**作为离线开发门；冻结前需按真实序列化重新测。旧案仅作容量样例：原完整消息 27,615 字节，现有28,000门只余385；一段紧凑的通用检查提示替换后只读估计约27,715字节，**这不是最终v3请求、更不是新案容量已通过**。新公告超门即标产品不支持，不删脚注/附录来过门。输出截断、大小超门或 `incomplete` 保留原答并停，不自动重试。
5. **检查点不等于内容验证**：程序可保证十个槽都出现、要点和编号形状有效、每个 `addressed` 指向要点，却不能保证 `not_stated` 为真、国家税种范围正确、四个日期没漏、编号真正支持解释。**人仍按答前参考审全部主张**；页面只读显示检查点和出处，不自动填政策字段、启用公告或计算现行税率。新增页面适配须显式识别v3，旧v2仍按历史格式读；不得静默转版。

## 离线实现次序与验收

**第一包：核心合同，不碰服务商。**新增 v3 提示/解析器/完整原文包及合成 fixture。固定十个检查点在提示和解析器中只定义一次，避免再次出现“解析器有限制但提示不说”。做错版本/摘要/编号、重复字段或编号、重复JSON键、无要点却 `addressed`、有明确事实但模型自称整组 `unknown`、`partial` 与 `incomplete`、输出字节边界等反例。合成公告把两种措施不同的国家组、四个相距远的追溯日期、入境或出仓条件、旧文和修订文混在脚注及不同段落，至少13个原子事实、54段编号；再替换国家/日期/段号做变形样例，不能硬编码 FR 的值。**造好的正确答案应可完整解析；造好的错答案必须在结构门或人工审阅表上显式失败，不能宣称解析器会自动识别法律错漏。**

**第二包：只读页面与假服务。**将 v3 检查点、要点及引文在公告人工表单旁只读展示；只用本地 fixture/假服务验证提示→包→原答→审阅预览，旧v2页面和冻结校验不回归；同案只发一次、异常/未知结果不重试。遇历史旧v2源码摘要锁住，新增独立 v3 入口，不在原文件上改常量刷绿。

**第三包：是否值得新的真实试验。**离线门全过后，先沿[原未见方案](ANNOUNCEMENT_READING_UNSEEN_PILOT_20260928.zh-CN.md)按固定官方筛选顺序另锁一份真正未见且完整可输入的公告，并在模型回答前冻结事实参考、全主张评分、型号/参数、真实POST、当天价格与整案预算、一次性账本。需另行明确一次收费授权；未知结果不重试。事前门为：技术合同通过、参考关键事实及子条件全对、无范围扩张/无据肯定说法、所有引文真正支持要点；任一失败即该新案例不通过并停，不事后调提示重报“未见通过”。单案通过也只说明该案例初步合格。

**人工省事另测。**不能把更完整的模型答案当作读者省时。没有两位读者×两份均未见公告的交叉操作和计时/补查/改写/错误记录，就继续写 `not_measured`；这项不阻挡离线开发，但阻挡“AI帮人省时”的产品宣传。
