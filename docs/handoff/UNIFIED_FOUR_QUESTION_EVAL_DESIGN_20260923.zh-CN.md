# 统一四题评测：评分口径与最小接线设计

日期：2026-09-23。状态：设计已实施，统一四题离线验收通过；**尚未进行统一四题真实模型测试**。本设计与实施记录不覆盖历史冻结、原答和成绩。实施验收见[本轮记录](runs/20260923-UNIFIED-FOUR-QUESTION-IMPLEMENTATION.zh-CN.md)。

## 先分清四件事

1. **工程与守卫是否可靠**：检查范围确认、数据计算、来源绑定、超时/坏答案拒绝、审阅和导出。用离线测试和真实流程记录说明。正确拦截错误答案是守卫有效，不能记为模型答对。
2. **某个模型配置的回答质量 `Q/R`**：在同一题包、同一规则和同一渠道下，`R` 是收到并保存原答的题数，`Q` 是原答在结构、预算、事实、回应问题和解释用处上均通过审阅的题数。无效 JSON、空答、截断、超预算已有原答时留在 `R`，整题不通过；接口无响应且未保存原答不算内容错误，另列接口故障。语义未审完不公布最终百分比。
3. **选定配置的整链交付 `D/N`**：`N` 是事先锁定的用户场景数，当前为四；`D` 要求自然问题→确认范围→可复算事实→真实模型原答→生产解析→人工审阅→可导出报告整条链实际完成。`Q/R` 不是 `D/N`；未运行、接口失败或审阅未完成均不能冒充已交付，并分别说明原因。只有整版验收闭合后才写最终整链比例。
4. **作品集中的“AI 效果证据”主观评分**：此前的 4/10 指目前拿得出的可靠证据仍少，**不是 Luna、DeepSeek 或项目运行时恒定的正确率**。换模型可以改变第 2、3 项的实测结果；不做同版实测，不能自动提高证据分。工程守卫和可复算的经济事实也不会因为换模型自动变化。

因此展示时不设一个脱离配置的“TradeShock AI 准确率”。每行记录确切模型/API 名称、推理参数、渠道、题包及评分版本、收到原答数、整题通过数、接口故障、未运行题、成本/耗时与主要错误。聊天中已有项目历史的作答只作开发参考，不与真实 API 成绩混算。四题全过只称“该配置在本版本四个已开发场景通过”，不称普遍 100% 正确。[OpenAI 官方评测建议](https://developers.openai.com/api/docs/guides/evaluation-best-practices)也强调任务专属测试、自动检查与人工判断结合，以及生成输出的可变性。

## 新统一四题的固定规则

- 保留 `evals/public_brief_v1/scenarios.json` 的四个自然问题与同一已发布数据、政策证据；Q1/Q2/Q4 使用 `trade` 模式及 `public-brief-explanation-v1`，Q3 使用 `policy` 模式及 `public-policy-explanation-prototype-v2`。四题对所有候选模型采用相同的逐题输入；Q2 的程序追问上下文保持固定，不引入其他模型的 Q1 回答。
- Q3 的内容门槛继承独立开发诊断中政策变化、适用范围、条件/例外、局限和逐项政策来源的要求，同时继续检查贸易解释的观察引用，不作因果或价格定论。**新建统一四题评分附件**明确其正式适用范围；旧 `SCORING_POLICY_Q3.zh-CN.md` 写明仅供单题开发诊断，不直接改名当正式成绩。旧 `SCORING_V3.zh-CN.md` 的正文定义只列贸易解释，应由新附件明确覆盖：政策解释、贸易解释及观察理由合计 2000 Unicode 字符。
- 现有四项整题判断不变：原答结构/引用合法，事实正确，回应必要问题，有具体且受支持的解释增益。与纯程序报告比较时，重复数值而没有增加理解不算“AI 有用”。评审标明是否 AI 辅助、是否盲审；不修改原答补分。
- 一配置 Q1→Q4 每题至多一次；重大内容错误、预算/结构失败或结果未知按冻结停止条件处理，不自动重试。停止后的题写 `not_run`，不算模型答错，也不从计划数中消失。API、聊天模拟、离线替身分别汇报。
