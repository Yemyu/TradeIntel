# TradeShock AI：发布前的产品决定（2026-09-25）

这份决定只针对当前代码和已做过的验收，不把早期计划当成已实现功能。它是下一阶段的执行依据；旧案例、冻结评测和原始数据不改。

## 现在到底是什么产品

第一版是一个**本地运行的美国商品贸易研究助手**：用户用普通话提问，系统提出官方商品范围、进口/出口方向及可查月份；用户确认后，程序从已发布数据计算月度金额、图表、来源和限制；用户可以另外请求模型解释，逐项核对后才采纳。已登记的政策案例有独立入口，但“自动发现并可靠分析任意新政策”尚未实现。

它不是实时全网贸易资讯、投资建议，也不是能够判断政策因果效果的系统。所谓“最近”指本项目**已发布数据的末月**，不是网站当天的最新数字。目前进口有 48 个不连续的已加工月（2016-01 至 2018-05、2025-01 至 2026-07），出口有连续 12 月（2025-08 至 2026-07）；通用查询只开放美国、全部来源/目的地或中国，以及单次最多 24 月的已核验范围。商品名匹配需用户确认，不能承诺所有中文说法都能识别。

## 核查结果与决定

| 环节 | 证据和现状 | 本版决定 |
| --- | --- | --- |
| 数据与数据库 | 进口 48 月、出口 12 月的文件和 MySQL 镜像已经全量逐月读回对账；报告代码 `TradeDataRepository`、`ExportDataRepository` 仍读文件。 | **文件是报告的发布依据，MySQL 是同版、可用 SQL 查询的副本。**不为“用了数据库”而临时切换网页读数。新文件版本发布后需重做镜像验收。 |
| 用户查询 | `/api/trade/prepare` → 用户选商品/确认范围 → `/api/trade/report`；有真实小麦、乘用车和其他商品的浏览器验收。 | 保留先确认后执行、进口与出口分别注明口径。对超出范围的问题明确说明无法回答，不猜商品或补数据。 |
| 页面与报告 | `/preview/` 已把项目介绍、工作台和报告阅读合在一套页面；两份真实报告的 A4 PDF 已逐页核对。 | **不再新建第二套前端**。当前任务不是视觉重做，而是证明别人能复现这套页面和数据报告。 |
| 模型解释 | API 请求、保存原答、结构校验和人工审阅链已实际接通；[现有回答复核](runs/20260925-TRADE-AI-VALUE-REVIEW.zh-CN.md)发现 v3 六份原答没有显示额外帮助，v4 小麦开发回答主要复述页面关系卡。 | 保留可选、待审阅的实验性入口；暂不能宣传稳定 AI 分析、准确率或预测能力。v3 的独立盲审和新任务的增益验收仍是 AI 内容门槛。 |
| 新政策 | 已登记案例、候选导入和受控流程与通用商品查询分开。 | 第一版不宣称“输入任意新政策，自动更新并出可靠简报”。这是后续独立里程碑，不能用现有商品报告冒充。 |
| 交付 | 本机隔离副本已用 124 个文件复现三类贸易报告；普通 Git 克隆仍不带数据。网站默认监听 `127.0.0.1`，没有公网身份验证。 | 保留本地数据补充包和明确的复现命令；新电脑/全新环境及公网服务是不同发布门槛，本轮不部署公网。 |

### 为什么 MySQL 暂不接管网页

SQL 副本已经有实际用途：同版装载、查询和逐行对账展示数据工程能力，不是空摆设。当前文件查询有版本与文件摘要校验，且用户浏览器链路已验收。现在改用 SQL 会增加 MySQL 在线、凭证、跨环境初始化、查询等价性和新故障处理工作；尚无代表性查询证明性能或用户体验收益。将来若文件扫描成为实测瓶颈，再用相同商品/月份/方向比较文件与 SQL 的**结果、耗时和版本绑定**，通过后才切换；不是因为 SQL 已经导入就必须切换。

## 本地演示数据包：已完成本机隔离复现

通用报告需要 **124 个已发布数据文件**（48 月进口、12 月出口、60 月商品目录与清单/中文索引），共 578,630,811 字节。商品目录对应这些月份内已发布的全部商品，不是只支持小麦；小麦只是本次端到端验收样例。生成与只读核验脚本为 `scripts/trade_demo_data_bundle.py`；样包在 `tmp/handoff-runs/trade-demo-data-20260925/`，含逐文件字节数、SHA-256 和数据版本。数据包不含源码、原始 Census ZIP、API 凭证、MySQL 文件或历史运行记录；目标目录已存在时拒绝覆盖。

验证记录见[本地演示包验收](runs/20260925-TRADE-DEMO-BUNDLE.zh-CN.md)。已把 `src/`、`web/` 和数据包复制到隔离项目根目录，用复制后的源码和数据完成普通进口、普通出口、双向报告三条路径，并在新开的本地网页中完成“小麦进口”提问、商品确认、月份确认、报告生成及刷新恢复；12 个月金额和来源可查。没有读取原始 ZIP、模型密钥或 MySQL；模型/API调用与外部网络请求均为 0。页面在报告中明确说明本次未调用模型。

这证明：**在本机已有 `.venv` 的条件下，复制后的代码和数据可复现三种数据报告，不依赖 MySQL 或 API 密钥。**它还不证明可在新电脑/新虚拟环境或其他操作系统直接安装运行；本轮也没有在隔离副本重新导出 PDF。旧政策入口不在该数据包范围内，不能据此宣称它也可移交。外部分发位置、公网部署及公开服务仍未决定。本轮只新增脚本和本地 `tmp/` 数据包，未提交、推送或公开。

在仓库根目录从完整已发布数据生成新包（不得选取已存在的输出路径）：

```bash
PYTHONPATH=src:. .venv/bin/python scripts/trade_demo_data_bundle.py create --output tmp/handoff-runs/trade-demo-data
```

复制数据包的 `data/` 与 `BUNDLE_MANIFEST.json` 到项目根目录后，按清单核验：

```bash
PYTHONPATH=src:. .venv/bin/python scripts/trade_demo_data_bundle.py verify --root .
```

只有返回 `status: verified` 才表示这 124 个数据文件与清单和版本一致；它不代表安装依赖或整个应用已完成发布。

## 后续发布门槛（不和下一包混做）

- **AI 内容**：先完成已有 v3 原答的独立盲审；若 v4 要宣称比程序报告更有用，另冻结未参与开发的题、人工评分规则和停止条件，再做有限真实模型验收。结构正确、短连接成功、模型更贵，都不能直接替代内容证据。
- **政策自动更新**：明确官方来源、范围映射、版本发布和人工确认；用未参与开发的新公告做端到端验收后才对外承诺。
- **公网产品**：在用户明确决定公开交互服务后，另做登录/权限、HTTPS、密钥隔离、存储和部署复现。当前 localhost 服务不能直接开放到互联网。

因此目前可以如实展示“已有真实数据、可审阅模型草稿的本地原型”，还不能称“可接任意新政策、自动更新、AI 稳定可用的完整公网产品”。
