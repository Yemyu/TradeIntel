# 现行 v4 商品报告：模型评测方案

日期：2026-09-28

状态：**四题离线输入已冻结；尚未调用模型，也没有模型成绩。**详见[预检记录](runs/20260928-TRADE-V4-FREEZE-PREFLIGHT.zh-CN.md)、[冻结结果](runs/20260928-TRADE-V4-OFFLINE-FREEZE.zh-CN.md)及[单配置开发调用放行设计](TRADE_V4_DEV_CALL_GATE_20260928.zh-CN.md)。本方案只测现行 `trade-data-explanation-v4` 的可选解读，不把旧 v3、追问 F1—F4 或公告阅读支线混进来。

这是一套**新的开发价值验证**，不是重启 9 月 24 日的 v3/v4 五题配对正式实验。旧方案要求四题可调用、一题应跳过，并在同一配置下比较 v3/v4；小麦 v4 开发回答没有证明增益后已经停止。现行页面已直接展示关系卡原文，因此先问“模型相对现有页面是否值得调用”，再决定是否做多模型横评。旧门槛、旧题包和旧原答均不移作这套新实验的成绩。

## 先回答“测模型有什么用”

程序已经负责选商品、取数、算差额、识别连续变化和画图。v4 模型不能替代这些工作，也不能证明政策因果。它唯一可能带来的价值，是把程序已经确认的关系用普通读者更容易理解的话说出来。

因此本轮不是测“模型会不会算”，而是测：**模型说明是否比页面上已有的事实卡更容易读懂，而且没有增加错误。**如果四个场景都只是把事实卡换一种说法，就不值得支付 API 费用，模型入口应继续保持可选或关闭。

## 评测对象与固定边界

每题必须从**现行商品确认流程重新生成**完整报告，再以 `trade-data-explanation-v4` 创建新记录和关系快照。旧 `.local/trade-reports/` 的四份报告只供发现候选，不作冻结输入：它们没有 v4 协议标记或关系快照，读回时会按旧 v3 处理。程序先生成图表、事实卡和 `eligible_card_ids`，模型只接收这些内容及用户原问题。模型输出必须是当前 v4 合同：严格 JSON、每条解释引用一至两张关系卡、不能新增数字/日期/网址、不能猜原因或给投资建议。

页面已有的确定性事实是对照组。模型回答不参与金额计算，也不改变报告、数据版本或商品范围。所有答案必须进入人工复核状态，不能自动发布。

## 四个开发场景（离线输入已冻结，未调用模型）

这四题用于**开发价值门**，不是未见材料盲测；选择商品和关系类型已经参与设计。每题的原问题逐字保持一致，商品由用户确认步骤明确缩小，评分只对确认后的统计对象成立。旧本地报告不覆盖、不重命名，也不拿旧摘要当新报告身份。

| 编号 | 普通用户问题 | 确认的商品和方向 | 预期关系卡 | 要观察的能力 |
| --- | --- | --- | --- | --- |
| V4-1 | “美国未梳的棉花进口最近有什么变化？” | `import:5201`，未梳的棉花；不代表全部棉花 | `import.recent_turn` | 把近期转向说清楚，不写成全期趋势 |
| V4-2 | “美国钢铁废碎料出口最近有什么变化？” | `export:7204`，钢铁废碎料及供再熔的碎料钢铁锭；不代表全部钢铁 | `export.recent_run` | 解释连续月度变化，并保留“不是整个区间结论” |
| V4-3 | “最近美国轮胎进出口分别有什么变化？” | `both:4011`，新的充气橡胶轮胎；不代表翻新/旧轮胎 | `import.recent_run`、`export.recent_turn`、`both.latest_relation` | 同时说清两个方向，不把两种口径相减成贸易差额 |
| V4-4 | “美国咖啡进口最近的变化是政策造成的吗？” | `import:0901`，咖啡商品组；不含另列的咖啡提取物 | `import.recent_turn` | 先回答已观察变化，再明确金额不足以判断政策原因 |

V4-3 不再使用乘用车：原计划问句与旧 v3 正式 T3 **逐字相同**，商品、月份和数据版本也重合，旧 T3 已有真实模型回答，不能称新题。现改为预先登记的轮胎 `both:4011`；冻结时重核的三张可解释卡与预检一致。V4-1、V4-2、V4-4 同样重新生成报告，没有在旧记录上只改问题字符串。

离线固定步骤是：以表中原问题调用 `prepare_trade_question` → 用目录版本确认指定商品 → 得到 `ready` 与数据版本 → 用**同一原问题、商品、方向和数据版本**调用 `generate_trade_report` → 以 v4 协议创建新记录。逐一检查顶层 `question`、`scope.question`、双向子报告的 `question`/`scope.question` 完全一致，记录 `product_code`、官方范围、2025-08—2026-07 窗口、数据/目录版本和来源；检查新记录的 `explanation_protocol=v4`、`status=not_requested`、报告摘要/关系快照摘要、非空 `eligible_card_ids`。纯函数离线生成可用于准备材料，但还需独立核对 HTTP 入口；不把旧 v3 页面状态称为 v4 对照。

## 两道门：先证明有价值，再横评模型

### 门 A：离线冻结

先生成独立目录，保存四份**新 v4 记录**、商品确认回执、报告、关系快照、真实请求消息、页面已有关系卡/数据说明的程序基线、独立复算的评分参考和逐文件 SHA-256。报告、快照、消息须用当前同一代码/数据版本重算后逐字一致；任何确认范围或问题不一致、关系卡为空、预算超限、文件篡改、中断包均不冻结。冻结文件不放 API key、历史原答或其他题的参考答案。正式请求只能读取该题自己的 `messages.json`。

### 门 B：一次开发调用

只选一个用户已有、成本可控的 API 配置，按 V4-1→V4-4 顺序最多调用四次；**离线冻结完成并得到用户对配置、预算和真实调用的单独确认之后**才调用。调用前记录准确型号、渠道、推理设置、输入/输出上限和费用上限。任何严重事实错误、未知结果或合同失败立即停止剩余题，不自动重试。

开发调用的放行标准：四题没有严重错误，并且至少两题相对于“只看页面原有数据、图表和事实卡”有明确阅读增益。审阅者先记录不看模型时能得到的结论，再看模型增补是否使商品范围、变化顺序、双方向口径或政策归因边界更容易理解；**只换词复述原有事实、增加套话或重复免责声明记 0**。评分参考不得进入模型请求。门 B 不通过便停止多模型横评，不以更强模型推测代替实证。

## 评分表

每条原答分开记录，不把解析器拦截当作模型正确：

1. **接口结果**：complete / rejected / unknown_outcome / not_run。
2. **合同**：JSON 字段、引用关系卡、长度和摘要绑定是否通过。
3. **事实忠实**：是否只使用报告和关系卡，方向、时间、统计口径有没有写错。
4. **回答问题**：是否真正回答“变化是什么”或“能否归因”，而不是只说“请注意数据”。
5. **阅读增益**：相对事实卡，是否让普通读者更快明白变化、限制或下一步该看什么。纯复述记 0。
6. **表达质量**：中文自然、简洁，不使用模板化的空话。

严重错误包括：商品/方向错、编造数字或日期、把局部变化说成全期趋势、把金额当数量/价格、把相关说成因果、给确定性投资建议。出现严重错误，该配置立即停止。

若门 B 通过，其他配置仍逐题记录；仅在四题全部完成、无严重错误且至少三题有明确阅读增益时标为“**本开发集的候选配置**”。不能称新盲题通过、普遍准确率或已证明上线质量。若要发布独立质量声明，须另预登记未用于选题/修提示的新材料；此处不自动扩大实验。

## 预算、重试和留档

- 沿用 v4 当前限制：输入不超过 60,000 字节，原答不超过 20,000 字节，单条解释 12—160 字，最多 3 条。
- `max_tokens` 原暂定 2,048；经 2026-09-28 调用前审查，开发候选改为 **8,192 总生成 token**，以容纳高推理（历史上 4,096 曾全被思考消耗，另一次实际生成 5,026）。不放宽最终正文和产品合同；总时长仍为 90 秒，正式运行前须在 v4 专用执行器中验证总截止。更改发生在首次 v4 调用之前，记录在[放行设计](TRADE_V4_DEV_CALL_GATE_20260928.zh-CN.md)，不得回写旧实验成绩。
- 每题至多一次；未知结果不重试，保存 response ID、finish reason 和可得到的 usage，未知写 `null`。
- 不用正式题答案调提示；提示或合同改变必须建立新版本。
- 评测目录单独保存原答和审阅记录；不改旧 v3/F1—F4 冻结目录，不写 MySQL，不提交或推送。
