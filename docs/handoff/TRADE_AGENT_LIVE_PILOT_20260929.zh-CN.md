## 首条实测前的硬门

1. 先修并测商品候选的反例：搜“玉米”当前还会把英文描述含 `CEREALS (EXC CORN)` 的 `1904` 标成 `exact_product`。否定描述**不是正向同义词**：`1005` 应是直接候选，`1904` 不可当准确商品自动查询；其他仅有词面关联的候选可排后展示并标“相关/待确认”。豆油 `1507` 前、原料大豆 `1201` 后且后者不可代查的既有行为保留。加入回归测试，不以删光模糊候选换绿。
2. 用假服务检查实际 `messages + tools + thinking` 请求体，确认 schema、参数、消息轮次能按现行适配器发送；核报告和会话存档对重复请求、未知结果不会自动重发。不得为了首题通过临时改题目、参考或评分门。
3. 试验入口保存非敏感配置身份与代码/数据哈希、唯一请求编号、实际工具名和关键参数、响应状态与 usage；**不得保存/打印 API Key 或 Authorization 头**。当前会话只存工具名/状态，尚不足以审阅错选商品；补最小审计记录并保证个人本机文件不入 Git。
4. 先给首题设限：最多 **4 次**模型回复、**8 次**工具调用、每次 `max_tokens=4096`、每次超时最多 90 秒；理论输出上限 16,384 token，不是账单金额上限。只发 **一个用户问题的一次尝试**，无自动重试；任何未知结果先查本机状态与服务商账单。正式金额预算须在发送当天据官方价格和当前账户再核，并由用户确认一次收费尝试。其余四轮暂不放行。

## 如何判定及停止

首题先看真实 provider 是否返回合法 `tool_calls`，工具能否完成、报告是否存档和刷新恢复；再看商品、方向、月份、数据口径、具体金额、模型文字是否切题且每句有据。前四项是**程序功能**，后两项是**模型表现**，分开记录。只用格式正确不能算过关；金额以程序报告为准，模型文字的无据额外结论仍算问题。

首题若出现 HTTP 4xx、工具 schema 不兼容、无工具作答、错商品/错方向、编造金额、无据因果、超限或 `unknown_outcome`，立即停止后续题，保留原请求/响应状态做诊断，不能换参数重发同题然后把新结果算原成绩。首题通过后，再按相同已锁配置逐一放行②—⑤；任一严重错误即停，非严重表述问题单列而不事后改标准。

最终逐题公开“工具链成功/范围正确/数字正确/无严重无据说法/解释是否提供额外帮助”，列失败类型和实际调用次数/usage。若五题都跑完，只有 **5/5 范围正确、0 严重错误、四道应有报告的题均完成、缺8月题诚实说明不足**，才称这组开发题通过；仍不能外推任意政策和商品，也不能给所有模型标“准确率”。
