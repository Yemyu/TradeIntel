# TradeIntel 当前能交付什么

日期：2026-09-28。本文只归纳已存验收记录；不把开发样例当成通用模型准确率或独立法律意见。

## 一句话

这是一个在个人电脑本地运行的美国贸易数据与政策公告研究工具。用户提供公告原文，逐项确认政策字段和它与统计商品的关系；程序再按已核验的本地月度数据生成贸易事实，或在范围无法对应时只整理公告原文。它不会自动寻找新政策、判定今天的税率、计算政策造成的影响，也没有公开在线服务。

## 四种报告路线

| 路线 | 用户能看到什么 | 现有验收证据 | 主要边界 |
| --- | --- | --- | --- |
| 编码相符 | 按公告列出的完整 HTS8 商品展示选定月份的中国大陆来源进口额 | 旧 R2 人工案例：18 个税号、12 个月；2026-07 合计观测额 71,062,824 美元；HTTP、页面和重启读回通过 | 编码相符不代表每笔进口实际符合排除条件；金额不是关税额、政策效果或因果结论 |
| 上层商品背景 | 若公告只列部分细码，可看其较宽父级商品组的进口背景 | `84139190` 的 2026-07 样例覆盖目录中 16 个十位子码，金额 57,474,068 美元；定向查询、报告及页面回归通过 | 父级商品组包含公告未覆盖的商品，不能称为公告商品金额或政策覆盖额 |
| 中国大陆贸易背景 | 对广泛的中国货品公告，查看数据包中的中国大陆来源进口总量 | `2025-02` 与 `2026-07` 两个月分别从官方原始 ZIP 复算，并与已发布 CSV、分类目录核对；数值为 34,097,678,346 与 25,291,684,967 美元 | 目前只核两个月；不含香港，也不代表该政策实际覆盖金额。全新公告的完整页面端到端验收尚未完成 |
| 只整理公告原文 | 保留 13 个字段、未知原因和原文引文，不生成贸易金额或图表 | USTR 2025-16733 的空白隔离全链、重启、中英文页面、刷新和 A4 打印通过；EO14259 首次页面问题及修复回归另有记录 | 需要人提供并确认原文。参考由 Astra 审阅，不是独立法律金标；不说明现行适用状态 |

已见的旧 R2、2026-17925、2025-02293、2025-07325 和 2026-19498 还做过四路开发分流检查；它们是开发样例，不是随机留出或准确率。两份新公告都与对华关税有关，但法律工具不同：一份涉及对等关税和邮政低值包裹，一份延长 Section 301 产品排除。样本仍只有两份，不能据此推断任意公告都能自动分析。

## 使用时实际要做什么

1. 在本地打开页面。新公告需要用户粘贴官方全文和网址；系统先存成未启用候选。
2. 对照原文确认 13 个字段。每个已知字段要有原文引句；暂时无法核实的字段保持未知并写原因。
3. 人工选择四种路线之一。尤其要分清公告限定的法律商品范围与月度统计实际覆盖的商品范围。
4. 对可统计路线，选择已经发布的本地月份并生成报告；对无法统计的公告，生成不带贸易金额的原文事实卡。

这一流程使用项目本地的数据文件和数据包，不依赖 MySQL 云服务。它目前是单用户本地原型；仅把代码放到 GitHub 不会自动获得可访问网页、模型 API 或远程数据服务。

## AI 到底做了多少

上述四种关联报告由程序按规则整理数据，公告字段与关联路线由人确认；两份新公告回放均为 0 次模型 API 调用。因此这些验收证明的是文件、字段、分流、金额核对、页面和恢复流程，不是 AI 自动读懂公告的能力。

另有一项独立的 R2 三字段阅读开发诊断：[DeepSeek `deepseek-flash`/high](runs/20260928-R2-READING-SEMANTIC-VERDICT.zh-CN.md)和[GPT-6 Luna Max 聊天窗口](runs/20260928-R2-LUNA-CHAT-DIAGNOSTIC.zh-CN.md)各有一份回答，七项预定事实均覆盖 7/7；DeepSeek 多出一条无据的附件缺失断言，按事前门槛未通过，Luna 本次未发现无据额外说法。它们使用同一已见公告，但模型、调用渠道和会话上下文没有隔离，**不是公平横评，也不能把差异归因于模型强弱**。这两次诊断不属于上面的新公告产品回放，也没有测量人工省时。AI 自动阅读能否帮人少查、少改，以及对未见公告是否有效，仍未验证；因此不能承诺自动发现或每日更新政策。

## 当前判断

政策—贸易关联的四条路线已接入本地页面；严格商品路线、上层背景和原文事实卡有实际流程证据，国家背景有两个月的原始数据复算证据，但还没有一份陌生公告走完国家背景页面全链。适合称为**本地可演示原型**，不适合称为已上线的自动政策分析服务或已验证的通用 AI Agent。R2 的一次 API 回答和一次对话窗口诊断只提供已见开发样例证据，不改变这个判断。

接下来不再无限增加公告样本。只有碰到具体失败或重要覆盖缺口才开新验收；否则先以此文档作为本地产品当前范围说明。
