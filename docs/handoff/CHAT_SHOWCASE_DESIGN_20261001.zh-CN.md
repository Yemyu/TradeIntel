# 聊天工作台与案例展示改版方案

日期：2026-10-01。设计阶段原稿由GPT-6 Sol Max制定；后续GPT-6 Luna Max已实施U1/U2，当前结果见[U2记录](runs/20261001-U2-FOUR-CASE-SHOWCASE.zh-CN.md)。功能、有限页面和两份实际PDF检查完成，真实IME及200%缩放待确认。本文件下方保留设计时约束和阶段建议，不将原“待实施”当当前状态。用户已确认“公开展示网站 + 本地运行版”，不购买服务器、不承担访客模型费用。

## 1. 本轮要完成什么

把现有查询表单改为可连续交流的工作台；让公开网站通过四个存档案例展示真实用途，让愿意使用的人自行运行本地版。保留已有计算、工具选择、范围约束、政策证据、审阅和保存功能，不重新搭 Agent 框架。

两个实施包完成并验收后停止，不自动追加模型横评、数据采集、微调、多智能体、每日更新或云服务。此次只准备可发布的静态产物，不自动提交、推送、上传数据或开通 GitHub Pages。

用户的实际诉求是自然对话与可读报告，不是把安装、模型调试和审计信息全堆在提问页。Agent 是后台选择并执行工具的工作方式，聊天是它的交互入口，报告是其中一种成果。

## 2. 核对所得的现状

- `web/design-preview/index.html` 已有项目页、工作台、报告页和中英切换；首页 COBE 动效与中国/美国标记保留，不在这轮重做。
- `live.js::showAgentConversation` 将会话写进 `#scope-preview`。商品选择、方向选择、范围确认也用同一个容器并清空它。

- 模型设置同时显示常用型号下拉框与重复的型号输入框，且与提问混在一起。它不是缺少 API 接口，问题是组织方式差。
- `app.js` 的英文建议按钮固定填钨/光伏问题，与本地已改为大豆的显示文案不一致。

- 打开过本地报告后，首页的示例链接仅改变 `#report`，可能继续显示本地报告；必须明确报告来源。

## 3. 交付方式固定下来

| 版本 | 用户看见什么 | 网络及费用 |
| --- | --- | --- |
| 公开展示版 | 项目介绍、四个案例、存档对话、完整图表报告、本地运行说明 | 仅静态资源；没有模型设置、自由提问提交或 `/api` 请求 |
| 本地运行版 | 同样的案例入口，加真正的聊天、独立数据查询和模型设置 | 原本机后台；本人配置 API。只有主动发送助手问题或测试连接才调用模型 |

公开版不能提供“任意输入后显示固定报告”的假聊天。案例允许切换、展开对话、查看工具步骤、打开报告；不模拟实时工具执行或新生成过程。明确写“案例记录”，报告说明存档日期和数据截止月。

公开版不扫描、探测或自动连接 `localhost/127.0.0.1`。本地版也不因为打开项目页、案例、设置或刷新就调用模型。浏览器不直接连接 MySQL；继续由已核验文件支持日常查询。

### 两种运行模式的识别

1. `<html>` 默认 `data-runtime="showcase"`，脚本统一读 `document.documentElement.dataset.runtime`；未声明也按 showcase 处理。
2. `web_app.py` 仅在自己提供 `/preview/` 和 `/preview/index.html` 时替换这个固定标记为 `local`；标记必须唯一，不能全局替换文本或依据 URL 参数启用。
3. `app.js` 使用显式标记区分展示/本地文案；`live.js` 只有标记为 local 且路径属于正式 preview 时初始化。移除所有只检查路径就启用后台的判断。
4. 公共构建还要去掉 `live.js` script，作为第二道隔离。即使部署在 `/TradeIntel/preview/` 也不能调用 API。
5. 文件、案例 JSON 和图像使用相对资源路径，兼容 GitHub Pages 仓库子路径；不可硬编码站点根 `/cases/` 或本机端口。

## 4. 页面和视觉结构

保留暖白、深绿的现有风格，但减少大框套小框、重复边框和无意义留白。无需新字体、付费模板、新依赖或新动画。

### 本地工作台

桌面：左侧约 220px 的窄栏，中间是消息区，消息下方是固定的输入区。消息正文最大宽度约 760px。页面占据导航下方可用高度；只有消息区滚动，输入框不与按钮重叠。

- 左侧：新对话、本浏览器保存的对话、查看案例；底部模型设置入口。
- 顶栏：会话标题、当前模式，以及紧凑的型号/连接状态。不要放一长串 API、版本摘要或费用说明。
- 中间：初始提示和少量自然问题建议；开始后按时间顺序显示用户消息与助手回复。
- 底部：同一个 `#question-form/#question` 输入，按钮叫“发送”；数据模式下叫“查询”。Enter 发送，Shift+Enter 换行，输入法 composition 时不发送；空白内容拒绝。
- 正在等待：立即显示用户消息和“正在处理…”状态。当前接口不是 SSE，不能假装已经完成某个工具或输出模型思考。拿到结果后才显示已保存的实际步骤。
- 完成：摘要 + 每份报告的小卡片。留在工作台，不自动跳走；卡片明确商品、进口/出口、伙伴范围、月份和主/附加报告。
- 需要澄清：作为助手消息呈现；只显示该轮真实问题/选项，不把一段长确认流程放在对话之外。
- 失败/结果未知：该轮消息内说明；旧报告卡仍可打开，不把旧报告冒称本次成功，不自动重试。

移动端：左栏折叠为菜单，主体单列；输入区避让 safe-area、用 `dvh` 及回退值，不能靠固定桌面高度挤出发送按钮。消息和图表长文本可换行，只有完整金额表可横向滚动。控制按钮点击区域不少于 44px。

### 报告阅读

本轮复用独立 `#report` 页面，不同时做分屏与第二份报告 DOM。这样先解决聊天割裂，又不牺牲图表阅读和打印宽度。

- 报告卡点击后打开报告页；“返回对话”保留原会话与输入草稿，不能创建新会话。
- 查看附加报告不改变追问主范围，打开报告不触发模型调用。
- 用 `activeReport={origin:'local'|'case'|'legacy_sample', id}` 明确来源。示例链接必须显式选择案例，不能只改 hash。
- 案例打开不覆盖 `tradeintel_live_*`、`tradeintel_agent_*` 本地记录。返回对话时从本地已有状态恢复。
- 报告正文保留金额、逐月图、必要解释与原口径。来源和计算说明在末尾折叠，不增加左侧主目录项。相关的“尚未核对”不能隐藏成已核对，但不在各处反复刷相同警告。
- 图表金额/日期/份额来自已保存事实，不为视觉新增统计结论或跨期增长计算。打印继续展开数值表与必要来源，未审阅模型草稿不进入 PDF。

### 模型设置

移到独立 `<dialog>`，由设置按钮打开。桌面最大宽度约 560px，移动端不越界；每个字段有可见标签。

顺序：服务商 → 型号 → 本服务商已支持的推理配置 → API Key → 保存/测试连接。

- 常用型号选择后不再显示重复文本框，选“自定义型号”才显示输入。
- 型号候选来自现有 `/api/model/status`；不能把预置选项标成“已验证可用”。本轮不新增型号、不核价、不升级供应商配置。
- 推理配置仅沿用后端现在支持的枚举。GLM/千问无对应参数时显示“服务商默认”，不声称能设 high；DeepSeek 的参数可配置不等于每个接口必然接受它。
- API 用 password 输入；同服务商可沿用已保存密钥，换服务商遵守既有验证。保存后清空表单密钥，不写 localStorage、URL、案例 JSON 或 console，不回显已有密钥。
- 保存不调用模型；测试按钮明确提示短请求可能计费。打开 dialog、切服务商和关闭 dialog 均不测试。保存后刷新状态，不给“保存成功”贴“已连通”。
- 已配置/未测试、短连接成功、测试失败分开标识。短连接成功不等于任意问题可靠。
- 用原生 dialog 管理焦点、Esc 关闭和返回触发按钮；不新增弹窗库。进行中的真实请求不能通过关闭弹窗变成已取消。

### 数据模式与会话历史

用顶栏两个明确选项“研究助手 / 数据查询”，取代中部孤立 select。未配置模型的首次使用继续默认数据查询；显式选择继续被记住。不因切到研究助手就产生 API。

- `#chat-messages` 专门显示助手对话；`#scope-preview` 仅供数据模式的商品/方向/范围卡使用，不相互清空。切换语言只重绘当前模式。
- 数据查询结果标为程序结果，不伪装成模型回答；确认前不执行报告查询。主输入区可共用，但模式内容、草稿和提示分开。
- 复用 `askAgent`、request_id/session_id 和 pending 协议。刷新/读报告/语言切换均不重新 POST。
- 对话左栏只建立本浏览器的轻量索引，最多 20 条，存 session_id、标题和更新时间；服务器仍是会话事实来源。不遍历 `.local`，不新增全量会话列表 API。现有保存会话读回成功后补进索引。
- 切会话只 GET，失败不删除服务器原件；不能恢复时显示状态。未决请求保留到服务器状态确认，不由导航、切模式或新对话偷偷清除；新对话不能解释为取消或重试旧请求。
- 输入草稿按模式/会话保留在内存，页面刷新丢草稿可接受；不新增完整聊天正文的浏览器存储副本。

### 案例数据合同

新增 `cases/index.json`，schema=`tradeintel-public-cases-v1`。四项固定字段：id、title.zh/en、description.zh/en、kind（real_agent_run/edited_evidence_report/guarded_run）、recorded_on、data_cutoff、model（仅请求名与已记录的推理配置；C3为null）、limitations.zh/en、asset。

每个 `cases/{id}.json` 使用 schema=`tradeintel-public-case-v1`，包括：

- `turns`：role与已精选问题/程序回复；原中文问题保留，英文是明示的翻译。selected步骤只含已发生工具的中文/英文标签，不含参数、思考正文或原HTTP响应。
- `reports`：改用案例内 `r1/r2` 等别名，含kind、question、白名单scope、summary、series和官方来源。正常数据报告的scope仅保留商品代码/名称/官方英文、方向/伙伴、起止月与口径；both仅逐方向嵌套相同字段。
- `reader_view`：只导出经过校验的facts.text/text_en、unanswered和method；将report_id映射为案例内别名。没有政策字段就不造政策说明。
- `evidence_meta`：已有数据版本、原件SHA（不含路径）、来源URL。C3逐商品事实仍保留真实原指标，编辑说明与存档原文分开。
- C4无reports，单列 `requested_month/latest_available_month` 和原程序澄清；不把模型错误标正确。

不能直接序列化 GET 会话/报告响应：它们是本机读取接口，不是公开出版白名单。禁止递归复制原始配置、会话/请求ID、路径、异常对象、usage明细、模型raw/parsed、未审核解释或fixture原文。URL只允许 http(s) 官方来源；禁止本机/file/javascript/data URL。未知字段拒绝，疑似凭证字符串构建失败，不能靠“删一个api_key键”充当脱敏。

构建器 `scripts/build_public_showcase.py`：从明确的四案映射读取原件，生成受限静态目录和本地核验记录；默认只写新的 `tmp/handoff-runs/showcase-<run-id>/site/`。已存在目标目录拒绝覆盖。核验记录与原件映射放同级 `audit/`，不在site内。正常不联网、不调用模型、不修改原件。单独 `--verify` 对已构建目录校验字段、金额引用、文件摘要和静态文件清单。

静态文件按允许列表复制，不递归复制web/tmp/docs/.local/vendor整目录；仅页面、CSS、app/case/read-only模块、cases JSON、净化data.json、必要COBE bundle与许可。case加载失败要显示具体“案例暂不可用”，不能回退成钨报告或联网查询。
