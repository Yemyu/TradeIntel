## 本轮实施结果（2026-09-21）

A/B/C 已按本文件的边界落地到当前生产构造器，仍然是离线改造，**没有调用任何模型/API**，也没有修改旧冻结记录。

- **A：输入视图**：新增 `src/tradeintel_ai/public_input_view.py`。送给模型的是可逆的紧凑视图（指标表、完整观察目录、政策事实和限定），完整报告与政策原文仍由主机保存；`restore_view(build_view(...))` 会逐字节恢复原始业务对象。

- **C：读者报告**：`public_report` 现在真正渲染政策背景，包括存档标记、生效时间、原产地、逐税号税率、条件/例外状态、限制和官方来源链接。模型不能改写这些事实。

本轮仍未完成自然语言提案入口、固定追问摘要、独立参考答案和供应商真实 tokenizer 核对，因此四题仍是诊断材料，不是冻结评测；下一步应由 Astra 做一次输入/合同最终审查后再决定是否发真实请求。

## 目标与边界

保持现有“面向普通读者的政策与贸易数据简报”目标。不是换模型掩盖产品输入问题，不恢复因果研究，不增加新Agent或数据库。本文件先记录 Astra 的设计依据，再记录 Luna 的离线实施；正式四题仍未冻结。

成功标准：同一生产构造器产生精简、可回查的模型输入；完整数据仍留在主机；模型能解释规模、来源结构和获准比较；报告实际呈现政策事实。输入达到既定16000 token估算硬门、8000目标后，再准备统一四题。不能删法律条件、未知状态或只给测试额外资料。

## 已核实的原因

实测来源：`tmp/public-brief-eval-v1/diagnostic-no-qwen-20260921/q1/snapshot.json`。

- JSON用户正文822948字节，含系统消息及再次JSON转义的messages为856233字节。两种计量口径不得混用，更不能把字节叫tokens。
- evidence为786693字节，其中244个metrics共623496字节，51个observations共142923字节。
- metrics重复source_ids数组566726字节，observations重复source_ids数组118425字节；源集合只有两种。它们是宽泛的数据来源集合，不应描述为逐指标精确定位。
- 在内存中把source_ids数组替换为集合引用，保持字典展开后严格相等：正文822948→145766字节，约减少82.3%。这证明优先去重有效，但不是生产实现，也未证明达到token硬门。
- policy_context33143字节，其中逐商品details占大头；不能按长度直接裁切。
- 当前`_observation_catalog`取前六项：五个环比加第一个商品同比，六项全为comparison。虽完整evidence中有规模和来源结构，模型合同却不准引用对应观察，Q1难以有用回答。这是输入选择问题，不是模型能力结论。
- `public_report`目前没有政策正文/事实段；上轮只接了模型输入。Q3要求政策事实由程序报告承载，而模型又被禁止输出税率数字，因此只修模型输入还不够。

## 实施顺序与结果（一个实施阶段，三个验收块）

### A. 可逆去重，保持全部业务信息（复核未通过）

新增独立`public_input_view.py`，不要改旧单月`brief_business_view`及冻结实验。接口：`build_view(report, policy_context)`与`restore_view(view)`。

1. source_ids数组精确去重为source_group_ref；独立表存每个数组，顺序也保持。空数组、不同顺序不能被错误合并。未知引用、重复ID、冲突定义拒绝。
2. metrics用有显式columns的rows表达，保留所有字段和值，包括null、单位、分母、status、period/base_period、source引用。字段存在性须可还原：未知字段/混合schema拒绝，不默默丢弃。禁止靠缩写含义猜字段。
3. policy_context允许对重复的完整字符串/对象精确去重；仅在明确协议字段处使用引用，不替换自由文本中的同名词。提供可读段落表、逐商品适用关系；含义、限定、例外、逐字引文、来源摘要一个不删。
4. 完整request/evidence/policy context保留在快照；送模视图包含原始摘要和view版本。去重字典若模型需要理解必须实际送模，不能放到模型看不到的sidecar后声称保留语义。
5. 验收`restore_view(build_view(...)) == 原业务对象`；金额、null、数组顺序严格相同。包括正文出现引用式字符串的反例。未知字段不能静默遗漏。

先仅做A实测预算。如果仍超门，返回Astra，不能自作主张砍月份、删除商品、法律条款或改参考答案。暂不采用有损摘要/向量检索替代法律条件。

### B. 观察目录与输出合同解耦（复核未通过）

“最多输出六条解释”不等于“最多提供六条可引用观察”。

- 提供完整51条观察的可读紧凑目录（按当前request实际数量，不硬编码51），保留id/kind/scope/comparability、metric_ids和fact_sentence。指标详情只存一次，通过ID引用。
- parser依据同一构造器的目录允许引用，仍限制输出最多六条。不得按模型名字、Q编号或参考答案挑观察。
- 如果目录在未来更大规模下超预算，先受控拒绝要求缩小用户确认范围，不静默截前六条。五商品六个月当前支持范围必须先验证。
- watchlist传完整程序定义及rationale，不只传ID。对于有政策材料的报告，程序应提供policy_revision；上限三条可按固定优先级：next_trade_release、policy_revision、coverage_gap（存在缺口时）或origin_mix。不得宣称价格/库存已监测。
- 结构验收：当证据存在对应类别时，目录包括level、composition、comparison；所有引用解析到原对象。输出仍只生成解释，不重新算数。

### C. 政策事实真正进入读者报告（部分实现，兼容与观察清单待补）

- 给报告增加可选、已验证的policy_context。由已绑定版本的服务器提供，不能从浏览器任意policy_context接受；渲染时再核验其policy_id/data_version/policy_view。
- 使用现有政策事实合同，输出存档政策标记、逐商品附加税率、生效事件/原产地、限定和例外状态、官方来源。未知保持未知；不得称现行综合税率。
- report摘要包含政策字段，prepare/save/load/review/export必须保留；AI合并报告时不得丢掉它。旧无政策报告可按原路径回放，不迁移或覆写旧快照；新带政策报告必须全链保存。
- 合同变化需版本区分：新公共输入视图单独版本；旧已保存messages按原版本重建/验证，不让新构造器使旧快照全部失效。不改旧冻结哈希“刷绿”。
- 页面改版仍后置，这里只补程序报告Markdown/已有HTML渲染内容，不设计新前端。

## 正式评测入场条件

1. 上述A/B/C离线回归通过；四题由真实生产构造器重新生成到新目录，旧诊断包保留。
2. 核验自然问句→选卡/上下文→范围提案→用户确认；如果入口仍需手工request，明确只是解释组件评测，不能标端到端。
3. Q2接固定程序摘要，不接任一模型Q1答案；将必要摘要与选卡信息接入生产追问路径，不能只补测试prompt。
4. 单独复算评分参考，保存数据/政策/代码/messages摘要；候选不读reference，当前设计长对话不算干净模型测验。
5. 采用项目已登记的token估算方法测实际完整请求（含系统、合同、去重字典、追问摘要）；记录方法。不同厂商实际tokenizer有差异，估算合规不等于账单精确。没达到门槛不发。
6. 六配置上限24答：Luna最高、Sol中、GLM4.6V/Air开启思考、DeepSeek Flash/Pro low；模型真实配置最终冻结时再核对适配。先Q1/Q2，重大错误停止。新协议实验假设、程序基线、防泄漏和停止规则沿用日常场景方案。
