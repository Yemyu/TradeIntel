# TradeIntel 前端方向与 ThreeUI 选型

> 状态：设计建议，尚未实施。目的不是给现有功能换皮，而是把同一套已验证的政策、数据、解释与审阅流程，整理成普通用户能理解和使用的产品。

## 结论

前端采用**一个统一网站、三种阅读场景**：

1. `/`：项目展示首页；
2. `/workspace`：用户提问和确认研究范围的工作台；
3. `/report`：面向人的报告阅读页。

ThreeUI 只负责首页主视觉、流程动效和少量导航反馈。工作台保持克制，报告正文不使用 3D 动效，以真实图表、中文排版、来源脚注和打印效果为主。

用户已明确暂不使用 Pro。第一版使用免费组件，并允许从其他免费库取得相近效果；不依赖付费模板。

## 免费替代补充（2026-09-23）

已查官方源码与文档，尚未安装或做浏览器性能验证：

- **首页地球首选 [COBE](https://github.com/shuding/cobe)**：MIT，原生 canvas 接口，无需为了地球引入 React；官方示例支持标记、弧线和旋转。用于实现与 Network Globe 同类的点阵地球效果，不承诺像素级复刻。演示：[COBE](https://cobe.vercel.app/)。它与 Data Field 二选一，避免首页堆两套主动画。
- **更复杂地球备选 [Globe.gl](https://github.com/vasturiano/globe.gl)**：MIT，支持多种地理数据图层；只有确实需要更复杂的弧线、区域和交互时采用，首版优先 COBE。
- **流程连接动效参考 [Magic UI Animated Beam](https://magicui.design/docs/components/animated-beam)**：连接政策、数据库、AI解释和报告四个节点，适合讲清工作流程；React实现需评估适配成本，不能直接当原生HTML插件使用。免费源码仓库：[Magic UI](https://github.com/magicuidesign/magicui)。
- **粒子背景备选 [React Bits](https://reactbits.dev/backgrounds/particles)**：源码可用，当前许可为 MIT + Commons Clause，允许集成应用；不称纯MIT。由于项目当前不是React，优先已有ThreeUI免费背景或COBE，避免为小装饰迁移前端。

建议原型组合：COBE地球 + 自有中文排版 + 轻量SVG流程动画 + 结构化报告真实图表。获取代码可由开发者完成，无需用户手动复制。该组合只确定素材候选，最终颜色、比例与动效强度仍须通过页面原型判断。

## 推荐视觉方向

名称：**编辑部式贸易研究工作台**。

- 主色：深海军蓝、墨黑、纸张白；蓝紫仅用于数据流和交互高亮。
- 气质：可信、安静、现代，介于研究简报与数据产品之间；不做证券交易终端。
- 首页可有一处 WebGL 动效；进入工作台和报告后逐渐减少动效。
- 正文优先中文可读性，数字用等宽字体，结论、证据、限制分层展示。
- 所有动画支持 `prefers-reduced-motion`；移动端和打印版自动换成静态图。

## ThreeUI 组件选择

### 第一选择：Community 组合

| 组件 | 用途 | 采用方式 |
|---|---|---|
| [sublevel.studio](https://threeui.com/landing-pages/sublevel-studio-landing-page) | 首页的信息结构参考 | 借用模块化项目格、浮动导航和“系统工作流”叙事，不整页照搬 |
| [Data Field / Structure Flow](https://threeui.com/three-js/structure-flow/data-field) | 首页 Hero 的全球数据氛围 | 作为唯一主要 3D 动效；不表示真实贸易路线 |
| [Command Bar / Animated Top Dock](https://threeui.com/css/animated-top-dock/modern) | 全站导航 | 映射为“项目 / 开始研究 / 报告 / 方法与来源” |
| [Layered Planes / Diagnostics Panel](https://threeui.com/ui-elements/diagnostics-panel/layers) | 首页流程说明或工作台空状态 | 五层分别表示政策、范围、数据、解释、审阅；不承载真实指标 |
| [Complete Shelf](https://threeui.com/hero/complete-shelf-landing-page) | 案例与报告库 | 仅借用编辑式“研究卷册”布局，报告正文不用书架动效 |
| [3D Paper](https://threeui.com/three-js/3d-paper/original) | 报告封面或分享卡 | 可选；只用于封面，打印时替换为静态封面 |

Community 代码和 ThreeUI 自有 Community 资源为 MIT；字体和第三方资源仍按各自声明处理。

### 可选的 Pro 升级

| 组件 | 价值 | 风险与结论 |
|---|---|---|
| [Agent AI](https://threeui.com/landing-pages/agent-ai-landing-page) | 完整的“问题→流程→架构→案例”叙事 | 结构最接近本项目，但 65 张图、约 6.5 MB，且容易把受约束助手写成过度自治的 Agent；仅作付费备选 |
| [Network Globe](https://threeui.com/backgrounds/network-globe) | 全球点阵与跨境弧线非常贴合贸易主题 | 只能作为氛围图；未接真实数据时必须明确不是实际贸易流 |

官方当前价格页显示 Pro 上线价为每年 99 美元，Lifetime 为一次性 199 美元，价格可能变化。第一版不依赖这些付费组件。

### 明确不选

- [Aureon Markets](https://threeui.com/hero/aureon-markets)：视觉漂亮，但太像证券交易平台，与“不提供投资建议”的边界冲突。
- 固定动画的 Charts / Cinematic Dashboard：不是真实数据图表，放入报告会误导读者。
- Kage、Renaissance、Inkbound 等重型叙事模板：主题不匹配且资源过重，影响报告阅读。
- Performance Gauges：汽车仪表语义，不适合贸易研究。

## 三页信息架构

### 1. 项目展示首页 `/`

目标：让申请审核者或首次访问者在一分钟内理解“它不是一个聊天 Demo”。

顺序：

1. Hero：一句产品定位、一个主 CTA“开始研究”、Data Field 动效；
2. 当前能回答什么：政策事实、受控贸易数据、通俗解释、可追溯来源；
3. 五步真实流程：提问→确认范围→程序计算→AI解释→人工审阅；
4. 一个已验证案例：用真实报告中的三项核心图表展示；
5. 质量证据：数据版本、测试、模型差异和安全门，避免堆内部术语；
6. 项目边界：不是实时税则核定、不是因果识别、不是投资建议；
7. CTA：打开工作台或阅读完整案例。

首页不再直接堆放所有旧研究入口、历史按钮和技术状态。

### 2. 用户工作台 `/workspace`

目标：普通用户能完成一次研究，不需要理解 A3、v2/v3、hash 或状态码。

桌面布局：

- 左栏：当前研究问题和任务记录；
- 中栏：自然语言问题、系统识别出的政策／时间／商品范围、确认按钮；
- 右栏：数据准备、解释、审阅、报告四个阶段的状态，以及“打开报告”。

主要路径只保留一条：**提问→预览范围→确认→生成证据→生成解释→审阅→查看报告**。原始 JSON、摘要、版本指纹和调试信息统一放进“技术详情”。公告导入、更新检查和旧实验移到次级入口。

### 3. 报告阅读页 `/report`

目标：把结构化 `public-report-v1` 渲染成读者能快速理解、可打印的报告，而不是重新让模型写一篇文章。

主阅读顺序：

1. 标题、问题、统计期和三句话摘要；
2. 四张核心指标卡：最新月全部来源金额、中国来源金额、中国份额、覆盖商品数；
3. “发生了什么”：政策时间线和适用商品表；
4. “数据怎么变”：
   - 全部来源金额与中国来源金额的月度趋势；
   - 中国来源份额趋势；
   - 最新月主要来源构成；
   - 商品×月份热力图或小倍图；
5. “怎么理解”：只展示已审阅的 AI 解释，逐条绑定对应观察；
6. “接下来关注什么”：下一次数据发布、政策修订、来源结构、覆盖缺口；
7. “不能从这份报告得出什么”；
8. 可折叠的来源、方法和版本详情；
9. 导出 PDF / Markdown。

图表只读取后端提供的结构化事实，不在浏览器重新推导金额或生成结论。完整月表放在可展开区域，来源列表做脚注或抽屉，不再占据正文大半页面。

## 接入现有项目的边界

保留：

- Python `ThreadingHTTPServer` 和现有 API；
- 会话、确认、固定版本、任务去重、解释审阅和导出门；
- `public-report-v1` 结构化报告对象；
- 当前使用 `textContent` 和 URL 白名单的安全渲染习惯；
- 旧演示页作为历史证据。

第一版不引入 React/Vue，也不重写后端。新增共享样式和白名单静态资源路由，重做首页与工作台页面壳，并增加一个从结构化报告对象渲染的 `/report` 页面。ThreeUI Community 的视觉元素优先用独立静态渲染或按其设计语言复现；如果后续确认必须直接使用其 React 组件，再单独评估构建层，不把前端迁移与视觉改版捆绑。

## 第一版验收标准

- 首次访问者 60 秒内能说清产品输入、处理和输出；
- 首页只有一个明确主路径；
- 工作台刷新后不重复创建任务，旧 API 兼容；
- 报告中的数字、状态、解释、来源均来自同一份绑定报告对象；
- 未审阅解释不得伪装成正式结论；
- 手机、桌面和打印版均可读；
- 关闭动画或 WebGL 失败时仍能完整使用；
- 不显示内部路径、完整摘要、协议版本等面向开发者的信息；
- 旧的前端 DOM 测试继续通过，并新增报告安全、刷新和导出门测试。

## 实施顺序

1. 先做低保真页面结构和视觉令牌，确定首页／工作台／报告三页的共同外壳；
2. 先完成真实报告阅读页，因为它最直接改善项目的可用性和展示效果；
3. 再精简工作台主流程，保持现有 DOM ID 和 API；
4. 最后完成首页动效与项目故事，接入一份真实案例；
5. 浏览器验收、移动端和打印检查后，再判断是否值得购买 Pro。
