## 1. 产品目标和完成边界

面向希望读懂国际贸易变化的非专业中文读者，提供政策与数据观察简报。核心问题是：发生了什么、数据如何变化、为什么值得关注、后续观察什么。学生和研究人员也可展开查看证据。

受众广泛不代表数据范围无限。V1明确显示支持的政策及贸易统计范围；现有主案例是美国所列五类商品的消费进口统计，不能称全球贸易全景。第二公告完整范围与已覆盖子集分别展示。首页可展示已登记政策卡片；“最近贸易怎么样”未选范围时给出可用卡片并澄清，不能默默回答五类商品却包装为全部贸易。

第一版交付一次提问到简报的完整应用：选定政策/商品 → 确认可读范围提案 → 固定版本的事实计算 → AI解释 → 阅读、追问和下载。首页、工作台、报告阅读属于一个网站，复用同一报告对象。

每日简报是后续运行方式：对登记来源检查公告变化，新统计发布后重算。当前三个包交付按需简报和更新状态，不代表已部署全天候抓取/定时推送。调度上线需要另验来源发现、运行机器、失败恢复和频率；不能用已有单文件抓取器冒称全面自动发现。没有新数据时只报告无变化或新政策信息，不每日重复调用模型生成相同内容。

不做因果识别、买卖建议、个性化资产配置、企业策略或确定性价格预测。可以解释有依据的机制和不确定性。信息整理也可能误导读者，定位和免责声明不等于零风险；正确口径、时间、来源和未知表达才是质量要求。正文不反复堆风险提示。

## 3. 用户流程和请求合同

新请求 schema_version=analysis-request-v1，字段固定为：

- original_question：原始问题，不用程序拼接问题覆盖；
- policy_id、policy_binding：服务端确认的政策及原文版本；
- products：唯一的HTS8列表，保留用户完整范围；
- window：start/end/anchor_month、mode（latest/explicit）、selection_reason；
- comparisons：mom/yoy/series/origins的明确列表；
- data_version：服务端已核验发布版本；
- policy_view：archived_event或verified_as_of，policy_verified_at可空；
- requested_as_of：用户要求的知识截止日期，可空；
- schema_version。请求摘要包含全部规范字段；有序/无序字段按固定规则规范化。

自然语言处理先从登记政策/商品别名与明确日期解析出候选，再校验。任意模糊政策名、非登记商品、两种可能时间含义需要一次简短澄清。LLM可后续提出候选，但不能直接授权SQL或修改发布状态。V1接受有限中文常用表达，不声称任意自然语言准确理解。

默认最新共同完整月M，近6个月M-5..M，环比M-1、同比M-12。用于同比的基月不需要强行画进6月图。显式日期优先；只有单月需求也不自动扩大正文。缺基月时仅该比较不可用，不补0。共同范围有落后月份需说明；不能静默删商品。上月追问以会话明确anchor为基准，无anchor先澄清。追问改动生成新请求及报告，旧报告保留。

确认提案用“范围、统计截至、比较窗口”三项自然语言呈现，一次确认即可，不逐指标审批。历史知识时点若缺发布时间记录，返回无法还原当时已知资料；允许用户另选事后历史观察，但不能自动将它叫历史预测。

新月份能力从已核验发布manifest产生；同步去掉现有查询器硬编码日期上限的依赖，但保留legacy显式窗口兼容。candidate/下载未完成内容不能成为最新月份。

## 4. 确定性证据合同 temporal-evidence-v1

必须包含 request_digest、policy_binding、data_version、coverage_by_month_product、comparability、metrics、observations、sources、limitations。全部ID由服务端派生，跨版本不复用。每个metric包括value或null、单位、商品/来源地范围、period/base_period、分母定义、状态及source_ids；null必须有reason。

固定公式：金额变化=current-base；增速=(current-base)/base*100，base=0为null；中国份额=C/W，W=0为null；份额变化用百分点；多月份额=sum(C)/sum(W)。金额精确相加后再显示舍入，不对显示值求和。金额图与份额图分开单位。ΔW=ΔC+ΔOther是会计分解，不称政策贡献。

来源地按代码聚合、名称仅显示。前五按最新月金额排序，以代码打破同值排序，另列其余合计；排名比较固定商品范围。缺来源行只有经提取完整性证明可视为0，否则未知。零值保留。不同商品的份额不直接平均，也不由美国进口来源占比推中国出口依赖。

可比性是每个商品×度量×比较区间的 reviewed/unverified/incompatible 记录，含官方定义/过渡证据。仅审核六月到七月不能放行全年同比。多商品合计只有全部比较构成可比且范围固定才reviewed。不变税号不证明定义不变。

unverified可列原值，比较增速/排名/连贯趋势结论不可用；序列图分段标注待核区间。incompatible不连线直接比较。允许其余已reviewed比较照常显示，不因一个商品问题放弃整个报告，但不得暗缩原范围。连续下降须至少3个连续、严格下降、覆盖和口径均有效的月度观察，说明未季调。

每个观察指定kind（level/comparison/composition/coverage）、metric_ids、source_ids、scope、comparability和程序生成的事实句。AI不能自行创建新数值事实。

## 5. AI解释合同 public-brief-explanation-v1（本次锁定）

保留旧E协议不修改其历史语义。新协议用于多期报告，在同一provider完成路径和审阅服务按schema分派。输入包括用户问题、完整所选政策条件/例外及原文引用、上节证据、程序选定至多6个解释观察和可用观察项目录。超过输入预算直接返回程序稿/待配置，不截断法律条件。

输出仅以下顶层键：schema_version、interpretations、watchlist。严格JSON、重复键拒绝、未知字段拒绝。

interpretations为0—6项，每项恰含 observation_id、kind、text；kind为meaning或hypothesis；同一(observation_id,kind)最多一次；text为1—350个字符。watchlist为0—3项，每项恰含watch_id、rationale；rationale为1—200个字符。允许空列表代表未提供解释，不能算AI完成。

模型只解释或选择观察重点，数字、日期、商品名称、政策动作、数据源和观察时间由报告渲染器从证据绑定。text/rationale禁止阿拉伯数字、百分号、URL、HTML；这是格式减错规则，不代表能拦住中文数字或语义越界。引用仅由有效ID解析，拒绝跨任务、无证据或不符合可比性权限的观察。假设必须在页面显式标为“可能的解释，尚待验证”。

watch目录由程序提供稳定类型：next_trade_release、origin_mix、policy_revision、coverage_gap。每项具备关联观察ID、需要看什么、为什么能帮助判断、官方来源（若有）、known或unknown的下次日期；没有已登记日程就显示待官方发布。企业披露/价格数量等未接入资料只能进入“可进一步补充的资料”，不得写成已监测或已发现。来源份额变化只写结构变化，不能直接确认企业转单或供应替代能力。

事实通过而AI失败时照常提供程序稿，明确“AI解释暂不可用”，保留原答和失败类别。不靠自动重试循环争取过关。结构通过的AI解释标为初稿；现有严重范围/数字错误规则命中则不附正文。结构检测不等于语义认证，整体采纳需最终人工样本审查。免责声明不能使无依据推荐合格。

## 6. 执行、持久化和审阅

沿用session/task主状态机；新增解释run作为task的子记录，避免A3的generation_started与模型调用混淆。run身份包含session、task、request、policy/data版本、证据摘要、protocol、实际messages摘要和模型配置摘要。

在现有session锁内从磁盘重读并原子领取：prepared→started→raw_saved→validated或failed；started无原答的重启→unknown_outcome。raw_saved恢复只重验，不重新调用。相同run重复点击最多一次provider执行；显式重试创建新run并保留旧run。新字段为追加兼容，不改旧状态历史。

每个run使用不可覆盖的目录；原答原子写完再解析，manifest和hash绑定所有内容，引用只接受服务端路径。快照内包含session/task/run身份；不能把两份内容相同但身份不同的快照交换。新回答取消旧报告的当前复核资格，旧报告和复核仍可历史查看。

interpretation_review_store按明确协议分派legacy/v2/E/public-brief-explanation-v1。新packet使用真实新schema文件，禁止伪造v2。复用追加revision、base_review_digest和竞争写保护。所有解释与watch条目具有稳定ID；审核时重新解析原答并校验证据绑定；拒绝项不在复核版中显示。

report-v1包含事实、解释、watch、sources、limitations、review_status、generation_channel。draft可阅读、可下载；reviewed只显示已接受内容并验证报告hash/审阅版本。A3旧确认仅批准纯程序稿，不批准AI。普通客户端不能自报api渠道、approved或内部完成状态。chat_simulation/stub只能开发CLI或测试注入，共用raw_saved后处理；usage未知写null。

## 7. 阅读和交付结构

同一report-v1生成Markdown和安全HTML，后续网页直接消费，不分别让模型写三份。

1. 标题、统计范围、数据截至、政策核验时间或“存档政策场景”；
2. 最多三条程序事实重点，可附相关AI解释；
3. 政策发生什么：生效/商品/条件/例外，不冒称当前综合税率；
4. 六月趋势、同比环比、来源结构和商品差异，缺口就地标注；
5. 通俗意义与待验证的影响路径；
6. 至多三条后续观察事项；
7. 关键局限和可点击来源，技术摘要在详情中。

首屏事实选取固定顺序：覆盖提醒（重大缺口时）→已核准比较的变化→最大金额或来源结构。数据不能支持“最大影响”就不使用这种标题。金额规模不是政策影响评分。事实重点最多三条不代表裁掉报告其余数据。

前端后置等待用户模板，结构已锁定：首页支持范围/示例，工作台问题/范围提案/结果，报告页集中阅读/追问/下载。无需每次生成新网站，不新开一套后台。更新检查和审阅管理放到次级入口。HTML纯文本转义及安全链接白名单；图表来自指标数组，禁止模型生成图表数字。

## 9. 验收矩阵和停止条件

| 验收场景 | 必须观察到的行为 |
|---|---|
| 中文问题不写月份 | 登记范围提案、最新共同完整月及历史窗口正确，确认一次后执行 |
| 无明确政策或要求全球所有贸易 | 澄清支持范围，无默认五商品冒充全部 |
| 显式单月/跨年/上月追问 | 尊重日期，追问基准正确，新旧报告各自保留 |
| 缺基月/缺来源/零分母 | 缺失与零区别，局部降级，分母为零不造增速 |
| 多商品/多来源 | 金额守恒，加权份额，前五+其余合计正确，百分点单位正确 |
| 仅六月到七月有编码审核 | 该比较可用，全期同比仍不自动放行 |
| 新公告18项只覆盖2项 | 完整范围缺口可见，选择子集后所有月份逐一核验 |
| 活动版更新/公告停用 | 旧报告保持快照，新生成按绑定/状态规则处理 |
| 实际入口生成到解释 | catalog/question可用，没有测试专用绕行 |
| 并发点击/中断 | provider stub计数一次；未知不重试，已有原答离线恢复 |
| 错JSON/非法ID/快照互换 | 受控失败、原答保留，不生成伪成功AI稿 |
| 草稿与复核版 | 草稿可读下载；修改原答/报告使复核失效；A3不能批准AI |
| HTML/伪链接 | 安全显示，不执行、不引入未经证据绑定的来源 |
| 新增政策但无新统计月 | 两种时间分别显示，不编造新贸易变化 |

实现单元测试按行为组合，不追求数量。每包只跑受影响回归及新边界；收口时再跑一次全量并按失败测试名对比本轮入场基线。历史1175项3失败49错误仅作线索，必须重新核实，不能沿用早期47项或改冻结哈希刷绿。
