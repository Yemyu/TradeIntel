## 要解决的用户工作

用户粘贴一份公告后，目前要自己理解并填写13个字段。拟增加“根据原文填写建议”，让用户直接核对值和出处。成功标准是少整理、少改错，同时保留未知和待补材料。不是要求模型重写已有图表，也不自动确认公告。

本轮核查的事实：`announcement_parser.py` 为少量 CBP 句式设计，商品代码仅排除 `990391` 前缀，时区存在固定返回 eastern standard time 的分支；不能把它当通用可信解析器。`policy_candidates.py` 能验证逐字引用，但字段 value 的语义并未因此得到验证。现有贸易桥只接受中国原产和完整 HTS8；公告字段抽得正确，也可能暂不能查数。

## 材料怎么分

1. R2 / FR 2025-23912：已见开发公告；已有人工参考，继续用作兼容性检查，不计新题成绩。
2. 新开发公告 D2：CBP CSMS 65794272，官方来源 https://content.govdelivery.com/accounts/USDHSCBP/bulletins/3ebf0e0 。本轮已阅读且据此制定边界，因此明确列为开发材料，不能再称独立留出题。
3. 后续验收 H1、H2：待请求合同、提示词和评分标准锁定后才选定。各取一份不同政策事件的官方公告；不得是 R2/D2 的更新、转载或同一附件。选一份完整商品清单型、一份存在范围限制或外部附件依赖型。先按公开来源、格式、长度和依赖条件登记选材理由，不按模型表现挑题。当前未选定、未封存，不宣称已经有盲测包。

“未见”仅指未进入本项目的提示调试、示例或实现过程，无法保证基础模型预训练未见。设计者可准备参考；被测独立请求只能看到正文和输出合同，不能看到参考、评分表、旧答及本对话。若同一开发者看完验收输出后修改实现，这两题即转成已见回归材料，原成绩保留，不能重跑后覆盖首轮。

D2 的用途是验证：第99章申报码与商品码分开；计税基础和额外税率一起表达；夏令时照原文；正文缺商品附件时主动报缺；全国别适用不擅自缩成中国范围。该公告按铜含量规定税负，并包含特定例外，不能用整件商品贸易金额直接计算政策税额。它是历史原文阅读练习，不核定今天仍有效的税则。

设计时仅浏览 D2 官方网页，没有下载/解析它的 DOCX 附件；随后执行包已保存官方 HTML、最终 URL 与 SHA256，并提取正文（包含题名和发布时间），见 `evals/policy_extraction_v1/sources/` 和离线包。固定正文-only任务，不把附件内容从搜索或模型记忆补入。附件是缺失依赖而不是一个漏做的下载步骤；正文-only可正确返回不能确定商品清单。若将来做正文+附件，另立任务版本。

## 固定输入和输出

复用现有13字段结构及 disabled 候选流程，不建第二套登记库。新增离线请求准备与响应适配，先不接页面。

输入只包含：一份已保存公告的版本、原文段落、任务说明和13字段合同。程序预先决定段落切分和版本，不允许模型生成版本或改原文。输出只含13字段的 `known/unknown/conflict`、值、理由和引文定位。无法确定必须 unknown；conflict 用于相互矛盾的依据，不能把条件税率分支当矛盾。

具体类型约定：日期为 ISO 日期；时间为24小时，时区保留原文；商品码保持现有 precision 枚举；第98/99章代码不得进入商品列表；只有明确列出的完整商品范围才能标 whole_hts8。HS10 不截短成完整 HTS8。rates 和 rate_meaning 可用原合同容许的结构化值同时表达数值、计税基础、条件及申报码；不得为了适配旧的“税号→单一数值”写法而丢掉条件。修改前检查所有读取 rates 的消费者；若其假定数值映射，则新增仅提案适配，禁止直接传给该消费者。

unknown 的值统一 null 并说明欠缺信息。conditions/exceptions/revisions 用可逐项核对的条目；原文未声明例外不等于“无例外”；未提供后续修订不等于“截至今天没有修订”。引用匹配与语义评分分别记录。候选再走原 build_candidates 校验，只保存为建议；人工编辑、提交、确认流程保持现有语义。

## 怎么评分

先固定逐字段参考及必须覆盖的原子事实，每一项列出原文位置、可接受写法、缺失时应答状态和严重程度。参考初稿由当前助手整理，必须标为“AI 辅助参考、待独立复核”，不能标作人工金标。完成一次独立复核并登记分歧裁定后才有正式分数；没有独立复核可以做开发检查，但不能以此宣传正确率。

对照：旧确定性解析器原样运行；AI 使用同一正文，单次回答；人工从空白表整理的耗时基准本轮不测，不臆测。旧解析器报错也保留，不能先针对新题修规则再当原始对照。

| 项目 | 记录方式 |
|---|---|
| 输出可用 | JSON/13字段/类型/原文引用是否通过，分项报告 |
| 事实正确 | 正确的原子事实数 / 实际断言数，原始分子分母同时保留 |
| 信息完整 | 已覆盖必要事实数 / 参考中的必要事实数，按公告分别列 |
| 克制程度 | 错误 known、应知却 unknown、正确 unknown 分开统计 |
| 整理负担 | 无需改动字段数、需新增/删除/更改的事实条目数；不是时间节约率 |
| 后续可用 | 能否安全提交候选；能否查数另列及说明缺少什么 |

整题通过须同时满足：机器合同通过；零严重错误；日期、原产地、商品范围、税率基础、条件/例外无必要事实遗漏；其余必要事实覆盖率至少90%。严重错误包括虚构依据、错日期/原产地、章99当商品、部分范围扩成整码、铜含量税率套整件金额、缺附件仍补造商品、把历史规定称为现行已核验规定。全答 unknown 不会因零错误而通过。

开发采纳门：两份开发公告上都零严重错误、机器合同通过，且 AI 比原解析器合计至少多提供3个完全正确且可直接保留的字段；该门只决定是否值得做 H1/H2。正式两题必须逐题通过才能开放页面试用；2/2仍只表示两案例验收，不写成普遍100%可靠。任一题失败保存首答并暂停接线，先归因到模型、合同、提取或原文依赖，不默认换贵模型。

## 预算与停止

离线先行：准备 R2、D2 原文/请求/参考草稿；哈希固定正文、实际请求、提示版本及相关代码文件，记录 git HEAD + 脏工作区文件摘要，不能只记提交号。规则输出与模型输出分目录。

真实调用拟定上限：单一候选模型，开发2次（R2/D2各1），达门后验收2次（H1/H2各1），总计最多4次，不扩成模型排行榜。每次输入不超过24,000 UTF-8字节，输出最多4,096 tokens，90秒超时，无自动重试。超输入预算不截去条款，登记超限并停止；输出截断/空响应/未知结果不能评分，也不自动重发。现有去重账本与原答存档可复用。供应商明确型号、推理参数支持、价格和金额上限须在调用前核验并登记；本设计不授权立即消费。费用上限未定就只做离线包。

聊天内独立模型作答可先检验合同，但单独标 `manual_chat`；不能把它的耗时、费用或成功率混作 API 成绩。具体模型取已有可用配置，并在首个真实调用前选定，不在本文虚构最新型号或推理选项。
