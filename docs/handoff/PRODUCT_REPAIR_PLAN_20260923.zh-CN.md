# 商品查询与模型接入修复方案

状态：2026-09-23 完成代码与本地数据核查并写定方案；P1 已按本文件实施和验收，P2—P6 尚未实施。本文件覆盖旧记录中“仅剩密钥和前端”的判断。最初的设计轮未启动批量处理或真实 API 调用；随后用户要求开始实施，P1 仅进行了明确授权的一次短连接测试。

## 1. 交付目标

TradeIntel 是面向普通读者的美国贸易数据与政策分析助手。用户用自然语言提出商品、国家或政策问题，系统识别需求，查询已有资源，按实际覆盖生成图表与中文解释。政策是可选分析背景，不是查询任何商品的前提。

当前优先交付美国贸易查询；不将其宣传为所有国家、所有商品、每天实时覆盖。第一轮实用验收必须同时包括已有钨案例和大豆这一新增商品；只证明“大豆不支持”不算通用查询完成。现有进口资源先接通，出口作为独立数据接入任务，不把进口数据改名为出口。

不恢复因果识别、投资建议、微调或多智能体。现有首页、工作台、报告页继续共用一个网站，不重新购买或替换整套框架。

## 3. 请求与查询设计

新增 `trade-query-v1`，不改变旧 `analysis-request-v1` 的语义。旧政策案例走兼容适配器，新商品走通用查询，两者最终产出统一报告对象。

请求字段至少包括：原始问题、reporter、flow（import/export/both）、商品候选及采用的分类版本、partner、时间窗口、问题类型、数据集版本、可选 policy_refs。商品名称与官方编码的映射须带依据，不让模型自行编造编码。

处理顺序：

1. 从明确商品编码、已核实名称/同义词、官方商品目录中查候选；规则不能确认时可用模型建议候选，但服务器必须回查目录。
2. 未明确进口或出口时显示一次必要澄清。例如“最近美国大豆贸易有什么变化”询问进口/出口/两者，不能静默默认进口。
3. 检查每个候选的数据覆盖。结果区分：已整理可查、本地原包可整理、需外部补采、当前不支持。覆盖必须落实到月份、方向、伙伴、分类版本和指标。
4. 生成可读范围说明。明确问题直接带出正确范围；只有歧义或大批量补采才额外打断用户。
5. 用受限查询参数调用数据服务，程序计算事实，再准备模型解释。问题超出范围时不生成不相关报告。

“最近”默认采用该查询范围最新完整月份之前的最近 12 个连续月份，并准备有条件可用的去年同期；不足时显示实际范围，不跨缺月连线。不使用机器日期冒充数据截止日。用户明确指定月份、国家或商品时优先遵守。同比需要分类口径可比，不可比就不计算该项。

政策检索独立调用已有 `policy_search`：仅把确实匹配商品、司法辖区及时间的文档附入报告；找不到政策不阻止纯贸易数据分析。旧公告附加税率不能写成现行综合税率。

## 4. 数据资源与 MySQL 的职责

统一数据目录记录：数据集ID、来源、进口/出口口径、月份、商品分类版本、伙伴粒度、可用指标、原包路径与摘要、加工文件、发布状态。原包存在与已经可查询是不同状态；只有核验通过的加工版本可用于报告。

复用 `inventory_census_import.py` 的解析与来源核验。把 `extract_policy_case_monthly.py` 的“政策必填”限制下沉为可选商品筛选，不复制第二套字段解析器。已有 HTS10 聚合只有“中国/全部来源”，不可从中虚构其他国家构成；需要伙伴分布时回到本地原始明细。

近期数据建设先选一个月和大豆做核验，再处理本地已有的 2025-01 至 2026-07。先检查文件完整性、分类资料和磁盘预算；逐月处理、可恢复，复用已核验产物，保留原始包。更早历史数据按查询需要处理，不为网页首版重跑全部历史。

MySQL 作为本地交互查询库继续使用。增加独立的通用贸易事实表与数据集/商品/覆盖登记表，不覆盖原 `trade_monthly` 历史政策表。金额使用整数/Decimal；唯一键必须包含版本、月份、方向、报告国、伙伴和完整商品编码。消费进口额与出口统计额分别命名，不能共享一个含糊的 value 字段。

查询通过 `TradeDataRepository` 的受限方法实现；模型不直接提交任意 SQL。已发布文件快照负责复现，MySQL 是这些版本的索引与查询副本；目录记录入库版本并核验行数/合计。数据库离线时可以读取同一核验版本的文件副本，并明确告知存储切换；没有等价文件则报数据服务不可用，不返回另一个案例。

出口另设适配器与任务：实施时核对 Census 官方出口源、商品分类、总出口/本国产品出口等口径，并建立映射；不得把进口 HTS10 直接当出口编码。先验证大豆一月，再补所需窗口。美国进出口都未接齐前，不宣传为完整美国贸易覆盖。

## 5. 模型设置与调用

设置页显示服务商、已核实的 API 模型ID、支持的推理选项及最后测试时间。展示名与请求名分开，保留高级自定义输入，但必须验证。预设从项目已有成功请求及实施时核对的官方文档生成，不能凭记忆写新型号；不同服务商不统一伪造 high 参数。

配置状态：未配置 → 已保存未测试 → 连接通过 / 测试失败。连接测试用极短固定请求，不发送报告资料；保存不自动收费。配置或推理参数改变即使旧测试失效。返回的模型标识只证明服务商回显，不推断底层版本。

生产调用复用经过核实的模型参数构建能力，包括输出上限、超时和支持的 thinking/reasoning 设置；与旧评测账本分开记录，旧冻结不变。输入/输出预算按完整请求计算，不能测试一个小请求就宣称报告输入也能成功。

错误记录采用结构化分类：

- 400/422：请求明确被拒绝；显示经过脱敏的错误代码/参数名，并给出修正方向。
- 401/403：凭证或模型权限未通过。
- 404：模型或接口不存在，需区分服务商错误码。
- 429：限流或额度相关拒绝，不能仅凭状态码断言余额不足。
- 超时、连接中断、部分 5xx：结果可能未知，记录请求阶段，不自动重发。
- 收到回答但格式/引用不合格：保存原答，显示回答校验失败，与连接故障分开。

不把服务商原始错误体直接显示或记录到普通日志；采用允许字段与密钥脱敏。用户修正配置后可显式创建新的调用尝试，保留旧尝试。无歧义拒绝无需重建整份数据报告；结果未知时说明可能已产生费用，由用户决定是否新试。并发点击仍只领取一次。

配置文件保持本地、权限0600、Git忽略；页面状态不回显密钥。设置页初始读取真实已保存的服务商与型号，不固定显示 GLM。浏览器缓存不保存密钥。

## 6. 报告与网页

统一使用一份报告对象，程序事实、图表和模型解释在同一对象中关联；网页不再根据税号临时拼第二套业务事实。商品显示中文名，编码放详情。用户问题决定内容重点，不是仅替换标题。

默认阅读顺序：直接回答问题的摘要 → 关键数值和时间趋势 → 来源国/目的地构成（确有数据才出现）→ 变化解释及后续关注点 → 相关政策（可选）→ 折叠的来源与方法。

程序负责金额、份额、同比环比及图表；模型解释其含义、指出可能机制与需进一步核实的因素，不能把金额变化直接归因政策。缺一项比较只在该图或段落旁解释，不用大量“尚未核对”占据全文。数据截止日期应显眼；机器摘要、哈希和内部ID放详情。

模型未配置/失败时显示可用数据报告及明确的解释状态，不能把程序文字称为AI回答。已准备好范围、模型连接通过的任务，可由一次“生成报告”触发既有查询和模型步骤；保留进度，不要求用户认识内部阶段名。人工审阅用于已有的采纳/正式导出标识，不阻止先阅读草稿。

修复：输入框/按钮窄屏布局、首页中国美国标记、刷新不强制跳页、任务切换不串报告、切换语言后的新报告框架文案、服务商切换后的型号选项、调用失败立即更新任务状态。报告页提供图表文字说明、完整表格、浏览器打印；PDF分页须实际检查后才称通过。

## 7. 实施顺序和每包验收

| 包 | 交付 | 必须通过 | 建议执行模型 |
| --- | --- | --- | --- |
| P1 止错与模型接入 | 问题/商品一致性检查；移除网页强制五商品；配置预设、读回、连接测试和错误分类 | 大豆不产生钨报告；明确钨问题仍可用；短请求真实返回；错误不串任务、不自动重复请求 | GPT-6 Sol High：参数兼容与错误边界仍需局部判断 |
| P2 统一资源与查询 | 数据目录、通用请求、受限查询接口、MySQL新增表及等价文件读取 | 数据目录如实区分原包/已整理；进口/出口不混；同版SQL/文件数值一致；缺月/无记录/零值区分 | GPT-6 Sol High：新旧请求与版本接口衔接 |
| P3 近期商品接入 | 大豆最小验证，再复用本地19个月原包形成通用进口查询 | 大豆多期报告真实可用；钨旧案例数值不变；指定伙伴能查询或准确说明粒度不足 | 最小实现 GPT-6 Sol High；规则与核验固定后的批处理 GPT-6 Luna Max |
| P4 出口接入 | 官方出口适配器、分类映射、大豆进口/出口分流 | 出口使用出口源；方向与统计口径清楚；两者问题正确组合而非混算 | GPT-6 Sol Max 先核定来源和映射；固定后 GPT-6 Sol High 实施 |
| P5 统一报告与页面 | 单一报告对象、中文可读解释、图表、来源、配置与任务状态 | 不同问题改变查询重点；刷新/追问/错误恢复可用；窄屏、双语框架及打印实测 | GPT-6 Sol High 接线；固定样式修改 GPT-6 Luna Max |
| P6 产品验收 | 新商品、新问题、失败恢复和真实模型的一次完整验收记录 | 见下方验收清单；没有正向模型报告不称整链完成 | GPT-6 Luna Max 执行；指标或证据解释有矛盾再定点审查 |

P1仅是止错与可连接，不等于整个目标完成。P3完成可交付明确标注为美国进口的版本；P4完成才扩大进出口覆盖声明。不得通过一直新增同一案例的测试来代替P2—P4。

## 8. 验收、预算与停止条件

工程验收用离线替身和实际文件，验证分类、数值、重复请求及恢复，不消耗 API。代表性场景至少包括：大豆贸易歧义、大豆进口、大豆出口、明确钨、仅光伏、两个商品比较、指定年份、最近趋势、指定伙伴、不存在的商品、数据缺月、服务商400与超时。每类必须检查实际查询字段和最终报告，不只看HTTP成功。

大豆与另一种非旧案例商品分别验证，以防把硬编码五商品换成硬编码六商品。商品目录中未直接调试的代表性条目作为保留验收样例；若失败后参与修复，该样例改记开发回归，另留新样例，不继续冒称盲测。

真实模型最小试用：假设是修正API模型ID/参数后可以实际生成与证据一致的解释；先1次短连接测试，再1次完整报告，默认不自动重试。固定同一问题、数据版本、代码版本与请求参数，保存原答、返回型号、用量、时间和解析结果；提示中不放标准答案或旧模型答案。输出上限采用核实过的服务商参数，运行前预估输入和账户费用；价格未知不编造，不使用无上限配置。失败即定位原因，不扩成全模型横评。

真实报告验收同时检查：问题匹配、统计方向和口径、数值引用、主要变化是否解释、政策条件、阅读性。连接通过≠报告正确，模型能力也不替代商品路由和数据质量。

每包完成更新STATUS同一当前节、记录实际测试及未完成项。全量测试已有历史冻结失败，执行前记录基线，不能修改历史摘要刷绿；新增失败必须定位。旧数据和原答保留，不执行删库、覆写旧数据或提交推送。

## 9. 回退与完成定义

旧政策案例代码、快照和评测记录保留；新增通用入口使用独立请求版本和新增表，失败可关闭新入口而不损坏原数据。错误报告保留尝试历史，修复后生成新报告版本。

第一版完成必须能让用户亲自提出已覆盖商品的问题，得到正确范围、真实多期数据、图表和至少一个已验证模型的解释；模型配置、报错、刷新、查看来源和导出能用。产品主页必须与实际覆盖一致。只增加拒绝提示、只展示存档报告、只跑通替身测试都不满足这一完成定义。
