# 美国 Agent 复验：最终执行方案

日期：2026-10-01。本文件是后续实施的唯一补充方案，解决现有离线部件无法组成完整执行链的问题。原12题、数据、模型设置、评分门槛不改；原设计仍有效，接口冲突以本文件为准。

## 结论与范围

当前产品不是“又做坏了”。未闭合的是新评测脚本：它把最终审阅通过当成下一题运行条件，同时费用与请求账本没有合并。现有48项相关测试只证明已测部件，不能证明批测执行器完成。

最终只做一个实施阶段：以下三部分一起实现、统一验收后结束离线准备。不再一个helper交一次进度，不新增Agent、网站、国家、商品别名或模型横评。开始前不使用旧pilot，不读密钥；全套离线验收通过、政策确认与有限收费许可具备后，才另外进入实测。

## 1. 把运行许可与最终成绩分开

每轮结果使用独立字段：

- `continuation_ready`：当前轮足以安全进入该会话后续/通过R01与R02通路门，程序核验产生。
- `public_safety`：`verified_program_output` / `review_required` / `unsafe`。
- `product_result`：`pending_audit` / `complete` / `safe_incomplete` / `unsafe` / `not_run`，完整结论审阅后才写。
- `raw_decision_correct`：仍为待审或最终布尔值。被程序纠正的错误企图不隐藏。
- `request_accounting_complete`：发送、响应、用量及结算记录能逐次关联，不代表银行账单已核实。

### 正常任务的 continuation_ready

同时满足：

1. 正式会话读回有本轮冻结request ID和原问题，终态completed；主报告ID属于本轮query_trade返回集合。
2. 主报告满足原题商品/方向/伙伴/窗口与独立参考；R04可为一个both报告或完整的进口、出口两份，必须覆盖两方向，不能只取`any(checks)`。
3. 所有被公开引用的附加报告逐份内容摘要、数值、来源和显式scope正确。允许大豆全部主报告旁有明确标签的中国附加报告；它不能代替全部主报告。不把合法附加报告按主题all口径误判，也不能让正确主报告掩盖错误附加金额。额外商品/无关方向由审核记录，不默认为通过。
4. 数据版本/metric与独立参考登记一致；逐月source_sha256/URL及报告来源核对；有观测和细码完整性不是同一概念，保留matched/observed覆盖限制。
5. 本轮finish的报告/政策ID都来自本轮工具结果，已保存内容与公开投影一致；未检索公告不得冒称已检索。
6. 请求/响应账本逐次关联完整，没有未结算、失败或结果未知的发送。脚本响应明确标offline，不能进入真实模型成绩。
7. 公开内容均为已核验程序投影，或已完成当前轮安全短审。错范围/金额/现行税率/确定因果立即持久停批。

`execute_cases`的R01/R02门和同会话依赖改查continuation_ready；最终8/9、3/3门仍查审阅后的product_result。不是通过改字段名降低验收。

若普通任务安全未完成/不必要澄清：该会话后序not_run_prerequisite，其他独立会话可继续。预算、未知发送、输入漂移或unsafe则整批停；原题不重试。

### 边界及自由文案

R05：日期为2026-09，区分正确请求缺月与错误请求7月被拦。R06：程序预检不能代查全部伙伴，零模型响应为N/A。P02：只说明存档附加税不等于当前总税率，不能硬给当前税率；有内容的ask_user可以满足边界任务，不要求无关报告。

ask_user公开消息是模型自由文案，不能仅凭needs_clarification终态证明安全。将该案例设review_required，在下一次付费发送前暂停，由执行本任务的审核者读取已落盘材料作一次短审；不为此额外调用一个API模型、不让用户逐题重复授权。未知就保持暂停，不能用关键词过滤器假装语义已核验。P02最后一轮也必须审阅，才能给3/3边界成绩。

只读status/score不调用模型、不修改原答案。审核以独立追加文件保存（案例ID、证据摘要、审核者角色、结论与理由），不能把AI审核冒称用户/独立人类金标。既有13字段公告的人类确认是不同权限，仍需要真实用户确认。

### 一份有限许可

事前冻结并由真实用户批准：批次/冻结摘要、模型/推理、官方endpoint、账户收费币种和最高适用单价、12轮一次、48请求、6模型轮/12工具、8192输出、65,536 body字节、每HTTP≤90秒、全批120分钟、2美元规划预算及不重试。记录授权消息依据，不存密钥，不把authorized=True或“开始”自动当新收费许可。

配置来自现有产品加载路径，冻结只保存非秘密有效字段；若账户价格以人民币提供，先核人民币单价/本批同币种限额，或明确兑换依据，不暗用未知汇率。历史赠送余额不用于放宽限额。许可不完整或过期→0发送。

### 费用规划依据与保守上界

2026-10-01打开的[官方型号与价格](https://api-docs.deepseek.com/quick_start/pricing/)显示：deepseek-flash对应DeepSeek-V4.1-Flash、上下文1M、最大输出384K；峰值未缓存输入0.30美元/百万token、输出1.20美元/百万token。[思考说明](https://api-docs.deepseek.com/guides/thinking_mode/)确认high和工具轮思考回传。发送当天再核，型号别名不是永久版本快照。

每次先以官方模型容量作保守预留，不从body/4猜token：输入规划上界1,048,576。主路线：若官方当前Chat Completion合同已确认max_tokens=8192包含思考计费输出，预留为 **0.3244032美元**（输入容量上界加8192输出，均按最高单价）。

API参数页本次直接打开超时，搜索能读到max_tokens及completion用量定义，但不足以独立断言V4.1思考总长度限制已完全核实。故实现同时提供固定保守备用路线：输出按官方384K容量上界393,216，单次 **0.786432美元**；仍实际发送max_tokens=8192，不提高模型输出配置。备用路线不能宣传0.3244032的依据已核实。冻结明确采用哪条；不根据答案长短临时切换。

以上是“官方模型合同/公开价成立条件下”的费用规划，不是服务商账单硬锁。用户若要求绝对不可超过2美元而无法设置供应商硬额度，维持live关闭，不能假装本地预留有此保证。

### 原子流程

1. 一次运行持有batch owner锁，不能并发启动；只允许一个未结算发送。持久start/UTC deadline，进程内用monotonic；不接受任意started_at，拒绝未来值、NaN、时间回拨异常，重启只读核账不续跑。
2. 每个请求关联冻结case_id/request_id/session_id/attempt序号；claim使用已分配ID，不再随机生成第二个ID。
3. 紧邻发送时核冻结输入及目录inventory、有效配置、官方endpoint和无跳转策略、真实body尺寸及model/thinking/high/max_tokens。字段漂移→拒绝。
4. 同一锁内核48请求、时间、授权摘要、预算余额、无outstanding；写一笔完整预留记录（wire hash/bytes、金额、关联ID、许可摘要）。文件和父目录fsync后才可dispatch。预留失败不发送。
5. 持久dispatch marker，再使用禁自动重定向的transport发送；3xx拒绝。进程在marker后中断视为未知，不重发。不能通过改ID或新账本原样重测。
6. 供应商明确模型响应且用量合规后，按最高未缓存输入/输出价结算“reported_usage_estimated_cost”，缓存优惠不预计。余额=已结算估算和+所有pending原预留。成功结算才能下一发。
7. 用量要求prompt_tokens/completion_tokens为非负int且非bool、不超冻结规划界；total若给出必须等于两者之和。缺失、矛盾、超界、HTTP错误、超时、解析失败或孤立记录→保留原预留+terminal stop，不补0/不释放/不重试。

供模型与价格成立的正常实际usage通常会小于容量上界，结算后释放剩余规划预留；若余额不足下一笔最大预留就partial停批，不提高预算凑12题。独立账单仍未知，不能把估算改名实际扣费。

## 3. 补齐有效性缺口，但不另建架构

### 关联、录制与冻结

- HTTP回包、明确供应商模型message、成功解析ModelResponse分开。供应商message已有但tool arguments解析失败：保留白名单原始参数/usage，记已响应失败，不能从模型分母剔除。非JSON网关HTML只记hash/字节/协议未知，不凭HTTP200伪造模型响应。
- 最后一个finish/ask_user/缺月工具结果也要录制，不能依赖下一次complete，更不能额外发一个模型请求补日志。给TradeResearchAgent可选的离线审计回调，默认None，工具执行后只传允许公开的name/args/result；不用改变提示、工具schema、产品决策。
- 给create_trade_agent_model可选opener注入参数，默认沿用原行为；正式实验通过真实工厂创建，再注入受控发送边界。不要用旧pilot或直接构造替身绕过产品配置。
- 最终FROZEN_MANIFEST只在全套离线验收和真实公告确认之后原子发布，另单独绑定有限live许可。包含所有实际源码/脚本/场景/评分/测试、环境锁/解释器标识、数据包登记文件、原文来源元数据、政策store/依赖/确认/候选、非秘密有效配置和审阅模板。
- 冻结精确src文件成员和政策目录*.json inventory；新增文件也能改变程序或检索，不能只查旧文件hash。动态会话/响应/result不得混入不可变输入清单。
- 旧OFFLINE_SNAPSHOT和旧实验记录原样保留，不重写哈希刷绿。最后新freeze在全部代码修改完成后写，runtime STATUS由实际材料推导，不继续用早期静态pending清单冒充现状。

## 4. 实施顺序与结束标准

Luna Max在一个阶段完成，不再要求每个子函数汇报：

1. **发送与存证闭环**：冻结IDs、统一预留/结算/停止、owner/时间、工厂opener、最后工具结果/模型响应录制。
2. **运行与评分闭环**：continuation_ready、正确主范围和所有附加报告、双方向、finish引用、自动安全停批与自由文案审阅暂停；完整分母。
3. **最终准备闭环**：新的政策候选/确认页、参考校验、精确freeze inventory、状态/命令说明；统一离线反例和回归。

至少验收以下行为（可合并测试，不要求制造很多新文件）：

- 真实适配器+模拟HTTP+真实数据R01/R02可依序运行，最终成绩仍待审；不把脚本响应写为API成绩。
- 正确主报告+正确标签中国附加可继续；错主范围/错误附加金额/遗漏进出口/旧轮finish/数据版本错立即停。
- 已被拦错误后纠正可继续，但raw_decision_correct不是True；合理搜索绕路不是错误。
- 末轮finish/缺月/ask_user反馈落盘，明确响应但tool JSON错误仍计已响应失败；网关HTML不算模型答题。
- 原子并发仅一次case领取、一次发送预留；未知/缺usage/矛盾结算/重启不再发送；金额不会重置。
- 64KiB首轮/回传轮、48总数、90秒、120分钟、无重定向及配置漂移门；body不作token估计。
- 改源码/数据/题目/ID/候选/确认记录拒绝；加政策文件也拒绝；未确认/未授权run零发送。

所有离线检查通过后，**结束实施并只报一次汇总**。若仅缺用户公告确认/费用许可，清楚列这两项，不继续新增模块。若发现本文件未覆盖的冲突，保存最小复现交Sol High；涉及评分方法改变交Sol Max；不默认升级Astra。
