# v2 输入审查与剩余实施方案

2026-09-21。当前恢复入口；优先于之前的压缩方案与实施自评。

## 结论

当前五商品主案例的业务输入通过本轮离线审查，可以结束压缩阶段。它是经过验证的业务投影，并非原始 JSON 的逐字段无损传输。模型解释质量尚未测试；不能据此认定此前失败全部由输入造成。

产品目标保持：普通读者选择政策/商品后自然提问，程序提供官方政策与多期贸易事实，AI解释含义和后续观察，形成可读简报。按需使用、已登记范围、月度统计、政策存档状态均需如实呈现。因果识别、多智能体、微调、每日全网自动抓取不加入当前任务。

## 本轮复核和修正

1. 复现 v2 语义字典漏洞：把发送给模型的份额分母改为其他分母，再只重算 view hash，原 restore 仍通过。原因是 decoder 使用内部默认值忽略了 wire 的 semantics。现严格检查字典和明确的 measures 顺序；修改分母、交换顺序或修改数值均拒绝。
2. 有政策的报告现在优先列下一期数据、政策修订，再列统计缺口或来源结构。之前有缺口时 policy_revision 被排除的问题已修复。
3. v1 快照原先直接返回，跳过消息与证据的对应验证。本轮改为专门的“历史输入版本待迁移”错误并保留原文件。旧结果不进入新协议；需要新任务重新准备，不覆写历史、不重复调用。
4. 登记 CSV 的部分业务列确实与政策表重复，但原代码不校验相等。现校验列集合及被去重的名称、税率、日期、policy_id；变动/不一致受控拒绝。指标、来源、覆盖记录出现未声明新字段也拒绝静默忽略。
5. 更新旧端到端测试：从实际发送的 view 解码后核对政策原文、税号事实和全部观察，并以短别名回答完成 prepare→submit→review→export；不是删除旧政策断言。

## 业务投影边界（本轮设计裁定）

- 必须送出：全部月份/商品/指标/观察，数值、单位、分母、可比性和未知理由，观察到指标链接，政策原文、范围、生效条件、例外和官方来源。
- 可留主机：文件哈希、源文件年月/路径元数据，以及已经由 validate_policy_facts/validate_details 校验的逐字段 field_refs。模型当前不生成独立政策引文或新税率；政策引用由程序报告负责。如果以后让模型逐字段引用政策，必须恢复对应映射并重新审核合同。
- CSV 名称/税率/日期等只允许与已发送政策表完全相等时去重；不支持的新列直接停止。缺字段与 null 在本业务投影中按合同归一化，不能宣传原始字节无损。
- 此裁定明确替代早期“所有原始业务对象逐字段都必须发送”的规格。理由是当前模型职责只解释固定事实；复制审计信息没有解释收益。不能借此删除法律条件、未知说明或历史月份。

## 模型验收时的固定规则

假设：同一程序事实下，模型能提供具体、忠实、易读的解释。基准是纯程序报告。固定输入与评分要点；不能读参考、其他模型答案或本开发对话；不在正式题上调提示。每配置先Q1/Q2，重大语义错误停止该配置，未跑题不计错或对；通过再Q3/Q4，总上限24答，无自动重试。仅通过格式或泛泛拒答不采纳。

解释组件成绩与产品链路成绩分开。会话模拟与API成绩分开。至少一个入选API配置需实际走原答保存→解析→报告阅读/复核→导出。模型上下文、实际token和输出/推理预算在执行前锁定；接口失败单独记录。

只有以下情况返回Astra：独立复算不一致、需要改变分母/可比性/模型职责、法律信息遗漏、最终输入超硬门、旧快照或版本绑定需要迁移决策。不要因普通代码错误、文档整理或已锁定反例再次拆成设计任务。
