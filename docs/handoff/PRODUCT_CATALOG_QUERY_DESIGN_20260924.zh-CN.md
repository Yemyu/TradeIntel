# 商品名称查询设计（2026-09-24）

状态：A 包止错、B 包商品目录与确认链路均已实施并通过定向验收。B 包从已保留的美国月包生成索引，并下载财政部税则 PDF 建中文搜索辅助；两包都未调用模型。项目目标仍是普通读者提问后获得真实贸易数据和可读报告；政策资料是相关时才加入的背景。

## 1. 实际问题

底层月度明细不是只有大豆和玉米。当前自然语言入口在 `trade_query_flow.py` 只登记这两个商品组名；其他商品必须让用户自己写准确编码。这与面向普通读者的工作台不相称。

本轮还用真实 `prepare_trade_question` 复现了两类错误：

| 原问题 | 当前返回 | 应有行为 |
| --- | --- | --- |
| 最近美国大豆和小麦出口有什么变化？ | `ready`，只选大豆 `1201` | 识别多商品，先请用户选一种；不能忽略小麦 |
| 最近美国大豆和咖啡出口有什么变化？ | `ready`，只选大豆 `1201` | 同上 |
| 2026年5月和7月美国大豆出口有什么变化？ | `ready`，只取2026-05 | 询问要分别比较两月，还是查询5月至7月的连续区间 |
| 美国大豆出口7月有什么变化？ | `ready`，取默认最近12个月 | 先确认“7月”的年份 |
| 美国大豆和1201900090进口有什么变化？ | `needs_product`，把名称和细码当成两个商品 | 提醒“大豆全组”与“该细码”范围不同，让用户选择 |

这些是内容正确性问题，先止错，再扩大支持面。不能以“页面会让用户确认范围”作为忽略原问题的理由。

## 2. 已有来源与采用规则

本机保留的 Census 进口 `IMDB*.ZIP` 和出口 `EXDB*.ZIP`，每个月都附 `HSDESC.TXT`（HS2/4/6 商品组英文描述）和 `CONCORD.TXT`（进口 HTS10、出口 Schedule B 十位码英文描述）。2026-07 包实测进口约20,393个十位码、出口约9,787个。成员名在不同月份有大小写差异，读取时按大小写无关匹配。月度原包的 URL 和 SHA 已在对应发布清单中，分类索引应引用这些来源，另记录所读成员的 SHA 和解析器版本。

进口和出口各建自己的候选索引，保留 `flow / month / level / code / official_en / source_url / source_sha256 / member_sha256`。最近共同窗口是 2025-08 至 2026-07；进口另外还有 2016-01 至 2018-05、2025-01 至 2026-07 的月包，**中间不是连续数据**。第一版优先服务最近共同窗口，历史月份按实际可用目录逐月开放。索引文件采用可复算的项目级发布文件，不强制增加新数据库服务；MySQL 查询副本另按既有同版核验计划处理。

美国进口使用 HTS、出口使用 Schedule B。两者在 HS2/4/6 层级有共同基础，但十位细码不能互换：同是大豆，本地2026-07进口有 `1201900090`，出口有 `1201900095`。[Census 定义](https://www.census.gov/foreign-trade/reference/definitions/index.html)和[Schedule B 常见问题](https://www2.census.gov/programs-surveys/trade/schedules/b/sbfaq.html)支持这个边界。[USITC HTS 历史目录](https://www.usitc.gov/harmonized_tariff_information/hts/archive/list)与[Census Schedule B 年版](https://www.census.gov/foreign-trade/schedules/b/index.html)供按日期复核；本地月包中的英文描述用于本产品的数据查询范围，不充当关税裁定。

中文查询需要另建按 HS4、必要时 HS6 对齐的名称索引。[中国财政部发布的2026年税则](https://gss.mof.gov.cn/gzdt/zhengcefabu/202512/t20251231_3981044.htm)和[2025年税则公告](https://gss.mof.gov.cn/gzdt/zhengcefabu/202412/t20241230_3950785.htm)可作为中文品目名称来源；先小样验证提取质量，再决定是否处理完整 PDF。中国来源只辅助搜索和中文展示，最终商品范围以所选月份的美国 `HSDESC/CONCORD` 为准。源文件无法完整解析或逐码对齐时，要列出未覆盖范围，不能宣称支持全部中文商品名。

## 3. 用户看到的流程

1. 用户仍在同一个输入框提问。系统先识别贸易方向、日期表达、明确编码和商品词。如果发现两个商品、两个不连续月份或含糊的“7月”，先澄清。
2. 从当前方向和月份的官方分类索引找候选。精确编码和已核实别名可定位一个候选；一般名称只给排序后的少量候选。中文名称索引与英文官方描述都可搜索；模型以后可以帮助改写检索词，但不能直接指定最终编码。
3. 候选卡给普通人看完整范围：例如“咖啡及咖啡壳、含咖啡代用品（HS4 0901）”，并显示进口/出口、可查月份；展开后看英文原名、十位细码数量和来源。用户明确选中后才查金额。
4. 若问题问“咖啡”，候选可能涉及生咖啡、焙炒咖啡及提取物等不同编码；系统不能把包含咖啡壳的 `0901` 悄悄缩写成“咖啡豆”。“小麦”对应的 `1001` 官方组名是“小麦及混合麦”，卡片需完整显示。两例的英文范围已在本地2026-07 `HSDESC` 核实。
5. 查询结果仍进入现有报告页；金额、趋势、图表由程序计算。模型解释需要用户单独触发，并继续绑定已确认的数据报告。

查不到候选时说明具体限制并允许用户搜索/输入编码。纯商品问题不能因为目录无命中而自动落进旧钨或光伏政策案例；只有明确提到已登记政策且范围匹配时才走那条路径。

## 4. 服务端合同

保留 `/api/trade/prepare` 和 `/api/trade/report`，扩展字段而不改旧报告含义。

`prepare` 可返回 `ready`、`needs_direction`、`needs_product_choice`、`needs_period` 或 `not_available`。新增商品候选至少包含：稳定候选 ID、`flow`、`level`（HS4/HS6/HTS10/ScheduleB10）、`code`、美国官方英文范围、中文检索名及其来源、可查月份、分类索引版本、必要的范围提醒。普通页面默认展示名称和范围；哈希放内部记录和可展开来源处。

页面选择候选后，再传 `selected_product_id` 与 `catalog_version` 请求 `prepare`；报告请求继续携带数据版本，并携带同一商品选择与分类索引版本。服务器重查所选候选是否仍存在、方向/月份/编码是否一致，再生成报告；客户端不能自报一个未经目录验证的编码或把进口十位码用于出口。旧大豆/玉米入口仍经同一个确认过程，不能成为绕开校验的特例。

跨月查询必须核查每个月的分类组与描述。HS4/HS6组在所选窗口存在且范围稳定时，按各月有效十位细码的共同前缀分别汇总；如果组名/范围发生实质变化，先缩小时间范围或给出明确的不可比较提示。十位细码发生停用、改名或拆并时，不能继续画成同一条趋势。保留现有“无记录”和真实零值的区别。98/99章等特别编码先不通过普通商品名自动选择。

## 5. 实施包与验收

### A 包：立即阻止静默答错（已完成）

已修改解析器：商品连接词另一侧出现未识别范围时返回 `needs_product`；多个分开的月份或无年份的月份返回 `needs_period`；明确月份区间保留原范围；商品组和所属细码并列时要求确认范围。工作台只有在用户问题明确提到政策/关税等内容时才进入旧政策案例流程。变更集中在 `trade_query_flow.py` 与 `web/design-preview/live.js`，无需新目录下载，不调用模型。

验收结果：方案列出的5个反例均不能进入 `ready`；真实本地数据探测确认未生成缩窄范围。明确区间“2026年5月至7月”返回 `2026-05` 至 `2026-07`，“最近12个月”返回目录中的连续12个月；混合进出口通过已有集成测试。定向 Python 27 项、页面 Node 4 项通过。完整记录见[A 包运行记录](runs/20260924-A-COMMODITY-PARSER.md)。

### B 包：用分类目录扩大可查商品（已完成定向验收）

从本地原包构建按方向、月份和来源摘要绑定的分类索引；验证2025-08与2026-07包的成员大小写、字段长度和内容哈希。再接中文 HS4 名称来源、英文检索、候选选择卡以及报告版本重校验。先用小麦、咖啡、茶、棉花等未参与旧大豆/玉米开发的商品验证，再留一批未参与调试的商品做独立验收。商品词有歧义时显示候选，不以第一名直接出报告。

验收门：小麦/咖啡等提问出现正确候选及完整范围；选中后的最近12个月结果逐月等于现有受限查询对同一编码组的求和，并从原包的官方商品汇总表独立复算至少两个未参与开发的商品月；商品名称、进口/出口十位细码和年份不能混用；篡改候选 ID、换数据版本、缺分类来源均被拒绝并要求重新确认；页面刷新后仍显示所选范围。检查中文目录解析覆盖与抽样准确性，再决定能否对外使用“广泛中文商品名可查”的表述。

实施结果与边界见[B 包运行记录](runs/20260924-B-COMMODITY-CATALOG.zh-CN.md)。当前已能按 1,223 个中美同码 HS4 中文标题搜索，但日常说法的同义词仍不是全覆盖；不能将“标题编码覆盖约 98.4%”写成“自然语言识别准确率 98.4%”。小麦、咖啡、茶、棉花、手机、汽车、巧克力、原油等在真实目录中得到候选，汽车等泛词需用户选范围。两件未参与开发的商品月已独立对照官方原包汇总金额，浏览器走通新提问到报告及刷新恢复。动态交互的英文文案、MySQL 同版核验及模型横评仍待后续阶段。

两个包都不触发真实模型调用。B 包完成后，再继续既定的完整报告与多模型验收；那是另一个阶段，不能拿候选搜索通过率代替 AI 解释质量。
