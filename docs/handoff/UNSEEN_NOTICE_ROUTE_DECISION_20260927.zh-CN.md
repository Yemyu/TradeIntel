# 陌生公告验收的路线裁定：先修正报告边界

日期：2026-09-27。依据为 [事先固定的里程碑](NEXT_MILESTONE_20260927.zh-CN.md)、[五份公告筛选原记录](runs/20260927-UNSEEN-NOTICE-SCREEN.zh-CN.md)及当前代码的只读核查。此文是筛选后的**新决策**，不追改上一轮筛选条件或成绩。代码基点 `b555138`；工作区另有大量既有未提交文件，本轮不覆盖它们。

## 裁定

**先修正“公告原文说了什么”与“报告月份实际上适用什么政策”的边界；不为 2019 年 List 4 立刻建设通用修订链。** 完成安全边界后再另立一轮未见公告验收。通用修订/排除/编码版本链只有在要提供“截至某日的实际适用税率”时才是必需功能；现阶段的报告目标是有出处的公告内容和相关商品的已发布贸易数据，不是假装完成法律适用或政策效果判断。

2019 年 List 4 保持“文本结构合格、完整正向验收未通过”。原公告记载 10%，但官方后续公告至少在原定生效前把它改为 15%，后来又调为 7.5%；已查到的两次变更也不等于核全修订和排除链。因此 10% 只能叫“2019-08-20 这份原公告记载的数值”，**不能叫当时实际执行的税率，更不能叫现在的税率**。此前固定的五份候选已用完；这份材料已经用于发现设计缺口，以后不再称作未见留出材料。

数据同样限制结论：通用 HTS10 发布目录有 2016-01—2018-05 和 2025-01—2026-07，缺 2019 年 List 4 生效前后相邻月份。项目其他旧表虽有 2019 年记录，却是 List 1 商品，不可拿来补 List 4。`39269099` 的 2018-05 目录与明细细码集合还有待核对的差异；2026-07 又是另一组细码。因此不能把两端金额拼成“政策前后变化”或“2019 至今增长”。这些问题不是更强模型能补出的观测数据。

## 产品应当怎样说

- 页面先说明：“这份公告原文记载的税率和条件”；紧邻显著说明：“后续修订、排除及报告月份的实际适用税率未核对”。不能把警告只藏进来源折叠栏或报告末尾。2019 例子可进一步明确“原公告的 10% 在生效前已被修订”，但不据仅两份后续公告推断当前数值。
- 数据部分称“相关商品在所选月份的美国进口观测”，写清商品、月份、覆盖缺口和来源。可以展示 2025—2026 的近期贸易情况，但不能因此暗示原公告 10% 在这些月份适用；若用户明确选 2016—2018 月份，只能称远离事件的历史背景，不是紧邻政策的基线。
- 公告生效日晚于已发布数据末月时，只能显示实施前可见数据；没有数据就写“暂无实施后观测”。任何情况都不自动给政策效果、现行税率、应纳税额或投资结论。
- 旧报告也遵守这个阅读边界。旧记录缺少新状态字段时，前端按“现行适用状态未核对”保守呈现，不能因兼容性缺省为“仍有效”。导出和刷新后的文字须一致。页面上 `latest_available_month` 现在是**所选区间内**最近可用月，不能写成整个数据库的最新月份。

## 下一执行包：只做安全边界，不扩产品类型

1. `src/tradeintel_ai/announcement_statistics_report.py`：报告 `policy` 里增加不破坏旧字段的明确状态，例如 `rate_evidence_scope: "source_document_only"` 和 `current_applicability_status: "not_verified"`。这些是程序对**核验范围**的声明，不从自由文本 `revisions` 猜测现行法律状态。报告的摘要/存档照常覆盖新字段；确认摘要、贸易金额、既有 R2 商品/月份不变。若接口将来要求 `current_applicable_rate`，当前版本须明确拒绝，不能把原公告 `rates` 复制过去。
2. `web/design-preview/live.js`：标题、税率汇总与逐码详情都写“公告原文记载”，在走势图与公告详情之间放可见的“现行适用状态未核对”说明；中英文都做。旧 `announcement-statistics-report-v1` 存档没有新增字段时仍按未核对处理。导出视图不得比页面少这句限定。
3. `web/announcement-import.html`：确认范围时说清这是**所选区间内**最近可用月，告知公告原文税率不会被核定为报告月份现行税率。不要把 2019 年 168 页 PDF 裁掉附件来迎合当前约 256 KiB 的文本导入入口；完整原文超过能力时显示不支持并保留原件/摘要，不启用候选。
4. 对应 Python 报告与 Node 页面测试：给出原公告 10%、另有 15%/7.5% 修订但未形成完整链的反例；验证页面和导出不出现“现行 10%”语义。测旧存档、未知日期、未来生效但只有实施前数据、R2 数值不漂移、重启读回。若旧记录没有可安全渲染的关键字段，就受控拒绝，不在 UI 猜。

这一步**不做**：逐税号现行税率引擎、全 PDF/OCR 导入、补造 2019 月份、改变老实验冻结件、调整筛选门刷通过、再跑模型 API。不得把 `revisions` 一栏的自由文字直接解释成完整修订链。

## 实验与验收顺序

安全修复先用**合成反例和已见 R2 回归**验收，不能自称陌生公告泛化。假设是“来源税率与现行状态分开后，用户不会把原文税率误认为报告月份适用税率”；对照为当前页面/旧存档；代码与数据版本记录在执行日志中，R2 既有金额作为不变基线。指标不是模型正确率，而是错误现行税率声明 **0**、旧存档无安全默认 **0**、R2 金额/版本漂移 **0**，以及中英文页面、导出、重启恢复的限定文字均可见。预算为 **0 模型 API、0 MySQL 写入**，先定向测试，再浏览器查看；任一错误声明或历史数据被当成政策效果即停止扩展。

修复通过后，**重新预登记**下一轮最多五份官方公告：先写明来源、原文/附件可完整保存与核验、美国进口/中国原产/完整 HTS8、明确生效与入境条件、与已发布数据的时间关系；逐份留排除原因。上一轮五份及 R2 都是设计已见，不算新一轮未见样本。若没有合适材料，报“当前支持范围或数据时效不足”，不要继续挑容易题。通过门仍是从空白页人工确认到可复算、可恢复的报告；正式经济信息价值必须有与问题相称的可用月份和商品覆盖。遇到未来生效公告可以验“实施前情况说明”，但不能冒充实施后结果。独立重算一月一商品；不把数值回归和 AI 能力混作一个分数。

2019 List 4 若单独用于**历史流程负例/兼容性测试**，还须先核完整原文及附件、页码和摘要，解决 `39269099` 在 2018-05 的应有细码与发布明细差异，逐字段人工复核，并明确距离事件至少 16 个月、没有近端政策前后观测。现有页面只支持粘贴有限长度的文本，不能声称已完成 168 页 PDF 的空白导入。即使这些都通过，它也只证明诚实处理缺口，不计入上一轮完整正向验收。

只有以后确实要回答“某税号在某日实际适用什么”时，再另行设计逐税号、逐生效区间的官方修订、排除、条件和编码链；先用一个税号和一个日期作最小独立核验，缺任一环即返回未知。它不作为本轮修复的隐藏任务。
