# 三项公告阅读建议：真实调用前的判定

日期：2026-09-27。范围仅是新公告人工填写时的辅助阅读，不是普通商品查数、报告解释或政策自动发布。本次为只读复核，新增模型调用 0 次；没有改旧回答、账本、候选或数据库。

## 结论

**现有 `r2-v1` 离线包不值得直接发一次真实模型请求。**它已证明原文和编号可以封存、畸形回答可以拒绝，却没有证明三条简短建议能帮人填写字段。先做一次有明确终点的离线修订；若修订后仍无法在表单中减少查找和核对动作，就停止这条支线，不继续花 API 调用试运气。人工导入、确认和报告主路径不受此决定影响。

## 依据

1. R2 已见开发公告被拆为 **326 个物理行**，请求 **24,894 字节**，只要求三个简短回答。关键税率段落被断在 L223–L234：初始 **0% 是本次新增税率**，2027-06-23 的提高幅度尚未公布，原有的 **50% Section 301 税率另计**。行号虽能回溯原文，但孤立一行常不足以理解完整句子。
2. L299–L312 同时写中国原产、其他反倾销/反补贴等税费继续适用、以及仅针对保税区入区身份规则的 `domestic status` 例外。当前提示只说“条件和例外不要省略”，输出每字段一条建议、最多 8 个行号；很容易把适用条件、例外和一般免税混在一起。程序只核对行号存在，**不会证明行号真的支持模型的解释**。
3. 现有页面仍需人工填写 **13 个字段**及其状态、理由、引文；部分值是税号/税率等结构化内容。三条阅读建议即使正确，也不会自动填表。此前 R2 的 HTTP 验收使用了预先人工整理好的字段，没有记录一个人在页面逐格填写的时间或修改次数，因此不能宣称省时。
4. `r2-v1` 只有合成回答的结构测试，没有真实模型回答。旧的 13 字段试验也都未进入语义评分；不能把格式通过、引用可定位或旧调用接通当作本路线有效的证据。

## 下一包：一次离线修订，不调用 API

目标是让建议成为人工能直接对照的**逐条阅读笔记**，而不是另一份难核对的短报告。只改隔离的阅读建议模块、准备脚本及其测试；不改原文、原候选合同和公告启用门。

1. 把模型看到的物理行改为**连贯段落/条款编号**。完整原文仍全部送入，不按关键词截掉其他段落；每个编号可无损映射到保存正文的精确起止位置、原 `section_id` 和原文摘要。长段在句子或原始换行边界分割，不能切断引用而丢文字。离线验收为原文字节可复原、版本/摘要改变即拒绝、R2 关键段落在一个或少数相邻编号中可读、请求不过预算门。
2. 三个字段改为**若干独立要点及各自出处**，而非每字段一条笼统文字。通用提示只解释“新增税率与总税负”“生效/原产地/商品/入境条件”“特定例外与其他税费”如何区分；**不得把 R2 的 0%、50%、2027 日期等参考答案放进模型请求**。未知和原文冲突仍可如实返回，缺附件不得补造。
3. 用合成回答在表单旁做一版只读预览：点击要点能看到对应完整原文，不代填、不提交、不启用。由 R2 现有人工核准内容建立三字段逐事实核对表，至少分别检查“0% 不是总税负”“未来税率未定”“原有 50% 独立”“FTZ 例外不是普遍关税豁免”“其他税费仍适用”。参考表只供人工判分，不进入请求。
4. 记录人工基线：独立完成这三个字段需要查找哪些原文、填几条实质内容和引文；以后同材料只比较**实质改写/补查次数**。没有实际计时就不报节省分钟数。R2 是开发已见材料，不报泛化准确率。

离线修订的停止门：若来源编号仍把关键条款割裂、预览无法让人直接跳到核对处、三字段参考无法逐条评分，或需要删减法律条件才塞进预算，**结束 AI 辅助填表支线**。若全部过关，再单独冻结服务商实际型号、端点、推理参数、请求/输出字节、费用估算和一次调用上限，取得明确授权后才允许发一份 R2 开发请求；未知结果不自动重试。真实回答必须同时满足格式与引用合法、上述关键事实无严重误读、人工补查/实质改写确实少于基线，才考虑下一公告。任何一项失败即停，不换题刷成绩。
