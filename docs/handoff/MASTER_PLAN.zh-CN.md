## 1. 目标和真实进度

用户明确要一个可聊天、可接新政策、可持续更新、AI有实际帮助的贸易政策研究助手。最终目标保留完整产品；先交付可验证的T1，再扩到T2，不把固定案例当最终完成。

最终用户路径：给官方公告/提出问题 → 找到条文与商品 → 查真实贸易数据 → 程序计算暴露规模和结构 → AI给有出处的解读 → 用户查看证据/修订/导出 → 有新资料时更新版本与报告。

新政策刚发布时可报告：改了什么、哪些商品相关、最近可用贸易规模、中国来源份额、证据支持的机制与待观察指标。需要区分“已知事实”“有条件情景”“未知”。当前资料不能给可靠的数值走势预测；研究文献库/弹性参数/情景模型不是本轮完成条件。将来加入须独立设计和验证。

现状：数据工程与T1基础链有验收记录；G1已采纳。G2两次开发输出严重越界、已停止。v3是未采纳离线原型，45项测试通过是上轮记录；本轮未重跑全套。真实页面、T2接入、受控更新仍待完成。上一轮完成度百分比无权重或可验收分母，不继续用作进度或质量指标，改用本文件六个里程碑。

## 2. 技术决策：用单助手和可恢复工作流

### 必需能力与可选技术

| 能力 | 本项目选择 | 理由 |
|---|---|---|
| 读取外部资料再回答 | 必须；形成可评测的政策RAG | 回答应依据当前登记资料和用户提供的新公告 |
| 检索方式 | 精确政策/版本/HTS过滤 + BM25；再按引用关系补共同条款 | 税号和生效条件不能只靠语义相似度 |
| 向量/混合检索 | 可选升级，不是RAG定义要求 | 在同义问法或跨语言召回确实不足时对照验证 |
| 多智能体 | 不作为完成条件 | 现有步骤明确，一个助手调工具加程序工作流足够；增加角色不保证准确 |
| 模型训练/微调 | 不作为完成条件 | 当前首先需要正确材料和可验证的输出质量 |
| 聊天状态 | 必须 | 保存选定政策、商品、月份、版本、用户确认；每轮重新解析变更，不把聊天当训练 |
| 定时更新 | 必须具备可运行任务和版本保护 | 自动检测/下载/暂存；政策语义变化经确认发布 |

核心接口（建议新增适配模块，现有业务函数复用）：

- retrieve_policy(query, policy_id, version, products, as_of) → hits + required_context + coverage + citations。
- get_trade_metrics(approved_request) → 确定性指标和范围；禁止模型自由写任意SQL执行。
- build_brief_evidence(...) → 业务视图 + 完整审计映射。
- explain(...) → 引用型输出 + raw + usage + 待审结果。
- ingest_policy(...) → 候选字段与原文位置；confirm_candidate(...) → 有记录的确认。
- refresh_sources(...) → 暂存版本/差异；publish(...) → 原子发布；失败保留旧指针。

工作流状态保存：received → evidence_ready → generation_started → response_saved → needs_review → exported；每步持久化。发生started但没有响应时不盲目再调用。幂等键绑定request/version/model/prompt；重复点击不重复计费。用户确认与开发者测试审阅分开记录。

## 5. S1精确规范与预算决策

先补工程缺口再真实调用。此次选择：单次解释调用 + 去除重复业务表达 + 可逆审计sidecar。当前27个事实的资料量无需为了缩短输入增加第二次LLM。长文T2通过检索选取相关条文，但时间/原产地/共享限定和例外不能被top-k截掉。

业务视图采用可读JSON：request/policy identity、fact短ID和完整事实句、observation短ID与解释、policy_products（税率、名字、条件/例外状态及原因、字段来源ID）、policy_scope（日期/时区/事件/原产地）、sources（每段原文/URL只出现一次）、limitations、boundary、catalog hash。保留全部所选商品，不去掉非榜首以讨好预算。

审计sidecar保存原ID/短ID双向映射、每字段原路径、机器哈希/路径及重复关系；restore(view,sidecar)必须等于原messages业务JSON。重复条文使用source_id引用，其唯一原文在sources；重复共同条件明确继承，差异必须显式。原始档案保留全量。禁止丢字段后只靠原bundle拷贝冒充可逆，必须验证业务字段对应关系。aliases只替换标识字段，不能全局替换自然语言。输入不包含snapshot/评测参考；目录与调用方预期evidence hash核对。

优先利用已有build_view/restore和pack/unpack的去重思路；不要让模型展开深层$groups表才能读法律条文。plain JSON作为默认可读业务输入；pack的12245仅作为测量对照。

预算：旧8000是旧实验的工程门槛，不是已验证的模型上下文上限，旧包保持原值。本方案允许新v3协议使用目标≤8000、硬上限≤16000的保守输入估算，每次最大输出2000，单次超时90秒。正式调用前核验供应商模型上下文、参数兼容和账户实际配额，输入加输出不能超过其限制；不在本轮假定模型能力/免费包适用。新阈值只写新配置和新账本。超过16000停止该请求交Astra，不继续压缩法律内容。此为预算设计，不是本轮API执行授权。

S1待修列表：

- A3补全全部观察、并列、policy_facts业务字段、商品税率/条件/例外、时区、来源、局限，来源段落只显示一次。
- 单商品范围构成100%明确“本次仅选一项”；构成比例句明确美国消费进口；比例格式化使用Decimal而非再转float。
- 每个ID在set/membership之前校验类型，包括observation_id、policy source_id、metric_type；畸形JSON统一ValueError。
- 全商品请求与requested_products或policy rate集合完整匹配；必要profile键不可用get(None)混同缺失。校验policy sources和bundle同ID文本/摘要一致，字段引用绑定同policy/version，来源缺失不静默忽略。per_product只允许在相应原产地共同字段使用。
- 不把catalog自身重算哈希当外部可信；导出使用输入快照+调用方预期版本绑定。

## 6. S2真实AI验收（独立协议）

假设：完整事实句+清楚的政策原文+引用型解释能减少范围改写，并给出有帮助的解释。A3是完整程序事实/观察/政策报告；B3自由解释，C3引用型解释。B/C同一question和业务视图，仅输出契约不同；模型/参数一致，不能拿旧B做公平对照。

数据隔离：已见七月开发题用于调试；四个原正式任务未经确认不得查看参考/输出。题目选择、模型、输入、评分规则先冻结。若执行者已接触参考，该题降为开发并回Astra重新封存，不能自称留出。案例属于已知政策迁移，不称新政策盲测。

预算封顶10个解释请求：开发B/C各1、四正式题B/C各1。参数先核验GLM-4.7可用性；同轮固定模型。没有自动重试、自动修答或备用模型。规划API若确实需要，另在新协议单列≤2次；UI真实生成复用正式C槽，不加隐形调用。每次网络前写started，保存原答/原始错误/usage、请求摘要和版本。完成状态不确定即停止。

开发C首次严重错误即停止C支路并回Astra；B作为基准出现内容错误记录其失败，不自动叫停仍未运行的C，除非暴露共同资料错误。正式C出现严重错误停止采纳，不再修prompt刷剩余题；保留已运行与未运行。此规则与旧G2不同，仅用于新实验协议。

采纳门：四个C全部完成，零严重数字/政策/分母/商品/范围错误；至少3题原文无需实质重写可用，至少3题相对A3有明确受支持增益。增益可包括：按问题选重点、解释金额与份额的不同决策用途、联系商品统计范围与条款限定；泛化警示、复述、引用存在不能单独计分。先逐条写支持证据和错误，再汇总，不先写分数。小样本结果只对这些题有效，不包装成总体准确率。

审阅节奏：R1审完离线证据后运行开发B/C，交Astra一次；开发通过才允许正式题，执行方逐题核对严重错误，语义拿不准就暂停该支路，四题完成统一交Astra采纳。Astra不必审每个格式修复。若失败，提交根因与最多两个可选方向；禁止无限追加新轮。

浏览器验收：提问→确认→生成一次→打开原文→审阅保存→下载→重开相同版本；另测刷新恢复/重复点击/错误提示。先fixture验UI；真实生成计入S2。记录截图/下载文件哈希/操作结果；工具不能下载则保留该项未验，不能改成HTTP成功。

### T2新政策与检索

先支持官方HTML和原生文本PDF。复用现有解析库；扫描件低文本量标requires_ocr，不捏造解析。原文件URL/抓取时间/哈希/页码或段落位置保存。字段包括政策ID、发布/生效/时区、事件、原产地、编码及精度、税率含义、限定、例外状态、修订关系；每字段value/status/evidence location/quote。AI提候选，程序验类型/引文/日期冲突，人工确认后登记。

检索接口采用Haystack本地BM25，先筛policy/version/发布截止日；正文命中后按引用依赖补生效、原产地与商品共同条款，区分候选命中和已确认适用。中文问题保留术语桥接基准。HTS8精确匹配，HS6和HTS10标partial/ambiguous/absent，不能自动把附件税号泛化。发布日过滤不等于现行合法有效性。

检索验收预先冻结12条问题：6正常原文/同义问法、2共同限定、2跨版本、2无证据；每条标必须证据集合和不能返回的案例。正常与限定8题的required-context召回至少7/8；关键生效/原产地/例外依赖零漏项，版本污染零；2无证据题明确不足。只测检索，不作回答准确率。embedding/rerank仅在基准暴露同义召回不足后另批对照：同题同语料、固定模型版本、至少多找回2条漏项且不损失关键限定；不能在同一留出集反复调。

新公告迁移验收：由Astra在看模型输出前选定一份未参与开发的官方公告、字段参考及来源；Workbuddy可先完成候选接口和已知案例fixture。新公告抽取真实调用单列≤2次（已知开发1+新公告1），无自动重试；关键字段正确或明确未知、零无据肯定，未知不能冒充成功。若都未知，抽取可用性不通过。未选公告以前不虚构已完成盲测。

### 自动更新

提供refresh CLI和可外部调度入口，首期只允许已登记官方来源。自动检查→下载暂存→校验/差异→新candidate→人工确认发布；明确用户想要的自动检测已实现，但不能将未知修订自动批准。定时频率/机器与外发目的地未指定，交付命令/配置模板，不擅自创建持续任务。

下载使用超时/大小上限、白名单与重定向检查，不让任意文档链接读本机地址。贸易新月份、原月份修订、政策新条款分别版本化；数量/编码/文件坏了保持旧版。更新报告以最近已发布统计为准，不能叫“今日贸易量”。情景分析若缺数据只列机制和观察指标。

验收至少：无变化零重复版本、合法新月、旧月修订、坏ZIP/解析失败、政策冲突、发布中断与恢复、旧报告复现。通用网络幂等GET可有有界退避；模型调用不能自动重试。
