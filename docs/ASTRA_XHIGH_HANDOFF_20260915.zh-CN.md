## 4. 请集中解决的四个决策问题（按优先级）

### P0：证据怎样约束推断，而不是只检查引用编号？

现象：引用 ID 正确，仍能带入不受支持的法律或交易假设。关键词提醒只能辅助，可能误报否定句，也挡不住换一种说法。

需要 Astra 判断：分别定义事实、解释、调查建议的支持标准；如何区分“可以调查的假设”和“证据支持的重点”；哪些由程序保证、哪些保留人工判断。比较现有接口改良与必要架构调整，不默认再加一个模型裁判就解决问题。

交付要求：有具体输入/输出例子、错误机制、最小改动边界和采纳标准。不得靠删除所有分析、只剩免责声明来获得通过。

### P0：AI 要提供什么实际增值？

现象：查数有用，但泛泛的“需要企业合同/税单”未必值得用户使用这个助手。之前不同入口的能力也不一致。

需要 Astra 判断：锁定一至两个真正有价值且数据支持的用户任务；说明 AI 相较确定性报告多做了什么。识别当前任务是否给了模型足够信息，是否要求了数据根本支撑不了的结论。

交付要求：设计一份目标报告结构，逐项标出来自数据计算、政策证据、模型解释还是未知。不要预先手写答案冒充生成结果；不要暗中把产品改成纯查询器。

### P1：固定案例怎样变成可复用流程，而非越来越多特殊分支？

现象：主案例逐商品税率、第二案例统一税率、自然语言入口与结构化入口存在不同契约。现有事实卡基于固定存档，不等于任意新政策可用。

需要 Astra 检查：政策/商品/条款/版本的绑定是否足够明确，逐商品适用条件是否保留；共用字段和案例特殊字段如何组织；新增政策需要人工登记什么，AI 可以提取什么。明确最小支持范围，不扩成全球平台。

交付要求：复用现有模块的接口决策和迁移验收标准；第二案例不能仅靠开关直接发布。

### P1：怎样一次验收，结束反复修补？

现象：聚焦测试通过不代表模型内容通过；历史全量测试记录有失败和错误，尚未全部分类；页面实际使用仍未确认。

需要 Astra 判断：哪些失败属于当前产品缺陷、旧冻结实验的哈希保护或不可复现依赖；划定当前产品测试集与历史存档，不得更改冻结哈希来强行变绿。

交付要求：有限的工程回归 + 小规模真实业务评估 + 实际网页操作验收，给出完成与停止条件。不能只增加测试总数，也不能把待人工审阅自动当失败或自动当通过。
