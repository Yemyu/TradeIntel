# TradeShock：项目介绍与演示入口

## 一句话理解

它是一名范围有限的“贸易政策研究助手”：你用中文提出问题，它先把查询范围列给你确认，再查本地官方贸易数据、寻找政策原文，生成带来源的中文报告。

不是训练一个新的ChatGPT，也不是证明关税一定造成了某个变化。我们把现成大模型、检索、数据计算和执行约束组合成特定场景的应用。

## 三分钟看成果

推荐先打开[三文件展示入口](showcase/README.zh-CN.md)，内容已集中为项目说明与两份真实报告，可直接阅读，不需要运行环境。

1. 打开[真实组合报告](experiments/phase-0140-live/combined-report.zh-CN.md)，先看贸易金额，再看政策解释和原文证据。
2. 看[该报告的审核说明](experiments/phase-0140-live/README.zh-CN.md)：金额上涨是描述性观察，不是政策造成的效果。
3. 看[固定六题验收](experiments/product-acceptance.zh-CN.md)：保留反向比较失败。后续修复的是程序保护，没有把失败改写成成功。

这些链接展示存档结果，不产生API费用。报告引用的部分同目录JSON只保存在原始本机运行目录，展示摘录不是全部审计文件。

## 各部分负责什么

| 部分 | 实际作用 | 边界 |
|---|---|---|
| 数据工程 | 官方数据采集、清洗、商品口径、MySQL数据层及分析表 | 新电脑完整重建尚未验收 |
| 描述性分析 | 程序计算进口额、变化额与变化率 | 不等于因果效应 |
| 大模型规划 | 把中文需求转成结构化范围 | 可能理解错，执行前需确认 |
| 政策检索与生成 | BM25/词法检索、查询扩展、原文窗口、GLM引用式回答 | 两份历史公告的已索引正文，不是全网政策库 |
| 执行保护 | 只读、范围和方向检查、调用记录 | 不是通用语义正确性保证 |
| 因果研究 | 尝试建立可信对照与识别条件 | 尚无可采纳的因果估计 |

没有训练/微调模型，没有多智能体系统。AI价值在于受约束的业务流程，不是技术名词数量。

## 在自己的电脑上怎么用

你现在这台电脑已有虚拟环境、数据和本地模型配置，不需要重新安装MySQL或反复输入密钥。按[中文操作说明](learning/using-the-research-entry.zh-CN.md)运行并检查预览即可。日常报告读取准备好的文件，不需要同时打开MySQL终端。

确认前看国家、商品、月份、比较方向；政策问题另外看资料截止日。输入yes才执行。错误或方向不一致时不要强行确认。新问题会产生新API调用，不继承存档报告的审核通过状态。

新电脑则需要虚拟环境、requirements.txt依赖，以及分析数据、政策快照和校验清单。仓库展示材料不等于全部本机数据；目前不能承诺“下载仓库后一条命令重建所有结果”。不要把`.local`或凭据配置打包给别人，外发之前需单独检查。

### 数据是否齐全

项目根目录运行：

```bash
.venv/bin/python scripts/verify_portable_data.py
```

它只读取并计算四个容易被Git忽略的文件的大小和SHA-256，不下载、不修改文件。输出`"status": "ready"`才代表当前机器的这组数据齐全：两份政策PDF、政策来源清单，以及约45 MB的HS6贸易面板。缺失或哈希不一致会返回非零状态。详细路径和官方下载地址在[data/PORTABLE_DATA_MANIFEST.json](../data/PORTABLE_DATA_MANIFEST.json)。

这不是完整项目重建验证，也不意味着因果分析已经可用；面板是严格工作流的冻结依赖，当前因果识别仍被匹配条件阻断。

需要传递文件时，可以生成一个普通文件夹（不压缩、不覆盖已有目录）：

```bash
.venv/bin/python scripts/prepare_portable_data_bundle.py --output tmp/portable-data-bundle
```

它只复制清单中的四个文件，并生成中文说明和文件指纹；没有API配置、密码、原始Census压缩包或临时运行记录。接收者把文件夹里的`data/`合并到已准备好的项目根目录，再运行核验命令。这个文件夹不是独立项目，不能单独启动软件。

## 申请材料可用的事实草稿

> 构建基于美国官方贸易数据与历史政策公告的AI研究助手，集成中文结构化查询规划、BM25政策证据检索、GLM引用式回答和确定性贸易计算；实现执行前范围确认及错误方向拦截，并保存来源与调用记录，开展有界场景验收和失败分析。

这是项目事实草稿，不是已提交的简历。讲述时应说明使用AI辅助开发，能解释自己的业务判断和验证方式。不能写“训练了大模型”“证明关税造成某百分比变化”“RAG准确率显著提高”“独立测试准确率83.3%”或“企业级生产系统”。
