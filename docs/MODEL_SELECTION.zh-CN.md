## 先看清评分对象

此前口头所说“AI 效果证据 4/10”容易误解。它只是**当前项目的 AI 验证充分度主观评价**，不是某个模型的正确率，更不是产品接入不同模型后都不变的分数。今后模型成绩按确切型号、推理配置、题包/评分版本和渠道分别列行：`Q/R` 为收到原答中整题验收通过的数量；接口无答、待审阅、未运行另列。最终选定配置的“用户提问到审阅导出”完整链路另记 `D/N`，不能用回答通过率代替。相关定义与新统一四题接线见[设计记录](handoff/UNIFIED_FOUR_QUESTION_EVAL_DESIGN_20260923.zh-CN.md)。

较强模型可能在同题上给出更好的解释，但需要实测；更换模型不会修复缺失的数据、失效的题包或程序错误。以下旧组结果仍按原协议保留，不合并出一个产品通用准确率。

## 低成本方案：两种配置，每种四题一次

首轮建议先用 SOL 中推理＋Luna 最高做低成本对照；国内 API 候选按六配置清单分批加入，不再安排千问。各自在无项目历史的新会话独立作答；当前对话已见失败分析，不能用于公平打分。最终运行时推荐必须有实际 API 验证。Astra 中用于审查及必要时追加对照，首轮不测最高/Ultra。这是节省预算的项目选择，不是性能排名。

四题规格如下，具体证据与独立参考尚需准备并在开跑前一起锁定：

1. 多商品业务题：解释金额榜首与中国来源份额，明确分母和比较范围。
2. 单商品/范围题：所选范围的占比不能推广到整个市场，不混淆政策登记与贸易覆盖。
3. 政策限定题：新增与既有税率、未来未知调整及有条件例外，提出证据支持的研究重点。
4. 信息不足题：缺商品、月份或必要证据时准确说明缺口，不编造报告。

至少一道业务题采用未参与开发的材料；候选收到相同证据、问题和输出要求。每题独立上下文，每模型一答，无中途提示修改、补答或自动重试。答案、其他模型回答和评审文件不进请求。

先跑前两题；严重语义错误则停该候选，显示已答/计划及未跑数，不把未跑算错或通过。两题均通过，再跑后两题。最多8次回答；达到用途便停止加测更贵档位。新设计是后续评测协议，不解除旧实验停止标记。

中文输出目标150—250字、固定JSON。每题争取约4000输入tokens以内；关键证据放不下时提前报告，不能删法律条件。最终入选配置还需一次完整长输入真实链路验证，短题成绩不证明长输入可靠。

付费API需记录输入、输出、推理tokens及费用；短答案不代表推理成本低。实际API模型ID、价格和预算未知时先不报虚构金额、不发付费请求。会话会消耗订阅额度，精确用量不可见就记“未知”，不能记0。本次只做设计，未启动新模型调用。

## 项目收口标准

可以将目标收敛为“明确支持范围、需人工审阅的贸易政策研究助手V1”。模型是产品依赖，错误回答仍然影响产品质量，不能因为错误来自模型就算完成。

V1至少需要：

- 所选配置通过固定四题业务/边界验收；这只是小规模验收，不是生产质量保证。
- 真实API完整输入→生成→人工审阅→导出贯通，错误回答不能直接变成核准报告。
- 新公告接入与受控更新在真实持久状态验证；已有fixture不等于完整验收。
- 启动方法、适用范围、失败处理及历史测试问题说明清楚。

达到以上目标便可收口，数据扩充和自动化升级作为下一版本，不继续为所有假想政策无限改提示。目前优先换候选做固定小样本比较，不能仅凭带答案的对话演示宣布“唯一瓶颈已证实是模型”。

方法参考：[OpenAI评测实践](https://developers.openai.com/api/docs/guides/evaluation-best-practices)强调明确指标、代表性任务及评审；四题、两配置和停止规则是本项目的成本取舍，不是官方质量保证。
