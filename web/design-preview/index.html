TradeIntel 是一个开源贸易研究 Agent。用商品名称或编码提问，可以查询进出口数据和相关政策，再接着问其他方向、伙伴或月份。

AI 理解问题、接续追问，并根据工具返回的结果决定继续查什么。程序核对查询范围与数据，计算金额，生成带图表和出处的报告。

项目功能

能做什么

商品查询

查询商品的美国进口或出口金额，查看可用月份、最新数值和逐月图表。名称不明确时，助手会先确认商品范围。

连续追问

问完大豆进口，可以继续问“出口呢？”。也可以换商品、改查中国伙伴或调整月份，不必每次重新交代整个问题。

政策资料

检索本地已登记的政策文档，查看相关原文、出处和共同条件。资料命中与商品是否实际适用是两回事。

AGENT

如何工作

助手不是按固定表单逐项填参数。模型把用户的问题转成查询步骤，读取工具返回的结果，再决定补查、询问还是完成任务；程序负责执行查询和检查数据。

  1. 01模型

    理解问题

    识别商品、方向、伙伴和时间；接着前一轮问题处理追问。

  2. 02模型与工具

    查找并查询

    模型查商品目录和可用月份，选择查询参数；工具读取对应记录，核对范围并计算金额。

  3. 03模型

    根据结果继续

    读取返回结果，决定是否补查另一个方向或政策资料；有真实歧义时询问，完成时提交本轮报告与引用。

  4. 04程序与网页

    保存并展示

    检查报告和引用，保存结果，展示摘要、月度图表、详细数值和出处；用户可以返回对话继续追问。

需要补查时，第3步会回到第2步，而不是每个问题都走一次固定流程。工具检查仍然有效：缺少的月份不填成零，也不能未经确认改查其他月份。现有报告的摘要和图表由程序生成，不是模型自由撰写的经济分析。

数据底座

数据来源与范围

贸易数据来自美国人口普查局逐月商品明细，商品名称与编码来自官方目录。项目将原始文件整理为按月查询的数据表，并保留来源、版本和文件校验信息。

  1. 官方原始文件

    逐月贸易明细及商品目录。

  2. 整理数据

    按商品、方向、月份与伙伴整理金额。

  3. 核对与登记

    检查金额、范围、文件摘要，登记可用版本。

  4. 查询用数据

    本地服务读取已登记的处理结果。

数据工程部分提供 MySQL 镜像和核对脚本；日常网页查询读取已登记的 CSV 数据文件。MySQL 是数据工程的一部分，不是公开展示网站的在线数据库。

技术实现

各部分负责什么

模型 API
理解问题和追问，结合工具结果安排查询；有歧义时询问，完成后提交报告与引用。可配置不同服务商。
Python
本地服务、查询工具、范围校验、金额计算与报告保存。
CSV + JSON
贸易记录、商品目录、数据清单与已保存的对话和报告。
MySQL
数据镜像与核对脚本，不承担网页主查询。
BM25 + 编码匹配
检索本地政策原文并保留相关条件。
HTML / CSS / JavaScript
双语展示、对话与共用图表报告；COBE 提供地球动效。

使用方式

阅读展示，或在本地使用

公开展示

直接阅读已保存的问答和报告，不发送新的模型请求。钨与光伏案例是一份资料编辑稿，用来展示政策与进口图表的阅读形式；不是一次保存的模型对话。

本地使用

准备 Python 3.12 和发布的数据包，启动本地服务，再配置自己的模型 API，即可在浏览器里提问。没有模型时，可用数据查询模式手动确定范围。安装步骤和数据包下载见快速开始。
